# 工作负载

**时间范围**：2018-05-25 至 2022-11-24（GDPR 前 4.5 年）。与 Enforcement Tracker 和 GDPRhub 的比较也使用同一时段（§5，PDF p.8）。

**语料规模**：

| 内容 | 数量 |
|---|---|
| 执法先例 | 3,343 |
| 官方指南 | 5,600 |
| 合计 | 8,943（摘要称 8000+） |
| 去掉驳回、拒绝、未发现违规的执法 | 2,795（用于罚款分析） |
| 引用第 17 条（RTBF）的决定 | 175 |

（§5.1、§5.2 脚注 5、§5.3，PDF pp.8–10）

**爬取管线**：47 个来源网站；Python 约 15K 行，BeautifulSoup + Selenium 下载，PyPDF 转文本，Google Translate 译成英文。在 GCP n2-standard-4 上完整构建约 22 小时（顺序爬取，每次下载后等 2 秒）；无新增时的增量运行不到 1 小时；平均每月新增约 200 份，作者建议每月爬一次（§4.1，PDF p.6）。

**过滤**：排除 2018-05-25 之前的文件，并保留含 GDPR、General Data Protection Regulation、EU 2016/679、条款名称或其各国译名（如西班牙的 RGPD）的文件；每个 DPA 随机抽 25 份检查，假阳性率不超过 5%（§4.3，PDF pp.6–7）。

**RTBF 编码**：由一名有隐私法课程背景的计算机研究生对 175 份决定做开放编码，16% 的决定含两个以上失败原因；三位作者（两名计算机、一名法学）随机抽 25 份复核，未发现分歧（§5.3，PDF p.10）。

阅读者分析：一致性复核只覆盖 25/175 份，且未报告一致性系数，因此 16 类失败的分类可靠性证据有限。

依据：[PoPETs 2023(4)，16 页](https://lawfulcomputing.org/papers/pets2023.pdf)，§4.1、§4.3、§5、§5.1–5.3，PDF pp.6–10。
