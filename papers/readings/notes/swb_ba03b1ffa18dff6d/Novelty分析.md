# 贡献与评价

**论文声称的贡献**（§1，p.3）：

1. 把 Chain-of-Thought 扩展到表格场景，以变换后的表格存放中间结果；
2. 在 WikiTQ、TabFact、FeTaQA 上取得当时最佳结果。

**与相近工作的区别**（§2–3.1，pp.3–4）：Dater 的分解步骤固定，只有选行、选列；Binder 可调用新操作，但仅限 SQL/Python 解释器能执行的操作。Chain-of-Table 由 LLM 按输入动态选择操作序列，作者称可接入多种工具的操作。

**评价**：核心新意在于"中间状态是表"，并由 LLM 逐步规划操作，形式上接近一个由 LLM 驱动的、小型操作代数的交互式查询计划。附录 A.2 的留一消融显示每个操作都有贡献：去掉 `f_group_by` 使 WikiTQ 下降 5.43 点，去掉 `f_select_row` 使 TabFact 下降 4.40 点（Table 5，p.13）。

阅读者分析：操作池只有 5 种，不含连接，聚合只有 `f_group_by` 的计数（附录 A.1，p.13），求和、平均等计算依赖 `f_add_column` 由 LLM 直接填写单元格值；因此它并非完整的关系代数。论文没有分析 LLM 填值出错的比例。

阅读者分析：效率比较（Table 4）只统计"生成样本数"，未统计 token 数或延迟；每步都把整张中间表放进提示，长表的 token 成本可能更高，原文未量化。
