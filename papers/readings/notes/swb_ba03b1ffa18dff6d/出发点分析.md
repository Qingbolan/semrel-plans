# 出发点

表格通过行列交互承载信息，比纯文本更难让语言模型理解（§1，p.1）。已有路线有两类：一是为表格专门预训练（TaPas、TAPEX 等）；二是用 LLM 提示做推理，包括通用推理（CoT 等）和程序辅助推理（Text-to-SQL、Binder、Dater）（§1–2，pp.1–3）。

作者指出两类提示方法的共同问题：推理步骤以自由文本或代码表示，不适合复杂表格。Fig.1 的例子中，国籍与人名写在同一单元格里，例如 `Alejandro (ESP)`，于是通用 CoT 会数错前三名，生成的 SQL 也无法按国籍分组（Fig.1，p.2）。

程序辅助方法受单次生成限制：LLM 无法根据问题修改表格，只能在静态表上推理（§2，p.3）。Dater 虽会分解表格，但其操作仅限选行、选列，且对所有表和问题固定，作者认为它更接近"LLM 辅助的数据预处理"，而不是推理链的一部分（§2，pp.3–4）。

出发点因此是：把表格本身作为中间"思维"，让每一步推理对应一次可执行的表操作，并由 LLM 动态规划下一步（§1，p.2）。
