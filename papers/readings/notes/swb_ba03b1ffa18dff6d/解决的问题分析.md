# 解决的问题

**形式化**（§3，p.4）：每个样本是三元组 `(T, Q, A)`，T 为表格，Q 为问题或陈述，A 为答案。表格问答中 Q、A 均为自然语言；事实验证中 Q 为陈述，A ∈ {True, False}。目标是给定 `(T, Q)` 预测 A。所有表格都序列化为文本，正文采用 PIPE 格式（附录 D，p.16）。

**推理流程**（Algorithm 1，p.4）：

1. 操作链 chain 初始化为开始标记 `[B]`。
2. `DynamicPlan(T, Q, chain)`：LLM 基于当前表、问题和操作历史，从操作池中选下一个操作 f（§3.2，pp.4–5）。
3. `GenerateArgs(T, Q, f)`：LLM 为 f 生成参数，用简单正则解析（§3.3，p.5）。
4. 用程序执行 `f(T, args)` 得到新表，并把 `(f, args)` 记入链中。
5. 生成结束标记 `[E]` 时停止，再由 `Query(T, Q)` 根据最终表作答（§3.4，p.5）。

**原子操作池**（附录 A.1，p.13）：`f_add_column`（新增列存放中间结果）、`f_select_row`、`f_select_column`、`f_group_by`（分组并计数）、`f_sort_by`。作者称框架可容纳更多操作，但留作未来工作。

**工作单位**：一个表–问题对，经若干轮 LLM 调用后输出一个答案。搜索策略为贪心，不做 self-consistency 采样（§4.5，p.9）。
