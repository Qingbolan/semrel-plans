# 具体用例

**付款—发票匹配**（Figure 5，§5.1–5.2，PDF pp.7–8）：企业收到银行流水（账户、业务伙伴名、金额、过账日期、自由填写的备注），要与 SAP 中未结发票（VBELN、KUNNR、ZTERM、WRBTR 等字段，分散在发票头、金额/到期日、客户三张表）对应。

实验从学术式设定逐步加难：

1. Clean：扁平视图、1:1、备注含正确参考号、金额与名称完全一致；
2. + Errors：参考号多/少位、金额小幅偏差；
3. + Multi-Matches：一笔付款付多张发票或多笔付一张；
4. + Multiple Tables：发票按原 SAP 多表呈现。

Exp. 6 单独注入四类错误：金额扣减至多 0.1 美元、改动 assignment 号、改动 billing 号、业务伙伴名缩写（如 “KL Technologies” 代替 “Kim & Lee Technologies”）。名称错误造成的下降最大，数值字段错误影响较小（Figure 6，PDF p.8）。

阅读者分析：此用例对应本项目中的“语义连接/实体匹配”算子，但它被表述为逐对二分类，成本为 O(N×M)；作者在 §7 估算 1,000×1,000 对需约 1,462 美元，提示实际系统必须先做候选裁剪（阅读者分析）。

依据：§5.1–5.2、§7、Figures 5–6，PDF pp.7–8、12。
