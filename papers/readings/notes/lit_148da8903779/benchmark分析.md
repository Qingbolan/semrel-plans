# 评测与边界

**基线**（§4.1，p.7）：SGLang（仅 GPU 的 radix 缓存，驱逐后重算）；SGLang w/ HiCache（分层 radix 缓存，异步把常用节点备份到主存，按层流水重叠加载与计算）。指标为端到端延迟，报告相对 SGLang 的加速比。论文明确不评测输出质量，理由是不改变模型与解码。

**实验 1（单工作流，Figure 5，pp.7–8）**：所有设置下 KVFlow 加速最高。A10G 上 8192/32/32 时，比 HiCache 快 1.83×，比 SGLang 快 2.91×。固定前缀 8192 时平均加速 1.48×，4096 时 1.28×。输出越长收益越小，因为解码时间占主导。H100 上部分大上下文设置中 HiCache 收益很小甚至变差，作者推测为 SGLang 流水调度问题。

**实验 2（高并发，Figure 6，pp.8–9）**：KVFlow 相对 SGLang 最高 1.25×；HiCache 在高并发下表现差，例如 1024 固定提示、64 并发时只有 SGLang 的 0.57×；KVFlow 相对 HiCache 最高 2.19×。作者认为 HiCache 的被动回载打乱了调度，且 SGLang 的碎片化 KV 布局限制 PCIe 利用率，KVFlow 同样没有解决碎片问题。

**实验 3（PEER 风格，Figure 8，p.9）**：KVFlow 相对 SGLang 与 HiCache 最高分别 1.12× 与 1.08×。

**边界**：论文没有独立局限章节。正文说明：并发过高、显存全被活跃请求占用时不在优化范围内（§4.2，p.8）；输出很长时收益递减（§4.1，p.8）。阅读者分析：微基准提示为随机 token；未报告方差；未与其他工作流感知调度系统（如 Autellix）直接比较；“最高”加速比都取自特定设置，不应外推为平均收益。
