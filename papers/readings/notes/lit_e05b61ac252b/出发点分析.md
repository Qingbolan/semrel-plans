# 出发点

表格广泛用于表格问答、事实核查、表到文本等任务，CoT 等提示技术已让 GPT-3.5 在一些表格任务上表现不错（§1，p.1）。但作者指出两点空白（§1，pp.1–2）：

1. 缺少系统研究来检验 LLM 是否真正理解表格结构、以及理解到什么程度；
2. 表格序列化与提示的输入设计五花八门且缺乏共识——TaPEx 用 `<HEAD>`、`<ROW>` 特殊标记，TABBIE 同时按行和列序列化，TableGPT 用模板把属性-值改写成句子。

因此作者提出核心问题：**什么样的输入设计最能让 LLM 理解表格？** 并据基准发现设计改进下游任务的提示方法（§1，p.2；§3 开头）。

此外，长表受模型上下文限制（text-davinci-003 为 4k token），截断会破坏结构；作者在 token 超阈值时随机抽样行，并按剩余容量追加 1-shot 示例（§2.2，p.3）。

阅读者分析：研究对象是“把表格作为文本放进提示”的范式，结论受当时模型（2023 年 GPT-3.5/4）与 4k 上下文约束影响较大。

依据：§1–2，PDF pp.1–3。
