# 解决的问题

**输入**：数据环境 `E`，可包含数据库、文件及沙箱代码可访问的资源；用户自接入，或从 Spider、LiveSQLBench、SpreadsheetBench 等基准中采样（§2，PDF p.2）。另有每任务 API 预算、MCTS 迭代数、目标轨迹数及三档模型池（Cost-Effective / Capable / Premium）配置（§4.1，PDF pp.3–4）。

**输出**：数据智能体轨迹，每条是 `(state, tool call, observation)` 元组序列，可含“错误—诊断—修复”片段；以 SFT 多轮样本或 ICL 示例两种方式导出（§2，PDF p.3）。

**工作单元**：一个“任务”= 从数据依赖反推出的分析问题，附执行得到的答案键与执行证据。轨迹只有在确定性校验器确认其执行输出复现了建任务时记录的证据、且最终答案与答案键一致时才被保存（§2，PDF p.2）。

**优化目标**：在每任务预算下最大化轨迹质量。质量是 0–1 分数，由执行信号（如步骤成功率、分析进展）与对答案键的确定性检查组成（§3，PDF p.3）。原文未给出该分数的具体公式与权重。
