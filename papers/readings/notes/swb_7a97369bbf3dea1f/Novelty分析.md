# 贡献与评价

**系统组成**（§2，PDF pp.2–3）：

1. **任务池构建**：先剖析环境（schema 元数据、样本行），用预定义 SQL 模板发现数据依赖（如多表共享的客户 ID、各地区取消率差异），再让 LLM 把依赖表述成问题；依赖先执行再出题，结果作为答案键。随后重放解题步骤、重跑查询确认结果稳定，并剔除 LLM 不访问数据就能回答的问题。
2. **Trajectory Explorer**：MCTS，节点是分析状态、边是由某一 LLM 配置生成的工具调用；同一环境的任务共享前缀（schema 发现、数据剖析只跑一次）；执行出错时不丢弃，而是分出修复分支并保留为训练数据。
3. **Learned Cost Model**：从状态特征（轨迹进展、schema 覆盖、近期错误历史）对每个可行配置（算子、模型、上下文长度、推理强度）打分，即预测奖励 μ 加探索项 σ；由排名靠前配置的分歧决定分支宽度 K，并随预算减少而收窄；用岭回归在线更新 bandit 参数。

阅读者分析：这是“MCTS + 上下文 bandit 选模型 + 执行验证”的组合工程，新意在于把代价感知的模型路由与跨任务前缀复用放进轨迹合成。作为 4 页演示论文，算法细节（奖励定义、特征、MCTS 参数）与消融都很简略。“严格隔离下游基准以防污染”只是断言，原文未说明如何验证；任务源本身包括 Spider 等公开基准（阅读者分析）。
