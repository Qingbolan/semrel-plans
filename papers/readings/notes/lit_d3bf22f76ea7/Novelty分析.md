# 贡献与评价

**原文贡献（§1，p.2）**：

1. 一个模块化、可解释的框架，把复杂问题分解为 SQL、LLM 或 VLM 步骤；
2. 在多个混合问答 benchmark（含多模态）上取得大幅领先；
3. 计划优化策略，以及保存全部中间结果以便调试。

**其他设计**：作者自行构造“混合子集”，并提出 Relaxed Exact Match（REM）指标：先用 LLM 把答案格式对齐到金标准，再做精确匹配，剩余分歧由人工检查语义等价（§3，pp.4–5）。

**评价（阅读者分析）**：LLM 步本质上是对一列逐行做语义映射并生成新列，相当于把语义 map/extend 算子嵌入 SQL 计划。新意在于计划由 LLM 一次性生成、并能在 SQL 与 LLM 步之间多次交替，而不是在执行优化上有新方法。

**评价（阅读者分析）**：REM 引入了 LLM 归一化和人工判断，与其他论文的 EM 数字不可直接比较。混合子集依据 Binder 生成的 SQL 是否含 UDF 来筛选，筛选标准本身依赖一个基线方法。

**评价（阅读者分析）**：Table 7 显示 GPT-4o 在 WikiTQ 上共用了 46 个 LLM 步、1,530 个 SQL 步（p.21），说明在这个“混合”子集上，大多数步骤由 SQL 完成。

依据：§1、§3、Appendix A.7、D，PDF pp.2、4–5、21、24。
