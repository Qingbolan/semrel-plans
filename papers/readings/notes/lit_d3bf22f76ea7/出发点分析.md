# 出发点

真实表格常常在结构化字段里夹带自由文本或图片。SQL 和 Python 擅长结构化运算，却处理不了文本、缺失值和隐含关系；LLM 理解语义，却受长上下文和数值、时间推理的限制（§1，p.1）。

**示例（Fig.1，p.1）**：WikiTQ 问题“Which country had the most competitors?”需要先从车手姓名推断国籍，这一步 SQL 做不到；之后再按国家分组计数，这一步 LLM 容易出错。

作者认为现有方法各有不足（§1，pp.1–2）：

- Binder、BlendSQL 把 LLM 当作 SQL 中的 UDF，属于单步执行，复杂查询时 LLM 难以写出正确的多步逻辑；
- H-STAR、ReAcTable 先剪枝表格，但 API 调用开销大；
- ProTrix 只有“先计划后推理”两步，难以处理多跳问题。

因此作者提出：让 SQL 与 LLM 按步交替执行。
