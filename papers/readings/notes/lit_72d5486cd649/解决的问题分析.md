# 解决的问题

论文围绕三个研究问题（§2，PDF p.3）：
- Q1：主流 Text-to-SQL 基准的标注错误率是多少？
- Q2：标注错误如何影响智能体的表现与排行榜排名？
- Q3：SAR-Agent 检测标注错误的效果如何？

**审查单元**：一个标注样例 = 自然语言输入 T（用户问题 + 可选外部知识）+ 金标准 SQL Q，作用于数据库 D。只要命中 E1–E4 任一类即记为错误；错误率 = 错误样例占比（§4.1，PDF p.5）。

**SAR-Agent**（§3.1，PDF pp.3–4）：
- 输入：标注 (T, Q) 与数据库模式（表名、列名、列描述）；Spider 2.0-Snow 平均每库 812.1 列，因此只提供金标准 SQL 引用的表；
- 动作：execute_query（执行验证查询并返回结果）与 terminate（生成报告），每轮提出一个针对性验证查询，历史查询和结果保留在记忆中，最多 30 轮；
- 输出：验证查询日志 + 诊断报告（是否有歧义、SQL 是否正确、解释、建议修正查询）。作者不评测建议修正查询本身的准确率。

**三步审查**（§4.2，PDF p.5）：SAR-Agent 自动检测 → 两位作者独立核验所有被标为错误或歧义的例子（分歧时四位作者共同讨论），领域知识对照权威来源并执行验证查询 → 根据发现的模式在同库其他例子中补充人工检查；BIRD Mini-Dev 还并入 Arcwise 已报告的错误。

**SAPAR**（§3.2，PDF p.4）：把 SAR-Agent 嵌入标注流程——自动审核 → 标注者认可则修改，不认可则交 SQL 专家裁决 → 修订后回到第一步，循环至通过。

**修正与重评**（§5.1–5.2，PDF pp.7–8）：从 BIRD Dev（1,534 例）随机抽 100 例，按 SAPAR 修正问题、外部知识、SQL、模式，必要时向数据库插入区分性记录；指标为执行准确率 EX、排名和 Spearman 相关。
