# 具体用例

**例 1：按页总结**（Figure 1，p.3）。问题“能总结第 5–7 页的要点吗？”。

1. 系统先把 PDF 解析为元数据：页列表 [1..11]、各章节标题及所在页（如 “2 Related Works”，pages [2, 3]）、表格标题及所在页；
2. LLM 看到问题和元数据后调用 `fetch_pages(pages: [5, 6, 7])`；
3. 取回第 5、6、7 页的文本作为上下文生成摘要。

按块检索只能找与“总结要点”语义相近的块，无法保证覆盖这三页。

**例 2：按章节抽取**（附录 B.5，Table 7，p.17）。问题“‘Create Using This Format’ 一节列出了哪些文件格式？”。PDFTriage 调用 `fetch_section()` 取回该节，答出 CSV、JPG、LPT、PDF、PNG、PS、RTF、XLS、XML；按块检索的回答是文档没有提供该信息。

**失败例**：问题“用一句长句总结第二段”。PDFTriage 取了错误的章节而不是第一页，按块检索不知道段落顺序，两者都答错（Table 7）。

阅读者分析：这些例子说明结构元数据适合“按位置指代”的问题；对“第二段”这类需要细粒度顺序的指代，现有函数集仍不够。

依据：Figure 1，PDF p.3；§3.2，p.4；附录 B.5、Table 7，p.17。
