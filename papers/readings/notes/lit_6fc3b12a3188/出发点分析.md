# 出发点

语义查询引擎（以 LOTUS 为代表）把语义连接实现为嵌套循环：对每一对行调用一次 LLM 判断自然语言条件是否成立。作者指出语义算子的单位字节开销比关系算子高出多个数量级，因此整条查询的代价由语义算子主导（§1，p.1）。

论文以两个场景说明需求：检方比较高管陈述与邮件，寻找“相互矛盾”的文本对；二手交易网站把自由文本广告与求购描述配对。两者都要求自然语言理解和常识，且条件不一定是相似性（§1，Example 1.1–1.2，p.1）。

代价估算：1 万条广告与 1 万条求购、每条约 100 token，用 GPT-4 逐对比较约需 60 万美元（§1，p.2，按当时每千输入 token 3 美分计）。作者认为传统块嵌套循环连接的思路可以迁移，但 LLM 有特殊约束：输入与输出共享一个硬 token 上限，输出一旦触顶整个请求作废，输入需重发（§1，p.2）。

阅读者分析：动机的核心是“费用”，不是延迟或准确率；论文的实现也明确只按顺序调用、不做并行。

依据：§1，PDF pp.1–3。
