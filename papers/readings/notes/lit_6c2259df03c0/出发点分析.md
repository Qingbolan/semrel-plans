# motivation

Claude Code、Codex CLI 等代码 agent 正被当作自主工程师使用，其真实价值取决于能否在文件系统里处理大规模数据：在目录层级中导航、从数百个候选里找出相关文件并执行恰当操作，而无需用户指明目标。作者称这需要"代码智能"（写出正确程序）与"数据智能"（在复杂数据环境中定位并利用正确信息源）的结合。

现有基准把两者分开评测：代码类（HumanEval、SWE-bench、Terminal-Bench 等）通常假设所需数据已备好；数据类（DS-1000、DA-Code、DABstep、KramaBench、DAComp 等）则把所有相关文件直接交给 agent，多用独立 Python 脚本，很少要求在终端中与大规模数据交互。作者认为这使基准表现与真实开发脱节——数据很少"被端上银盘"。构造这样的基准也不容易：随机生成的干扰文件很容易被区分，而人工整理数百个相关文件又不可扩展。

依据：[arXiv:2606.15300v1，37 页](https://arxiv.org/abs/2606.15300)，§1–2，PDF pp.1–3；§3.1，p.3。
