# problem

- **输入**：任务 T＝数据集 + 文本用户目标（封闭或开放的数据科学问题）。InsightBench 场景中还提供任务元数据里的探索性假设（开放式问题）作为引导。
- **输出**：对用户目标的文本回答 s*。
- **流程（Algorithm 1）**：GENERATE-CANDIDATES 产生 N 个候选计划（ensemble / base / conditional）；SELECT-STATES 选 M 个（random / MaxEnt / clustering / goal-align）；每个被选计划在 LangGraph 定义的确定性路线上执行：Feature agent → 代码迭代修复循环（Coder → 执行 → Analyzer → Editor，最多 3 次）→ Finalizer；AGGREGATE 由聚合器（self：同一模型；leader：更强模型）汇总。agent 只读文本日志，不看生成的图像。
- **评分单位**：Infi-DA-Bench 为每题对错（官方规则函数，数值误差超过 1e-6 或格式错即判错）；InsightBench 为每条真值洞察是否被找回（428 条，Claude Opus 4.6 作为评审逐条给布尔判定），准确率＝找回洞察数/总数。

阅读者分析：研究问题是"测试时预算在计划层面如何分配"，而不是新的分析能力；输出质量完全依赖于两个既有基准的评分口径。

依据：[arXiv:2607.14386v2，17 页](https://arxiv.org/abs/2607.14386)，§2–3、Algorithm 1，附录 B–C，PDF pp.2–4、9–11。
