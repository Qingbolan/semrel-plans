# usecase

附录 C（Fig.5）的代表性轨迹：在一个多表企业工作簿上的 FRTR-Bench 查询中，agent 先做宽泛的行检索，再定位目标列，提取各事业部数值，并与合并报表表交叉核对，最后给出带单元格级出处的答案；共 4 次工具调用，作者称前沿模型平均 3–6 次。

组合工作流用例（FINCH）：规划器把一条财务指令拆为 1–6 个子任务的 JSON 计划（类型 search/excel/io/web，含依赖），要求在每个子任务中保留全部过滤条件（日期范围、阈值），跨表检索须同时定位源和目标位置；search 执行器负责定位，excel 执行器写入数据、公式、格式和图表，io 执行器写 PDF/DOCX 等输出。

阅读者分析：这类"先检索定位再写回"的模式与语义数据处理中先抽取后物化的流程相似，但这里的核心是带出处的跨表定位，而不是对整表做批量语义算子。

依据：[arXiv:2603.06503v1，15 页](https://arxiv.org/abs/2603.06503)，§3.3，附录 C–D，PDF pp.5、14–15。
