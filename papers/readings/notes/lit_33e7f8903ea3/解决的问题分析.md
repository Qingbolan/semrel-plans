# 解决的问题

**输入**：用户在多轮会话中提出的自然语言请求，以及开发者配置的插件（YAML schema + Python 实现）、规划示例和代码生成示例（§3.1、§5.2，pp.5–6、9–10）。

**输出**：给用户的自然语言回复，以及可下载的产物（CSV、图片等）；中间产物是 Planner 的计划和 Code Interpreter 生成并执行的代码片段（§3、§5.3，pp.3–5、10–11）。

**工作单位**：Session（一个用户的会话，含独立 Jupyter 进程和插件集）→ Round（一次用户请求到回复）→ Post（Planner 与 CI 之间的一条消息，可带代码、日志等附件）（§3.1，pp.5–6）。

**执行流程**：Planner 先生成初始计划，再按子任务依赖（顺序、交互、无依赖）合并成最终计划；每个子任务交给 Code Generator 生成代码，生成后做 AST 规则检查，再由 Code Executor 执行；执行失败最多重生成 3 次，Planner 按结果修改计划（§4.4、§5.1–5.3，pp.7–11）。

这是一个工程框架问题，不是有形式化目标函数的优化问题；论文没有定义成功率之外的成本或延迟目标（阅读者分析）。
