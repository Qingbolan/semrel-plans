# 贡献与评价

**原文声称的设计要点**（§4、§5，pp.6–11）：

| 设计 | 内容 |
|---|---|
| 代码优先 | 每个请求转成 Python 代码；插件是代码中可调用的函数，数据以原生对象（如 DataFrame）在内存中传递 |
| 受限代码生成 | 可配置规则做 AST 检查，禁止特定包或函数；可开启仅插件模式 |
| 有状态执行 | 每个会话一个 Jupyter kernel，可本地或 Docker 容器运行 |
| 两阶段规划 | 合并顺序依赖的子任务，减少 LLM 调用 |
| 自我纠错 | 执行异常或校验失败后重生成，最多 3 次 |
| 动态插件选择 | 按请求只把相关插件放进提示 |
| 示例与经验记忆 | 规划/代码示例存 YAML；从对话中提炼“经验提示”供后续检索（§5.4） |

**阅读者分析**：各组件（ReAct、代码解释器、函数调用、示例注入、沙箱）都有先例，贡献主要是把它们组合成“插件即函数、状态在 kernel 中”的框架并开源。论文没有消融实验验证两阶段规划、动态插件选择或经验记忆的效果，只有单个示例说明（如 §9.1 中 LLM 调用从 6 次降到 3 次）（阅读者分析）。

依据：§4–§6、§9，PDF pp.6–12、19–21。
