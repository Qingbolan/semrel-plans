# 出发点

作者指出当时的 LLM 智能体框架（LangChain、Semantic Kernel、AutoGen、JARVIS 等）在领域数据分析上有三点不足（§1，pp.1–2）：

1. **缺少富数据结构支持**：嵌套列表、字典、DataFrame 在轮次之间或插件之间传递时，要么落盘，要么编码成字符串/JSON 放进提示，数据大时易出错。
2. **缺少系统地注入领域知识的方式**：难以按领域要求控制规划与代码生成。
3. **不够灵活**：插件只能覆盖常见需求，为每个临时查询写插件不现实，需要把插件调用与自由代码执行结合起来。

**动机例子**（§2，pp.2–3）：对 SQL 数据库中的时间序列做异常检测。专用算法需要一个时间戳列和一个浮点列；智能体要先拉数据、查看 schema，再调用算法并可视化。由此归纳出 8 项需求：插件、富数据结构、有状态执行、ReAct、自然语言回复、代码生成、领域知识注入、产物持久化。
