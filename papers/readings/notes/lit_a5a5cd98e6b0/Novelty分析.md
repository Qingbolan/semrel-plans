# novelty

作者自述贡献（§1.1，p.3）：
1. 据作者所知，首次把混合问答的上下文表述为关系数据库；
2. 提出开源查询语言 BlendSQL，在 SQL 逻辑与 LLM 推理之间编排并优化混合函数；
3. 用少量上下文示例，BlendSQL 能以 35% 更少的 token、且 parser 不直接访问非结构化上下文的条件下超过端到端方法。

附录还给出两个工程点：从 AST 推断 ingredient 期望输出（如 = 'CA' 时提示“示例输出 CA”，或期望布尔时用正则约束解码 ((true|false);)+，A.1，p.12）；VQA ingredient 扩展到图像（附录 C）。

**诚实评估（阅读者分析）**：
- 思想上与 BINDER 很接近（作者明确承认“最相似”），差异主要在 SQL 专用、多表、约束解码与可扩展 ingredient，属工程与表示层面的改进。
- “35% 更少 token”出现在摘要与贡献，而结论写“45% fewer prompt tokens”；两处数字不一致，论文未解释（Figure 4 只给图）。
- BlendSQL 单独使用时 33% 的 HybridQA dev 题无法产出预测，主结果 57.76 依赖“失败时回退到端到端”，因此“超过端到端”的结论需结合回退理解；不回退时为 52.89（比端到端高 3.76 个点）。
- FEVEROUS 上明显落后端到端（68.03 vs 83.21），说明“SQL 作为中间表示”并非对所有混合任务有利。
- 优化仅是规则式的“先执行 SQL 谓词”，没有代价模型。
