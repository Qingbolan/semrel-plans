# 工作负载

**数据库系统**：Oracle、MySQL、PostgreSQL、DM8（达梦），指标与日志由 Prometheus 等适配工具采集（§7.1）。

**测试异常**（§7.1、Table 4）：

| 数据库 | 测试场景数 |
|---|---|
| Oracle | 178 |
| MySQL | 114 |
| PostgreSQL | 127 |
| DM8 | 139 |
| 合计 | 558（阅读者分析：四项相加） |

异常分五类：(1) 日志同步与管理（Oracle LGWR 等待、ACTIVE redo 组过多、DM8 redo 异常增长）；(2) 资源争用与并发（Oracle 热块争用、活跃会话激增）；(3) SQL 优化（Oracle 异常逻辑读、PostgreSQL 全表扫描）；(4) 硬件与系统资源瓶颈（如 MySQL CPU 飙升）；(5) 写性能（PostgreSQL 后端进程刷脏页过多）。Table 4 列出 17 类常见根因及其在四库中的分布，例如 PostgreSQL 独有 BGWRITER/CHECKPOINT/WAL 参数问题、死元组、统计信息过期等。

**标注与划分**：真值来自专家 DBA 撰写的运维报告；作者称测试异常与图中内容不同——图中不显式包含与测试用例相同的根因或解决方案（§7.1）。论文没有说明场景如何采样（真实生产事故还是注入）、每类场景数、各场景根因个数分布，也没有给出训练/测试划分的具体流程。

**运行环境**：Ollama + 单张 RTX 3090 运行 32B 蒸馏模型；知识图基于 KYD Zhiyan 平台；数据采集用 DBAIOps 社区版工具。消融（Table 6）只在 Oracle + DeepSeek-R1 32B 上进行。

阅读者分析：工作负载是"运维诊断场景"，不是查询集合；"不含相同根因"的隔离声明没有给出检验方法，而 Table 4 的根因类别与图中异常模型显然同域，因此泛化结论应谨慎理解。
