# 贡献与评价

**作者声明的贡献**（§1）：

1. 自称首个把知识图与推理 LLM 结合、识别根因并给出修复方案的数据库运维系统。
2. 图形式的经验模型：超过 2,000 个顶点、800+ 异常场景、覆盖 25 种数据库系统。
3. 相关性感知的异常模型：多指标关联、频率控制、低代码诊断工具，用于发现隐式相关指标。
4. 两阶段图演化：用 Cypher 遍历并在相关异常模型之间建立交叉边（邻近发现），再用自适应检测函数 ADF（波动 σ、动态基线 B_t、偏离 D、状态函数、加权得分 S）决定是否继续扩展；最后用结构化提示 ⟨异常、条件、指标、经验、输出要求⟩ 驱动 LLM 生成报告。

**规模与构建**（§4.2、Table 3）：半自动构建——人工勾勒 Trigger 顶点，其余顶点由文档自动抽取挂接（如 Oracle 的 15,000 篇 MOS 文档）；用 Cypher 构建 150,000 顶点约需 15 分钟。Oracle 图有 300,000+ 条边、82 个 Trigger、550 个 Metric、317 个 Experience、897 个 Tag 顶点；按库的顶点数为 Oracle 2,911、MySQL 1,786、PostgreSQL 2,272、DM8 2,259。经验来源为过去 10 年管理 5,000+ 数据库与 2,000+ 历史异常案例。

**阅读者评估**：

- 系统工程化程度高、已部署（摘要称 20 个真实场景），但贡献主要是系统集成；ADF 由标准统计量拼成，阈值 θ 与 S 的判定阈值按环境调节，论文未给出具体取值方法。
- 若干数字前后不一：顶点数在 §1 写"超过 2,000"，§4.1 例子中 Oracle 已近 1,850（82+550+317+897），§4.2 给出 2,911；Oracle Metric 顶点 550 与 Table 3 的 Oracle 第一行同值，Table 3 列序由抽取文本无法可靠还原（阅读者分析）。
- 经验图与异常模型来自作者公司的私有资产（MOS 文档、客户案例），图本身是否公开论文未说明，可复现性有限。
- 作者是该商业产品团队（Baisheng 公司）成员，评测存在利益相关，论文未讨论。

依据：[arXiv:2508.01136v1](https://arxiv.org/abs/2508.01136)，§1、§4–6、Tables 2–3，PDF pp.2、4–8。
