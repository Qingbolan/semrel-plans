# 贡献与评价

设计一，统一交互表示：指令、环境信息、工具说明与调用、观测都表示为 markdown 与代码单元。作者主张格式一致可降低小模型的认知负担（§3.1），但这是假设，没有单独消融。

设计二，基于 FST 的多阶段架构：DFS 式规划可前进、回溯替换当前子任务或终止；增量执行逐步完成子任务（§3.3）。

执行出错时进入自调试；后过滤阶段把调试痕迹替换为干净代码，修复失败时替换为简短诊断报告，避免污染上下文（§3.3）。

评价：规划、执行、自调试各自已有先例（ReAct、Data Interpreter、self-debug），新意主要在于用显式状态机组合它们，以及后过滤这种上下文清理机制（阅读者分析）。

消融（Table 5）只去掉规划或代码修复，没有隔离 notebook 表示本身的作用（阅读者分析）。
