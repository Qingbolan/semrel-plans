# 解决的问题

**数据构建**（§3，PDF pp.3–4）：

1. 输入 74 部法规/政策原文，人工整理为章–条–款树，从根到叶遍历，每条路径是一条规则，共 12,985 条。
2. 对每条规则，Grok-4.1 代理生成多条搜索查询、调用搜索工具（声称只看官方/权威域名）、总结并过滤，输出 JSON 案例：example_background、process_and_outcome、involved_parties、applicable_regulations_or_policies、reference_link、relation_to_rule（VIOLATES/COMPLIES）。
3. 由"规则 A→检索到的案例→案例引用的规则 B"三元组构建规则–案例知识图谱。

**评测任务**（§4.1，PDF p.4）：输入案例背景，输出 PERMITTED 或 PROHIBITED，单位为单个案例；指标为 macro-F1。

阅读者分析：标签来自搜索代理自己给出的 relation_to_rule，而非人工或原始裁决的结构化字段。Table 4 的评测提示文字称"根据案例背景和规则判断"，但模板中只有 {case_background} 一个变量，模型实际是否看到规则，原文没有说清（附录 Table 4，PDF p.17）。
