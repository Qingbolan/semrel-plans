# 评测与边界

**设置**（§4，pp.7–8）：
- 模型：OpenChat-7B、Llama3-8B/70B、CodeLlama-70B、GPT-3.5 Turbo、GPT-4o；
- Prompt 方式：明确提示问题可能有歧义，要求为每种解读输出 SQL；温度 0.5，取 5 个种子的平均（OpenAI 模型因成本只跑一次）；
- Beam 方式：标准 text-to-SQL 提示，取 beam=5 的 top-5 结果。

**指标**：基于执行结果的召回与精确率，以及 AllFound（歧义问题的金标 SQL 是否全部生成）。主要关注歧义问题上的召回。

**实验 1（零样本，Table 2，p.8）**：

| 模型（方法） | 召回 ambig | 召回 unambig | 精确率 ambig | AllFound |
|---|---|---|---|---|
| Llama3-70B（Prompt） | 30.7 | 64.5 | 42.7 | 1.9 |
| Llama3-70B（Beam） | 28.0 | 65.5 | — | 1.4 |
| GPT-4o（Prompt） | 27.1 | 63.4 | 51.1 | 0.4 |
| GPT-3.5 Turbo（Prompt） | 26.7 | 61.6 | 40.2 | 0.5 |
| CodeLlama-70B（Beam） | 25.4 | 56.2 | — | 0.1 |
| Llama3-8B（Prompt） | 18.0 | 45.4 | 30.2 | 0.1 |
| OpenChat-7B（Prompt） | 15.5 | 36.8 | 24.7 | 0.2 |

表中只列各模型较好的一种方法；全部模型的 AllFound 都不超过 1.9。

**实验 2（按类型细分，Table 3，p.9，Llama3-70B Prompt）**：歧义召回为范围 41.5、附着 12.7、模糊 35.6。附着类在无歧义问题上的召回也只有 24.0，需要 UNION 的 SQL 较难生成。

**实验 3（少样本，Table 5，p.10）**：1-shot 使 Llama3-70B 的歧义召回升至 32.4、AllFound 升至 3.7；GPT-4o 1-shot 的 AllFound 为 4.5。原文称差异可忽略，且多数提升不显著。

**附录 G（p.23）**：让模型判断问题是否有歧义时，约 80% 的问题都被判为有歧义（Table 7）。50 个错误样例中，34% 是“同一 SQL 的不同变体”。

**边界**（§5，p.10）：问题与解读可能有标注错误；数据库命名简单清晰，比真实库更规整；整库放进上下文既不可扩展也不安全，所以结果应视为上界；歧义类型未覆盖全部情况。

依据：[arXiv:2406.19073v2，29 页](https://arxiv.org/pdf/2406.19073v2)，§4–§5、Tables 2–5，PDF pp.7–10；附录 F–G，pp.19、23。
