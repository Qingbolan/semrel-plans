# 贡献与评价

作者声明的贡献（§1、§4）：

1. 首个仓库级数据工程任务集：在企业 SaaS schema 上生成/演化多层 SQL DAG，并区分架构、实现、演化三种任务类型。
2. 首个"真实开放式"数据分析任务集，要求报告、洞见与可视化。
3. 分层 rubric + 多路径设计：每个子需求枚举多条方法上不同的解法路径，Accuracy 条目尽量配数值锚点或伪代码锚点，其余用基于原则的软约束（App. F.1 的三层设计）。
4. 三级严格度的执行指标：CS（给定金标准上游、逐节点）、CFS（沿 DAG 级联，上游错则下游清零）、SR（全部节点正确）。用 CS→CFS 的落差诊断"编排瓶颈"。
5. LLM 评审有效性验证：300 份回答、7k+ rubric 条目的人工标注，跨评审、跨 α、8 次重复打分的稳定性分析（§3.6）。
6. 中文版 DAComp-zh。

阅读者评估：

- CS/CFS/SR 三级指标的组合确实能区分"单节点能写对"和"整条管线能跑通"，这是相对 Spider 2.0、DA-Code 一类单产物基准更有信息量的设计。
- DE 数据为在开源 dbt 项目 schema 上**合成**的数据（App. E.1、E.2.1），任务"企业级"体现在 schema 与代码规模，而非真实企业数据分布。
- 文本与表格存在若干不一致（见 benchmark 分析），降低了数字引用的可靠性（阅读者分析）。
- 评审模型 Gemini-2.5-Flash 同时也属于被评测模型（Gemini-2.5-Pro）所在家族；作者用 Table 8 的跨评审排名稳定性回应自偏好问题，但只覆盖排名，不覆盖绝对分数（Table 8 中同一模型在不同评审下分数相差可达十几个百分点）（阅读者分析）。

依据：[arXiv:2512.04324v1](https://arxiv.org/abs/2512.04324)，§1、§2.2–2.4、§3.6，PDF pp.2–6、10–11；App. E–F，pp.34–41。
