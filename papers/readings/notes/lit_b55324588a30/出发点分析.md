# 出发点

数据湖里表结构异构、表间连接关系未声明，用户为清洗、集成、分析等应用临时组合工作流；每出现一种新应用，处理流程就要专家从头设计和调参（§1，p.1）。规则方法需要逐任务构造规则，机器学习/深度学习方法依赖大量标注数据和领域知识（§1，p.1）。

已有 LLM 用于数据任务的工作（如 FM，Narayan et al., 2022）效果不错，但流程和提示都是逐任务手工设计，仍需用户手工挑选上下文示例（§2，p.3）。作者因此提出问题：能否找到一个对不同数据操作任务都通用、自动、无需人工的 LLM 方案（§2，p.3）。

作者还指出，直接用一条简单提示让 LLM 同时理解任务、抽取上下文并填值，相当于多跳推理，效果一般；所以要把任务拆成若干对 LLM 简单的步骤（§4.1，p.4）。

阅读者分析：动机针对的是“逐任务手工提示”的人工成本，而非计算成本；论文后面的 Table 7 正好显示自动化换来的是更高 token 开销。

依据：§1–2、§4.1，PDF pp.1–4。
