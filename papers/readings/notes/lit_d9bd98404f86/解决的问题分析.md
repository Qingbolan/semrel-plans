# 解决的问题

**回退检测**：设 `T(q,t)` 为查询 q 在时刻 t 的执行时间；若最新时刻 t′ > t 满足 `T(q,t′) ≥ φ·T(q,t)`，则 q 被判为回退，φ 由用户设定（§2，p.2）。

**输入**：同一查询在 t 与 t′ 的两份已执行计划（经 `EXPLAIN` 获取的文本）、目标 DBMS 名称、硬件规格；运行时错误场景中还包括执行日志（§2–§3，pp.2–3）。

**输出**：按 JSON 结构返回三项——`plan_diff`（计划差异摘要）、`recommendations`（与该 DBMS 兼容的 SQL 配置命令，通常是把计划恢复到原状的优化器提示或开关）、`reasoning`（建议与两份计划的关系）（Fig. 1 与 §2，pp.2–3）。

**工作单位**：一条回退的查询及其两个计划版本。作者强调与其前作 λ-Tune 的区别：λ-Tune 面向整批负载做自适应调优，DBG-PT 只关注单条回退查询（§1，p.2）。

Fig. 1 的提示模板同时要求“只输出 SQL 命令列表、不附加文本”和“严格遵循 JSON schema”，两条格式要求在文中并存，未说明如何协调（阅读者分析）
