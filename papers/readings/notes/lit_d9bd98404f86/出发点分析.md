# 出发点

查询性能回退的排查很难，尤其是多表连接的长查询，执行计划结构复杂。DBA 通常先对比回退前的高效计划和回退后的计划，查看连接顺序、连接算法、索引扫描或基数估计误差的变化，再用优化器提示、禁用某些连接算法等手段修复；这需要多年积累的系统内部知识，人工比对计划也很繁琐（§1，p.1）。

已有自动化方法（如利用执行信息改进索引推荐、消除学习式优化器的回退）需要与数据库深度集成并经过耗时训练，非专家难以部署（§1，p.1）。

作者认为 LLM 适合这一任务：它擅长识别两份计划的结构差异，并从网上技术文档和 StackOverflow 等排障讨论中学到修复知识，只需单次 API 调用、无需训练，可即插即用地支持多种 DBMS（§1，p.2）。

依据：PVLDB 17(12)，§1，PDF pp.1–2（4337–4338）。
