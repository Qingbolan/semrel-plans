# 评测与边界

**评测方式**（§4，p.6）：试点用户研究，两名经常做数据分析的研究生（气候、医学）各自提供数据。作者离线生成 Cocoon 画像，再按出声思考协议访谈两个问题：画像是否准确，以及 Cocoon 对今后分析是否有用。

**实验 1（气候数据，§4.1.1，p.6）**：Cocoon 报出重复、字符串异常（拼写错误、表示不一致）、数值异常、缺失值和伪装缺失值（如 "-"、"#Value!"）。P1 认为多数报警准确，并认为错误之处"有意思"，其根源在领域背景（单位变化、区间值、模糊类别）。P1 称以前由本科生手工翻 Excel 找同类错误，速度慢，希望 LLM 能直接修正拼写错误。

**实验 2（医学数据，§4.1.2，p.6）**：Cocoon 报出大量重复、测量值异常、字符串模式不一致、缺失值和伪装缺失值（0）。P2 对报警数量感到意外，表示不咨询数据提供方就难以确认真伪；P2 认为在与医院一小时的会议中，Cocoon 有助于快速扫描数据。

**无定量指标**：没有基线、精确率、召回率、误报率或运行成本统计；唯一的性能数字是每个数据集约 20 分钟的 LLM 响应时间。

**作者列出的局限（§5，p.6）**：错误类型有限，计划构建可能分领域的错误目录；界面需为每类错误提供可追溯的 SQL 查询和可视化；用户希望在同一系统内完成清洗；尚未验证画像能否改进 Text-to-SQL 或数据变换等下游任务。
