# 出发点

数据湖同时包含结构化（表、图）、半结构化（JSON、HTML）与非结构化数据（文本、图像、视频），分析常需跨模态，例如医生同时看 X 光与诊断报告（§1，p.1）。作者认为现有 LLM 方法有三项局限（§1，p.2）：

- **查询表达力有限**：ELEET 只支持文本与表，Palimpzest 只处理文本与图像，AOP 主要面向文档与文本；NL 直接映射到模态操作、NL2SQL 或要求用户写类 SQL 语言，都难以覆盖含糊且跨模态的数据湖查询。
- **推理开销高**：多数方法用一个统一大模型处理所有模态，GPT-4 级模型参数量巨大，延迟高。
- **知识与数据陈旧**：数据湖可能不完整或过时，LLM 内部知识也会过时，现有方法基于静态假设。

MCP 统一了 AI 智能体、外部工具与数据资源之间的交互接口，作者据此主张把各模态分析卸载到专用 MCP 服务器，并利用不断增长的现成 MCP 服务器生态（§1，p.2）。

阅读者分析：对 Palimpzest 等系统"仅支持某几种模态"的概括是作者的表述，未给出版本或依据细节；§2.2 中称 CAESURA "也称 ELEET"，而两者在其参考文献中是同一作者的两篇不同论文 [23][24]，此处说法存疑（阅读者分析）。

依据：§1、§2.2，pp.1–4。
