# 解决的问题

**问题定义 MMQP**（§2.1，p.3）：给定自然语言查询 Q 与数据集集合 D（每个数据集 Di 属于某模态 Mi），计算满足查询谓词的结果集 R，每个结果元组可以包含多个模态的数据项。评价指标为召回率、精确率与延迟。

**作者列出的三项挑战**（§2.1，pp.3–4）：跨模态查询规划；大规模数据上的高效推理；数据与知识的新鲜度。

**系统组成**（§3、Fig.2，pp.4–9）：

| 组件 | 内容 |
|---|---|
| MCP Client Manager | NL2Operator：LLM 智能体把查询映射到分层语义算子，每个算子绑定 MCP 服务器；Query Planner：把算子组成 DAG，用采样得到每元组处理时间和选择率，建立基于延迟的代价模型选最低代价计划；Iterative Operator Optimizer：服务器检索结果不足时可向上游请求改写，循环直至达到置信阈值 |
| MCP Server Manager | 过滤感知的向量索引（在满足过滤条件的点之间补边以保证图可达）；按模态的多模态 MCP 服务器 |
| MCP Augmentor | 数据增强：查询后触发爬虫/API 收集文档，经结构解析、MinHash+嵌入去重、实体抽取、至少两个独立来源交叉验证后入湖；模型刷新：查询驱动强化（重要性采样微调）、插入转成指令样本、删除用梯度上升/影响函数遗忘 |

阅读者分析：上述大多数组件在文中只是设计描述，没有实现细节或单独评测；初步实验固定了查询计划，因此 Query Planner、迭代优化器、索引和增强器都未被验证（阅读者分析）。

依据：§2.1、§3、§4.1，pp.3–9。
