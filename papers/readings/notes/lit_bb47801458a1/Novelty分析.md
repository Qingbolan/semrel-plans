# 贡献与评价

原文声称的贡献（§1，p.2）：
1. 在 DuckDB 内把五种语义算子实现为原生计划算子，复用向量化与 morsel 驱动的流水线并行；每个工作线程持有私有 CURL multi-handle 以并发发出 LLM 请求（§6，pp.7–8）。
2. SemaSQL：在标准 SQL 子句中插入 NL 表达式，支持子查询、CTE、窗口函数（§3.1）。
3. 逻辑层：辅助 LLM 以 CoT 做表达式压缩；谓词推导把 NL 谓词全部或部分改写为 SQL 必要条件并下推，带"自反思"校验，失败时回退原 SemFilter（§4，pp.4–5）。
4. 运行时 AQE：用 δ1 样本估计各 SemFilter 选择率并计算两两 MCC，MCC>阈值才允许融合；在 δ2 样本上试跑候选路径，以未批处理的参考路径结果作伪真值，淘汰精度低于 τacc 的路径，在延迟/token 二维上取帕累托前沿（§5.2，pp.6–7）。
5. 一个 20 查询、9 数据集的基准（§7.1）。

阅读者分析：各组件单独看都有先例——Lotus 的算子集合、批量 prompt [33]、Eddies/Aero 式自适应执行、ML 谓词推导 [13]；新意在于把它们放进同一个列式 DBMS 的优化器/执行器，并用 MCC 作为融合安全性的启发式。融合只支持两个一元算子、只引入一次融合；AQE 只覆盖同一流水线中的 SemFilter（§5.1–5.2 末），这限制了"端到端优化"的实际覆盖面。加速归因中，作者把主要收益归于向量化/流水线/异步执行（§7.2），而非语义优化本身。
