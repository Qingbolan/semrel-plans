# 出发点

作者认为 LLM 已成为 Text-to-SQL 的新范式（DIN-SQL + GPT-4 在 Spider 排行榜达到 85.3%），核心问题变成如何写提示，但当时缺少系统比较（§1，p.1）。具体有三点：

1. **提示工程缺少系统研究**：各工作在不同 LLM、不同框架下报告不同的问题表示，无法公平比较（Table 1，p.3）。细节差异影响很大，例如 OpenAI 官方示例用 “#” 区分提示与回复，去掉后性能明显下降（§1，p.1）。示例选择与组织（全信息 vs 只放 SQL）的最优选择也不清楚。
2. **开源 LLM 潜力未被研究**：以往工作集中在 OpenAI 模型，开源模型的上下文理解较弱，需要通过监督微调提升（§1，p.1）。
3. **提示效率是开放问题**：OpenAI API 按 token 计费、耗时且有限流，多示例提示尤其昂贵；先前工作只观察到准确率随提示长度呈倒 U 形（§1，pp.1–2）。
