# 出发点

LLM 与外部工具结合形成的智能体可以充当邮件、日历助理或带编码环境的“操作系统”。但 LLM 直接处理文本，缺少区分指令与数据的形式化机制；攻击者可在工具返回的第三方数据中插入恶意指令（间接提示注入），让智能体代表用户执行操作，例如泄露数据或执行任意代码（§1，p.1）。

已有基准不足（§2，pp.2–3）：
- 智能体基准要么只测把指令转换成单次函数调用，要么测多轮任务但没有显式攻击；
- ToolEmu 用 LLM 模拟工具和评分，而注入攻击也可能骗过这个模拟器/评估器；
- 提示注入基准多是文档问答、提示窃取等无工具场景；InjecAgent 最接近，但只把一段对抗数据作为单轮工具输出直接喂给 LLM，不评估智能体规划。

作者还认为静态基准在机器学习安全中用处有限：现有注入攻击多为通用模板，而针对某一攻击的防御很容易被自适应攻击绕过，因此需要能持续加入新攻击和防御的动态环境（§3.3，p.6）。
