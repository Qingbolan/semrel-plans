# 解决的问题

**基于规则的查询改写**（Definition 2.1、式 1）：输入一条可执行 SQL 查询 `q` 和候选改写规则集合 `R`；输出规则序列 `R*`，使改写结果 `q* = R*(q)` 与 `q` 等价且执行延迟最小，即 `argmin latency(q*)`。

**LLM 增强版本**（Definition 3.1）：提示由系统指令、规则指令（全部候选规则及简短说明）、一个从示例池选出的示例 `<q_d, R_d>`、以及输入查询拼接而成；LLM 输出规则序列，再由基于 Calcite 的规则执行器作用于查询树。作者额外定义了 “EMPTY” 规则表示不需要改写（§6.1.2）。

**工作单位**：一条 SQL 查询。训练阶段的单位是改写元组 `(q_t, d, R_t, m)`，其中 `m = c_0 / c_r` 为原查询代价与改写后代价之比（§4.1）；由此构造三元组 `<q_t, q_d+, q_d->` 训练表示模型。

阅读者分析：等价性保证来自规则本身的正确性，而不是对每次改写结果做验证；论文没有报告 Calcite 规则在三个数据集上是否出现过不等价改写。

依据：[PVLDB 18(1) 53–65](https://www.vldb.org/pvldb/vol18/p53-yuan.pdf)，§2.1–2.2、§3.1、§4.1、§6.1.2，PDF pp.2–5、8。
