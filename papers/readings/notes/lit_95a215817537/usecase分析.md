# 具体用例

**网银欺诈检测智能体**（§2.4.2，pp.8–9；§4.3，p.13）是论文贯穿全文的示例：

| 阶段 | 智能体做什么 |
|---|---|
| S1 业务理解与数据获取 | 把“减少漏判欺诈且避免过多误报”转成构建高精确率分类器的任务，安全获取交易与客户数据 |
| S2 探索分析与可视化 | 清洗并探索数据，可视化交易趋势以突出异常 |
| S3 特征工程 | 构造平均交易金额、登录频率、地理移动等特征 |
| S4 模型构建与选择 | 训练与评估模型，用精确率和召回率反映误判代价 |
| S5 解释与说明 | 用 SHAP、LIME 解释某笔交易为何被标记，支持合规与客户沟通；仪表盘汇总发现 |
| S6 部署与监控 | 打包上线并加固防对抗攻击，监控概念漂移并触发再训练 |

全程由智能体的角色、记忆和角色化模块协调规划、工具使用与反思，可信、对齐与安全作为横切要求。

阅读者分析：这是作者构造的说明性场景，并非某个被调查系统的实际运行记录；按 Table 2 的判断，S1 与 S6 恰是现有系统覆盖最少的阶段，因此这个端到端用例目前没有单个系统能完整实现。
