# 出发点

现有检索流程按模态分别处理：BM25、DPR 依赖抽取出的文本，多模态检索也依赖事先拆好的文本和图片单元（§1，p.1）。作者指出两个问题（§1，p.1）：

1. **预处理不易**：野外 HTML 结构多样，单一工具难以完整解析；幻灯片和 PDF 需要 OCR，并单独处理表格、图片，长尾文档外观很难都处理好。
2. **破坏原貌**：内容抽取打断视觉上下文和版式，而元素大小、位置可能编码了信息重要性。

另一个动机来自数据集：常用检索数据集（MS MARCO、BEIR 等）只发布预处理后的文本；DocVQA 等文档图像 QA 集合的图片池只有几千张，且给定真值图片，不能评估大规模检索（§2.3，p.3）。

阅读者分析：论文的核心主张是“截图是统一输入格式”，其实验检验的是这种格式在检索上是否不输或优于“解析后文本”，而非证明解析完全无用。

依据：§1、§2.3，PDF pp.1–3。
