# 出发点

GPT-4 类方法在 Spider 1.0 和 BIRD 上的执行准确率已达 91.2% 和 73.0%，但这些数据集多为非工业数据库：表和列少、SQL 简单、不涉及方言差异（§1，p.1）。

作者认为真实企业 text-to-SQL 工作流有以下特征（§1，pp.1–2）：

- 数据分布在不同数据库系统上，各有独特 SQL 方言与函数；
- 模式规模大（上千列）、存在嵌套结构；
- 需要借助项目代码库、外部知识和多步 SQL 完成数据清洗、转换与分析，形成完整的数据工程管线。

因此需要一个更贴近企业场景的基准，衡量模型是否能像数据工程师那样在环境中探索元数据、查阅方言文档、编写多条长 SQL。

该动机针对的是“执行正确性 + 环境交互”，并不涉及语义（LLM 内嵌）算子；它评测的是生成标准 SQL 的能力，而非在 SQL 中调用 LLM（阅读者分析）。
