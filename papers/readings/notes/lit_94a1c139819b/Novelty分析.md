# 贡献与评价

**贡献**（§1–2）：

1. 企业级 text-to-SQL 基准，覆盖六种数据库系统与方言、大模式与嵌套/分区/多 schema 结构；
2. 引入代码库与 DBT 项目级数据转换任务，把 text-to-SQL 扩展为智能体工作流；
3. 提供 lite/snow 两个自包含版本，便于与传统 text-to-SQL 方法比较；
4. Spider-Agent 基线框架（ReAct 式，多轮命令行与数据库交互，附录 C.1）及系统的错误分析。

**构造质量控制**（§2.2，pp.3–5）：8 名作者标注；从 1,021 条复杂 SQL 和 157 个转换项目中筛出 547 条 SQL 与 78 个 DBT 项目；为防数据泄露改写 SQL（84.2% 做表层改写，42% 做语义改写）；每例至少 3 人复核，首轮发现 45% 有错，第二轮降至 5%，随后全部修正；对评测脚本做“红队”检查。

**评价**：基准的主要价值在于真实规模的模式与方言、以及代码库上下文；以 SQL 长度定义难度较粗（作者在脚注中承认这只是常用参考指标，p.6）。

阅读者分析的几处口径问题：
- Spider 2.0 为 632 例，其中 DBT 78 例，Table 6 注称“Spider 2.0 由 lite 加 DBT 任务组成”，但 632−78=554，而 lite 为 547 例，论文未解释 7 例差异（阅读者分析）。
- 摘要称 lite 上最强 text-to-SQL 解析器仅 5.7%，v2 Table 4 中 Spider-Agent + o1-preview 在 lite 上 EX 达 23.22%；前者指传统解析方法（Table 5），两者不能混读（阅读者分析）。
- 无独立局限章节；评测依赖云数据仓库访问，复现需要 BigQuery/Snowflake 账号（阅读者分析）。

依据：§1–3、Tables 1–6、附录 C.1，PDF pp.1–7、33–35。
