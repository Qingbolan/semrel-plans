# 解决的问题

**总任务**（§3.1，Eq.1）：输入含文本与表格的财务文档 D、值类型集合 L 和分类体系 T，输出所有数值的三元组 {Fact, Type, Tag}；每个事实只分配一个最具体的概念。

| 子任务 | 输入 | 输出 | 指标 |
|---|---|---|---|
| FinNI（数值识别） | 一个句子或一张保留 HTML 结构标签的表格 + L | JSON 列表 {Fact, Type}，可为空 | 实体与类型同时精确匹配的 P/R/F1（附录 E） |
| FinCL（概念链接） | 实体 + 类型 + 上下文 | 一个 US-GAAP 概念 | 准确率 |

**值类型 L**：monetaryItemType、percentItemType、sharesItemType、perShareItemType、integerItemType；原始数据出现 11 种类型，取最主要的 5 种（§3.3、Figure 2）。

**FinCL 评测设定**（§3.6）：用 text-embedding-3-small 对分类体系概念编码，按语义相似度取前 h 个候选（正文实验 h=200），再由 LLM 结合上下文重排选出最终标签。整体结果以三元组的宏/微 P、R、F1 报告（Table 5）。

**抽取约定**（附录 D.3）：去掉货币符号、百分号和逗号；数量级词不展开（"10.6 million"只抽 10.6）。

阅读者分析：FinCL 的上限受检索器限制（Acc@200 约 0.33），所以 FinCL 准确率混合了检索覆盖与 LLM 重排能力，不是纯粹的"概念理解"度量。

依据：[arXiv 2505.20650v5，17 页](https://arxiv.org/abs/2505.20650)，§3.1、§3.3、§3.6、§4.2、附录 D.3、E，PDF pp.2–6、12。
