# 出发点

**成本结构变化**：AI SQL 中主导成本从存储和 CPU 转为模型推理，LLM 推理费用约占查询总成本的 80–90%，每次调用有秒级延迟，因此优化目标是减少 LLM 使用（§1，pp.1–2）。

**现有启发式不足**：常见做法是把关系谓词放在语义过滤之前；但当 WHERE 子句含多个 AI_FILTER 时，这一规则不够（§1 p.2，Example 1.1：同时要求“是研究论文”与“讨论数据库优化技术”）。应先执行更具选择性的过滤器以触发短路，但 AI_FILTER 的选择率与相关性依赖潜在语义，事先无法用直方图或 sketch 估计。

**已有优化器的局限**（§2.2，p.3）：Cortex AI SQL 收集运行时统计；Palimpzest 用 5% 样本估计选择率后对所有行使用同一静态顺序；Quest 同样用样本估计，但按 sel/cost 优先级逐行排序。三者都把每个过滤器的通过率当作固定的全局概率，内部节点按独立性假设组合，遇到概念漂移或局部相关（如按主题聚集、按时间排序）就会失效；而且都按后序遍历执行，不能在分支间跳转。

**两个关键观察**（§1 p.2）：
1. LLM 调用延迟很高，为运行时优化留出比关系查询宽得多的时间窗口，可以在执行中训练轻量模型。
2. 非结构化数据常带预计算嵌入，成本比 LLM 调用低 100–500 倍。但 Figure 2（GovReport，谓词“是否报道军事活动”）显示原始余弦相似度与 True 比例的关系噪声大且非单调，最高相似度区间甚至全为 False，因此嵌入应作为学习模型的特征，而不是直接充当选择率信号（§2.3–2.4，p.4）。

阅读者注：§1 写“每次语义过滤求值需要数百微秒而非纳秒”，与同节“秒级延迟”和 §4.7“数百毫秒”不一致，疑为笔误。
