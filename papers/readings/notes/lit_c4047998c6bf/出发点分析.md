# 出发点

现有查询改写主要依赖预定义规则：启发式方法按固定顺序应用规则，ML 方法和近期的 LLM 方法（LLM-R2、R-Bot）负责选择规则及其顺序。作者认为这类方法只能覆盖少数查询，还可能造成性能回退（§1，p.1）。

根源有三点：新规则难以发现和验证；固定规则依赖模式匹配，无法处理新的或复杂的查询模式；有些有效策略根本无法表达为规则（§1，p.1）。作者用三个例子说明人类专家能做而规则做不到的改写（§1，pp.1–2）：

- 用 CTE 消除嵌套子查询的重复计算（DSB 简化查询，延迟降低 37.5 倍）；
- 根据数据分布先做高选择性连接（比规则改写快 2.79 倍）；
- 按查询意图去掉无用的连接和子查询（Calcite 查询，快 2.17 倍）。

直接用 LLM 改写又面临两个挑战：保证等价（最强的 LLM 也有近 20% 的改写存在语法或语义错误），以及保证改写确实更快（需要数据分布、优化器估计等 LLM 通常拿不到的上下文）（§1，p.2）。

依据：§1，PDF pp.1–2。
