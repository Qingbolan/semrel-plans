# 评测与边界

**基线**：LearnedRewrite（MCTS + 学习代价模型）、LLM-R2、R-Bot（各配 GPT-4o、Claude-3.7、DS-R1），以及可访问统计信息和本文 SQL 校正器的单 LLM 智能体。GenRewrite 未开源，未参与比较（§7.1，p.9）。指标为平均/中位/P95 延迟、等价率，以及改进率（延迟降低至少 10%）。

**实验 1（平均延迟，Table 4，p.10，单位 s）**：

| 方法 | TPC-H | DSB | Calcite | StackOverflow |
|---|---|---|---|---|
| 原查询 | 69.84 | 32.62 | 23.88 | 48.02 |
| LearnedRewrite | 37.57 | 31.93 | 22.88 | 46.25 |
| LLM-R2 (DS-R1) | 56.73 | 9.16 | 16.90 | 43.42 |
| R-Bot (GPT-4o) | 32.64 | 21.75 | 22.21 | 46.43 |
| LLM Agent (DS-R1) | 42.79 | 13.53 | 15.18 | 27.14 |
| QUITE★（含提示） | 25.60 | 5.85 | 9.97 | 12.61 |

**实验 2（等价率与消融，§7.2，pp.10–11）**：

- 等价率：QUITE 在 TPC-H、DSB、Calcite、StackOverflow 上分别为 100%、96.8%、98.3%、90.7%（p.10）。
- 去掉 SQL 校正器：非等价查询从 5 条增至 11 条，改进查询减少 17 条。
- MDP：去掉后平均时间增加，加入 MDP 可使平均时间降低 52.2%。
- 提示注入：使平均时间再降低 1.8%、3.8%、0.3%。
- 模型组合：在 DSB 上，DS-R1+Claude-3.7（6.08 s）明显优于 DS-R1+GPT-4o（31.38 s）（Table 5，p.11）。

**实验 3（开销，Table 8，p.12）**：在 TPC-H 的 63 条查询上，平均改写时间和成本分别为：QUITE 218.25 s / $0.200，LLM-R2 391.23 s / $0.016，R-Bot 118.33 s / $0.417。

**口径不一致**：摘要称相对 SOTA“最高降低 35.8%”，对应正文中 DSB 上相对 LLM-R2 的数值；引言称相对最佳替代方案“最高 21.9%”，而正文给出的相对 R-Bot 的 TPC-H 降幅是 21.6%（§7.2，p.10）。在 SF=50 的整体延迟实验中，TPC-H 上 LLM-R2 降低 71.9%，略高于 QUITE 的 71.4%，但正文表述为 QUITE 全面领先（阅读者分析）。

**边界**：作者没有设独立的局限章节。系统定位于长时 OLAP 负载（§1，pp.2–3）；单条查询平均改写约 3.6 分钟（Table 8）；等价性通过执行结果比较判定，LLM 校验失败时退回原查询（§5.2、§7.1）。实验只在 PostgreSQL 上进行。

依据：§7、Table 4–8，PDF pp.9–12。
