# 评测与边界

**基线**（§4.1，PDF p.5）：两种单智能体设置。

- Prompt-only：单个 LLM 直接读取告警 JSON 输出报告，不调用工具，提示含任务说明、模式约束和每个工作流的少样本示例；
- ReAct 工具调用：单个 LLM 用与 CORTEX 相同的类型化工具，工具预算和轮数上限与 CORTEX 对齐。

原文主文未写明基线使用哪个 LLM；附录中 CORTEX 工作流使用 gpt-5-mini（pp.9–17）。

**指标**（§4.1，p.6）：可行动/不可行动的宏 F1、4 个子类的宏 F1、在不可行动预测上计算的误报率（FPR）；效率指标为输出 token、工具调用次数和端到端延迟。原文定义了可行动告警的召回率，但表中没有报告。

**实验 1（分诊质量，Table 4，p.6）**：

| 系统 | 可行动 F1 | 不可行动 F1 | 子类 F1 | FPR(%) |
|---|---|---|---|---|
| 单智能体（提示） | 0.61 | 0.73 | 0.49 | 29.8 |
| 单智能体（工具） | 0.66 | 0.77 | 0.54 | 24.9 |
| CORTEX | 0.78 | 0.86 | 0.69 | 14.2 |

CORTEX 的二分类宏 F1 为 0.82（§4.2）。

**实验 2（效率，Table 5，p.6）**：

| 系统 | Token | 工具调用 | 中位延迟（秒） |
|---|---|---|---|
| 单智能体（提示） | 2,100 | 0.0 | 28 |
| 单智能体（工具） | 4,152 | 1.3 | 44.6 |
| CORTEX | 23,600 | 3.1 | 152.4 |

CORTEX 比工具基线慢 3.42 倍，token 多 5.68 倍，但仍在作者设定的约 3 分钟/工单的 SLO 内（§4.3）。

**原文承认的局限**（§5，p.7）：数据集只覆盖 10 余个场景，受上游遥测可用性和质量限制；对分布偏移、提示注入和工具返回不完整敏感。

**阅读者补充**：结果无方差、无重复运行或显著性检验；测试集规模未知；没有与 AACT、AlertPro 等非 LLM 分诊方法比较（阅读者分析）。
