# 解决的问题

**输入**：用户在多轮对话中提出的自然语言 BI 问题（可能省略维度/指标或含歧义），以及企业数据库与知识库。**输出**：SQL 及其执行结果，进一步可生成洞察报告（归因、预测、诊断等）（§3.1，p.4863）。

**四个模块**（§3，pp.4863–4868）：

| 模块 | 作用 |
|---|---|
| 知识管理 | 存储数据库元数据、领域知识、任务材料（提示与示例）、历史对话；Elasticsearch 粗检索 + 图多跳遍历 + BGE 重排 + LLM 过滤列 |
| MRD-Q | 对话分析（判断是否同时含维度与指标，缺失则从历史补全）+ 意图查询（分为完整/缺信息/非 BI 三类，缺信息时主动追问，再用领域知识澄清歧义） |
| SQL 生成 | 表选择（关键词级相似度 + 嵌入 + 热度打分）；按标注量与领域相似度规则切换一步（微调）或两步（语义中间表示 SIR + SQL） |
| 数据洞察 | Planner / Data Preparation / Tool Execution 多智能体，基于 FunctionCall 与 ReAct |

**策略切换规则**（Eq.6，pp.4866–4867）：标注 Query-SQL 对数 ≥ α 且领域相似度 ≥ β 时用一步法，否则用两步法；实践中 α=500、β=0.7。

依据：§3.1–§3.4、Eq.1–6，pp.4863–4868。
