# 出发点

原文认为真实数据常含缺失值和错误，数据清洗需要领域知识或外部信息，而这些信息往往不在待清洗表内，因此实际系统仍依赖人工（§1，PDF p.1）。

LLM 已被设想用于数据整理，但三类问题并存：
- 云端公共 LLM 可以利用世界知识清洗“公开知识型”数据（场景 1），但对从未见过的企业本地数据无能为力，且无法解释建议值来自何处；
- 因此需要 RAG：由用户提供数据湖，检索相关元组后让 LLM 推断正确值（场景 2）；
- 把企业数据发给外部托管模型可能违反隐私要求，所以还要支持本地部署的 3B–13B 小模型，并用少量样例微调（场景 3）。

出发点是“系统能力演示”而非新算法；隐私与可解释性是选择架构的主要动机，原文未给出隐私或成本的量化评估（阅读者分析）。

依据：Abstract 与 §1，PDF pp.1–2。
