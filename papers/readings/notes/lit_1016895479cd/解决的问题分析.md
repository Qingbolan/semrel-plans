# 解决的问题

**定义**（§III-A，p.3）：给定含 m 条 SQL 的工作负载 W，从 W 引用的列生成候选单列/多列索引集合 I；在存储约束 S(I) ≤ S_c 下，选择子集 I* 使总代价 C(W, I) = Σ cost(q_j, I) 最小。cost 可以是估计代价（`EXPLAIN` + what-if），也可以是实际建索引并执行负载得到的延迟（p.4）。

**系统输入输出**（§V，pp.5–7）

| 项目 | 内容 |
|---|---|
| 输入 | 数据库、工作负载、存储约束、当前索引（通常为空） |
| 负载特征 | 各 SQL 用到的列及其 NDV、行数、类型；WHERE 谓词及选择率；JOIN/GROUP BY/ORDER BY 列及出现频次 |
| 示例 | 按"列频次 + NDV"元特征余弦相似度检索的 top-2 示例，迭代中替换为未见过的次优示例 |
| 每轮 LLM 输出 | K 个 `CREATE/DROP INDEX` 候选动作（温度 0.8） |
| 选择 | 加一个多数投票合并动作，共 K+1 个候选，按数据库反馈取最好（Best-of-N） |
| 输出 | 迭代结束时找到的最佳索引集合 |

**工作单元**：一次推荐 = 一个工作负载在一个存储约束下的一组索引。收益评估次数 = (采样数 + 1) × 迭代数：LLMIA(C) 为 8 个样本、4 轮，共 36 次；LLMIA(L) 为 4 个样本、2 轮，共 10 次（§VI-A5，p.8；Table III，p.10）。

依据：§III–V，pp.3–7；§VI-A5，p.8；Table III，p.10。
