# 解决的问题

形式化（§3.1，p.3）：数据库 D=(T, C, R)，其中 T 为表、C 为列、R 为表间关系（如主外键）；对任意问题 q，寻找映射 f(q, D) 输出语法和语义正确的 SQL y。零样本设定要求不使用任务标注数据，仅依赖预训练知识与给定 schema。

搜索建模：树 Ψ=(V, E)。根节点含 q 与 schema；中间节点存部分推理（列值、函数、子句及 CoT 文本）；边是构造动作；根到终止节点的路径组合成一条候选 SQL。Table 1（p.5）规定动作顺序，例如修正只能在生成之后，终止只能在生成或修正之后，且每个动作在一条路径中最多出现一次；作者计算可能的推理路径超过 3,000 条（§5.3，p.8）。

MCTS 细节（§4.2，p.6）：UCT 选择，优先访问未访问子节点；扩展时每个动作以温度 0.8 采样 3 次；终止时再以温度 1.0 采样 5 条 SQL，奖励 R = (1/N)Σ 1[Execute(y)=Execute(y_i)]；共 24 次 rollout。最终在所有候选中选执行结果一致性最高的 SQL。值检索：对 TEXT 列离线建 MinHash，在线用 LSH 召回与问题关键词相近的值，再按编辑相似度 0.3、语义相似度 0.6（text-embedding-3-large）过滤（§4.3，pp.6–7）。

- 输入：自然语言问题、数据库 schema 以及可执行的数据库实例（奖励与修正都要执行 SQL）。
- 输出：一条 SQL。评测单位：单个 (NL, SQL) 对的执行结果是否与金标准 SQL 一致。

依据：[arXiv:2502.17248v2（ICML 2025，PMLR 267），21 页](https://arxiv.org/abs/2502.17248)，§3.1、§4，PDF pp.3–7。
