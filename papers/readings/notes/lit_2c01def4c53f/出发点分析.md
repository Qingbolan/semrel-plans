# 出发点

作者指出，基于 LLM 的 Text-to-SQL 方法（主要是上下文学习提示与目标域监督微调）在两类场景下明显退化：一是“巨大”的数据库，schema 太长、无关表列太多；二是需要多步推理的复杂问题。Figure 1 的例子要求先算特许学校 SAT 优秀率均值，再找高于均值的学校，需要跨 frpm 与 satscores 两表连接加嵌套子查询。

此外作者认为现有方法忽视了 LLM 调用外部工具（如真实执行 SQL）与多模型协作。相关工作部分还批评 C3-SQL、DIN-SQL 等只在 Spider 系列上实验，部分依赖针对 Spider 的难度分类器或定制偏置，难以泛化到 BIRD 这类更复杂数据集。

Selector 的设计动机有两点：提示里无关 schema 项越多，生成的 SQL 越可能误用它们；完整 schema 会抬高 API 成本，甚至超出上下文长度。
