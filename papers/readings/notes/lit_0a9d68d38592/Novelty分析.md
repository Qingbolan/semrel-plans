# 贡献与评价

**原文贡献**（§1，PDF p.3）：
1. 带四层逻辑规则的多智能体架构，声称任务完成率 98.68–100%、代码执行成功率 94.56–97.10%，而去掉规则时为 74.48–92.03% 和 63.18–83.33%；
2. MultiVis 任务形式化（四场景）；
3. MultiVis-Bench：1,000+ 例，支持多模态输入和可执行 Python 输出；
4. 实验结果：参考图场景 75.63% vs 62.79%（LLM Workflow）/57.54%（Instructing LLM）。

**相对已有基准的位置**（Table 1，PDF p.3）：nvBench（25,750 例）、VisEval（2,524 例）等规模更大但只有文本输入、输出 VQL/Vega-Lite；MultiVis-Bench 只有 1,202 例，但唯一支持参考图、参考代码输入和多场景。

阅读者分析：
- 基准与任务形式化是最实在的贡献，填补了"多模态输入 + 可执行代码输出"的评测空缺。
- "逻辑规则"的定位被反复强调为"数学约束而非 if-then 规则"，但从描述看（迭代上限、参数截断、错误类型分派、确定性任务路由、输出格式校验）实质是工程化的守卫与重试机制；四个定理是对这些机制的直接重述，没有非平凡的证明内容。
- 正文多处数字不一致：结论称代码执行成功率 94.2% vs 71.3–78.5%、任务完成率 98.7% vs 85.6–89.2%、错误恢复 96.8%（§8，PDF p.22），与 Table 4（PDF p.19）的 94.56–97.10 vs 63.18–83.33、98.68–100 vs 74.48–92.03 对不上，且 96.8% 的错误恢复率在正文实验中找不到来源。引言称规则带来 17.58–31.70pp 提升，实际只对应 A–C 三个场景，D 场景仅 3.86pp（Table 3）。
