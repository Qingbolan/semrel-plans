# 解决的问题

**形式化**（§2.2，PDF p.4）：给定数据库 D、自然语言查询 Q、参考图 I_ref、参考代码 C_ref、待修改代码 V_old，学习映射 f: X→V，V 为目标可视化代码（可执行 Python/Altair）。按输入组合分四个场景：

| 场景 | 输入 X | 例子 |
|---|---|---|
| A 基础生成（BG） | (Q, D) | "按月显示销售趋势" → 折线图代码 |
| B 参考图生成（IRG） | (Q, D, I_ref) | 按参考图的堆叠柱状图样式画新数据 |
| C 参考代码生成（CRG） | (Q, D, C_ref) | 把 matplotlib 散点图代码改写为 Altair |
| D 迭代修改（IR） | (Q, D, V_old) | "x 轴标签竖排并加标题" |

**工作单元**：一个案例 = 一条查询加对应输入，输出一段可执行可视化代码；系统内部会先生成 SQL 再生成图表代码（Figure 3，PDF p.7）。

**系统组成**（§4，PDF pp.6–14）：协调者按 D≻C≻B≻A 的优先级确定性地给任务分类（CR-Rule 1），在最多 T_max=10 轮的循环中调用 DQ Agent（list_tables、get_table、get_foreign_keys、find_fields、execute_sql）、Vis Agent（检索 Altair 示例代码、执行代码；参考图由 Gemini-2.0-Flash VLM 直接读取）和 VE Agent（执行代码并由 VLM 做感知评估）。四层规则 CR/TE/EH/RC 分别负责协调决策、参数与执行环境、错误分类与恢复、迭代终止。

**形式保证**：定理 1–4 声称参数安全、有界错误恢复、10 轮内必然终止以及三者合取的"系统可靠性"（§4.3.3，PDF pp.11–12）。

阅读者分析：这些定理本质上由"有硬性迭代上限、越界参数被截断或报错"直接得出，保证的是终止和不崩溃，并不保证输出图表正确。
