# 解决的问题

**输入**：用户的自然语言任务描述，可以包含约束。例如“检测 SMS 垃圾短信，模型要轻量，准确率高于 95%，移动端延迟低于 100 ms”（Figure 1，p.2）。

**输出**：可部署的模型代码和推理端点，例如 Gradio（§3.2，p.4；附录 B.4，p.21）。

**流程**（Algorithm 1，p.5；Figure 2，p.4）：
1. 初始化：Agent Manager 做请求验证。指令不充分时，向用户追问；
2. 规划：Prompt Agent（经指令微调的 Mixtral-8x7B）把指令解析成 JSON，包含 user、problem、dataset、model、knowledge、service 六个键；Agent Manager 结合网页和论文检索，生成 P 个端到端计划；
3. 执行：Data Agent 和 Model Agent 按各自角色分解计划，再通过提示“假装执行”数据处理、模型搜索和超参优化，返回预期的指标、模型大小和推理时间，不真正运行代码；
4. 执行验证通过后，选出最佳方案交给 Operation Agent 写代码，再做实现验证；任一验证失败，就进入计划修订。

工作单元是“一条用户指令 → 一个可部署的流水线”。

“模拟执行”得到的指标由 LLM 推断，真实性要到实现验证阶段才得到检验（阅读者分析）。

依据：[arXiv:2410.02958v2，48 页](https://arxiv.org/pdf/2410.02958v2)，§3、Algorithm 1、Figure 2–3，PDF pp.3–6。
