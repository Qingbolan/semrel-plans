# 解决的问题

**输入**：一张表格，只以标题、行表头、列表头线性化（`Title: <TITLE>` / `Rows: <ROW HEADERS>` / `Columns: <COL HEADERS>`）提供给模型；单元格值只由解释器读取。另有累积的用户接受/拒绝记录。

**中间表示**：ReportGPT DSL，12 个算子：`get, sum, avg, max, min, argmax, argmin, std, eq, less_than, diff, proportion`。操作数只能是花括号引用的行/列表头或其他操作的结果，例如 `get({revenue}, {Q1})`、`diff(sum({revenue}), sum({expenses}))`。

**输出**：一组（评论句、程序、执行结果）三元组，每个程序对应一句评论；界面把程序中的表头按颜色高亮回链到表格单元。

**工作单位与循环**：每次前向从程序分布中无放回采样一批程序（批大小 5）→ 执行 → 逐条生成一句话 → 用户逐条接受或拒绝。拒绝标准有两条：含遗漏或幻觉；或按用户偏好属于平凡、无趣的评论。循环直到用户满意。已接受的程序不应再次生成。

阅读者分析：任务本质是“候选事实生成 + 人工筛选”，系统负责在表上产生可核对的计算性陈述，最终正确性由人兜底；它不处理跨句的连贯报告写作，也不允许 DSL 之外的计算（如同比增长率需由 `proportion`/`diff` 组合，嵌套深度受语法限制）。
