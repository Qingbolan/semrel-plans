# motivation

企业分析任务常是目标驱动的（如诊断客户满意度下降、寻找增长机会），可以有多种合理流水线，但正确性取决于数据本身。作者认为现有基准衡量的是流水线执行或答案貌似合理：KramaBench 评数据湖上的 data-to-insight 流水线，DAB 评端到端数据 agent 并刻意回避开放问题，UniDataBench/InsightBench/InsightEval 评多源分析，SemBench 在算子层评 AISQL、LOTUS、Palimpzest、DocETL 等语义算子引擎，DeepScholar-Bench 评长程综合。缺口是没有基准衡量系统是否恢复了数据背后正确的分析结构。

作者举例：agent 会把产品特定的材料缺陷和品牌级的物流延误事件合并成一个事件，或用通用电商客群代替数据中真实存在的人设；这些不是措辞问题，而是没有恢复生成数据的结构。标准指标（分类准确率、秩相关、聚类相似度）假设预测与真值表示对齐，而分析输出往往合并因子、改名或用更粗粒度，因此不适用。

依据：[arXiv:2605.24183v1，4 页](https://arxiv.org/abs/2605.24183)，§1–2，PDF pp.1–2。
