# 具体用例

用例：智能体独立完成一个 Kaggle 竞赛（§2–4，PDF pp.3–7）。

智能体在隔离容器中拿到竞赛描述和数据，先从根节点多次调用 Draft 生成若干初始方案，每个方案是一段在 Jupyter 中执行的训练代码，用 5 折 CV 得到代理适应度。代码出错的节点进入 Debug 循环，直到修好或用完预算。随后 MCTS 根据 UCT 选择叶子，对它应用 Improve；Improve 的复杂度提示随子节点数从 “minimal” 升到 “advanced”，记忆只看兄弟节点以保持多样性。24 小时结束后，提交验证分最高的节点，并按测试集分数是否达到该竞赛的奖牌百分位来判定成败。

原文给出的风险（§5.3，PDF pp.10–11）：以 AIDE greedy 为例，验证分随时间持续上升，而测试奖牌率趋于平稳甚至略降（Fig. 4a）。若提交验证分前 3 的节点并取其中最佳，奖牌率可再提高约 10%。

阅读者分析：这里“用验证分选最终解”的问题，与语义查询系统中“用代理分数选计划或模型”是同一类问题。
