# 出发点

原文认为实体匹配多被当作监督二分类：标注昂贵，且在一个"领域"（本文中指商品类目）上训练的模型难以迁移到其他类目，例如相机描述上训练的模型不易用于笔记本电脑（§1，PDF p.1）。

另一条路是直接零样本/少样本调用大模型，它们更通用，还能给出自然语言理由便于人工核对；但推理成本高。原文举例：1,000 个实体两两比较即可产生约 100 万候选对，按 API 价格会达到数千美元（§1，PDF p.2；附录 E，PDF p.15）。

因此作者的出发点是：只在训练阶段用大模型生成"解释"，把推理能力蒸馏到小型 seq2seq 模型中，部署时只运行小模型。脚注明确这与传统蒸馏不同，蒸馏的是"推理"而非任务输出本身（§1 脚注 2，PDF p.2）。

阅读者分析：这一动机与语义算子系统中"大模型做 join/匹配太贵"的问题同构，但本文只覆盖 blocking 之后的 matching 步骤，不讨论候选对生成。
