# 解决的问题

**输入**：一条简洁的临床审计问题（含 subject_id、hadm_id 等占位符实例化后的病人/住院标识），以及对受控环境的访问权。环境提供：按临床实体组织的病历检索工具（一次只限一个病人）、有上限的只读 SQL 兜底、带 pandas/numpy/scipy 的沙箱计算、以及共享政策文档库的列出/搜索/阅读工具。web 搜索被禁用。

**输出**：一份带引用的报告，包含四类判定之一——Yes、No、Indeterminate: Lack of Data（缺少判定所需证据）、Indeterminate: Medically Ambiguous（证据齐全但不支持唯一的临床解释）——以及陈述置信度；全部工具调用、检索记录、计算和政策片段形成可重放轨迹。政策引用格式为 `[policy: document L_a–L_b]`。

**评测单位**：一次 run = 一个系统在一个案例上的一次执行；主协议每个案例跑一次，共 750 runs。系统 = 模型 + 智能体框架（harness）+ 提示/脚手架 + 工具的完整配置。不同指标的分母不同：准确率用全部 runs，过程分与无缺陷准确率只用有可解析报告的 runs，病人证据 grounding 只用至少检索过一条病历的 runs。

依据：[arXiv:2608.07796v1，52 页](https://arxiv.org/abs/2608.07796)，§3.2、§4 开头、§5.1、§5.4，PDF pp.8–10、16–18。
