# 评测与边界

**评测形式**：本文是演示论文，§3 只描述四个演示场景（层次目录、语义检索、实时关系分析、算法扩展），没有基线、指标或数值结果（§3，p.4）。

**提及但未报告的评估**：作者称在 SchemaPile 上基于多个开源 LLM 实现并评估了层次生成算法（§3，p.4），正文没有给出评估方法与结果。

**定性对比**（§1，p.2）：

| 系统 | 论文对其的描述 |
|---|---|
| Aurum | 主要支持关键词检索相关表 |
| InsightPilot | 用 LLM 推荐下一步分析动作，不做数据发现 |
| Civilizer | 只能关联已有列与表，无全局层次视图 |
| Google Goods | 自动构建目录并支持关键词与特定属性查询，无语义检索与层次语义视图 |

**边界**：没有局限章节。阅读者分析：

- 无法从本文判断目录质量、检索召回/精确率、LLM 调用成本或在 170 万表上的构建时间。
- 层次聚类每轮都要调用 LLM 概括簇，规模扩大时的费用与一致性未讨论。
- 原型依赖 IGinX、Zeppelin、Milvus 与 OpenAI API，论文称将开源，但文中未给出仓库地址（仅给出 IGinX 项目主页）。
