# 解决的问题

**形式化（§3，p.3）。** 语义算子由自然语言字符串指定：filter 谓词、map 的逐行变换或 join 条件。解释式下，N 项的单目算子需 N 次 LLM 调用，规模 M 与 N 的集合上的 join 最多 M×N 次。编译式把成本从 O(N)（或 O(M×N)）次 LLM 调用压缩为一次编译调用。

**输入：** 自然语言谓词与行模式（filter/map）；join 额外附带左右表若干真实样本行，帮助模型观察取值分布重叠、选对连接键（§3 “The compiler sees global information”，p.3；§4，p.4）。

**输出：** 一个命名的确定性函数——compiled_filter(row)→True/False；compiled_map(row)→新值；compiled_join(row_l,row_r)→True/False，只保留匹配对。提示禁止在生成代码中调用 LLM（§4，Figure 2，p.4）。

**设计是有意简化的（§1，p.2）：** 直接的两阶段流程——先编译、再本地执行；没有路由或代价模型，SemBench 实验中只要流水线里有无编译版本的算子就用原生算子（§5.3，p.5）。

**范围：** 只覆盖逐项（per-item）算子 filter/map/join；sem_agg 等多项算子的决策规则更难抽取，未覆盖（§4，p.4）。评测单位：单算子查询（每查询一个谓词）以及 SemBench 的多算子查询。

**阅读者分析：** “编译”在这里是近似而非语义等价，作者在 §2 明确承认与传统查询编译保持精确语义不同；因此问题实质是“用程序合成近似一个 LLM 判定函数”，质量参照物是 LLM 解释结果本身。
