# 出发点

数据库异常种类繁多。作者举例说，一家数据库厂商三个月内遇到 900 多起异常，涉及慢查询、锁、配置等多个模块，而且这些模块与系统指标之间关联复杂（§1，p.1；Figure 1a）。人工 DBA 的诊断过程是迭代的：通知、告警、指标分析、事件分析、给出优化建议。DBA 培养周期长，人手无法覆盖云上数以百万计的实例，紧急情况下也难以及时响应（§1，p.1）。

已有半自动工具依赖经验规则或小型分类器，有三点不足（§1，p.2）：
- 无法利用诊断知识；
- 场景变化后要重写规则，或重新设计特征和标签并重新训练；
- 不能像 DBA 那样根据中间结果继续深挖。

作者称 GPT-4 直接做诊断的准确率低于 50%（§1，p.2），并据此提出三个挑战：
- **C1**：让 LLM 理解诊断问题，包括长文档知识抽取、知识匹配和工具检索；
- **C2**：单根因诊断中 LLM 过早停止和幻觉；
- **C3**：多根因异常需要多个 LLM 协作（pp.2–3）。

依据：§1，pp.1–3。
