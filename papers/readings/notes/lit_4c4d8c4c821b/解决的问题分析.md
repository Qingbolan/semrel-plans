# 解决的问题

**输入**：一次异常。先由 Anomaly Monitor 根据告警规则触发；Anomaly Profiler 再结合告警和查询统计生成异常描述，内容包括时间、摘要、严重程度和状态（§3，p.4；Figure 4）。

**输出**：诊断报告，包含标题、日期、异常描述、根因、解决方案和诊断过程摘要（§7 Step5，pp.8–9）。每个异常最多给出 4 个根因（§8.2，p.9）。

**范围**：单机数据库的根因，分为六类：并发负载、查询算子、计划与执行、数据问题、模式与配置、有害后台任务。应用侧和网络侧的异常不在范围内（§2.2，p.3，脚注 3）。

**流程**（§3–§7，pp.4–9）：
1. **离线准备**：按章节切分文档，构建摘要树，由 LLM 抽取 "Name/Content/Metrics/Steps" 四元知识块，对冗余块做人工复核；同时建立"类别-工具-API"层次，并为每个 API 写使用说明。
2. **提示生成**：按异常指标用 BM25 检索知识块；用微调后的 Sentence-BERT 匹配 top-k 工具。
3. **树搜索诊断**：UCT 选点，三个评估 LLM 投票作为 W(n)，逐节点反思并剪枝；20 轮内找不到新根因即终止（Algorithm 1）。
4. **协作诊断**：按知识聚类初始化专家，由 GPT-4 根据告警选择专家；专家通过发布-订阅方式异步交换结果，然后交叉评审、修订，最后生成报告。

阅读者分析：§7 Step1 写"初始化 7 个专家"（p.8），§8.1 写 D-Bot(GPT-4) 扮演"8 个专家角色"（p.9），两处数字不一致。

依据：§2–§8.2，pp.2–9。
