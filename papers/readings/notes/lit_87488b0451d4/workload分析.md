# 工作负载

**任务规模与分布**（Table 2，p.5；§5.1，p.6）：共 2,007 个任务，覆盖 139 个数据库。

| 维度 | 类别 | 数量（占比） |
|---|---|---|
| 难度 | Easy / Medium / Hard | 396（19.73%）/ 666（33.18%）/ 945（47.09%） |
| 类别 | 报告 / 单选 / 多选 | 668（33.28%）/ 579（28.85%）/ 760（37.87%） |

**来源**（§4.1，p.4；§3.3，p.3）：

- 结构化：从 BIRD、Spider、Spider2、DABStep 的 23,900+ 查询中人工挑出 4,127 个反映分析型负载（诊断异常、解释趋势、归因）的候选；每个带种子库、模式、示范 SQL 与可执行结果。
- 非结构化：1,600+ 份权威文件（学术文献、行业文档、技术规范、多媒体、企业案例）。
- 构造后：数据库、文档、网页证据占主导，图像/音频/视频为长尾；93% 的报告任务跨三种及以上模态，63% 存在源间相互依赖（一个源的输出参数化对另一个源的查询）（§4.2.2，p.5）。

**质量控制**：难度按 BIRD 标准从 SQL 复杂度、来源多样性、推理深度、领域知识四方面标注，Krippendorff’s α>0.78；单源可解是近半数拒绝的原因（p.5）。

**评测环境**：双路 AMD EPYC 9555、2.2 TB 内存；经 OpenRouter 调用模型，默认 DeepSeek-V3.2（§5.1，p.6）。

阅读者分析：任务是“SQL 种子 + 外部证据”的混合分析题，报告任务的金标准依赖 LLM 评审与细则，不是纯执行匹配。

依据：§3.3、§4.1–4.2、§5.1、Table 2，PDF pp.3–6。
