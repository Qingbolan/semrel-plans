# 具体用例

**FDA0182：爱荷华州酒类销售**（§4.2.2，p.4；Fig. 3，p.5）：

1. Iter 0：抽取种子库模式，执行示范 SQL，检索示范案例，形成 Base State。
2. Iter 1：分出两个候选分支。`db_explore` 执行 SQL 得到人均支出模式（如 ZIP 52003 排第 3，每月 $0.87–$1.64，3 月到 12 月波动 +88.5%），但被自我反思标为 Prune，理由是仅有统计模式而缺乏因果依据；`vector_search` 检索到一篇关于季节性方差分析方法的论文，标为 Continue。
3. Iter 2：存活分支继续分出候选，其中 `web_search` 检索到爱荷华 ABD 波本酒分销监管规定，达到 Sufficient。
4. 智能体据此起草一个报告任务：把人均波本酒消费分析与爱荷华监管模式对季节消费的因果评估结合起来，强制跨 SQL 结果与外部上下文推理；随后进入专家审核。

另一示例（Fig. 1，p.1）：问 2017 年哪个流量来源交易收入最高、差额多少，并要求关联电商增长模式、总结最新研究；智能体分别查询数据库、网页、PDF、视频等后综合成报告。

阅读者分析：这类任务把“SQL 聚合 + 文档/网页检索 + 因果解释”放在同一查询里，与语义算子系统的半结构化分析负载高度相关；但报告任务的正确性靠细则与 LLM 评审判定。

依据：§1、§4.2.2、Fig. 1、Fig. 3，PDF pp.1、4–5。
