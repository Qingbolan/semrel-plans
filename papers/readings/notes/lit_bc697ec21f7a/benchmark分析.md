# 评测与边界

**基线**：TDE（搜索式）、FM（直接用 LLM 输出结果）、DTT（预训练模型）、UniDM（LLM 数据处理统一框架）、Code LLM（只有通用指令和示例的代码生成，相当于本文主干）（§6.1，p.9）。标 `*` 的 TDE、FM、UniDM 数值引自原论文，只覆盖 SO 和 BQ，使用 GPT-3 text-davinci-002，与本文条件不同（§6.2，p.10）。

**实验 1（端到端准确率，Table 2，p.10）**：

| 方法 | SO | BQ | ETL | COM | SCI |
|---|---|---|---|---|---|
| TDE* / FM* / UniDM* | 63.0 / 65.3 / 67.4 | 32.0 / 54.0 / 56.0 | — | — | — |
| DTT | 4.1 | 1.1 | 26.1 | 9.3 | 4.4 |
| FM（GPT-4o） | 75.6 | 64.0 | 56.5 | 65.1 | 30.4 |
| Code LLM（GPT-4o） | 67.3 | 56.0 | 65.2 | 55.8 | 39.1 |
| MegaTran（GPT-4o） | 77.6 | 78.0 | 67.4 | 74.4 | 65.2 |
| MegaTran（GPT-4o-mini） | 75.5 | 74.0 | 60.9 | 69.8 | 52.2 |

正文称相对 SoTA 分别提升 12.0、14.0、2.2、9.3、26.1 个百分点。按表格核算，BQ、ETL、COM、SCI 四项可以对上，但 SO 上 77.6 比 FM（GPT-4o）的 75.6 只高 2.0，比 UniDM* 高 10.2，12.0 无法从表中复算（阅读者分析）。

**实验 2（成本，Table 3，p.11）**：总耗时如下，在 COM 和 SCI 上反而比 Code LLM 更慢。

| 任务 | 本系统 | Code LLM |
|---|---|---|
| SO | 5m32s | 6m20s |
| BQ | 8m51s | 13m52s |
| ETL | 8m23s | 8m54s |
| COM | 11m19s | 6m22s |
| SCI | 7m46s | 6m26s |


**实验 3（消融，Table 4，p.11）**：去掉弱转强提示后，GPT-4o 在 BQ 和 COM 上分别下降 14.0 和 13.9 个百分点，GPT-4o-mini 下降 20.0 和 18.6；去掉反思后，SCI 下降 30.4（GPT-4o）。Lazy-RAG 只在 BQ 和 COM 上被触发，带来 2–4 个百分点。

**实验 4–5（Table 5、Fig.9，pp.11–12）**：Eager-RAG 的查询次数约为 Lazy-RAG 的 5 倍，准确率不高于后者（SCI 上为 47.8 对 52.2）。SO 的 Pass@1/3/5 分别为 69.4/75.5/79.6。

**边界**：仅支持单列、逐值转换；多属性转换、嵌套转换和跨表连接留作未来工作（§8，p.12）。正文称 Lazy-RAG 在 SO、COM、SCI 上未被触发，但 Table 3 中 COM 有 3 次查询嵌入，ETL 为“-”，两者不一致（阅读者分析）。

依据：§6–§8、Tables 2–5、Fig.9，PDF pp.9–12。
