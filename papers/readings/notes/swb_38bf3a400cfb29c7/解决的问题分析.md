# 解决的问题

**任务定义**（§3.1）：给定风险定义（分类体系）D，判断文本是否违反 D。

| 设定 | 输入 | 输出 |
|---|---|---|
| 查询级 | 用户查询 q + D | y ∈ {Safe, Unsafe}，以及违反的子类集合 C ⊆ D |
| 回复级 | 助手回复 r + 作为背景的 q + D | 同上，评判对象是 r |

回复级把 r 作为评判对象、q 只提供背景，以覆盖"看似无害的查询引出违规回复"的情况（§3.1）。

**评测单位与指标**（§4.1）：FinGuard-Bench 的每个查询–回复对分别在两个层级评一次；主指标是 unsafe 类 F1，两层分别报告。子类预测 C 虽在输出中，正文主表没有单独报告子类级指标。

**附加问题**（§5.3）：能否只凭新机构的政策文件（无人工标注）适配到未见过的合规要求。

阅读者分析：这是带"条文体系"条件的二分类+多标签判定，本质上接近语义过滤算子（filter by policy），但判定依据是整套分类体系而非单条条文；论文没有要求定位违规片段或引用具体法条。

依据：[arXiv 2605.29427v1，19 页](https://arxiv.org/abs/2605.29427)，§3.1、§4.1、§5.3，PDF pp.2、6、8。
