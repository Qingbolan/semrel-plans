# 解决的问题

**形式化（§2，pp.2–3）。** 多智能体应用抽象为全局调用图 G=(V,E)，节点是 agent，边是允许的转移，可含环（重试循环）。一个工作流是 G 上的一次执行实例，即 agent 调用序列 a1,a2,…；每次调用是一个 LLM 请求。KV-Cache 分为全局缓存（跨工作流共享，如系统提示、工具描述、知识文档）与私有缓存（仅同一工作流下游 agent 可复用）。

**输入与输出。**
- 输入：每个活跃工作流已观察到的 agent 前缀 v1…vt、当前请求 prefill 最后一个 token 的隐藏状态、由离线轨迹估计的转移矩阵（§4.1，p.4）。
- 预测器输出：未来 K 步每步在 agent 集合（含 ⟨END⟩）上的概率分布（§4.1）。
- 缓存管理输出：GPU 显存不足时按 Score(c) 升序选择驱逐的 Radix Tree 节点；以及在纯 decode 批次中从主机内存预取哪些节点（§4.2–4.3，pp.4–6）。

**工作单元。** 缓存决策的单位是 Radix Tree 节点（页大小的 token 段，附录 G p.19 起提到）；评测单位是一次包含多并发工作流的服务运行，指标按工作流（端到端延迟）、按 agent 调用（TTFT）和按 token（命中率）统计（§6.1，p.7）。

**不解决的问题。** 不改变 agent 框架或工作流本身，不跨工作流复用私有缓存（作者认为解码随机性使其通常不可行，§2 p.3），预测器需针对具体工作负载训练（§5，p.6）。
