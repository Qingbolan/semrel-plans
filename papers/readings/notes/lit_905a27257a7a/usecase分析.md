# 具体用例

**论文用例：代码生成工作流中的重试循环（Figure 1，p.3；§3，p.3）。**

调用图包含 Planner、Analyzer、Coder、Tester、Committer 五个 agent（顺序按 Figure 1 布局读出）；图注写明 Tester 有条件地触发经 Analyzer 和 Coder 的重试路径，即重试循环，通过（Pass）后进入 Committer。

- 当当前 agent 是 Analyzer 时，单步预测器只看到下一步会调用 Coder，看不到两步后会再次调用 Tester，因而可能错误驱逐 Tester 的缓存，导致昂贵的重新 prefill（§3，p.3）。
- PBKV 的 K=3 预测器同时给出未来三步的分布；某缓存节点 c 的分数为各活跃工作流在每一步访问它的概率之和，按存活概率 s(k) 与置信衰减 γ^(k−1) 加权（Eq.2，p.5）。主实验取 K=3、γ=0.7（§6.2，p.7）。
- 若某工作流已经结束，其私有缓存成为 retired cache，被优先回收；只有 retired cache 耗尽后才按分数驱逐活跃缓存（§4.2.3，p.5）。
- 预取只在纯 decode 批次（作者测得 >90% 批次）中启动，预算为 min{空闲+retired 空间, 带宽×decode 步时长}，按单步价值贪心选择（§4.3，pp.5–6）。

**阅读者分析：** 对本项目而言，这个用例说明“语义算子流水线/agent 流水线的执行结构可作为缓存与调度信号”；但论文未处理语义查询算子，也未评测查询级正确性，只评测服务效率。
