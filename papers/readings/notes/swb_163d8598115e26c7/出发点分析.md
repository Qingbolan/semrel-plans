# 出发点

实体匹配（EM）要在 blocking 得到的候选集中找出与锚记录指向同一实体的记录。作者指出现有 LLM 方法有两个问题：

1. 多数方法对每个（锚，候选）对独立做 Yes/No 判断，忽略候选之间的相互关系，以及 clean-clean 场景下“至多一个候选为真”的集合级互斥约束；
2. 工业规模下锚记录数以百万计，推理成本是主要问题。COMEM 等人工设计的组合管线虽然让候选之间有交互，但对每个实例执行同样的算子序列，成本只是架构的副产品，不随实例难度变化。

因此作者希望学一个策略，按实例难度动态决定何时用便宜的局部检查、何时调用昂贵的列表式选择、何时停止。

依据：[ACL 2026 long 1258，13 页](https://aclanthology.org/2026.acl-long.1258.pdf)，§1，PDF pp.1–2；§2.2–2.3，PDF p.2。
