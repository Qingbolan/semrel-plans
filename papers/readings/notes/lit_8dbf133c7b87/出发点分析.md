# 出发点

企业应用中的 SQL（尤其是 ORM 生成的）常常冗余低效，优化器又容易被复杂写法误导。作者举了一个博客汇总查询：PostgreSQL v16 的执行计划照搬了查询的层次结构，需要几分钟；改写为单连接的扁平写法后快一个数量级以上（§1，pp.1–3，Fig. 1–2）。

DBA 通常借助 SQL 到 SQL 改写工具，这类工具应满足三点：语义等价、性能有提升或至少不回退、开销可接受（§1，p.3）。现有方法各有不足：规则式方法（LearnedRewrite、LLM-R2）的改写范围受限；纯 LLM 方法（GenRewrite）容易出现语义和语法错误；很多方法在计划空间而不是查询空间中做变换（§1，p.3）。

在 10 条 TPC-DS 微基准上，人工改写的 CSGM 为 11.84，而 SOTA 集成只有 2.49，作者称这说明现状与人类能力之间存在很大差距（§3，pp.5–6，Table 1）。
