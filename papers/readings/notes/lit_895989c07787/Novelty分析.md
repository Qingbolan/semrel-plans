# 贡献与评价

**论文声称的贡献（§1，p.2）：**
1. 编译式执行范式：把 LLM 从逐项运行时解释移到一次性代码合成。
2. SemBaker：通过薄适配器和各后端已有扩展入口接入 Palimpzest、LOTUS、Nirvana、DocETL，不修改其源码。
3. 基于代价模型的逐算子路由优化器，以及编译-执行并行的执行器：只在下一个要执行的算子仍在编译时才等待，编译产物缓存以复用，带重试（§2.3，p.3）。
4. 评测：平均 4.8–6.3× 加速、5.4–10.7× 成本降低，质量有竞争力。

**与同作者 Vision 论文（arXiv:2607.13407）的关系：** 本文 Table 1 的单算子结果与 Vision 论文 Table 2 完全相同，并明确标注来自 “our preliminary study [3]”（§3.1–3.2，pp.4–5）。新增部分是计划级路由、并行编译执行、多后端适配器、可选的 refine/validate 与 Prompt v1，以及三个 QA 数据集与 DocETL 任务上的端到端评测。

**阅读者评估。**
- 代价模型较粗：阈值是开发中测得并固定的经验常数，所有后端共用；选择率固定 0.5；可编码性仅为词法筛查（§2.2）。作者把动态选择率估计列为未来工作。
- “平均 4.8–6.3×”未在正文给出逐项计算方式；由 Table 2 看，个别组合编译更慢，如 SemBench+LOTUS 原生 8.20s、编译 20.42s，MMQA+LOTUS 23.97s→36.12s（p.6）。
- 质量并非全面持平：MMQA+PZ EM 0.490→0.415，Steam+DocETL 0.870→0.686，SemBench+Nirvana F1 0.793→0.586（Table 2）。
