# 解决的问题

形式化（§2）：数据分析建模为 POMDP (U, S, A, T, O)，状态由代码解释器 I 与文件集合 F 组成；智能体按 ReAct 产生 (z_t, a_t, o_t)，三者合为一步 τ_t，历史 h_t 见式 1。PRM R_θ 给出步级奖励 r_t，轨迹奖励为聚合（Sum 或 Mean，式 2）。

DataPRM 的输入是 h_t、此前的验证反馈 f_t=(r_0,c_0,…,r_{t-1},c_{t-1}) 与当前步 τ_t（式 6）；内部再运行一个 ReAct 循环，每步生成 (ẑ_k, â_k, ô_k)，可执行代码并通过 query_document / query_image 调用专家模型读取文档或图像；终止时输出分数 r_t 与理由 c_t（式 3–5）。

奖励空间为三值（§4.1.3）：1.0 严格正确；0.5 可纠正错误（如语法错误、路径错误，但触发了可用于纠正的环境反馈）；0.0 不可恢复错误（逻辑缺陷或幻觉）。附录 A 用贝叶斯/信息增益视角解释三值奖励：R = 0.5·G + 0.5·I[信息增益 > ε]。

使用方式：（1）测试时扩展：Best-of-N、Beam Search、DVTS 选轨迹；（2）RL：GRPO，总奖励 r_total = (1−β)·r_outcome + β·mean(r_prm)，β=0.5，并在末步 PRM 分数与真实结果不一致时以结果覆盖（式 7–10）。

工作单位：数据分析任务中的一步（思考 + 代码 + 执行观察）。
