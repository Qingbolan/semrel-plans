# 贡献与评价

**原文声称的贡献**（§1，pp.2–3）：

1. 表表示：LLM 为每列生成描述（模式叙述），再加 r=5 条随机抽样行（“列名: 值”拼接），把内容与上下文统一为文本后嵌入（§4，pp.6–8）。
2. 检索：BM25 与向量检索各取 n·k 个候选，按 α 加权的 min-max 归一化分数合并，再由 LLM 判官逐条判断相关/不相关，不相关的移到末尾（§5.1，pp.8–9）。
3. 两件产物：基于 SQL 模板生成内容问题、并以 Datasheets 的 51 个问题让 LLM 扮演数据创建者生成上下文的基准生成器；以及开源端到端系统（§6，pp.10–12）。
4. 工程优化：动态批大小（FeTaQA 的摘要生成从约 15 小时降到 2 小时）和按表分块嵌入（§4–5，pp.7–9）。

**阅读者分析**：每个组件（BM25+向量混合、LLM 二分类重排、模式描述）单独看都不新，作者自己也说新意在于组合（§5.1，p.8）。主要价值在于把“上下文问题”纳入表发现评测，并展示比行级索引小得多的索引也能取得更高命中率。

**阅读者分析**：评测基准由作者自己的生成器产生，上下文也是 LLM 模拟的，这会让结果偏向与系统表示方式相近的问题；BIRD 是唯一外部基准，且只有内容问题。

依据：§1、§4–6、§8，PDF pp.2–12、23。
