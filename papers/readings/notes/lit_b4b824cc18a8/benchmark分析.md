# 评测与边界

**设置**：Qwen2.5-7B-Instruct 用于摘要生成和 LLM 判官，r=5，BM25s + ChromaDB（HNSW），α=0.5、n=5；DGX A100 服务器（§7，p.13）。基线为全文检索（BM25）、LlamaIndex（逐行向量化的 RAG）、Solo（自监督表检索）。指标是 top-k 命中率。

**实验 1（端到端命中率）**：k=1 时 Pneuma 在所有场景中最高；Adventure Works 上为 71.53%，比全文检索、LlamaIndex、Solo 分别高 18.71、15.19、22.95 个百分点（§7.1.1，p.14）。Solo 在 Chicago 上无法运行（7.3 亿向量，约 1 TB）；k=5 时 Solo 和 LlamaIndex 被排除。

**实验 2（BIRD）**：Pneuma 在 original 上为 63.51%，比全文检索、LlamaIndex 高 57.93、19.94 点；annotated 上为 65.83%（§7.1.2，p.15）。LlamaIndex 每表只取前 5,000 行，回答 1,595 题用时 34 小时。

**实验 3（效率）**：100 道题的吞吐：625 张表时比 LlamaIndex 快 16.6 倍、比 Solo 快 5 倍；10,330 张表时为 29.6 倍和 6 倍（§7.2.1，p.16）。离线时间方面，Pneuma 比 LlamaIndex 慢 14.6–18.6 倍，但存储只有 0.6–0.68 倍；在 Adventure Works 上，LlamaIndex 需要 3,357.2 s / 14.5 GB，Pneuma 只需 97.7 s / 30.3 MB（§7.2.2，p.17）。

**实验 4（消融，Table 2，p.19）**：k=1 时混合检索与单路检索对比：

| 数据集 | 类型 | FTS | VS | 混合 |
|---|---|---|---|---|
| ChEMBL | 内容 / 上下文 | 75.40 / 44.22 | 73.00 / 53.24 | 83.00 / 50.88 |
| Adventure Works | 内容 / 上下文 | 74.40 / 48.24 | 67.70 / 57.55 | 81.40 / 56.08 |
| Public BI | 内容 / 上下文 | 72.10 / 49.80 | 42.90 / 57.65 | 71.10 / 57.75 |
| Chicago | 内容 / 上下文 | 50.10 / 41.18 | 40.92 / 57.16 | 55.09 / 52.25 |
| FeTaQA | 内容 / 上下文 | 54.05 / 40.10 | 25.17 / 44.90 | 56.14 / 46.96 |

原文称混合检索在 70% 的场景中最高；按 Table 2 逐格计算，混合检索最高的是 6/10 格（Public BI 内容题上 FTS 更高，ChEMBL、Adventure Works、Chicago 上下文题上 VS 更高）（阅读者分析）。LLM 判官优于 BGE 和 Stella 重排器，后两者几乎都会降低命中率；FeTaQA 内容题上 Qwen 判官为 58.24%（§7.3.3，p.19）。

**边界**：作者没有设独立的局限章节。上下文由 LLM 模拟，如何激励人工提供上下文不在研究范围内（§1，p.3）；行更新需要外部调用 API 触发重采样（§5.2，p.9–10）；非 instruct 模型在高温度下生成的摘要会出现幻觉并降低命中率（§7.4.5，p.22）。阅读者分析：只评测单表命中率，没有评测下游问答的正确性。

依据：§7、Table 2，PDF pp.13–22。
