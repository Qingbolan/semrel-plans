# 贡献与评价

原文声明的贡献（§1，p.2）：

1. 首个基于语言模型的端到端 knob 调优方法；
2. 训练数据生成流水线：合成工作负载、用 HEBO 标注配置、以代价模型代替真实执行；
3. 10 个代表性基准与 3 个真实基准上的评测，包括跨 schema 设置。

**关键设计**：

- OLAP 查询由 GPT-4-Turbo 根据随机选取的表 DDL、列值和示例查询生成，用 EXPLAIN 检查语法、失败则修复，执行超过阈值（如 1 小时）的丢弃（§5.1，p.5）。
- OLTP 工作负载通过随机调整预定义事务权重生成（§5.2，p.5）。
- 代价模型为梯度提升与随机森林回归的平均，输入为归一化配置与 14 个指标，输出为同一工作负载内归一化的性能，10 折交叉验证 R² 均值 0.862（§5.4，p.5；§8.4.2，p.12）。

**评价**：

- 原文显示的突出点是效率：调优时间在所有十个基准上最短（§8.2.1，p.8）。
- 作者称 E2ETune 在所有基准上超过其标签来源 HEBO，并归因于采样-排序（§8.2.1，p.9）；但 Table 2 中去掉采样-排序（贪心解码）只略降，例如 OLAP 同 schema 从 51.4% 降到 50.1%（阅读者分析：这一解释的证据有限）。
- 方法与 PostgreSQL 版本、硬件和 45 个手选 knob 绑定；§9 承认换数据库引擎需重新收集数据和训练（p.13）（阅读者分析）
