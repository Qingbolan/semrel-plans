# problem

**输入**：任意原始数据 D（如一个 CSV；Figure 1 用的是 1,354 人的“说出一张扑克牌”调查数据），不给预设角度或偏好，由系统自行决定报道什么（§3，p.5）。

**输出**：一篇 HTML 多媒体文章 U，要求叙事吸引人、视觉美观、内容可验证（§3，p.5）。

**中间产物与证据池**（§3.1–3.2，pp.6–8）：Detective 产出带来源 URL 的背景条目 D̃；Analyst 产出结果 R 与一一对应的代码 C；Editor 产出带上游指针的段落计划 F；Designer 产出素材规格 V（记录工具调用和提示词）。证据池 E = D ∪ R ∪ C ∪ F ∪ V。Inspector 把成稿拆成片段 u_m（句子、图表或交互元素），并把每个片段绑定到 E 中的条目。证据分两类：代码证据（脚本与具体行号）和引用证据（外部 URL）。Programmer 不产生新事实，只组装与按 Auditor 的建议修改。

**处理单位**：一个数据集 → 一篇文章；评测单位是一对“数据集 + 人类已发表原作”。

依据：[arXiv:2606.11176v2，35 页](https://arxiv.org/pdf/2606.11176)，§3、Figures 1–3，PDF pp.2、5–8。
