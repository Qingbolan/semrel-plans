# 贡献与评价

本文的贡献是组织方式，不是新技术。它用一个生命周期框架（Figure 1）串起训练数据、翻译方法、评测和调试，并将翻译方法按语言模型的演进分类（Figure 2(b)，PDF p.3）。

| 方法类别 | 教程覆盖的要点 |
|---|---|
| 基于 PLM | 新模型结构与学习策略（如 SC-Prompt），以及训练数据合成与增强（§2.2，p.3） |
| 基于 LLM | 提示工程、复杂度感知路由（EllieSQL）、监督微调、LLM 智能体（§2.3，p.3） |
| 模块化 | 模式链接、引入数据库内容、约束解码（PICARD）、自一致性；多智能体框架（如结合 MCTS 的 Alpha-SQL）（§2.4，pp.3–4） |

调试部分介绍了 NL2SQL-BUGs：它用两级分类法把语义错误分为 9 大类、31 个子类，并提供语义错误检测基准（§2.6，p.4）。§1 则写的是"七类 SQL 错误加基准标注错误"（p.1），两处分类口径不同（阅读者分析）。另外，§2.4 把 Alpha-SQL 标为引用 [58]，但参考文献 [58] 是 Stanford Alpaca，Alpha-SQL 实际是 [31]（PDF pp.4–6），属于引用编号错误（阅读者分析）。

阅读者分析：作为教程提案，本文只列出要讲的内容和代表性引用，没有比较各方法的效果数字。许多例子来自作者团队自己的工作（如 NL2SQL360/SuperSQL、Alpha-SQL、EllieSQL、NL2SQL-BUGs）。

依据：[PVLDB 18(12): 5466–5471，2025，教程提案，doi:10.14778/3750601.3750696，6 页](https://www.vldb.org/pvldb/vol18/p5466-luo.pdf)，§1、§2.2–2.6、Figures 1–2，PDF pp.1–4。
