# 出发点

当时最好的 ER 方法要在成百上千个标注实体对上微调预训练语言模型（Ditto、JointBERT 等）（§I，p.1）。LLM 的上下文学习（ICL）只需少量示例，但标准提示每次只问一对，每次调用都要重复任务描述和示例，API 成本很高（§I，p.1）。

作者给了一个估算：1,000 条记录约需 50 万次预测，每对约 90 tokens，用 GPT-4 时 3 个示例加 1 个问题的成本为 500,000×(90×4)×0.01/1000 ≈ 1,800 美元（p.1）。批量提示可以把多个问题合到一次调用里，但当时还没有针对 ER 的系统研究，也没有回答"该把哪些问题分在同一批""该给这一批配哪些示例"（§I，pp.1–2）。

作者还观察到，已有方法都是先确定批次，再选 top-k 示例，没有考虑所选示例是否覆盖了批内每个问题，由此提出基于覆盖的选择（§I，p.2）。成本模型同时计入 API 费用和示例的人工标注费用（§VI-A，p.8）。

依据：§I、§VI-A，pp.1–2、8。
