# 出发点

视频问答要求同时理解帧内空间关系和时间演化的因果动态（Abstract，p.1）。作者把现有方法分为两类（§1，pp.1–2）：
- Video-LLM（如 Qwen-VL）需要处理大量帧，流程冗余低效；
- 工具增强 LLM（如 DoraemonGPT）有三点不足：(1) 工具只覆盖单一维度（空间或时间）；(2) 工具数量与多样性失衡——加工具能弥补 LLM 缺陷，但 LLM 的不确定性使执行变复杂；(3) 缺少调度策略，工具调用无序。DoraemonGPT 依赖对中间数据库的 text-to-SQL 查询，作者称其经常失败，影响准确率与效率（§2.2，p.4）。

作者在最初设计中让规划器自由选择工具，发现它倾向直接调用通用的视频问答工具一步作答，即"工具链捷径"（Toolchain Shortcut），导致处理帧数多、准确率不高（§3.2，p.5）。这是提出 STAR 约束调度的直接动因。

依据：§1–3，PDF pp.1–5。
