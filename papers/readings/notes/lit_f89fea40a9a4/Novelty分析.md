# 贡献与评价

原文主张（§1 Contributions，PDF p.3）：
1. 首个面向数据湖的 LLM 流水线自动编排与优化框架，支持交互调整、增删自定义算子和异构数据；
2. 定义并实现 22 个语义算子（Table 1，PDF p.5），分逻辑/物理两层，每个算子可以有 prompt 实现或预编程实现，例如 Retrieve 可用向量近邻或 BM25；
3. 自动编排方法（链式生成 → DAG 改写 → 合并）；
4. 优化技术：代价模型（每个算子的代价是输入基数的函数，参数用样例负载拟合；基数用约 1% 均匀采样估计）、预取候选检索、并行执行、用 Summarize/Explain 管理上下文（§5，PDF pp.8–9）；
5. 实现与实验。

阅读者评估：
- 与 LOTUS（需手写 pandas 风格代码编排）、Palimpzest（需用户定义 schema 与逻辑计划）相比，AOP 的差别是从自然语言直接生成计划（§8，PDF p.12）。代价是计划正确性依赖 LLM 采样加规则合并，原文没有分析计划本身的正确率。
- §6 的数据湖扩展（嵌入链接、统一代价模型、混合 SQL/流水线执行、预对齐）和 §2 的过程奖励模型都只有设计描述，§7 没有对应实验。
- 22 个算子中有 Plan、Explain、Validate 等控制/反思类算子，与关系代数式的语义算子不是同一层次；原文没有给出算子语义的形式化定义。
