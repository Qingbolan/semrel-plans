# 解决的问题

**任务**：给定一个环境活动的相关法条文本（另加可选的 srl 标注和/或 io 规格），以及同类型的一个示例决策模型及其法条（1-shot），生成该活动的可执行决策模型（§3.4，PDF p.4）。

**输出单位**：每个目标是一个简化 JSON 形式的 DMN 决策图（有向无环图），由三类节点组成：外部输入变量（如"是否位于保护区？"）、包含决策表的决策节点（使用 UNIQUE/FIRST/ANY/COLLECT 命中策略）、唯一输出节点。Outcome 模型输出类别值（不适用/一般规则/告知义务/需许可），Requirements 模型输出布尔值（提交要求是否满足）（§3.1–3.2，PDF pp.3–4）。

**四种输入条件**：

| 条件 | 提示内容 |
|---|---|
| Text | 目标模型关联的法条文本 |
| Text+srl | 加 flintfiller-srl 抽取的 actors/actions/objects/recipients |
| Text+io | 加取自金标模型的输入、输出规格（固定接口，内部结构仍需推断） |
| Text+srl+io | 两者都加 |

**评价对象**：（i）与金标模型的结构相似度；（ii）在预设测试场景上执行后的结果等价性（§3.5–3.6，PDF p.5）。

阅读者分析：io 条件直接使用了金标模型的接口，相当于告诉模型"该问用户哪些问题、可能有哪些结论"，因此它衡量的是"已知接口时补全内部逻辑"的能力，而不是从零开始建模。作者在 §5.1 也承认这一点，并辩称接口本就是领域专家会先做的分析。

依据：[arXiv:2604.17153v1，10 页](https://arxiv.org/abs/2604.17153)，§3.1–3.6、§5.1，PDF pp.3–5、9。
