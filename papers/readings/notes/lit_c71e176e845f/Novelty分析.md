# 贡献与评价

**论文声称的贡献**（§1，p.3）：

1. 提出并解决 NL2BI 中的多轮对话问题；
2. 借助数据库视图技术，把 schema linking 转化为单视图选择；
3. 提出分阶段流程，让 LLM 输出结构化中间结果，复杂语义、计算和比较关系通过映射处理；
4. 在百度生产环境部署，接入多条产品线。

**评价**：系统思路偏工程：用小模型完成分类和改写，用 DBA 维护的视图消除连接，用模板而非 LLM 生成 SQL（阅读者分析）。"NL→JSON→模板 SQL"把 LLM 的输出限制在槽位填充，作者据此称所有任务都降为 DIN-SQL 意义上的 Simple 难度（§5.1，p.8）。

这种设计的覆盖面取决于 Superset 模板和预建视图；需要跨视图连接的查询会被单视图选择判为失败，并交给 DBA 处理，而不是由系统回答（§4.2，p.7）。因此它与通用 Text-to-SQL 不在同一问题设定下，与 DIN-SQL、MAC-SQL 的比较也不是同等条件（阅读者分析）

多轮匹配的"最近匹配模式"只看最近一条完整问题之后的对话，原文称其优于把全部历史作为序列输入，并说详见 §6（§4.1，p.5）；但 §6 只比较了端到端 UEX，没有这项对比的数值（阅读者分析）
