# 具体用例

Figure 4 与 §7.2（pp.7–8）给出的标签收集示例：一条涉及四张表（k、mk、t、mi）的 IMDb 查询。

1. 用 Bao_arm 搜索候选计划并在 PG 中实际执行，取最快者为最优计划。
2. 简化计划树：合并 bitmap heap scan 与 bitmap index scan 为一个 bitmap scan 节点，去掉对所有候选都相同的聚合节点，只保留扫描与连接节点。
3. 序列化为提示：先序遍历生成 4 个扫描提示（如 `SeqScan(k)`）和 3 个连接提示（如 `NestedLoop(k mk)`），再按中序得到 `Leading((((k mk)t)mi))`。

在 LLMOpt(S) 中，查询文本、统计信息和 5 个候选的提示序列一起作为输入，模型只输出最优候选的下标；在 LLMOpt(G) 中，模型输入查询与统计信息，直接输出上述格式的完整提示（Figure 5）。

阅读者分析：这一用例说明 LLM 的“计划”是 PG 可执行的提示文本，而不是自由形式的计划描述；对于语义算子查询，可借鉴其“候选序列化+列表式选择”的接口，但本文只覆盖关系 SPJ 查询。

依据：[arXiv:2503.06902v1，13 页](https://arxiv.org/abs/2503.06902)，§3.3、§7.2、Figures 4–5，PDF pp.4、7–8。
