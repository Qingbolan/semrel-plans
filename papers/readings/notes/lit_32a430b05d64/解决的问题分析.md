# 解决的问题

定义 4.1（p.5）：给定涉及 n 张表的查询 q，在由树结构、表顺序和物理算子构成的计划空间中寻找执行时延最小的计划 p*；真实时延只能执行后得到。

定义 4.2：LLMOpt 用两个 LLM 替换流水线两个组件：
- LLM_G(q, stats(d,q)) → h：生成提示序列 h（pg_hint_plan 的扫描提示 S、连接提示 J、Leading 连接顺序 L）；采样 16 次（温度 1）得到候选，再用 BAO 的 Tree-CNN 预测时延选最小者（Algorithm 1）。
- LLM_S(q, stats(d,q), H) → idx*：输入 BAO 的 Bao_arm 生成的候选提示列表 H，输出最优候选的下标（单个 token，一次推理，Algorithm 2）。

| 要素 | 内容 |
|---|---|
| 输入统计 stats | Card_Tb（PG EXPLAIN 估计基数与表行数）、NDV、Main_Value（高频值）、Min_Max、Hist（§7.1） |
| 标签 | 对每条训练查询执行 5 个 Bao_arm 的候选计划，取实测最快者为 h*（及其下标）（§7.2） |
| 训练 | 监督微调，交叉熵（§7.3） |
| 范围 | 不处理嵌套查询（pg_hint_plan 限制，§8.1） |

作者还修改了 pg_hint_plan：修正顺序扫描提示会使索引失效从而改变连接类型的问题，并在提供完整提示时跳过冗余搜索（§3.3）。

依据：[arXiv:2503.06902v1，13 页](https://arxiv.org/abs/2503.06902)，§3.3、§4–§7、Algorithms 1–4，PDF pp.4–8。
