# 解决的问题

**数据模型**（§2，PDF p.3）：表 T 是 N 行的无序集合，每行有 M 列，可含文本、图像等多种模态。可按定量方式访问的列为结构化列，否则为非结构化列。表中已存在的列称为具体列；查询中按需惰性派生、并不存在的列称为虚拟列。

**三类分析任务**（§2，PDF p.3）：

1. 条件聚合：先按条件过滤，再聚合；
2. 语义检索：按语义过滤条件取出相关行；
3. 抽象与聚合：按抽象属性分组后聚合。

**查询语言 UQL**（§3，PDF pp.3–4）：

- `SELECT "自然语言描述的属性" AS name`；
- `WHERE "自然语言条件"`，谓词按析取范式组织，可混合结构化比较；
- `GROUP BY "自然语言抽象标准"`；
- 沿用 ORDER BY（只作用于具体列）和 LIMIT；
- FROM 只支持单表，不支持连接与嵌套查询。

**假设**：LLM 能正确完成单行内的语义判断与抽取（§3 Assumptions，PDF p.4）。

**优化目标**：给定预算 B（约为逐行 LLM 调用次数），聚合查询要最小化估计方差，非聚合查询要最大化召回（§4.1–4.2.2，PDF pp.4–6）。

**输出**：聚合查询返回带重要性权重的估计值；检索返回行集合；抽象聚合返回（派生属性，计数）元组列表。
