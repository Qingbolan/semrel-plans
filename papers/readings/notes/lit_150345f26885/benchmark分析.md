# 评测与边界

**对比条件**：用户研究中只比较“仅语言输入”与“语言 + 多模态交互”两种条件，使用同一系统；没有与 LIDA、ChartGPT 等外部系统的对照（§5.3，p.9）。

**实验 1（用户研究，10 人，§5.3.2，p.9）**：参与者来自可视化领域，平均 4.2 年可视分析经验。

| 指标 | 结果（论文正文） |
|---|---|
| 任务完成时间 | 简单任务下降 18%，复杂任务下降 15% |
| 平均语言重试次数 | 从 0.79 降到 0.32 |
| 可视化正确性、意图准确性 | 复杂任务上提高 |
| 意图准确性（简单任务） | 多模态条件略低，作者归因于额外复杂度引起的误解 |

正文用了“significantly”，但未报告统计检验方法或 p 值；Figure 7 柱上的具体数值字号过小，本笔记不转录（阅读者分析）。定性反馈中 7/10 认为选择与过滤工具最有用。

**实验 2（专家反馈，§5.3.3，p.9）**：2 位制造业专家认为它可替代 Tableau 中的部分拖拽、筛选与参数设置，但需要回归、相关分析等计算能力；由于只向模型提供数据结构，此类计算无法直接完成。

**失败分析（§6.2，p.10）**：100 次任务执行中，26 次意图误解（布局误解 9、手绘趋势识别歧义 4、手绘选择对象识别错误 4）；4 次 D3 代码无法执行；12 次可运行但有缺陷（坐标轴位置 6、图例重叠 3、颜色语义不当 3）。用户通常在 3 次重试内得到满意结果。

**局限（§6.3，p.10）**：受 LLM 延迟与幻觉限制，缺少输出正确性校验；只提供元数据，复杂转换与计算不支持；仅覆盖 2D 屏幕交互。阅读者分析：样本量小（10 人、2 位专家），且头脑风暴用例本身偏向多模态，结论应视为初步证据。
