# problem

**输入（§2.1）**：关系数据库实例 D（基表及其模式）、自然语言查询 q（可附列说明或领域约定）、工具集 K = K_sql ∪ K_llm ∪ K_aux（DBMS 内关系处理、LLM 语义算子、模式查看/采样/摘要等辅助原语）。

**执行过程（§2.2）**：第 t 轮状态 s_t = (q, W_t)，W_t 是工作区（命名中间关系、模式与目录片段、统计/样本、执行轨迹）。动作 a_t = (工具, 参数, 消耗的工作区产物)；SQL 动作对固定快照是确定性的，LLM 动作可能随机且近似。可选 stop 结束并输出 y。

**语义算子（§2.3）**：llm_map（变换）、llm_filter（选择）、llm_rank（打分）、llm_reduce（关系→单值）、llm_join。逻辑算子与物理工具分离：一个物理 LLM 工具固定了模型、服务配置、提示模板、批处理策略和前后的 SQL 处理。

**目标（式 1–2）**：最大化 E[G(τ)]，其中 G(τ) = U(y; q, D) − λ·Σ c(s_t, a_t)，成本 c = c_sql + c_llm + c_aux，实际中 c_llm 占主导。查询时 U 不可观测（没有参考答案），只能在学习阶段用带参考答案的查询将 U 实例化为具体评分 S(y, y*)。

**输出**：最终结果关系 y；评测以执行准确率（与金标准结果完全一致）、元组级 F1、单元格级 F1 及 LLM 算子成本、时延衡量（§3.3.2、§4.1）。

阅读者分析：工作单元是"一个自然语言分析查询 + 一个关系数据库"，正确答案定义为在完整 BIRD 库上执行金标准 SQL 的结果，因此本质上是"缺失列需由 LLM 世界知识补全"的 Text-to-SQL 变体，不涉及长文本文档的语义抽取（SemBench Movie 迁移实验除外）。

依据：[arXiv:2606.03152v2，14 页](https://arxiv.org/abs/2606.03152)，§2.1–2.3、式 1–2，PDF pp.2–3；§3.3.2、§4.1，PDF pp.7–8。
