# novelty

原文贡献（§1 末尾列表）：
1. 把智能体式查询执行的优化表述为"智能体工作流优化"：规划与对中间结果的执行交替，把经典优化从"只比成本"推广到"质量—成本联合搜索"。
2. 用五个轴刻画计划空间，每个轴对应一个经典优化概念（Table 1）：执行范式 data-driven/code-driven（≈JIT 编译）、算子类型 scalar/aggregate（≈连接算法选择）、算子位置 聚合前/后（≈谓词下推）、选择范围 full/targeted（≈访问路径与物化）、投影宽度 narrow/wide（≈延迟物化）。共 16+4 种固定策略再加 1 个"自适应"策略，计 21 种（§3.1）。
3. EnumGRPO：用结构化计划枚举替代 GRPO 的温度采样来产生组内多样性；多粒度奖励（EX 0.5、TupleF1 0.3、CellF1 0.2，成本惩罚 0.2 作为同准确率间的决胜项）；组内相对优势；四阶段经验蒸馏（轨迹摘要→对比分析→ADD/UPDATE/DELETE 池更新→合并），整个过程只改提示中的经验池，属于"上下文内强化学习"（§3.2–3.4）。
4. 对比、消融与迁移实验。

消融（§5.2、Table 3B）：去掉计划枚举，EX 26.7%；去掉组内比较（类 Reflexion 逐条反思），EX 27.9%；完整方法 35.4%。两个变体都更便宜但更不准，说明二者都有作用。

阅读者评估：
- 主要新意在于把语义算子的物理/逻辑选择映射为可枚举的轴，并用"枚举驱动的组内对比"来获得更可靠的信用分配；学习到的是 32 条可读的自然语言经验（Table 5），而非一个模型。
- 与 LOTUS/Palimpzest 的比较并非同等条件：后两者执行的是由规划器借助金标准 SQL 与 BlendSQL 标注翻译出的固定程序（标 †），不做运行时重规划；这一协议差异是对比结果的重要背景，作者已说明。
- 学习阶段需要带参考答案的 40 条查询，学习成本约 77 美元，在 1× 规模下约 1,677 次查询才能回本（§5.7）。
