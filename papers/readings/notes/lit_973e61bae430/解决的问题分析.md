# 解决的问题

**形式化**：给定 knob θ1…θn 及其取值域，配置空间为各域笛卡尔积，目标是在某负载上找到使 DBMS 性能 f 最大的配置（式 1，§2.1，PDF p.3）。负载指一组 SQL 语句；性能指吞吐或延迟。

**系统输入**（§4，PDF p.5）：待调 DBMS（PostgreSQL 或 MySQL）、目标负载、优化目标（吞吐或延迟），以及知识来源（GPT-4、手册、网页）。**输出**：在用户给定预算（时间或迭代次数）内找到的最佳 knob 配置。

**工作单元**：一次“迭代”是向 DBMS 施加一个配置并跑一次目标负载的压力测试，得到一个性能观测（§8.1，PDF p.10）。离线调优在 DBMS 副本上进行，再把配置部署到生产环境（§9，PDF p.12）。

**中间产物**：Tuning Lake 是每个 knob 的自然语言调优知识集合；Structured Knowledge 为每个 knob 给出 `suggested_values`、`min_value`、`max_value`、`special_value` 四类属性（Def.1–2，§5，PDF p.6）。

依据：§2.1、§4–5，PDF pp.3、5–6。
