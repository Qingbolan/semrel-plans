# 出发点

DBMS 暴露大量 knob（文中举例 PostgreSQL v14.9 有 346 个），取值既有连续也有类别。基于 BO 或 RL 的自动调优靠“试错”，前人报告往往需要数百到数千次迭代，而每次迭代要跑一遍目标负载，耗时数分钟以上（§1，PDF p.1）。

作者把高成本归因于两点：要调的 knob 太多，以及厂商给的默认取值范围过宽（例如 `random_page_cost` 为 [0, 1.79×10^308]）（§1、Table 1，PDF p.2）。而 DBA 实际依赖手册和论坛经验，例如“`shared_buffers` 设为内存的 25%、不超过 40%”，这些文本能直接给出重要 knob 和合理区间。

§3 把动机拆成 M1–M4：ML 方法调优成本高；领域知识有用但没被利用；直接让 LLM 抽取会出现缺项和错误（Figure 2 中间）；现有 BO/RL 框架无法直接吸收结构化知识（PDF pp.4–5）。唯一的先例 DB-BERT 只用了“推荐值”，并以 RL 探索离散空间，作者认为其收敛快但结果次优（§2.3、Table 2，PDF p.4）。
