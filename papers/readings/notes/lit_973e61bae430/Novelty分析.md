# 贡献与评价

论文声明的贡献（§1，PDF p.3）：

| 模块 | 做法 | 位置 |
|---|---|---|
| 知识准备 | 从 GPT 抽取知识→对照官方系统视图过滤噪声→按来源优先级汇总→用 GPT 检查摘要与来源是否事实一致 | §5.1，PDF p.6 |
| 结构化 | 提示集成：K=10 个人工例子池，每个提示抽 n=3 个，按属性做多数投票 | §5.2，PDF p.6 |
| knob 选择 | 让 LLM 从系统、负载类型、查询执行计划瓶颈、knob 相互依赖四个层级挑选，无需训练 | §6.1、Algorithm 1，PDF p.7 |
| 范围优化 | Region Discard、按建议值和上下界构造 Tiny Feasible Space（β∈{0,0.25,0.5}）、为特殊值增设虚拟 knob | §6.2、Algorithm 2，PDF pp.7–8 |
| 搜索 | 先在小离散空间做粗粒度 BO，再复用代理模型在收缩后的全空间做细粒度 BO | §7、Algorithm 3，PDF p.9 |

论文还开放了 PostgreSQL/MySQL 知识库和两个评估 LLM 可靠性的数据集。

阅读者分析：核心新意不在 BO 本身（基于 SMAC3），而在“把非结构化文档变成搜索空间先验”，这一点与 DB-BERT 的区别由 Table 2 和 Figure 9（把 DB-BERT 的 BERT 换成 GPT-4 后无明显提升）支撑。各模块单独贡献的消融放在技术报告中，正文无法核验（§8.6，PDF p.12）。

依据：§1、§5–7、§8.6，PDF pp.3、6–9、12。
