# 解决的问题

**输入**：一条 SQL 查询（论文原型限于 SPJA：选择、投影、连接、聚合）和用户给定的关系 schema（只有 schema，没有实例），并假定已知每个关系的单属性键标签。

**输出**：与在 DBMS 上执行同一查询相同 schema 的关系；目标语义是“相对于 LLM 中存储的信息，答案正确且完整”，并不假设 LLM 信息本身完美。

**执行流程**（§4）：

1. 从 DuckDB 得到逻辑计划；
2. 叶子节点用提示检索键属性取值（如城市名），反复用“Return more results”追问直到不再出现新结果（也可用用户阈值终止）；
3. 选择算子对每个键发出是/否提示，如“Has city c.name more than 1M population?”；连接或投影需要未取得的属性时，在其前插入按键补取属性的节点，如“Get the current mayor of c.name”；
4. 把 LLM 返回字符串转为单元格值，统一数值格式（如 1k → 1000），用类型与值域约束过滤幻觉；
5. 已取得属性上的连接、聚合等由 Python 中的常规算子执行。

**设计假设**（§3）：每个关系有可用单属性表达的键（LLM 默认取最常见含义，如 Rome 默认指意大利罗马）；查询使用有意义的属性与关系标签；接受 LLM 事实不完全可靠。

依据：§3，p.3；§4、Figure 3，pp.3–4。
