# 出发点

声明式查询是数据库流行的主要原因，但 SQL 只能作用于有明确 schema 的结构化数据，大量以文本表达的信息无法直接查询。作者指出，从文本中抽取结构化数据已研究二十多年，仍费时易错：抽取流水线需工程师手工搭建、通常只能抽固定的属性对，每种关系都要训练样本，精确抽取带类型的 n 元关系仍未解决。

另一方面，LLM 在闭卷问答上进展很快，被证明存储了高质量事实，但它们不是为复杂 SQL 训练的；把 SQL 改写成自然语言问题不适合复杂脚本，答案文本还需解析成关系，且 LLM 在聚合等操作上表现差。

作者因此设想把 LLM 当作数据存储，用 SQL 查询它，并与传统数据库混合查询（Figure 2：数据库存关系数据，LLM 暴露来自邮件、文本、PDF 等非结构化来源的信息），服务于数据集成、补全、填补与清洗等场景。选择数据库优先而非 LLM 优先，是因为当时上下文长度不足以处理需要成千上万元组输入的聚合查询。
