# 解决的问题

形式化见 §2.1（p.3）：skill 是目录 `S = (M, R)`，`M` 为根 `SKILL.md`，`R` 为辅助参考、脚本或资源。给定固定 agent `π_θ`、初始 skill `S0`、演化集 `D_evolve` 与不相交的测试集 `D_test`，目标是不更新 `θ` 构造 `S*`，使 `S*` 在 `D_test` 上的通过率高于 `S0`。

**输入**：`S0`（人工 skill 或参数化知识生成的草稿）、演化集任务及其二值正确性判定。

**输出**：一个替换 `S0` 的新 skill 目录，推理时直接加载，无需检索。

**工作单位**：
- Stage 1：每个演化任务一条 ReAct 轨迹（查询、推理/工具历史、最终输出、正确与否）（§2.2）。
- Stage 2：每条轨迹由一个分析子 agent 产出一个补丁；失败轨迹交给可检查产物、对照 ground truth、验证修复的 agentic 错误分析者，成功轨迹交给单次调用的成功分析者；无法因果解释的失败被排除（§2.3）。
- Stage 3：按批大小 `B_merge` 分层合并补丁，去重、解决冲突、偏向反复出现的模式，最后转为 diff 编辑并做确定性校验（§2.4，p.3）。

两种模式：Deepening 从人工 skill 出发，Creation 从参数化草稿出发。主实验为“100% 自演化”：同一模型生成轨迹、提补丁、合并（§3.1，p.4）。
