# 出发点

数据准备把异构、带噪的原始表转换为可分析数据，作者引用文献称其占端到端分析时间的 60%–80%，原因是来源之间的异构、噪声与错位，以及清洗、连接、聚合等操作之间的迭代与相互依赖（§1，p.1）。

现有方法分两类（§1，p.1）：
- **传统方法**依赖输入–输出示例、转换模板或基于规则的程序合成（PBE 等），在受限场景有效，但不能灵活接受自然语言表达的意图；
- **LLM 方法**中，提示式方法直接从任务描述生成代码，决策没有基于中间执行结果，容易产出错误流水线；ReAct 式方法交替推理与执行，但轨迹是线性的，难以修改早先的决策——而在数据准备中，早期错误往往要经过多个依赖操作之后才暴露。

Fig.2 与 Example 1（p.2）给出动机例子：要构造“各导演在 2019、2020 年不同类型电影的评分”表，线性智能体可能过早地连接并聚合，之后才发现 genre 列是多值的；修正需要回到 movies 表的清洗决策处插入 Explode，再重做下游连接与聚合。

作者据此提出两个挑战（§1，p.2）：①如何在执行反馈下支持结构化探索和非局部回溯；②如何训练 LLM 掌握这种树式推理——仅用结果奖励的 RL 面临奖励稀疏，而现有 ADP 数据集（Parrot、Auto-Tables）多是短流水线，监督数据稀缺。
