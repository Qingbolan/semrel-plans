# 贡献与评价

**贡献**：

1. 给出“主动检索增强生成”的统一表述，把单次检索、按窗口/按句的被动多次检索和问题分解统一为“何时检索、检索什么”的不同选择（§2.3、§4，pp.3、5–6）。
2. 提出前瞻式检索：以模型“将要说的话”而非“已经说过的话”作查询，并以 token 置信度决定是否检索（§3.2，p.4）。
3. 为避免错误句子把检索带偏，提出遮盖低置信 token 的隐式查询，以及不需要人工标注的通用问题生成显式查询（§3.2.2，p.5）。

**评价**：消融对两个核心设计都有直接支持。下一句比上一句作查询更好（Table 3）；检索比例在 40%–80% 句子之间通常较好，过多检索在 StrategyQA 上反而降分（Figure 5，p.8）；遮盖阈值 β=0（不遮盖）劣于遮盖（Table 5，p.9）。

阅读者分析：多次检索基线是作者在同一设置下的重实现，作者明确说不是原论文的精确复现（§4，p.5）。各数据集的 θ、β、查询方式和是否合并单次检索都不同（Table 9，p.16），这些超参在开发集上选择（§5，p.6），而评测样本至多 500 条，所以部分增益可能对超参较敏感。隐式与显式查询在 ASQA-hint、WikiAsp 上几乎相同（Table 6），显式问题生成的额外价值有限。

依据：§2–6、Tables 3、5、6、9、Figure 5，PDF pp.3–9、16。
