# 解决的问题

**设定**（§2.1，p.3）：给定用户输入 x 与文档语料 D（如全部 Wikipedia 条目），生成含 m 句、n 个 token 的答案 `y = [s1,…,sm]`。检索器 `ret(q)` 返回文档列表，检索文档拼接在输入之前：`y = LM([Dq, x])`。

**主动检索框架**（§2.3，p.3）：第 t 步查询 `qt = qry(x, y<t)`，初始 `q1 = x`；生成 `yt = LM([Dqt, x, y<t])` 直到下一次检索触发或结束。每步只保留当前检索到的文档，丢弃之前的，以免超出输入长度。

**FLARE-direct**（§3.2，pp.4–5）：

1. 不带检索文档生成临时下一句 `ŝt`（实现上生成 64 token，用 NLTK 取第一句，附录 A，p.14）；
2. 若所有 token 概率 ≥ θ，直接接受；否则构造查询；
3. 查询为隐式（遮盖概率低于 β 的 token）或显式（对每个低置信片段，让 gpt-3.5-turbo 生成以该片段为答案的问题）；
4. 用检索结果重新生成该句。θ=0 时从不检索，θ=1 时每句都检索。

**FLARE-instruct**（§3.1，pp.3–4）：用少样本提示让模型在生成中插入 `[Search(query)]`；实现上把 “[” 的 logit 加 2.0，且检索后一段时间禁止再生成 “[”（附录 A，p.14）。

单位是一次生成中的一个句子步；方法只在推理时使用，不需要训练（§1，p.2）。

依据：§2–3、附录 A，PDF pp.3–5、14。
