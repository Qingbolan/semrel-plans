# 解决的问题

本文是综述，不定义单一任务，而是提出"双视角框架"（§1，p.2；Figure 1，p.3）。

**智能体视角（§3，pp.4–17）**

| 维度 | 分类 |
|---|---|
| 角色设计（§3.1） | 单智能体（多为 ReAct）、双智能体（规划者-执行者、编码者-审查者）、多智能体（软件工程团队式、最小功能智能体）、动态生成智能体 |
| 执行结构（§3.2） | 静态预定义工作流 vs 动态执行规划（含层级规划，Table 4） |
| 外部知识（§3.3） | 外部数据库、检索式方法、API/搜索引擎，以及混合方式 |
| 反思（§3.4） | 驱动方式（反馈驱动/目标驱动）、作用层级（局部/全局）、适应性（结构化/自适应） |

**数据科学视角（§4，pp.17–20）**：任务分为"构建机器学习模型"与"输出分析（洞见、可视化、叙事）"两类；流程循环为数据预处理 → 统计计算 → 特征工程 → 模型训练 → 评估 → 可视化（Figure 14，p.18）。

Table 3（p.10）从协调成本、可预测性、工业适用性等方面比较不同角色设计，例如单智能体适合快速临时分析，多阶段流水线适合需要稳定质量检查的生产场景。

阅读者分析：框架没有给出统一的输入/输出接口或形式化任务定义；"工作单元"随被综述系统而变，从一次数据清洗到完整 Kaggle 竞赛不等。

依据：§3–4，pp.4–20；Figure 1，p.3；Table 3，p.10；Figure 14，p.18。
