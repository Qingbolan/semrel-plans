# 贡献与评价

原文声明的贡献（§1，PDF p.4）：

1. 一个面向自然语言、对话式数据分析的 LLM 数据智能体架构；不同于典型端到端智能体，它允许全过程人工介入，以应对任务失败或误解用户意图。
2. 知识整合机制，可处理需要领域知识的任务，并在知识与指令不一致时提供灵活性。

**系统特征**：只用两个智能体（程序员与检查员），可分别由相同或不同 LLM 实现（§3.1，PDF p.8）；提供 OpenAI 风格接口以兼容 vLLM、LLaMA-Factory 部署的模型（§3.6，PDF p.14）；支持报告生成与代码导出（§3.5，PDF p.13）。

**作者给出的支撑证据**：检查员消融（Table S.2，PDF p.38）；与 MetaGPT 在一个画图任务上的耗时/token 对比（Table S.3，PDF p.42）；与 GPT-4 Advanced Data Analysis 的功能勾选对比（Table S.4，PDF p.42）。

阅读者分析（评价）：

- “程序员 + 检查员 + 自我修正 + 人工介入”是当时代码智能体的常见组合；Core 模式与 Data Interpreter/TaskWeaver 的工具机制相近，原文也承认二者类似（§4.2，PDF p.23）。主要差异在于 Full 模式暴露代码实现，使智能体能修改工具。
- 主要数据实验比较的是“LAMBDA 生成的建模代码得到的准确率/MSE”与“作者手写 R 的结果”，衡量的更多是 sklearn 等库模型本身，而非智能体相对其他智能体的能力。
- 正文未说明主要数据实验使用哪个 LLM；需查 Table S.6（PDF p.56）才知 ML 数据集评测用 Meta-Llama-3-8B-Instruct，知识整合对比用 GPT-3.5-turbo-1106。
- Table S.4 的功能对比为作者自评勾选，不是实验测量。

依据：§1、§3–4、Tables S.2–S.4、S.6，PDF pp.4、8–14、23、38、42、56。
