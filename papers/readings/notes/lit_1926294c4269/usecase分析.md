# 具体用例

教程中最具体的用例是 NL2SQL 中的 RAG（§2.1 “RAG”）：普通 LLM 可能不了解本地数据库的模式和取值，RAG 检索与请求相关的 schema 与数据值，拼进提示，再让 LLM 生成 SQL。同一模块还先用 LLM 识别查询意图，再检索相关 API（例如用于数据分析的 pandas API），指导 LLM 调用合适的接口。

第二个用例是数据标准化中的 agent（§2.1）：agent 把用户请求分解为 split/transform/validation 等子任务，生成优化后的流水线执行。第三个是数据库诊断：LLM 分析异常数据库指标，向 DBA 报告根因与可能的解决办法（§1）。

阅读者分析：这些用例都只有一两句描述，没有输入样例、输出样例或成功判据；若要在项目中复用，应以被引原始系统的论文为准。

依据：[PVLDB 17(12) 4213–4216](https://www.vldb.org/pvldb/vol17/p4213-li.pdf)，§1、§2.1，PDF pp.1–3。
