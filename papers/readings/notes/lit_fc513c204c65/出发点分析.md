# 出发点

作者认为一个学习型查询优化器（LQO）应同时具备三种性质：从自己生成计划的执行反馈中学习；无需长时间训练即可工作（避免冷启动）；在模式、负载和数据变化时无需大量人工与重训即可适应。

他们举例说明现有系统最多满足两条：Bao 能从错误中学习和适应变化，但需要数小时训练才有竞争力；FASTgres 没有冷启动且能学习，但负载变化时需重训；用微调 LLM 生成或选择计划的两项近期工作可以立即工作，但微调代价高，无法持续纠错。

作者的直觉是：不用 LLM 的 LQO 推理能力不足，只能靠大量训练数据或假设负载固定；用 LLM 的方法能即时适应，但靠微调纠错放不进 DBMS 关键路径。SERAG 因此改为通过检索历史执行记录、做少样本提示来“学习”，不更新模型权重。

阅读者分析：这三条性质是作者的定位框架，论文并未对 Bao、FASTgres 的训练时间或适应能力做对照测量，只引用其已有结论。
