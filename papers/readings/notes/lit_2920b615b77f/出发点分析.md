# 出发点

专用 text-to-SQL 模型（RAT-SQL、LGESQL、PICARD 等）需要大量高质量标注样例和微调，结构复杂、部署困难（§1–2，pp.1–2）。LLM 的上下文学习可免去大规模微调，但当时方法有两类问题（§1，pp.1–2；§2，p.3）：

- Rajkumar et al.（2022）提示设计简单，效果落后于微调模型；
- DIN-SQL 流程复杂，生成一条 SQL 要多次调用 API，又慢又贵；Nan et al.（2023）需要额外的难度预测器和多数投票的多次调用；
- 上下文学习方法尚未扩展到 SParC、CoSQL 等多轮数据集。

思维链（CoT）适合 text-to-SQL 的多步推理，但现有 CoT 需要人工挑选典型样例并手工标注，text-to-SQL 缺少自动生成 CoT 的方法（§1，p.2）。

作者把“每条 SQL 只调用一次 API”作为与 DIN-SQL 的核心差异，成本论证基于调用次数，论文没有报告 token 数或美元成本（阅读者分析）。

依据：§1–2，PDF pp.1–3。
