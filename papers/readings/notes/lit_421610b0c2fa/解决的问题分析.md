# 解决的问题

**输入**：自然语言查询 q 与数据库模式 S（多张表 T、列 C，以及表中数据）。**输出**：中间可视化查询 v（VQL），再翻译为可执行的可视化代码并渲染为图表 V（§2，p.2）。

VQL 沿用 nvBench 系工作：SQL 风格的数据部分加上可视化类型（`VISUALIZE BAR`）和分箱子句（`BIN ... BY WEEKDAY`）。论文给出的例子是对 `ALL_Documents` 按 `Date_Stored` 计数并按星期分箱（§2，p.2）。

**工作单元**：一条（NL 查询，数据库）对生成一张图。评测判断图能否渲染（Invalid）、是否满足查询要求（Illegal，含数据转换、图表类型、排序等检查），以及可读性分数（附录 A，p.13）。

**单表与多表**：processor 依据涉及表数与所需运算把查询分类为 single 或 multiple，composer 据此选择策略；多表情形需要连接或复杂聚合（§3.2–3.3，p.3）。

阅读者分析：任务的“正确性”由 VisEval 的规则检查决定（图表类型、数据、排序），并不检验用户意图本身是否模糊；这一点与 nvBench 2.0 所关注的歧义问题不同。

依据：§2–§3，PDF pp.2–4；附录 A，PDF p.13。
