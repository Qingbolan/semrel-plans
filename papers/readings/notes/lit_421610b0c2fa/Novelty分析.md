# 贡献与评价

论文自述两项贡献：（1）提出 nvAgent，把 NL2VIS 分解为可管理子任务的协作智能体流程；（2）用大量实验与消融验证分治策略的有效性（§1，p.2）。

| 组件 | 做法 | 原文位置 |
|---|---|---|
| processor | 数据库描述（列与示例值）、模式过滤、关系解释增强、复杂度分类 | §3.2，p.3 |
| composer | 按分类选策略；CoT + few-shot；草图→填充→组合 VQL | §3.3，p.3 |
| validator | VQL→Python 翻译、沙箱执行、把错误信息回送 composer 修正 VQL | §3.4，p.4 |

作者特别说明修正的是 VQL 而不是 Python 代码，因为 VQL 语法更简单；Table 4 中 VQL 修正通过率 71.36%，直接修正代码为 70.35%，且修正阶段 token 更少（1179 对 1365）（§4.5，p.6–7）。

**阅读者分析（评价）**：

- 各组件（模式过滤、CoT、few-shot、执行反馈）都是 text-to-SQL 中常见技术，新意主要在组合与在 VisEval 多表场景上的系统验证，而非新算法。
- 消融显示强骨干下 processor 几乎无益：GPT-4o 时去掉 processor 平均通过率反而从 83.80% 升到 83.97%（Table 2，p.6）。真正关键的是 composer（含 few-shot），去掉 ICL 平均通过率从 71.35% 降到 44.82%（Table 3，GPT-3.5）。
- Table 7（附录，p.14）注明 LIDA 与 Chat2Vis 不能处理多表场景（N/A），而 Table 1 仍给出两者多表通过率约 1.4%–2.3%；多表“领先 9.23 个百分点”实际上主要是与 CoML4Vis 比较（阅读者分析）。

依据：§1、§3、§4.3–4.5，PDF pp.2–7；附录 Table 7，PDF p.14。
