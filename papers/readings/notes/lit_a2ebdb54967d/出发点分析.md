# 出发点

原文把“知识密集型分析应用”作为动机：决策需要同时整合结构化表与非结构化文档（例：调查船只违规时，查表获得船只信息、解读法律文件判断严重程度、聚合历史违规、对干预措施排序）。LLM 让检索与推理流水线容易原型化，但实现仍要在 DBMS、搜索引擎等异构系统间编排，手动决定模型选择、提示改写、上下文管理、预测缓存等低层细节；质量、延迟、成本或规模要求一变就需要大幅重写，且跨系统搬运数据失去联合优化机会。作者把这比作关系模型之前的数据管理时代，主张以声明式 SQL 加优化来隐藏这些细节。

依据：[arXiv:2504.01157v1](https://arxiv.org/abs/2504.01157)，Abstract、§1，PDF p.1。

动机论证以叙述为主，没有用户研究或成本度量支撑“需要大幅重写”的说法。（阅读者分析）
