# 评测与边界

**无实验评测**：全文没有基线、指标数值或实验结果（§1–§8，pp.4073–4078）。唯一的"评测框架"是 Table 1 的五项成功标准，用来组织论文结构而非被测量（p.4074）：

| 成功标准 | 含义 | 对应章节 |
|---|---|---|
| Expressiveness | 声明式支持多种约束类型 | §3 |
| Executable Semantics | 检查内容、时机、失败动作有明确语义 | §4 |
| System Integration | 与查询接口、优化器、执行引擎集成 | §2 |
| Performance Awareness | 按代价与可靠性选择反应式/主动式执行 | §4.2 |
| Enterprise-Scale Applicability | 可观测、复用、审计、冲突检测 | §5–§6 |

**作者列出的开放问题**：

- 哪些 SIC 可通过受约束解码执行、如何高效对多属性施加不同约束（§4.2.1，p.4076）。
- 随机性约束可靠性的估计依赖人工标签，且受上游计划和数据影响，历史统计可能失效（§4.2.2，pp.4076–4077）。
- LLM 置信度的校准仍需研究（§4.2.2，pp.4076–4077）。
- 接口可用性需要用户调研验证（§3 开头，p.4074）。
- 多个约束可能冲突（如"完整病情"与"排除 PII"），需静态/LLM 分析并调整优先级（§6，p.4078）。

阅读者分析：SIC 本身也调用 LLM 判官，引入新的错误源和成本；论文承认这一点（约束可靠性需估计），但没有给出估计误差或开销的任何数据。引用本文时只能作为接口/架构设计的参考，不能引用其性能结论（阅读者分析）。

依据：Table 1，p.4074；§3–§6，pp.4074–4078。
