# 具体用例

**用例：脓毒症筛查查询**（Listing 1，§3，pp.4074–4075）。

医院分析人员在 `ehr_table` 上写一条 pipe SQL 语义查询：先用 LLM 把 `dob` 规范为 `YYYY-MM-DD` 并用正则断言格式；计算年龄；用三个 `EXTEND EXTRACTIVE` 提示从 EHR 中抽取体检、化验与既往史；用 `EXTEND ABSTRACTIVE` 摘要既往史；最后用提示词过滤"基于年龄、体检、化验与既往史可能患脓毒症"的患者，并别名为 `sepsis_filter`。

系统行为：

1. **抽取式 grounding**：确定性检查体检和化验文本是否逐字包含于 EHR。
2. **摘要约束**：摘要须与 EHR 事实一致、长度小于 1000、且不包含化验结果；违规时重试一次，仍失败则 CONTINUE 并标记元组。
3. **Soundness**：过滤算子的 LLM 同时返回 CoT（列出前提与推理步骤），由 LLM 判官检查前提是否有据、推理是否有效。
4. **Relevance**：默认检查抽取的既往史确实是"医疗史"而非"社会史"。
5. 优化器把约束下推到对应算子之后，并把约束文本附加到算子提示词中（§4.1，p.4076）。

在可观测性界面中，用户可按查询 ID 查看代价、约束选择率，并发起人工标注请求以计算随机性约束的精确率/召回率（§5，p.4077）。

依据：Listing 1，§3–§5，pp.4074–4077。
