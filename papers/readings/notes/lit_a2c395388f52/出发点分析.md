# motivation

语义算子（用 LLM 判定的过滤、连接、投影）常与关系算子组合成混合计划，执行代价同时来自昂贵的 LLM 调用和常规的数据库处理。作者指出已有工作的两个缺陷：(1) 忽视语义算子与关系算子的交互——Lotus、Palimpzest/Abacus、DocETL 等都只优化单个语义算子；ZenDB、iPDB、Cortex AISQL 采用把语义过滤上拉的启发式，但在多表查询中可能使中间结果膨胀；(2) 模型级联、近似查询处理等做法会改变算子的输出，多个算子组合后误差会累积。Listing 1 的例子（books 1K 行、reviews 5K 行）中，全部下推需要 4,000 次 LLM 调用；全部上拉借助函数缓存只需 3,300 次，但连接要处理未过滤的表。作者还引用 Snowflake 的数据：近 40% 的语义查询涉及多表。

依据：[arXiv:2604.09944v2（2026-04-24），13 页](https://arxiv.org/abs/2604.09944)，§1，Listing 1、Figure 1，PDF pp.1–3。
