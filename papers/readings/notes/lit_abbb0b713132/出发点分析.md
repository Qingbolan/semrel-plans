# motivation

数据库查询在封闭世界假设下求值：只能基于库内数据回答（§1，p.1）。对“超出数据库”的问题，直接做法是拒答；数据库社区也研究过基于不完整数据的启发式和众包（CrowdDB、Qurk、Deco、hQuery，§2.2，p.2），但人力成本高。作者转而探索用 LLM 补足缺失信息。

作者强调这类问题不同于开放域问答：它们在关系库中有部分依据，需要把结构化数据与 LLM 的世界知识结合起来推理（p.1）。动机例子（Figure 1，pp.1–2）：superhero(hero_name, full_name) 表中要列出漫威宇宙的英雄；库里没有出版商信息，但若把 LLM 视为一张含 hero_name 与 publisher 的表，即可写出 “SELECT … FROM LLM JOIN superhero … WHERE llm.publisher='Marvel'”。

相关工作的缺口（§2.2，p.2）：Galois 等愿景工作只做了初步案例研究——Galois 在 LLM 上执行 46 条 Spider 查询，不涉及关系库，并人工核对结果；缺少评测基准。作者指出 SWAN 基于 BIRD，其数据库平均行数是 Spider 的 270 倍。

阅读者分析：本文的定位是“先有基准、再谈系统”，HQDL 被作者明确称为“初步方案”（preliminary solution）；其价值主要是数据集与评测口径，而非方法。
