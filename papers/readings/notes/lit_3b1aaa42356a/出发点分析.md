# 出发点

作者认为 LLM 让数据分析从菜单式界面转向自然语言交互，企业希望“数据智能体”能自主理解意图、查询数据并给出洞察；但现有实现多为线性的 “ChatBI” 系统或孤立的查询翻译器，在复杂多步工作流中脆弱、执行逻辑不透明，难以在可信的企业场景落地（摘要、§1，p.1）。

作者归纳三项挑战（§1，pp.1–2）：
- **C1 异构鸿沟**：实际决策需要把结构化数据（如 SQL 中的销售记录）与非结构化知识（如 PDF 市场报告）交叉引用；Text-to-SQL 只处理数据库，RAG 只处理文档，缺少联合分析框架。
- **C2 复杂推理中的上下文爆炸**：单智能体架构把所有工具描述、中间观察和推理历史塞进一个全局上下文窗口，随工作流复杂度上升导致幻觉、失焦和不遵循指令。
- **C3 不可靠与低效**：LLM 的非确定性与严格数据工程要求冲突；现有智能体生成难以验证、调试或优化的“黑盒”执行链，并且顺序执行，错失并行机会（如取数与总结文本同时进行），延迟更高。

阅读者分析：这些挑战以论述方式提出，论文没有用实验或用户研究量化“上下文爆炸”或延迟问题的严重程度。
