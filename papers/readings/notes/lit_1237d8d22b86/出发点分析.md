# 出发点

传统优化器遵循“计划枚举+搜索”范式：枚举候选计划，用依赖启发式与经验调参的代价模型挑选最低代价计划；学习型优化器（DQ、Neo、Balsa 等替代搜索，Bao、HybridQO、Lero 等引导原生优化器）仍受初始枚举的候选集限制，可能错过更好的计划（§1、§2，PDF pp.1–3）。

作者受 LLM 在数学、编程等规划/推理任务上的表现启发，提出问题：能否不做显式枚举、直接由 LLM 生成执行计划？难点在于通用 LLM 不了解数据库实例信息和算子、算法、复杂度等专家知识，因此需要数据层面的“配方”和算法层面的微调目标，使其从多个现有优化器“蒸馏”经验，并有可能超过任一单个优化器（§1，PDF pp.1–2）。

§7.8 的 IMDB 案例（Fig.7）展示 PostgreSQL 因右子计划基数被低估约 30 倍而选择了最慢的计划，为“代价模型误估”这一动机提供了具体例证，但这是单个查询。（阅读者分析）
