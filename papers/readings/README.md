每篇包含：原文及版本说明、出发点、问题定义、贡献、工作负载、具体用例、评测与边界。`notes/` 保存正文，`papers/` 保存原文，`text/` 保存提取文本；`reviews.json` 保存发布清单、SHA256、阅读范围和逐项证据定位。`sources.json` 是原文阅读流程的来源记录。

READ 表示单人阅读与自查；不代表复现实验，也不代表独立审阅。EVIDENCE_CHECKED 必须记录不同于 reader 的 reviewer 及其核验的证据。

## 后续批次

1. 读取工作区指令，运行构建后的清单核对，优先选择带现有查询的 pending 论文。检查当前文件，避免覆盖其他工作的修改。
2. 获取原文，保存具体版本和 SHA256。阅读问题、方法、实验、局限相关正文，必要时阅读附录；用 PDF 渲染核对重要表格。遇到不可获取的全文，记录尝试过的来源及原因，继续其他论文。
3. 在 `notes/<paper-id>/` 编写七份解析。每个结论提供章节、页码或图表定位，明确输入、输出、样本单位、数据划分、基线、指标与比较条件。单独标明本项目派生任务和分析推断。
4. 将完成项加入 `reviews.json` 与 `sources.json`，状态为 READ。证据 `basis` 只能为 `explicit`（原文释义）或 `inference`（阅读者分析）；混合事实与分析的段落应拆分，或保守标为 inference 并解释边界，不使用笼统的自由文本类型。`src/paper_reviews.py` 校验原文哈希并发布七栏，保留已有 queries 来源关联。不要重复往身份配置中存放解析正文。
5. 运行 `python3 -m unittest discover -s tests -p 'test_paper*.py'`；测试导出可能不含查询，所以随后必须执行 `python3 scripts/build.py`。
6. 执行 `python3 scripts/audit_paper_completion.py` 刷新待补列表，再运行 `python3 scripts/validate.py`。该清单使用 canonical URL 合并身份，并将已有 workload 中的完整 usecase 内容视为已存在。
7. 每批报告具体完成论文、剩余量与阻碍。任务已设置为本聊天每小时续做、每批最多 10 篇；完成全部条目后暂停自动任务。没有新进展时保持安静。不要自行提交或推送。
