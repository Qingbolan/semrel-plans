# 贡献与评价

**论文声称的贡献**（§1，p.2）：
1. 提出 LLMCompiler：Planner、Task Fetching Unit、Executor 三组件，让开源与闭源模型都能并行调用函数；
2. 在“完全可并行”任务（HotpotQA、Movie Recommendation）上相对 ReAct 1.80×/3.74× 加速、3.37×/6.73× 降本；
3. 新建 ParallelQA，覆盖带依赖的调用模式，最高 2.27× 加速、4.65× 降本、约 9% 准确率提升；
4. 通过重规划支持 24 点等动态任务，相对 Tree-of-Thoughts 约 2× 加速；
5. 在 WebShop 上相对基线最高 101.7× 加速、成功率提升 25.7%（§1 贡献列表；§5.4 正文给出的提升是相对 ReAct 28.4/20.4 个百分点、相对 LATS/LASER 6/5.6 个百分点）。

**阅读者评价——优点**：
- 把静态依赖、带依赖的并行、动态重规划、交互式决策分开评测，没有用一种模式代表全部（§5.1–5.4）。
- 加入 ReAct†（专门提示以减少循环和过早停止），并以它作为延迟比较的基准，避免只赢弱基线（表 1、附录 A）。
- 把延迟、token、美元成本分开报告，并有流式 Planner 消融（表 2、表 C.1）。

**阅读者评价——不足**：
- ParallelQA 只有 113 题，由 GPT-4 生成、人工标注，并刻意只选 Wikipedia 首段能回答的实体，排除了检索失败（§5.2、附录 I），所以它测的是分解与调度，不是开放检索能力。
- 不同实验用的 GPT 型号不同（gpt-3.5-turbo、gpt-4-turbo、gpt-4），WebShop 中 LATS/LASER 的数字取自原论文而非重跑（附录 D、表 3 标题），跨实验横向比较需谨慎。
- 原文有几处自相矛盾：见“评测与边界”页末尾。

依据：§1、§5、表 1–3，PDF pp.2、6–9；附录 A、B、C.1、D、I，pp.13–16、21。
