# 解决的问题

**任务定义**（§2.3，p.3）：

- 输入：一个自然语言查询和对应系统的遥测（指标、调用链、日志）；
- 输出：根因三元素（组件、开始时间、原因）的某个子集，结构化 JSON；
- 七种目标：三元素的所有非空组合，3 个单元素、3 个双元素、1 个三元素。七种目标是按输出字段组合划分，不代表七种不同的探索结构（阅读者分析）。

**评分**（§2.3、§4.1，pp.3、6）：所有要求的元素都对才得 1 分，否则 0 分。为避免文字表述差异，所有可能的原因和起源组件都预先写在 prompt 中；开始时间允许 1 分钟误差。另报 Partial：至少一个要求的元素正确的比例（Table 2 注）。

**查询中给出的信息**（§2.4 Stage 4，p.5）：30 分钟的故障时间窗、所属系统；同一窗口可能有多个故障先后发生，因此查询中给出实际故障数量。

**方法：RCA-agent**（§3，Figure 4，p.5）：

| 角色 | 职责 |
|---|---|
| Controller | 主决策者；按"异常检测 → 故障识别 → 根因定位"的通用流程，并按指标 → 调用链 → 日志的顺序分析；目录结构与数据 schema 动态注入 prompt |
| Executor | LLM 代码生成器 + 有状态的 Python 内核；执行失败时根据错误栈自我修正，成功则把结果回报给 Controller |

**边界**：预给候选空间与故障数量，不能直接等同于开放类型、未知故障数的生产诊断（阅读者分析）。

依据：[原文](https://proceedings.iclr.cc/paper_files/paper/2025/file/d29b8d53678015079e1d245c023e49d2-Paper-Conference.pdf)，§2.3–2.4、§3–4，pp.3–6。
