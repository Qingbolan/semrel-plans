# 评测与边界

**比较方法**（§6.2，p.764）：`SBR`（TelegraphCQ 原有路由，按全局选择率的反比概率路由）；`Content-Learns`（本文方法）；`Content-Knows`（被告知每个算子的最佳分类属性和每类最佳顺序，仅作理论界，只在 Stream-Star 中出现）。

**指标**：总执行时间；路由调用次数。作者指出路由调用的改进是执行时间改进的上限。

**实验 1（偏斜，§6.3，Figs.3–4）**：类数等于连接数；每类有一个算子选择率为 A，其余为 B，A 从 5% 到 95%，保持总体选择率 5%。偏斜越大收益越大，A<B 时尤其明显；最多减少 67.8% 路由调用（8 个算子、最大偏斜）；平均来看，A<B 时少 26.9%，A>B 时少 10.2%。

**实验 2（随机选择率，§6.4，Figs.5–6）**：每个查询跑 50 条流。1600 万次路由调用中，用错分类器的只占 6.4%。算子越多改进越大；结论中称执行时间最多改善约 35%（§7）。

**实验 3（总体选择率，§6.5，Fig.7）**：6 路连接，总体选择率 5%–35%，每点为 50 条流的平均，图中标注的改进值在 13.0%–25.1% 之间。

**实验 4（Lab 数据，§6.6–6.7，Figs.8–9）**：

| 指标（Q2，50 个随机查询平均） | 相对 SBR 的改进 |
|---|---|
| 路由调用 | 8% |
| 总执行时间 | 5% |
| 算子求值时间 | 7% |
| 元组被丢弃前的路由调用 | 18% |

作者解释收益不大的两个原因：TelegraphCQ 自身有与路由无关的开销（网络 I/O、排队）；57.2% 的时间里算子选择率接近 0% 或 100%，此时没有可利用的相关性。人为增加算子代价（0–500 µs）后，执行时间改进随代价上升。

**实验 5（开销，§6.8，Fig.10）**：SBR 与 CBR 的总开销（路由加统计更新/学习）都约占执行时间的 4–5%。单算子查询 Q1 上路由无从改进，CBR 比 SBR 慢约 0.8%（10 次运行平均）。

**边界**：
- 只考虑单属性分类器和单个算子，属性组合、算子组合留作未来工作；桶数、抽样率、样本大小还需手工设定（§8）；
- 画像用无条件选择率，没有利用条件选择率（§4.1）；
- 非过滤算子没有实验（§4.5）；
- 合成数据中只有一个相关属性，真实数据上的收益明显小于合成数据。

依据：§6–8、Tables 2–3、Figures 3–10，pp.763–767。
