# 解决的问题

**输入**：自然语言查询；多模态数据源（表、图像集合、文本集合）；一组带说明的算子。图像和文本集合以特殊的两列表呈现给 LLM，例如 `painting_images(img_path, image)`，从而可以参与普通连接（Figure 4 说明，p.5）。

**输出**：可执行的多模态查询计划，结果可以是单值、表或图（§2，p.2）。

**三阶段规划**（§3.1，Figures 2–3，pp.3–4）：

| 阶段 | 做什么 |
|---|---|
| Discovery | 用稠密检索筛出相关表、图像集合等，再让 LLM 挑相关列与示例值 |
| Planning | LLM 生成自然语言的逐步逻辑计划，prompt 中带少量示例（few-shot） |
| Mapping + 执行 | 每个逻辑步骤逐一映射为物理算子及参数并立即执行，上一步的输出喂回 LLM 再决定下一步 |

**错误处理**（§3.2，p.4）：把报错信息加入 prompt，并用六个问题让 LLM 分析原因；据"计划是否有缺陷""是否有更合适的计划"两问的回答，决定回退到 Planning 还是 Mapping 阶段重来。作者明确说这不保证可执行，更不保证正确。

**不解决的问题**：计划的代价优化（§2、§5 列为开放问题），以及计划正确性的自动验证（阅读者分析）。

依据：[arXiv 2308.03424v1](https://arxiv.org/abs/2308.03424v1)，§2–3、Figures 2–4，pp.2–5。
