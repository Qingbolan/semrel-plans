# 出发点

**数据湖已不只是表**（§1，p.1）：企业把数据组织成成千上万个由不同团队管理的来源，同一内容可能以表、知识图谱、文档等多种模态出现。回答一个问题可能需要关系运算、图搜索和模型推理的组合。

**例子**（Example 1.1，Figure 1）：问“多年来哪支球队在控卫位置上选中的球员平均最高？”。直接问 LLM 会因缺少 NBA 球队信息而答不好；如果先用 SQL 从球队表取出相关信息、再放进提示，就能答对。结构化表帮助回答了非结构化文本问题。

**已有工作的不足**（§1–2）：
- 数据发现（unionable/joinable 表搜索、领域发现）大多只针对结构化表；
- CMDL、Symphony、Thetis 面向多模态数据湖，但没有形式化的算子和查询计划；
- LOTUS、Palimpzest、ELEET、CAESURA 等以 LLM 为核心，而不是提供统一声明式接口的端到端系统，也不覆盖不需要 LLM 的查询。

阅读者分析：本文支持“端到端异构数据发现—查询”这一问题早已被明确提出，但不支持“已有完整方案解决了它”（阅读者分析）。

依据：[arXiv 2504.02059v1](https://arxiv.org/abs/2504.02059v1)，§1–2、Example 1.1、Figure 1，PDF pp.1–3。
