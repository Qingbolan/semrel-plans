# 出发点

**示例场景**（Figure 1，§1 p.2）：研究者用一个 Palimpzest 程序检索论文：先 filter “是否关于数据系统”，再 map 概括贡献，最后 map 判定与个人兴趣的相关度。同一程序可编译成不同物理计划：图中“最大化质量”计划示意为 Acc 0.90、$10.0、400 s；“质量最大且费用 < $1”计划为 Acc 0.80、$0.75、300 s。这些是示意数字，不是实验结果。

**物理实现空间巨大**：在作者的实现中，单个语义 map 约有 2,800 种物理算子，全部规则合计约 3,000 种（§2.3 p.4、§4.1 p.8）。一个有 M 个算子、每个 N 种实现的计划有 O(N^M) 种组合，无法逐一采样（§2.3）。

**已有优化器的不足**（§1、§6）：
- LOTUS 用代理模型优化 join、filter、group-by、top-k，DocETL 用 LLM 做查询重写；二者都只优化质量，不满足费用或延迟的显式约束。
- Palimpzest 早期版本靠采样加启发式估计和选择。

**三个技术难点**（§2.3 pp.4–5）：
1. 语义算子的质量没有直方图、基数估计这类统计量，只能靠调用 LLM 采样估计，而采样本身很贵；
2. 经典 MAB 只找单个最优臂，约束优化需要找到整条 Pareto 前沿；
3. Cascades 依赖最优性原理（最优计划的子计划也最优），有约束时不再成立，只保留每组的“最佳”子计划可能违反约束。

**输入边界**：Abacus 的输入是已写好的语义算子程序（pipeline 或 DAG）、优化目标和数据集，而不是开放式 agent 对话；验证数据、先验和 LLM judge 都是可选的辅助输入（§2.2 p.3）。
