# 解决的问题

**输入**（§2.2，p.3）：一个语义算子实例（算子模板 + 自然语言意图，如 `SemFilter` + “标签含合规声明”）；含非结构化属性的输入关系；可选验证集；可选的质量/延迟/费用权重 (w_q, w_l, w_c)。

**输出**：一个可执行的物理算子 DAG，每个算子绑定具体实现与调好的参数。部署时选使效用 U = w_q·Q − w_l·L̂ − w_c·Ĉ 最大的计划；权重全为正时该计划是 Pareto 最优（§2.1，p.3）。预设权重：质量优先 (1, 0.1, 0.1)、平衡 (1, 0.4, 0.3，默认)、效率优先 (0.1, 1, 1)。

**TxRA**（§3，pp.4–5）：在关系代数上加任务算子，以 `Apply`（类似 CROSS APPLY）把 OCR、TxtQA、ImgCls 等结果作为带类型的新属性追加到每行。任务算子按输出角色分五类：结构、属性、关联、生成、潜在向量（§4.1，Table 1）。

**可证明安全的重写**：两个任务算子互不消费对方产出的属性时可交换；过滤谓词不引用任务产出属性时可下推。例如 OCR → TxtQA 有依赖，不能互换（§3，p.5）。原型只实现 FilterPushdown 和 CommutativeReordering 两条规则（§4.3.1）。

**逻辑规划**（§4，pp.5–7）：最多 B_log 次种子合成尝试（默认 3），每次“起草 → 确定性校验 → LLM 修复”至多产出一个种子计划；再展开结构重写和两类语义替代模板（分区抽取、跨模态代理，如 VQA → OCR + TxtQA）。语义替代不假定等价，只在验证信号上更优时保留。

**物理规划**（§5，pp.7–8）：每个任务算子按 symbolic、specialized、general-purpose、composite 四族各合成一个实现，再按廉价特征打难度分、按百分位分桶路由。BO 联合调整路由切点、后端参数和关系阈值，每个计划最多 15 个连续参数（§5.2）。默认 50 个验证样本、20 次 BO（§7.1.4）。

**运行时保护**（§6，pp.8–9）：合成代码先做 schema smoke test，在隔离环境限时运行，失败则重合成；运行时异常或置信度过低时退回默认 LLM。输入行数 N ≤ 300 时跳过优化直接用 LLM。

阅读者分析：这些是作者的系统设计，不能据此证明所有合成代码正确；语义替代的正确性只由小验证集上的经验排序保证，验证标签来自 teacher LLM 而非人工。
