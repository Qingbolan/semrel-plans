# 出发点

**运行示例**（Figure 1，p.1）：在 `Products JOIN Brands` 的 SQL 中，`SemFilter` 要求找出包装标签上出现“FDA approved”之类合规敏感声明的商品图片，再按品牌计数。这个过滤可以直接问视觉 LLM，也可以先 OCR 再做文本问答。

**现有优化器的盲点**（§1，pp.1–2）：现有 SQPE 优化器不把一个语义算子实例的内部任务结构暴露给关系优化，因此无法对中间输出做过滤、重排、跨后端路由、阈值化或联合调参。Figure 2 总结了四种现有执行模式：

| 模式 | 代表 | 做法 |
|---|---|---|
| Direct LLM | 通用 | 每行一次 LLM 调用 |
| Proxy Cascade | LOTUS | 便宜模型或嵌入打分，决定哪些行升级给 LLM |
| Reduced Context | Palimpzest/Abacus | 切块后只把 top-k 块交给 LLM |
| Pipeline Rewrite | DocETL | 管道级分解 |

**三个挑战**（§1，p.2）：
1. 意图是开放式自然语言，没有代数形式，需要为每个意图合成任务 DAG；
2. 合适的后端随输入而变：有的行用确定性规则即可，有的需要专用小模型，只有难例需要 LLM，因此要逐行分派；
3. 计划空间是多目标的且评估昂贵，搜索必须节省样本、受预算约束。

**多目标设定**（§1–2.1，pp.1–3）：模型推理主导延迟和费用，输出又随机且依赖后端，所以要在质量、延迟、费用之间按用户权重选计划，而不是最小化单一指标。

阅读者分析：这里的输入是已绑定的关系和可访问的图片/音频列，不是在未知网页环境里找数据的 data agent。

依据：[arXiv 2606.29151v3](https://arxiv.org/abs/2606.29151v3)，§1、§2.1、Figures 1–2，PDF pp.1–4。
