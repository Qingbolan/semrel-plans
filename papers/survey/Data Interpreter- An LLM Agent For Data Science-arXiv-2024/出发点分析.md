# 出发点

**数据科学流程的特点**（§1，p.1）：数据处理、特征工程、模型训练等任务相互依赖，需要反复修正；数据和需求在过程中不断变化，后一步依赖前一步的中间结果。

**已有方法的不足**（§1，p.2）：
- 已有 LLM 数据科学工作多聚焦单一任务（特征工程、模型选择、超参调优），在固定流水线中运行，缺少端到端评估；
- 难以应对中间数据的实时变化，也不能随任务依赖的演化动态调整；
- OpenInterpreter、AutoGen 等框架生成静态计划、一次执行（§3.2，p.5）。

**作者的思路**：把数据科学工作流重写为分层图建模问题，任务是节点、依赖是边；再用“可编程节点生成”实时生成、修正、验证每个节点的代码（§1，p.2）。

**具体需求示例**（Figure 2，p.4）：根据水泵传感器读数预测机器状态，需要依次完成数据探索、相关性分析、异常检测、特征工程、训练、评估和可视化；可视化任务需要用到前面模型产生的预测结果来计算混淆矩阵。

依据：[arXiv 2402.18679v4](https://arxiv.org/abs/2402.18679v4)，§1、§3.1–3.2、Figure 2，pp.1–5。
