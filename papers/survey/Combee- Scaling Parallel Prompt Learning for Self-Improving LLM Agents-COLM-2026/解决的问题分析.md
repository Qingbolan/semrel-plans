# 解决的问题

**输入**：一批（bs 条）智能体轨迹及其反思；当前上下文产物 C_t（ACE 的 playbook 或 GEPA 的系统提示）；底层提示学习方法的生成、反思、更新函数（附录 C，p.16）。

**输出**：更新后的上下文 C_{t+1}。形式化为 F̄_t = Agg(F_t^(1), …, F_t^(bs))，C_{t+1} = Update(C_t, F̄_t)；Combee 只替换其中的聚合步 Agg（§3 p.4、附录 C）。

**目标**：改善“质量—延迟”权衡——训练时间（墙钟）尽量短，同时学到的上下文在留出任务上的准确率接近顺序学习（§1，p.2）。

**三个机制**（§3，pp.4–6）：

| 机制 | 做法 | 默认值 |
|---|---|---|
| 并行扫描聚合 | n 条反思分成 k 组，组内先各自聚合，再把 k 个更新合并 | k = ⌊√n⌋，两级 |
| 增广打乱 | 每条反思复制 p 份后打乱再分组，降低被“坏分组”丢掉的概率 | p = 2 |
| 动态批量控制器 | 试跑候选批量测延迟，拟合 T_epoch(bs) = A·bs^−α，取边际收益降到阈值 τ 的批量 | τ = 峰值斜率的 1.6% |

**适用范围**：要求底层方法输出文本反思并聚合到共享产物；作者在 ACE 与 GEPA 上实现（§3 p.4）。

阅读者分析：Combee 优化的是“学习过程”的吞吐，不是任务执行本身。17× 是学习耗时的改善，不能改写为业务任务执行加速 17×。

依据：§1、§3，PDF pp.2、4–6；附录 C，p.16。
