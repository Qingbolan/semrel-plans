# 具体用例

**场景**（§4.2，表 1，p.7）：用 ACE 为 AppWorld 上的 ReAct 智能体学习 playbook。训练集 90 个多步 API 任务，每轮并行跑一批任务、各自写反思，再由聚合 LLM 把反思整理成 playbook 条目。

**不用 Combee、直接调大批量**：

| 批量 | 训练时间 | playbook | 平均分 |
|---|---|---|---|
| 1（顺序） | 86 分钟 | 1,578 token | 58.1 |
| 10 | 19 分钟 | 2,329 token | 65.4 |
| 40 | 5 分钟 | 526 token | 55.7 |

批量 40 时，聚合 LLM 一次面对 40 条反思，只留下很少条目，分数接近不学习的 53.3。

**用 Combee（批量 40）**：
1. 40 条反思各复制 2 份，打乱后得到 80 条；
2. 分成约 √40 ≈ 6 组，每组由聚合 LLM 生成一份局部更新；
3. 再把各组更新合并成本轮的 playbook 更新。

结果：训练 7 分钟（比顺序学习快约 12×），playbook 6,887 token，平均分 65.8，SGC 60.7，均为表中最高；成本 $1.67，与顺序学习的 $1.62 相近。

**playbook 被压扁的样子**（附录 J，pp.21–22）：Formula 批量 100 时最终只剩 21 条，多是“输出百分比还是小数”这类重复的格式提醒，大部分条目有用计数 h=0。

阅读者分析：第 1–2 步的具体分组数是阅读者按 §3.1–3.2 的默认规则（p=2、k=⌊√n⌋）推算的；原文没有给 AppWorld 这一运行的分组细节，也没说明 √n 取的是复制前还是复制后的条数。

依据：§3.1–3.2、§4.2、表 1，PDF pp.5–7；附录 J，pp.21–22。
