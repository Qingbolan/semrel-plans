# 出发点

**传统数据系统的三个局限**（§1，pp.1–2）：
1. **人工设计的流水线**：数据清洗、分析流水线针对特定任务手写，迁移到新领域（如从金融交易到医疗记录）要大量修改；
2. **语义能力有限**：系统假设存储的数据集完整且权威（query-time completeness），难以处理数据湖中的嵌套表头、合并单元格、术语不一致的财报等异构数据；
3. **被动处理**：只响应预定义查询或报表，不能主动发现趋势、异常和必要的更新。

**驱动场景**（§1，p.2）：零售连锁收入下降时，传统系统只报告“销售下降”；Data Agent 应主动提出假设（竞争对手促销、恶劣天气、配送评分下降），编排语义流水线从天气 API、评论平台、竞品网站取证，再综合分析并给出决策建议。

**与已有系统的区别**（§1、Table I，pp.2–3）：工业平台（AWS Glue）需人定义工作流；LLM 编排框架（LangChain、AutoGen）缺少语义数据组织和面向数据的优化；工作流编译器（AutoML、Airflow）需人工 DAG；NL2SQL（DIN-SQL、DAIL-SQL）只做结构化映射，没有多步工具编排、反馈和记忆。

**三个挑战**（§1，p.3）：自主流水线编排（LLM 幻觉、缺领域知识、算子组合空间大）；语义解释成本高；主动处理需要持续预测和调整。

依据：[arXiv 2609.24137v1](https://arxiv.org/html/2609.24137v1)，§1、Table I，pp.1–3。
