# 贡献与评价

**作者贡献（阅读者归纳）**：
1. **任务编译**：从任务规格生成领域整理程序，把代码、小模型、相似结果和 LLM 组合起来，避免每条记录都付大模型费用（§1–2）；
2. **质量—成本优化**：在效果容忍范围 G 内选择 LLM 调用最少的模块组合与配置，而不是所有任务走同一个固定级联（§3）；
3. **按需数据访问**：LLM 根据上一步工具返回选择下一个动作，例如在表发现中交替搜索和查看 schema，解决一次提示放不下全部候选的问题（§4、附录 B.1）。

**优化器的效果**（Table 4，§6.1，p.11）：在两个实体匹配数据集上，GEN 找到的 Max 与 Opt 计划与穷举搜索（约 5 万个计划）完全一致；SPE 的 Max 计划相同、Opt 计划略差，但需要搜索的计划数减少 99.5%（650 与 782 个）。

**优点（阅读者分析）**：
1. 9 个数据集、5 类任务同时报告质量与 LLM 调用比例，显示部分整理工作可以跨记录摊薄（§6）；
2. 表发现给出真实工具轨迹和检索基线，“探索”有具体定义（附录 B.1、C）；
3. 各任务使用各自的评价指标，没有统一用宽松的 LLM 打分。

**不足（阅读者分析）**：
1. 成本代理只是“交给 LLM 的记录比例”，不含代码生成、小模型训练与不同 token 长度，不能直接换算为总费用（§6 参数设置）；
2. CacheReuse 与 ModelGen 依赖相似性或伪标签，分布变化时效果约束需要重新估计（§3–4）；
3. 表发现在 OTT-QA 上反而低于不带工具的 LLM（67.8 对 71.0），作者归因于表标题无意义而误导工具选择（附录 B.1，Table 8）；
4. 正文称 SEED “优于 MatchGPT Generic”，但 Abt-Buy 上 MatchGPT Generic 的 F1（95.8）高于 SEED Max（92.8），只在 Amazon-Google 上成立（Table 3）。

依据：[arXiv 2310.00749v3](https://arxiv.org/abs/2310.00749v3)，§1–6、Tables 3–4、8、附录 B.1、C，pp.1–18。
