# 评测与边界

**基线**（§6，p.9）：
- 生成式系统（同时计规划与执行成本）：CAESURA+（原 PLM 算子常超时，改为 LLM 算子）；ClaudeCode（只能调用自身 Claude 模型）；ClaudeCode+（可调用 gpt-4o-mini）。
- 程序式系统（专家预写计划，不计规划成本）：Palimpzest + Abacus MaxQuality（在相同环境重跑）；BigQuery（直接引用 SemBench，用 Gemini-2.5-Flash，单价高于 gpt-4o-mini，且并行执行）。

**实验 1（主结果，Table 2，p.9）**：每查询平均执行费用（美元）与质量。

| 系统 | Additional | MMQA | E-Com | Movie |
|---|---|---|---|---|
| KathDB-FAO | $0.030 / 0.92 | $0.031 / 0.85 | $0.079 / 0.77 | $0.004 / 0.81 |
| CAESURA+ | OOM | $0.154 / 0.53 | $0.174 / 0.20 | $0.003 / 0.44 |
| ClaudeCode | $4.399 / 0.86 | $34.676 / 0.70 | $10.520 / 0.72 | $1.402 / 0.81 |
| ClaudeCode+ | $0.201 / 0.92 | $0.065 / 0.69 | $0.176 / 0.79 | $0.007 / 0.77 |
| Palimpzest | 未实现 | $7.161 / 0.78* | $2.402 / 0.66 | $1.309 / 0.52* |
| BigQuery | 未实现 | $0.142 / 0.32 | $2.254 / 0.70 | $0.553 / 0.75 |

\* 含至少一条 12 小时超时的查询。KathDB-FAO 的规划费用分别为 $0.73、$0.34、$0.57、$0.38，ClaudeCode+ 为 $1.33、$1.49、$1.19、$1.01。

作者称 KathDB-FAO 在四个场景中三个质量最好或并列最好；E-Com 比 ClaudeCode+ 低 0.02，但执行费用低 2.2 倍；相对 ClaudeCode+ 总费用最多低 4.2 倍（§6.1）。

**实验 2（规模，Figure 7）**：E-Com 在 sf500/1000/2000 上，KathDB-FAO 各规模都最便宜、质量最高；Palimpzest 在 sf1000、sf2000 上因成对 LLM join 超时，CAESURA+ 在 sf1000 内存溢出。

**实验 3（粒度与分组，Table 3、Figures 8–12，§6.2–6.3）**：
- 原子粒度在难查询上质量最高，易查询上三种粒度相近；
- 分组代价比较方法中，list-rank 在 Additional 上把执行成本降到原子计划的 0.14×，llm-guess 0.48×，stub-fn 0.60×；后两者规划成本约为原子计划的 13×，list-rank 不超过 1.72×；
- 排序宽度 w = 10 最优；融合组代码只在执行时为获胜计划生成（after）最便宜。

**实验 4（契约，Figure 13）**：需求传播提高质量、降低执行成本，规划成本几乎不变。

**实验 5（复用，Figure 14）**：reuse-before 在两组工作负载上都降低规划成本；best 组还降低执行成本，worst 组几乎没有执行成本收益。

**边界**：
- 原文承认：逻辑重排未实现（§3）；样本可能触发不到提前终止路径，更准确的采样留作未来工作（§4）。
- 阅读者整理：58.8% 是执行成本降幅，不含规划成本；KathDB-FAO 自身的规划费用是执行费用的 7–95 倍；Movie 上 CAESURA+ 执行费用更低；BigQuery 的模型、价格与并行口径不同；复用实验只说质量“大致稳定”，未给完整质量数字；多数系统串行执行。

依据：[arXiv 2609.28761v1](https://arxiv.org/abs/2609.28761v1)，§6.1–6.5、Table 2–3、Figures 7–14，pp.8–11。
