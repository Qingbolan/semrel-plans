# 出发点

**信息缺失是常态**：传统优化器依赖基数、顺序、直方图、函数依赖等统计；数据集成面对的是异构、自治、甚至不是数据库的来源，源描述通常只给出与全局视图的语义映射，这些性质事先不知道，而且可能随时变化（§1，p.1）。

**已有自适应技术各管一段**（§2.1，pp.1–2）：

| 类别 | 代表 | 局限（作者观点） |
|---|---|---|
| 调度类 | pipelined hash join、query scrambling | 只掩盖延迟，CPU 受限时无效 |
| 冗余计算 | 多计划竞争 | 浪费计算 |
| 计划分区 | choose nodes、mid-query re-optimization | 只能在物化点/阻塞算子之后改计划，坏的流水线段跑完前无法纠正 |
| 数据分区 | eddies、SteMs | 局部贪心路由，持续“探索”占用资源 |

**作者主张**：一个兼顾全局长期规划与局部决策的数据分区框架，能在流水线执行中途换计划，并发现、利用选择率之外的来源性质（顺序、可预聚合的重复）（§2.1–2.2，p.2）。

阅读者分析：这篇论文的核心前提是“来源性质只能在执行中观察到”，并把观察结果转成计划变化；它处理的是已知查询下的物理计划选择，不涉及查询语义本身的发现（阅读者分析）。

依据：§1–2.2，PDF pp.1–3。
