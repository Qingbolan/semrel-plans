# 评测与边界

**环境**（§7.1，p.14）：AMD EPYC 7452 32 核、256 GB 内存、单块 NVIDIA A40（48 GB）；多 GPU 实验用 2 GPU。

**基线**（§7.1，p.16）：
- EvaDB：静态 Cascades 式优化器，含 UDF 结果缓存复用与谓词重排；
- Viva：静态优化，用 3% 输入估计 UDF 统计；只开启谓词重排，关闭会影响准确率的输入过滤和模型替换；
- Ray Serve 自动伸缩（Default 与 Tuned 两种配置），替换 Laminar 做对比（§7.4）。

**实验 2（路由策略，§7.3）**：Q1 关闭 Laminar，cost / score / selectivity-driven 相对不重排分别 1.83×、1.76×、1.62×（Fig. 7）；开启 Laminar 后 cost-driven 在 Q3、Q5 上比 score-driven 快 2.3× 与 1.12×（Fig. 8）。Q6 上 DLB 中位时间优于 round-robin，最坏情况优于队列长度策略（Fig. 11，10 次运行）。

**实验 3（伸缩，§7.4，Fig. 12–13）**：Q3 上 Laminar 优于两种 Ray Serve 配置；2 GPU 相对 1 GPU，短视频 1.3×、长视频 1.9×（§7.6 又称短视频“只有 1.2×”，原文前后不一，阅读者分析）。单 GPU 利用率接近 100%，2 GPU 时因中央队列拥塞而下降（Fig. 14）。

**实验 4（拆解，§7.5–7.6）**：Q3 上 EvaDB + Eddy 得 1.36×，再加 Laminar 再快 6×；Q5 上 Eddy 得 1.27×（Fig. 15）。短视频时启动画像与伸缩占总时间 34%，长视频降到 6%（Fig. 16）。

**准确率**：Aero 与 EvaDB 结果完全相同（§7.2，p.17）。

**边界**：
- 原文 §8 承认：启动画像与伸缩开销在小数据上显著；中央队列在扩展时成为瓶颈，多队列又会破坏 Eddy 的顺序决策；暂不支持 join 上的 UDF，也未使用 CUDA stream、MPS、MIG。
- 阅读者整理：单机、最多 2 GPU；查询数少且由作者构造；无美元成本或 LLM token 指标；Q6 的 LLM 运行在 CPU 上，与 API 调用型 LLM 的代价结构不同。
