# 解决的问题

**输入**：一条 SQL 查询，WHERE 子句是多个 ML UDF 谓词的合取（例如 `['person'] <@ ObjectDetector(frame).labels AND ['no hardhat'] <@ HardHatDetector(frame).labels`），以及视频帧、图片或文本数据（§3.1，p.6）。

**改写方式**：Aero 在静态优化器中加一条规则，把含多个 UDF 合取的计划改写成一个 AQP 算子；静态优化器不决定谓词顺序和并行度（§3.1）。

**运行时要决定的两件事**：
1. 每个数据批先送哪个谓词（Eddy，§4）：依据运行中测得的代价、选择率和缓存命中率；
2. 每个谓词开多少 worker、批次发给哪个 worker（Laminar，§5）：依据 GPU 利用率、显存占用和输入大小。

**输出**：与静态计划相同的结果集。作者假设 UDF 行为确定，因此顺序改变不影响结果；实验中 Aero 与 EvaDB 结果完全一致（§7.2，p.17）。

**边界**：只处理已知 UDF 谓词的合取，不涉及 join 顺序（§8 列为未来工作）；不做模型替换或输入过滤这类以准确率换速度的优化（§7.1）。“结果一致”只说明与固定模型输出一致，不代表模型对人工标签正确（阅读者分析）。

依据：[DOI 10.1145/3725408](https://doi.org/10.1145/3725408)，§3–5、§7.1–7.2、§8，pp.6–17、22。
