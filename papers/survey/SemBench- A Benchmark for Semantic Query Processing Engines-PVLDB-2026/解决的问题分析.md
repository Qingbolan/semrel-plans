# 解决的问题

**数据模型**：扩展关系模型，单元格可以是图像或音频；实际存的是文件路径，所有被测系统都支持这种格式（§3.1，p.3）。

**算子**：Table 1 定义 5 类语义算子，语法沿用 LOTUS 并做了扩展（p.4）。

| 算子 | 定义 | 原文示例 |
|---|---|---|
| sem_filter | { t ∈ T \| M(l)(t)=1 } | 根据 X 光片筛选肺部有病的患者 |
| sem_join | {(t_i,t_j) \| M(l)(t_i,t_j)=1} | 匹配同一动物的两张图片 |
| sem_map | { M(l)(t) \| t ∈ T } | 从商品描述中抽取品牌名 |
| sem_rank | 按 M(l) 排出前 k 个 | 按正面程度给评论排序 |
| sem_classify | { (t, M(l)(t)) \| t ∈ T } | 按图片判断动物种类 |

**gold 与质量指标**：gold 由一条关系查询得到，即把语义谓词换成对源数据人工标签的判断，不使用 LLM 充当裁判（§3.3）。

| 查询类型 | 指标 | 归一化到 [0,1] |
|---|---|---|
| 检索 | F1 | 本身即在 [0,1] |
| 聚合 | 相对误差 | 1/(1+relative_error) |
| 排序 | Spearman | 实测都 >0，不再变换 |
| 分类、映射、部分 join | ARI | 实测都 >0，不再变换 |

各表中同名的 Quality 列混合了以上几种指标，所以不能把每一项都读成准确率（§5.1，p.7）。

**规模口径**：Scale 是主实体表的行数，其他表的规模由它推出，类似 TPC-H 的 scale factor。基准只沿数据量扩展，不测多用户或并发查询吞吐（§3.3、§5.1）。

**受控条件**：所有系统统一使用 gemini-2.5-flash，并关闭推理；适用的系统把温度设为 0。各系统保留默认的提示模板，所以比较中仍包含提示设计的差异。Palimpzest 关闭了 Abacus 优化器和模型选择，因此这不是完整优化器之间的比较（§5.1–5.2，p.7）。

阅读者分析：某个系统缺少算子、执行出错或超时都有具体原因，不能把它的费用记为 0 来表示“可执行且免费”。

依据：[arXiv 2511.01716v2](https://arxiv.org/abs/2511.01716v2)，§3.1–3.3、§5.1–5.2、Table 1，PDF pp.3–7。
