# 出发点

**成本结构变化**：语义算子由 LLM 求值，每字节处理成本比关系处理高出多个数量级。因此优化重点从关系处理转向减少 LLM 调用；同时 LLM 输出有随机性，结果质量也成了要优化的指标。作者把问题概括为“在最小化 LLM 延迟与成本的同时最大化准确率”（§1，p.1–2）。

**现有基准不覆盖**：TPC-H、TPC-DS、JOB 只测关系处理，无法指导减少 LLM 调用次数、输入 token 或模型规模的技术。多模态 QA 基准（如 EHRXQA、M3SciQA、MMBench）评测的是模型输出质量，不测成本和执行时间（§1、§2.4，pp.2–3）。

**引例**（Example 1.1，p.1）：表 `Cars` 的 `pic` 列存汽车图片，查询 `SELECT COUNT(*) FROM Cars WHERE AI.IF(pic, 'the picture shows a red car')` 只有一个语义 filter 加 COUNT，LLM 调用已成为主要成本。这条查询经少量改写后，LOTUS、Palimpzest、ThalamusDB 都能执行。

**做法取向**：把带人工标签的数据集组合成多表场景，用标签代替语义调用来生成 gold，这样不同接口的系统可以在同一份答案上比较。查询中既有多数引擎都能执行的简单查询，也有需要“较少见”算子的复杂跨模态 join，后者是为了推动系统扩充算子（§1、§3.2）。

阅读者分析：SemBench 的价值在于公开同一查询在各系统上的支持情况与成本-质量表现。它并不声称汇总了各系统论文的原始工作负载。

依据：[arXiv 2511.01716v2](https://arxiv.org/abs/2511.01716v2)，§1–3，Example 1.1，PDF pp.1–4。
