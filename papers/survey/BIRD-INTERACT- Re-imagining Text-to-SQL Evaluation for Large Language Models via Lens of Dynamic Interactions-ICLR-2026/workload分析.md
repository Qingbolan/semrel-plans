# 工作负载

**来源**：LiveSQLBench 的单轮任务、数据库沙箱、元数据与分层知识库；12 名专家把单轮题改成交互题（§3.1–3.2，p.4）。

**规模**（Table 1，p.5）：

| 统计 | LITE | FULL |
|---|---|---|
| 任务数 | 300 | 600 |
| BI 任务 | 195 | 410 |
| DM 任务 | 105 | 190 |
| 不同测试用例数 | 135 | 191 |
| 每题歧义数 | 5.16 | 3.89 |
| 每题子任务数 | 2 | 2 |
| 每题交互数 | 13.04 | 13.64 |
| 标注一致率 | 93.33% | 93.50% |

LITE 使用更简化的数据库，用于行为分析与快速开发（§1）。

**任务单位**：一个任务 = 一个含歧义的优先子任务 + 一个后续子任务；后续子任务只在前者成功后发布，且可能依赖前者创建的对象或修改后的状态（§2）。

**运行设置**（§5，p.7）：7 个模型（2 开源、5 闭源），全新 PostgreSQL 14 Docker 实例；用户耐心默认 3，a-Interact 基础预算 6；温度 0、top_p 1；因成本只跑一次。用户模拟器平均每题 0.03 美元（Table 2 注）。

阅读者分析：这是带人工注入歧义的合成交互负载，数据库与知识库来自 LiveSQLBench，不是真实生产对话日志；BI 与 DM 比例约 2:1（阅读者分析）。

依据：§2–3、§5、Table 1–2，PDF pp.3–7。
