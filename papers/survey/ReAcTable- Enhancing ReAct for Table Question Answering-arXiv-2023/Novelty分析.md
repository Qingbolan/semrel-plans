# 贡献与评价

**论文声称的贡献**（§1，p.2–3）：
1. 提出 ReAcTable：把 CoT + 外部工具（ReAct）用于 TQA，LLM 生成代码，执行器生成中间表，再回馈给 LLM；并用多数投票提升准确率；
2. 在 WikiTQ、TabFact、FeTaQA 上与训练类和免训练类方法对比；WikiTQ 68.0%，比最佳已有方法高 2.1 个百分点；
3. 消融：最大收益来自两种执行器迭代生成中间表；并考察不同 LLM 与投票方式。

**阅读者评价**：
- 优点：Figure 1–2 的骑手例子清楚说明为什么需要“先变换数据再回答”，Python 抽取国家、SQL 计数的分工与人类做法一致。
- 优点：消融拆得清楚——去掉中间表（Codex-CoT）WikiTQ 从 65.8% 降到 49.4%；去掉 Python 执行器从 65.8% 降到 62.5%（Tables 4、8）。
- 优点：把需训练与免训练基线分开报告，没有用一个总排行掩盖监督成本差异（Tables 1–3）。
- 新意有限：本质是 ReAct 在单表上的实例化加工程细节（异常重试、投票），s-vote、e-vote 都沿用已有工作（[18][26]）（阅读者分析）。
- 投票的增益不稳定：Codex-CoT 加 s-vote 反而从 49.4% 降到 47.7%；最佳投票方式随模型变化（Tables 4、10–11），作者把自动选择投票方式列为未来工作。
- 正文 §4.4 有两处笔误：称 text-davinci-003 在 TabFact 上最高 52.5%（t-vote），但 52.5% 是 gpt3.5-turbo 在 WikiTQ 上的 t-vote 结果，text-davinci-003 在 TabFact 上最高为 83.6%；又把“execution-based voting”括注为 s-vote（阅读者分析）。

依据：[arXiv 2310.00815](https://arxiv.org/abs/2310.00815)，§1、§3.4–3.5、§4.2–4.4、§5.3–5.4、Tables 1–11，PDF pp.2、5–11。
