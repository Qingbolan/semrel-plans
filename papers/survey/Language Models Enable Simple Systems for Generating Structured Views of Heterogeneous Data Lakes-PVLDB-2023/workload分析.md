# 工作负载

**要验证的问题**：从少量文档生成的可复用抽取函数，能否比逐文档 LLM 抽取便宜得多，同时靠多函数聚合保持结构化视图的质量（§4，p.8）。

**16 个设置**（§4.2，p.9）：

| 数据 | 格式 | 规模 | 金标准属性 | 考察点 |
|---|---|---|---|---|
| SWDE Movie | HTML | 8 个网站，每站 1,063–2,000 页 | 每站 8–274 个 | 与 SoTA 比较；属性从简单（runtime）到复杂（cast） |
| SWDE University | HTML | 5 个网站，规模同上 | 同上 | 同上 |
| NBA 球员维基页 | 复杂 HTML | 随机 100 页（1940 年代至今） | 19 个 | 属性值不总在单独的 DOM 叶节点，如选秀信息含轮次、年份、顺位、球队 |
| Enron 邮件 | 文本 | 50 万封 | 15 个 | 无结构文本 |
| FDA 510(k) | PDF | 随机 100 份，最长 20 页 | 16 个 | 无结构长文档 |

8 + 5 + 3 = 16 个设置。50 万是语料规模，不代表每封邮件都有完整金标准（阅读者分析）。

**任务单位**：文档 × 属性。函数生成使用 10 篇文档（§4.3.2）。另测 LLM 处理的 token 数和估算费用；作者认为墙钟时间与费用都与 token 数成正比（§4.1）。

**数据协议**（§4.2，p.9）：SWDE 基线需要训练数据，做按网站的交叉验证；Evaporate 不需训练，直接在所有网站上评测以覆盖相同样本。每个数据集单独处理以对齐基线协议；对混合来源，用 TF-IDF + K-means 可在无监督下完全恢复文档来源（Figure 5）。

依据：[arXiv 2304.09433v3](https://arxiv.org/abs/2304.09433v3)，§4.1–4.2、Figure 5，pp.8–9。
