# 贡献与评价

**作者的贡献**（§1，pp.2–3）：

1. **系统接口**：不靠领域训练，从异构文档自动发现属性并生成结构化表（§2–3）。
2. **计算复用**：把逐文档 LLM 推理换成样例驱动的函数生成加批量执行，LLM 调用数随属性数而非文档数增长（§3.2）。
3. **质量恢复**：多候选函数加适配的弱监督，处理低质函数、空输出歧义和开放取值空间，使低成本抽取的质量反超 Direct（§3.3、§4.4）。

**阅读者评价——优点**：

- 同时评测开放属性发现（OpenIE）和给定 schema 抽取（ClosedIE），任务与评测对象清楚（§4.1）。
- Direct、Code、Code+ 分开对比，能看出代码复用与聚合各自带来什么：Code 比 Direct 在 SWDE 上平均低 21.9 Pair F1，Code+ 又追回并反超（Tables 2–3）。
- 覆盖 HTML、邮件和 PDF，说明格式复用是现实的替代路线（§4.2）。
- 换用 GPT-4、Claude-V1、Jurassic Jumbo-2 验证了框架在不同模型族上可用（Table 5）。

**阅读者评价——不足**：

- 自动生成的函数可能犯同样的错，质量估计又依赖少量 LLM 伪标签，弱监督聚合不是正确性保证（§3.3）（阅读者分析）。
- 实验按来源分别处理文档；真实混合数据湖需要聚类，格式漂移会带来额外成本（§4.2）（阅读者分析）。
- 生成程序适合格式可编码的属性；需要逐条开放语义推理的字段，不能据平均 token 降幅推断同等节省（阅读者分析）。

依据：[arXiv 2304.09433v3](https://arxiv.org/abs/2304.09433v3)，§1–4、Tables 2–5，pp.2–12。
