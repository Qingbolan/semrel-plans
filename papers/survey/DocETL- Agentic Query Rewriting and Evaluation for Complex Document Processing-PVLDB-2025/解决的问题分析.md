# 解决的问题

**数据模型**（§2，Table 1）：JSON 对象是文档，JSON 数组是集合；用户在 YAML 中声明每个算子的提示、输入与输出 schema。

**算子**：

| 算子 | 作用 |
|---|---|
| map / filter | 单文档 LLM 投影 / 过滤 |
| reduce | 按 key 聚合，可按批“折叠”，用 scratchpad 跟踪中间状态（Figure 2） |
| resolve | 对一个或多个 key 做实体规范化 |
| equijoin | LLM 判定的连接 |
| unnest / split / gather | 展开数组；按 token 切分长文档；为每块补上相邻块作背景（不改变块数） |

**重写指令**（§3）：13 条新指令，分三类：数据分解（如文档分块、多级聚合）、投影合成（如把一个 map 拆成独立并行投影或串联投影）、LLM 特有的改进（如 gleaning 自检重试、重复 key 消解）。它们是让智能体实例化提示与参数的“指引”，不是对任意 LLM 输出都成立的严格等价规则。

**优化流程**（§4，pp.3040–3042）：
1. 验证智能体为当前算子生成任务相关的评判提示，并判断其是否已足够好；不够好才重写；
2. 生成智能体按指令产生候选计划；新合成的算子立即递归优化；
3. 在样本上运行候选，先逐文档打分取平均，留下前 6 名，再两两比较，胜场最多者入选；
4. 样本按文档长度加权抽取；并按上游选择率放大后续样本量，如两个上游选择率为 0.5 和 0.3 时样本扩大 6.67 倍。

**优化目标**：只针对准确率；代价与延迟约束明确留作未来工作（§4，p.3041）。

阅读者分析：后续工作（如 MOAR）才引入多目标优化，不应倒填进 2025 版 DocETL（阅读者分析）。

依据：§2–4、Tables 1、Figures 1–2，PVLDB pp.3037–3042。
