# 出发点

**原文示例**（Example 1.1，§1，pp.3035–3036）：记者要从超长的警务记录中抽取警员姓名及其不当行为，再跨文档归并。即使用强模型，单次 map 也会因上下文过长、任务复杂而漏报；同一警员在不同文档中可能写作“Officer Smith”或“J. Smith”，导致汇总分裂；同一案件的多份文档还会造成重复计数。

**核心判断**（§1，p.3036）：LLM 输出质量往往不足以完成复杂数据处理，不能把用户给出的算子当作固定的；需要把复杂、易错的操作分解为一系列更简单、更准确的操作。例如 map → map（先删无关内容再抽取），或 split → gather → map → reduce（分块、附上相邻块作背景、逐块抽取、全局汇总）。

**为什么需要自动化**：分解方式几乎无穷，每种分解还可递归应用，参数（如每次汇总多少段）难以手调；即使是 LLM 专家也要大量试验（§1）。提示编译（DSPy 等）依赖示例，而长文档难以放入示例，也解决不了任务本身的困难（§1，p.3035）。

**现有系统的假设**（§6，pp.3045–3046）：LOTUS、Palimpzest、Aryn 大多假设任务简单到强模型无需分解即可完成，优化集中在代价（谓词下推、模型级联）；都不支持超出上下文窗口的文档。

依据：§1 Example 1.1、§6，PVLDB pp.3035–3036、3045–3046。
