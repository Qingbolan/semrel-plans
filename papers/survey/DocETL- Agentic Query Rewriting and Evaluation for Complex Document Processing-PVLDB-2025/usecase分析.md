# 具体用例

**原文示例**（CUAD，§5.1，p.3043）：从每份合同中抽取 41 类条款的文本片段。

**未优化管道**：一个 map，提示里给出 41 类条款的一句话描述，输出 schema 为含 `clause_type` 与 `text_span` 的对象列表。

**优化器的改写**：把这个 map 改为“隔离投影分解”（指令 11）：21 个独立 map，每个只抽 1–3 类语义相关的条款（如把协议名称与生效日期放在一起），最后用一个 reduce 合并。优化器选择了隔离投影而非文档分块，作者据此认为 LLM 擅长从长文档中有针对性地抽取少量信息。

**效果**（Tables 2–3）：F1 由 0.379 升至 0.477，召回率由 0.430 升至 0.719，幻觉率由 7.2% 降至 0；执行成本由 0.08 美元升至 1.46 美元，耗时由 23.43 秒升至 180.30 秒，另付一次性优化成本 1.58 美元。

**另一个用例**（Steam，§5.2）：评论文档超出上下文窗口。优化器把单个 map 改为 split（每块 104,652 token，不加 gather）→ 每块两个带一轮 gleaning 的 map（分别抽正面、负面评论）→ reduce 合并并按时间排序。

**真实场景案例**（§5.5，p.3045）：加州警务记录（超过 128K token）中识别警员不当行为，优化管道使召回率比未优化管道提高 90%；细节在技术报告中。

依据：§5.1–5.2、§5.5、Tables 2–3，PVLDB pp.3043–3045。
