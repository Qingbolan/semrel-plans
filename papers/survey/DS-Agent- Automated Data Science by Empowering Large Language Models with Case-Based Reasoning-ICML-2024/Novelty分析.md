# 贡献与评价

**论文声称的贡献**（§1、§6）：
1. 把 CBR 接入 LLM agent，形成开发阶段的自动迭代流程：检索 Kaggle 经验，再按执行反馈重排案例、修订计划；
2. 部署阶段使用简化的 CBR，只改写一个成功案例的代码，降低对基础模型能力的要求，使开源 LLM 也能用；
3. 在 30 个任务上验证两个阶段的效果和成本。

**支持证据**：
- 消融（Table 2，GPT-4，12 个开发任务的平均 best rank，越低越好）：完整 DS-Agent 为 2.08，去掉 ReviseRank 为 2.58，去掉 CBR 为 3.41。去掉 ReviseRank 后相当于 RAG 式 agent（§4.2.2）；
- 部署阶段向开发阶段保存的代码案例学习，几乎在所有任务上都优于向文本形式的人类经验学习（§4.3.2，Figure 6(a)）；
- 上下文中放 0 个案例时最差（退化为 zero-shot）。案例多于 1 个时表现迅速下降，作者解释为多余案例干扰了单例改写（Figure 6(b)，GPT-3.5）。

**阅读者评价**：
- 新意主要在于把执行反馈引入案例选择（ReviseRank），并把“探索”和“低成本复用”明确拆成两个阶段。CBR 和 RAG 本身都不新；
- 部署阶段要求新任务与开发任务“同分布”（文本/时序/表格的分类或回归）。实验没有证明结果能迁移到任意新领域；
- 附录 C.1 称 GPT-4 版在 4 个表格任务中 2 个大幅超过 AutoGluon、另 2 个持平。按 Table 6，这只在 best-of-5 时成立；按 5 次平均，GPT-4 版只在 MAE（267 对 305）上更好，RMLSE、Accuracy、AUROC 都略差；
- 唯一的基线是 ResearchAgent（开发阶段）和 zero-shot/one-shot（部署阶段），没有与其他数据科学 agent 比较。

依据：[arXiv 2402.17453v2](https://arxiv.org/abs/2402.17453v2)，§1、§4.2.2、§4.3.2、§6、Table 2、Figure 6、附录 C.1 Table 6，PDF pp.1–8、16–17。
