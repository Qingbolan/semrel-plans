# 具体用例

**原文示例**（WebArena Maps 站点，§3.1.3、Figure 6，p.6）：在线处理地图站点的测试任务时，智能体先遇到“Show me {location} on the map”这类任务，成功后归纳出工作流“按名称找地点”：

```
# 要找到 {location}，先在 OpenStreetMap 上搜索 "{location}"
fill('145', {location})
click('147')
```

之后遇到“Tell me the zip code of {location}”。智能体复用前两步定位地点，再增加读取结果、回报邮编的步骤，形成更复杂的工作流“获取某地邮编”：

```
fill('145', {location})
click('147')
# 搜索结果列出多个地点……该地点包含邮编
send_msg_to_user("The zip code is {zip-code}")
```

**使用前后**：没有工作流时，每个任务都要重新摸索搜索框和结果页；有工作流后，前几步可直接照做，模型只需处理新增部分。共享的是操作方法，邮编本身在当前页面读取，不从旧任务复制。

**规模化的效果**：Maps 站点的累计成功率在前约 40 个任务内快速上升，之后趋稳，相对不更新记忆的基线差距最高达 22.5 分（§1 Figure 1、§3.1.2 Figure 5，pp.1、5）。Table 1 中 Maps 的成功率为 43.3%，BrowserGym_ax-tree 为 25.5%。

**反例**（§5、Figure 7，p.10）：把“订机票”工作流包成一次性执行的动作时，输入“New York”后页面会弹出附近机场列表，而预设动作序列看不到这一中间状态，无法选择正确选项。

阅读者分析：这是案例说明，不是单例消融；论文没有报告“有/无该工作流”时这道题的对照结果。
