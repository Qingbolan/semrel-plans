# 出发点

**问题场景**：网页智能体要完成查订单、找地点、订机票这类长步骤任务。现有做法多是把一组固定样例通过训练或上下文学习交给模型，对与样例相似的动作序列有效，但任务上下文或环境一变就不稳（§1，p.1）。

**两点不足**（§1，p.1）：
1. 不能抽取跨任务共享的可复用子过程，复杂任务因此难以拆解；
2. 每个任务独立求解，不会从过去的成功和失败中学习，无法随时间适应。

**观察**：人会从过往经验中抽象出常用流程再用于新任务。Figure 1 中，WebArena 地图站点的“按名称找地点”被先学会，随后成为“获取某地邮编”等更复杂工作流的子目标（§1，pp.1–2）。

**设计取向**：直接照搬整条旧轨迹会把旧商品名、旧页面元素等具体值带进新任务；AWM 因此在归纳时把具体值替换成 `{product-name}` 这类变量，并按子任务粒度切分（§2.3，p.3）。

阅读者分析：这一动机支持“复用操作方法”，不支持“复用旧答案”。工作流里的邮编、订单号等事实仍需在当前页面上重新读取。

依据：[arXiv 2409.07429v1](https://arxiv.org/abs/2409.07429v1)，§1、§2.3、Figure 1，PDF pp.1–3。
