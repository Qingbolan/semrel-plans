# 解决的问题

**输入**：自然语言指令 q；环境状态给出的观察 o（网页 accessibility tree 等）；智能体的基础记忆 M（内置动作文档，如 CLICK、TYPE）；以及过去的经验集合 E，每条经验 e = (q, 轨迹)，轨迹由 (观察, 动作) 步骤组成（§2.1，p.2）。

**输出**：智能体按 L(q, M, o) → a 逐步生成动作，直到 STOP 或达到步数上限。AWM 额外要求一个归纳模块 I(E) → W，产出工作流集合并并入记忆 M + W，再用于后续任务（§2.1，p.2）。

**工作流表示**（§2.2，p.3）：每个工作流 = 文字描述 d + 步骤序列；每步含三部分：当前页面状态的自然语言描述、推理、可执行动作（如 `stop()`）。具体值被抽象为变量。

**两种模式**（§2.3，pp.3–4）：

| 模式 | 经验来源 | 记忆更新 |
|---|---|---|
| 离线 AWM_offline | 训练样例按网站拼成一个提示，一次性归纳 | 测试时所有任务共用同一组工作流 |
| 在线 AWM_online | 只用测试任务，按流顺序处理 | 每做完一题，由 LM 评估器（Pan et al. 2024）判 0/1；判为成功才归纳并加入记忆 |

**评测口径**：WebArena 看执行结果的功能正确性（任务成功率）；Mind2Web 看元素准确率、动作 F1、步骤成功率和任务成功率（所有步都对才算成功）（§3.1–3.2，pp.4–6）。两者不可混用。

阅读者分析：工作流只是放进上下文的指导，当前页面仍需逐步观察和操作，不是跳过执行的结果缓存。在线模式的效果依赖任务顺序和成功判别的准确性，论文未对评估器误判率单独报告。

依据：[arXiv 2409.07429v1](https://arxiv.org/abs/2409.07429v1)，§2.1–2.3、§3.1–3.2、Figures 2–4，PDF pp.2–6。
