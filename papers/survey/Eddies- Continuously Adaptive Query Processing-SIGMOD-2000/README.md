# Eddies: Continuously Adaptive Query Processing

查询开始时选定的算子顺序，可能因远程源负载、算子代价或选择率的变化在执行中失效。Avnur 与 Hellerstein（SIGMOD 2000）提出 Eddy：一个位于数据源与算子之间的路由算子，每条记录完成一个算子后由 Eddy 决定下一个可执行算子，从而让同一查询内不同记录走不同顺序。

路由用有界队列的背压感知算子速度，用“彩票”（lottery）票数感知过滤效果，并以窗口机制淡化旧反馈。在 River/Euphrates 原型的合成实验中，Eddy 接近较好的固定顺序，并在索引代价于运行中交换时优于两种固定顺序；连接输入延迟到达时则暴露出票数策略的误判（§4）。
