# 贡献与评价

**1. 把算子顺序交给运行时路由**：Eddy 位于数据源与算子之间，算子处理后的记录返回 Eddy，再被送往下一个可执行算子。执行顺序由这一循环中的路由选择形成，不同记录可以走不同顺序，同一查询也可以随反馈改变顺序。

**2. 说明重排成立的算子条件**：论文分析连接的同步屏障、对称时机与顺序约束，并据此选择适合自适应执行的流水线连接算法，使路由自由度与正确性要求的状态约束对应起来。

**3. 同时利用处理速度和过滤效果**：

| 机制 | 感知什么 | 局限 |
|---|---|---|
| 有界队列背压（Naive Eddy） | 算子处理速度：慢算子队列易满，新记录难进入 | 不能判断哪个算子更早排除记录 |
| Lottery 路由 | 算子收到记录加票、返回记录减票，按票数决定路由概率 | 早期积累的优势可能长期主导 |
| 窗口机制 | 定期用近期反馈替换旧票数 | 仍是启发式 |

**局限（阅读者整理）**：
- 路由依据是启发式反馈，不保证每次都选最优顺序；
- 连接输入延迟时，“收到记录但没有输出”可能表示记录暂存在哈希表中，而非被有效过滤，票数策略会据此误判；
- 记录一旦存入某个连接的状态，其他连接不能直接拿它继续处理，论文的延迟实验揭示了这一点。

因此，这项工作的贡献是让给定查询的流水线持续调整执行顺序；它没有消除所有预优化选择，也没有完成任意历史状态的迁移（阅读者分析）。

**与语义算子工作的关系（阅读者分析）**：Eddy 的逐记录路由是后来 LLM 语义过滤自适应排序（如 Aero、Larch）的直接前身；LLM 调用延迟高，使逐记录决策的开销更容易摊销。
