# 出发点

**研究问题**（§1，p.1）：代码生成、函数调用和数据分析能力的进步，能否让 LLM 仅凭给定数据集就完成假设的搜索与验证？作者想系统回答“当前最强 LLM 在自动数据驱动发现上能做到什么程度”。

**为什么难评**：真实世界的数据驱动发现跨领域、形态多样，很难建立可复现的评测（§1 p.1）。从数据得出科学结论不只是写出能跑的代码，还要选对人群（上下文）、变量和关系形式，并且目标里的术语往往不等于数据列名，例如“土地利用”对应 `habitat type`（§1，p.2）。

**已有基准的缺口**（§2，Table 1，p.3）：

| 基准 | 与本文的差别（据原文） |
|---|---|
| QRData | 多为教科书式统计/因果题，有唯一数值答案 |
| DSBench | 数据科学任务，选择题或短答，不需领域知识和假设发现 |
| BLADE | 假设验证做成选择题，每步操作限于 select、map、group-by 等小集合 |
| AutoML 数据集 | 面向训练模型，而非开放式发现 |

**设计思路**：用“上下文—变量—关系”三元结构描述假设，既能覆盖大量真实任务，又能逐维度打分；任务从已发表研究的可复现分析中重建，使难度接近真实研究（§1 p.2、§3）。

阅读者分析：本文评测的是“给定文件内”的发现能力，不涉及在开放数据源中寻找数据，也不涉及跨任务复用证据。

依据：§1–3、Table 1，PDF pp.1–3。
