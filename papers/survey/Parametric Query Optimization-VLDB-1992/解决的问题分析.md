# 解决的问题

**形式化**（§3.1，p.106）：S 为查询所有可用计划的集合；计划 s 的代价写作 c(s, p, x)，p 为优化时未知、运行时才知道的参数向量，x 为不变参数。计划函数 s(): P → S 把每个参数值映射到一个计划；参数化查询优化要找最优计划函数，即对任意参数值都给出最优计划的那个。计划函数把参数域划分为若干“像分区”，同一分区内计划相同。

**两种等价表述**：
- Formulation A：对参数域中的每个取值分别做一次传统优化，再把结果拼成计划函数；
- Formulation B：在计划函数空间上做一次优化。

两者原理上等价；A 更易理解，B 处理起来更高效（§3.1）。

**例子**（Example 1，p.106）：参数为缓冲区大小 B = [2, 151] 和某关系的索引类型 I = {无索引, 聚簇 B 树, 非聚簇 B 树}，参数域共 450 个取值；A 要解 450 个独立优化问题，B 只解一个问题。

**本文实际研究的问题**（§4.1）：只把缓冲区大小 b ∈ [b_min, b_max] 作为参数，对 select-project-join 查询求计划函数；计划空间含深树与浓密树，代价为 CPU 与 I/O 的加权和。

阅读者分析：输出是事先算好的“参数 → 计划”查找表，运行时不再优化；它说明“不同运行条件走不同计划”可以是一次优化的结果，而不必在运行时才规划（阅读者分析）。

依据：§3.1、§4.1、Example 1，VLDB pp.106–107。
