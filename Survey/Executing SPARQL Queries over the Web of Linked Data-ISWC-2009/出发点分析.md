# 出发点

**开放数据空间**：Linked Data 原则要求实体用可经 HTTP 解引用的 URI 标识，描述中可含指向其他数据源的 RDF 链接，整体构成一个全球分布的数据空间。由于它是开放的，回答查询所需的数据源无法事先全部知道（§1，pp.1–2）。

**驱动例子**（Fig. 1，p.2）：查询“ESWC'09 上与 ontology engineering 相关论文的作者电话”。论文列表和主题来自 Semantic Web Conference Corpus，主题名称来自各主题 URI 的权威来源，电话来自作者自己的 FOAF 资料。这类查询无法由单个数据集回答。

**现有方法的缺口**（§1、§7，pp.2、14）：
- 联邦查询（DARQ、SemWIQ）要求每个源提供查询服务，并且不主动发现新源；
- 集中式方案（OpenLink 镜像、Sindice/Swoogle/Watson 等爬虫索引）事先收集数据，需要大量资源，数据时效受限于爬取时间。

**思想来源**：在应用运行时查找 URI 的想法来自 Tabulator（Berners-Lee 等）；本文把它放进查询执行本身，使每个应用不必自己实现链接遍历（§7，p.14）。

依据：[作者预印本](https://olafhartig.de/files/HartigEtAl_QueryTheWeb_ISWC09_Preprint.pdf)，§1、§7，pp.1–2、14。
