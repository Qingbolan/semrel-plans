# 贡献与评价

**论文声称的贡献**（摘要、§1、§6）：
1. 提出一组多模态算子，作为扩展关系运算、表达跨模态分析任务的统一接口；
2. 形式化系统的关键步骤：数据发现、查询规划、查询处理、结果汇总；
3. 指出实现与优化这些步骤的研究挑战，并讨论 LLM 带来的机会；
4. 展示初步工作：CMDBench（多模态来源发现）与 CypherBench（自然语言到 Cypher）两个基准。

**§4 列出的挑战**：
- 统一数据模型：把一切放进带不同属性的表无法表达跨模态关联；需解决跨模态实体关系；
- 多模态数据发现：可训练跨模态表示学习模型把各模态映射到同一向量空间并设阈值，但高质量标注难获得；
- 查询优化：跨模态执行顺序、子计划并行、跨模态代价估计、历史信息收集、跨模态谓词下推；
- 混合负载：模型推理既可作谓词也可作算子的物理实现（如 LookUp 用 RAG，文本 Aggregation 对应摘要）；
- 可用性（自然语言接口、交互式结果探索）与引入 LLM/agent 的机会。

**阅读者评价**：
- 优点：明确承认来源和模态可能不在用户输入中，问题比“给定表上的问答”更完整（§1、§3）。
- 优点：算子不限定为 LLM 调用，能容纳 SQL、图查询和模型推理（§3.2）。
- 不足：核心的联合优化只停留在问题清单，没有系统实现，也无法量化整体收益（§4–5）。
- 不足：§5 的两个基准分别检验发现和图查询，不能检验跨组件的误差传播（§5）。
- §6 结论称“展示了一个构建在企业数据湖上的原型作为概念验证”，但正文没有任何原型描述或结果；§5 开头称评测针对“Section 2 介绍的组件”，实为 §3（阅读者分析）。

依据：[arXiv 2504.02059v1](https://arxiv.org/abs/2504.02059v1)，摘要、§1、§3–6，PDF pp.1–6。
