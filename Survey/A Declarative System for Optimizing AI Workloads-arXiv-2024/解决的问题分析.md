# 解决的问题分析

来源：[原文](2405.14696v2.pdf)，§3–5。

- **输入**：预注册 Dataset、用户定义的输入/输出 schema、转换与过滤程序、显式依赖，以及运行时间/费用/质量策略。
- **输出**：所选物理计划的执行结果；系统依据估计值选择计划，不提供硬约束必然满足的保证。
- **核心困难**：模型、代码、输入长度和执行顺序会同时影响成本与质量；不执行全部候选，就很难准确判断哪种组合最合适。
- **核心做法**：以 convert 表达 schema 间的数据转换，在依赖允许时重排 convert/filter；用少量 sentinel 计划采样估计统计量，比较模型选择、代码合成、输入 token 缩减等实现，按用户策略选取候选 Pareto 前沿上的计划。

## 实现与范围

原型实现 filter/convert 重排、模型选择、代码合成、多字段提示组织及输入 token 缩减；模型级联明确尚未实现。用户需要指定步骤和依赖，系统不是直接从任意自然语言问题自主探索环境（§3–4）。

采样使用三种单模型 sentinel 计划，并以全 GPT-4 champion 输出估计算子质量；这是质量代理，不是真实标签。论文承认采样停止条件和 sentinel 选择仍较粗糙（§4.3）。

已经按 Dataset 缓存中间结果，并识别不同程序的共享计算；记录缓存质量统计、根据质量要求变化失效属于未来工作（§3.5）。不能把该系统说成没有结果复用。

## 实验证据与边界

评估法律邮件发现、房源搜索、医学 schema 匹配三个工作负载。§5.4 的完整选计划流程包含采样开销，九种任务/策略组合中七种满足约束；医学成本上限 $2 实际为 $3.16，房源 F1 要求 >0.80 实际为 0.79（表 1）。

房源任务三种策略的平均运行时间与费用分别比全 GPT-4 基线低 67.5% 和 65.7%，论文报告 F1 高 6%（§5.4）。这是具体任务与配置的收益，不能外推为所有语义查询。

最大 90.3× 加速来自法律邮件任务中 32 workers 的并行原型对比单线程 GPT-4：运行时间 16,712s → 185s，费用 $51 → $5.60，F1 0.97 → 0.81（§5.5，表 2）。不能解释成纯优化器或等质量条件下的加速。

医学场景的动机包含按论文寻找数据集，但评估描述聚焦表格筛选与字段匹配，不足以证明通用的数据源发现或执行时开放探索能力（§1、§5.2）。
