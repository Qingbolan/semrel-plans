# 解决的问题

**输入**（§2.1，p.2）：用户选定的文档集合、可抽取属性及其文字描述、一条 SQL 语义的 SPJ 查询。过滤可为等值、开区间或闭区间，可任意组合成合取、析取或混合表达式；join 用连接图 G={T, E} 表示。聚合优化留作未来工作。

**输出**：查询结果元组；中间产物是逐文档的抽取顺序与 join 执行顺序。

**每次抽取的降本**（§4，pp.8–9）：
- 两级索引：先用文档摘要嵌入排除主题不符的文档，再在片段级索引中检索相关片段；
- 证据增强检索：抽样约 5% 文档让 LLM 返回属性值及来源片段，把这些片段嵌入后做 k-means（默认 K=3），用聚类中心作为额外检索向量；样本中找不到某属性时，让 LLM 依据属性名与描述合成约 20 个代表片段作为证据；
- 自动阈值：文档阈值 τ 与片段阈值 γ_i 都由样本上的抽取结果确定，实现中再各加 0.1。

**过滤排序**（§3.1，pp.4–6）：c_k 为该文档上属性相关片段的 token 数，p_k 为样本估计的选择率。

| 表达式 | 排序规则 | 依据 |
|---|---|---|
| 合取 | 按 (1−p_k)/c_k 降序 | Lemma 1 |
| 析取 | 按 p_k/c_k 降序；SELECT 与 WHERE 共有的属性先抽取 | §3.1.3 |
| 混合 | 对表达式树递归求解 | §3.1.4 |

排序为 O(n log n)，而逐文档穷举是 O(|D_Q*|·|A_w|!)。

**join**（§3.2，pp.6–8）：先执行一侧的过滤并抽取 join 键，把另一侧的 join 转成 IN 过滤，与该侧其他过滤一起排序。Lemma 2 证明这样的计划期望代价不高于“先分别过滤再 join”的谓词下推计划。多表 join 时先选两表执行，完成后再决定下一张，形成 left-deep 计划。

阅读者分析：Lemma 1/2 的最优性是在论文的代价模型下成立的，前提包括谓词独立、选择率由样本准确估计；相关谓词或估计误差不在保证范围内。

依据：[arXiv 2507.06515v2](https://arxiv.org/abs/2507.06515v2)，§2.1、§3.1–3.2、§4、Lemmas 1–2，PDF pp.2–9。
