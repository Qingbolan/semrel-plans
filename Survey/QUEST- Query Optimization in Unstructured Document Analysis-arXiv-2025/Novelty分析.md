# 贡献与评价

**论文声称的贡献**（§1，p.2）：
1. 执行时优化器，按文档生成实例最优的查询计划；
2. join 转过滤的技术，保证不劣于经典谓词下推；
3. 两级索引，过滤无关片段，降低抽取成本且不损失准确率；
4. 实验中相对 SOTA 基线节省 30%–6 倍成本，F1 提高 10%–27%。

**阅读者评价**：
- 核心变化是把优化决策下沉到单篇文档：同一查询中，便宜且能提前拒绝的属性先抽取，join 产生的候选键也参与过滤排序。它同时减少每次调用的 token 和调用次数，而不只是换小模型或只做检索。
- 按 (1−p)/c 排序是经典的过滤排序结论；新意在于 c 按文档而非按查询估计，并且 join 被纳入同一排序框架。
- 两级检索和证据聚类可能漏掉信息；LLM 合成的证据在样本中无相关片段时使用，其可靠性没有单独评估。
- 多表 join 只在当前 left-deep 扩展中做贪心式自适应选择，不是对任意连接图的全局最优枚举。
- §2.4（p.4）称架构“自然支持”并发查询、跨查询缓存抽取结果，但同时声明多查询优化及其基准测试超出本文范围。不能把 QUEST 视为已验证的多查询批处理系统。
- §5.2 称 QUEST 比 PZ、RAG、LOTUS、ZenDB“约快 2 倍”，但 Table 3 中 LCR 上 QUEST 2.68 s 对 ZenDB 2.73 s、PZ 2.85 s，差距只有 2%–20%；约 2 倍只在 WikiText/SWDE 上成立（阅读者分析）。

依据：[arXiv 2507.06515v2](https://arxiv.org/abs/2507.06515v2)，§1、§2.4、§3、§5.2、Table 3，PDF pp.1–8、9–11。
