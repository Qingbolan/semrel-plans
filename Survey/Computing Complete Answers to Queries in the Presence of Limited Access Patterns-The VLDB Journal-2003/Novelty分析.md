# 贡献与评价

**论文声称的贡献**（§1，p.3）：
1. CQ 稳定当且仅当其最小等价查询有可行顺序；两种判定算法；判定问题 NP 完全；
2. UCQ 的类似结果与两种算法；
3. CQAC 的稳定性判定算法；
4. datalog 稳定性不可判定，并给出充分条件；
5. 不稳定 CQ 的完整答案在某些数据上仍可算，提出指导规划的决策树。

**机制要点**：

| 组件 | 细节 |
|---|---|
| CQstable | 先最小化查询，再用 Inflationary 算法检查可行性；最小化使复杂度为指数级（§3.2） |
| CQstable* | 先求可回答子查询 Qa，再检验 Q 是否等价于 Qa（Theorem 3.2） |
| 决策树 | 最小化 → 可行则稳定 → 否则求可回答子目标 Φa，看所有输出变量是否被 Φa 绑定 → 执行线性计划得 Ia → 必要时用穷举计划取不可回答子目标的元组 → 判断完整或给出上下界（§7.2，Figure 14） |
| 规划策略 | 悲观策略在“需下探一层才知道”时放弃；乐观策略继续执行；选择取决于用户需求、计划代价与 Ia 为空的可能性等统计（§7.2） |

**阅读者评价**：
- 优点：清楚区分“可行”（依赖书写形式）与“稳定”（语义性质），避免过早拒绝查询；不稳定时仍给出上下界，对用户有用。
- 优点：§7 允许借用查询之外关系的绑定，并在执行后才判定完整性，比静态的源选择更进一步。
- 局限一：前提是关系语义与访问约束准确；来源若返回不完整结果，完整性推理失效（§2 模型假设）。
- 局限二：穷举计划可能递归访问很多关系（§7.3）；论文只证明“能否”，不分析取证代价是否可接受。
- 局限三：没有系统实现与实验；乐观/悲观策略的选择只给出考虑因素。
- 局限四：作者在 §8.1 承认 UCQAC 等查询类的稳定性仍需研究。

阅读者分析：对当代“运行中取证、事后判定完整性”的系统设计而言，§7 是一个严格的前身：中间结果产生新的访问参数，完整性要等执行后才知道（阅读者分析）。

依据：§1、§3、§7–8，修订稿 PDF pp.3–10、24–30。
