# 解决的问题

**输入**（§2，p.3）：一个数据集、一个自然语言任务（例如“报告上月食品消费超过 1,000 美元的客户的平均消费”）、一个预定义算子库。

**原子算子**（§2，p.4）：语义算子（semantic filter、grouping、join、extraction，可由 LLM 调用、LLM 生成的程序或嵌入匹配实现）、关系算子、系统 API（Spark、Flink）、对 PostgreSQL/ClickHouse/DuckDB 的 SQL；外部系统通过 MCP 接入。

**输出**：一条可执行、经优化的算子流水线及其结果。精度按任务的参考输出（返回记录、数值、排序、聚合统计）评估（§2，p.4）。

**过程**（§2，pp.4–5）：
1. 语义数据组织：树形语义目录 + 嵌入 + 向量索引，用稀疏关键词嵌入与稠密查询嵌入检索相关数据；
2. 编排：把请求转为任务图，规划智能体按逻辑与资源约束定序，验证智能体对非确定算子做低成本 dry run 并选最优候选；
3. 优化：用语义目录估计语义算子基数，动态规划选期望代价最低的流水线；
4. 执行：语义算子级联——ANN 检索、上下阈值剪枝、轻量 LLM 粗筛、强 LLM 精判；
5. 低置信度或执行错误触发反馈闭环（Table II 列出事件驱动的组件激活规则）。

**错误检查**（§4，pp.8–9）：语法错误用 schema 校验、算子签名检查、流水线语法校验和静态 dry run；语义错误用三种策略——多候选流水线交叉验证、合成数据一致性检查、Pipeline2NL 一致性评估。

**记忆**（§3，pp.6–8）：工作记忆 + 长期记忆（情景、语义、程序性）；提取、插入/更新/删除、检索、整合四类操作；冲突条目不覆盖，而是作为并行版本挂在版本图上（Algorithm 1）。
