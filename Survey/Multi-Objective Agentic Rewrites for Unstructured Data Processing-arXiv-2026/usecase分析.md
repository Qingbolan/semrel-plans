# 具体用例

**原文示例**（CUAD，§5.1.2、§5.3，pp.11–13）：从法律合同中抽取 41 类条款的文本片段。

**初始流水线**：一个 map，一次性要求模型抽出所有条款类型，输出 `{clause_type, text_span}` 列表，模型 gpt-4o-mini。

**MOAR 找到的做法**：在一条最高准确率的 CUAD 流水线中，agent 在 LLM map 之前插入一个代码算子，用正则匹配定位与条款相关的段落，并截取每个匹配周围的固定长度窗口，只把这些窗口交给 LLM。作者报告这一步使成本降低 48.76%，准确率提高 3.1%（§5.3）。

**结果**（Table 4–5，pp.12–13）：

| 方法 | CUAD 最高 F1 |
|---|---|
| MOAR | 0.762 |
| PZ / Abacus | 0.694 |
| SA（gpt-5 简单 agent） | 0.521 |
| MOAR（无搜索） | 0.495 |
| DocETL-V1 | 0.471 |
| LOTUS | 0.402 |

MOAR 达到 PZ 最高准确率只需其 0.290× 的成本，达到 DocETL-V1 的只需 0.073×；这些节省不含一次性优化费用。CUAD 的优化花费 $44.0、约 5,536 秒；最准流水线在全量数据上的执行成本约 $45.3，外推到 100 万篇约 $88.9k（Table 6）。

阅读者分析：PZ 使用 Abacus 作者提供的流水线并加倍样本数；比较的是“最佳准确率”，不代表每个成本点都有同样差距。

依据：[arXiv 2512.02289v4](https://arxiv.org/abs/2512.02289v4)，§5.1–5.3、Tables 4–6，pp.10–13。
