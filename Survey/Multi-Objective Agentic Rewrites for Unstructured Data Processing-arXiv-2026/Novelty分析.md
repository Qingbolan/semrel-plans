# 贡献与评价

**论文声称的贡献**（§1，p.3）：
1. 可扩展的改写指令库：在 DocETL 原有 13 条基础上新增 18 条，含模型替换、上下文截断、算子融合，以及用合成代码替代 LLM 调用；新增“代码合成”（4 条）与“算子融合与重排”（5 条）两类；
2. 多目标搜索算法：不假设最优子结构，在有限评估次数内寻找同时改进准确率与成本的改写序列；
3. 六个真实领域工作负载上的评估：最高 11× 准确率提升，同等准确率下推理成本最多降低 99%。

**Figure 1 的例子**（p.2）：加重情节流水线中准确率最高的 #46 经过四次改写得到：换便宜模型（#2）→ 数据分解为分块处理（#6）→ 改进 map 提示（#24）→ 改进 reduce 提示（#46），且成本低于用户原计划。

**高准确率流水线的特征**（§5.3，Table 7，p.13；29 条最高准确率流水线）：79% 使用投影合成（先压缩文档），48% 包含 agent 写的代码；模型替换最常见（25 次）但从不单独出现；最常用的模型是 gpt-5-nano（41%）。

**优点（阅读者分析）**：
1. 准确率与成本共同驱动，逻辑改写有明确用途；
2. 以完整流水线为评估单位，能捕捉上下游相互影响；
3. 报告了优化开销与外推到 100 万篇文档的执行成本（Table 6），便于判断何时值得优化。

**不足（阅读者分析）**：
1. 质量依赖 40 篇优化样本与评估器；Pareto 计划从样本到测试集的准确率平均下降 4.7 个百分点，Medec 与 Sustainability 下降约 9–10 个百分点（Table 11）；
2. Medec 上去掉搜索的消融（0.755）反而高于 MOAR（0.742）（Table 4），搜索算法的优势并非处处成立；
3. 有限预算下的启发式搜索不保证全局最优；作者也指出 56–78% 的已探索流水线对最终前沿没有贡献（§7）；
4. 优化本身要 $16.7–188、约 0.6–2.3 小时（Table 6），低频或小规模任务难以摊薄；
5. 依赖 gpt-5 这类前沿模型实例化指令。

依据：[arXiv 2512.02289v4](https://arxiv.org/abs/2512.02289v4)，§1、§3、§5.2–5.3、§7、Tables 4、6、7、11，pp.1–14、附录。
