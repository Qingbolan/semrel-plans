# Workload 分析

**要验证的问题。** 检验同一代码库中多个敏感源点分析，是否重复理解共同片段，以及在工具观察后注入历史分析能否获得净费用收益。

**数据、任务单位与gold。** 从F-Droid取得173个真实开源Android应用，规则发现5927个源点；152个应用有源点。Main50选择源点最多50个应用，4685任务；Strat15为15应用1284任务，抽20%即257任务审计。单位是一个source到sink类别的分析。审计gold来自各系统报告并集的人审，不是所有真实泄漏全集。指标token/API总费用、相对precision/recall/F1；无墙钟结果。

**具体use case：输入目标 → 使用前 → 使用后。** 原文§II中不同源点的路径汇入共同分发/回调逻辑。使用前各Agent从各自source重新读同段代码；使用后工具返回代码锚点即匹配已有解释，仍检查当前输入对应的下游路径。共同代码不等于相同泄漏结论；案例未单独提供完整金标准收益。

**Baseline与比较条件。** 标准OpenCode、FlowArk-enabled OpenCode，Strat15还比较Mem0与Analysis-Log RAG及模块消融。同任务顺序、描述、代码访问，差别是记忆机制；任务顺序串行，后任务只能用之前已完成知识。总费用603.49→441.59美元已计管理44美元，不能只报分析调用省下的部分。

**证据边界。** 固定代码快照、源点最多应用选择有利于重叠；审计非绝对召回，本地embedding未完整货币化。能支持本领域重复分析，不是开放数据环境普遍性或并发调度证据。
