# 解决的问题

**输入**（§2，附录 A）：自然语言任务描述、输入输出 API 定义（如 `entity_resoluion(entity1, entity2) -> is_same`）、少量示例，以及输入数据；可选用户提供的工具。

**输出**：一条混合执行流水线及整理结果。流水线由若干模块按顺序组成，前面的模块不确定时把记录转给后面的模块，最后兜底的是 LLM（§1、Figure 1）。

**四类模块**（§4）：
- CodeGen：LLM 生成代码处理记录，可生成多个分支并在验证数据上检查、修复；
- CacheReuse：复用完全相同或相似查询的已有 LLM 结果；
- ModelGen：用 LLM 伪标签训练小模型（实验中为 t5-small）；
- LLM：直接调用 LLM，支持批量查询，并可通过“思考—动作—观察”循环按需调用工具（Figure 4）。

**优化目标**（Definition 3.1，§3，p.5）：给定用户可容忍的效果差距 G，在所有计划中找成本最低、且效果 A(P) > A(P*) − G 的计划，其中 P* 是效果最高的计划。成本用交给 LLM 处理的记录比例（LLM R）表示（§6）。

**搜索方法**（§3.1–3.2）：仿照基于代价的优化器，先收集统计，再逐个添加模块并复用最优子计划；假设被支配计划的后代不会成为最终最优计划的一部分。通用优化器（GEN）之外，还有利用数据整理任务特性的专用优化器（SPE），进一步缩小搜索空间。

**边界（阅读者分析）**：整理任务的降本与表发现任务的效果是两组不同实验，表发现主要依赖带工具的 LLM，不能把实体匹配的调用节省套用到探索任务上。缓存相似性和伪标签也不是正确性保证。

依据：[arXiv 2310.00749v3](https://arxiv.org/abs/2310.00749v3)，§2–5、Definition 3.1、Figures 1、4，pp.2–10。
