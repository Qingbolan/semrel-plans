# Novelty 分析

机器状态预测等数据科学任务需要先探索数据，再选择清洗、特征、建模和验证步骤。初始需求不能给出所有可执行细节，代码错误与中间结果又会改变下一步。Data Interpreter 研究如何让 Agent 在持续运行和验证中修订任务，让用户的高层目标真正落成可执行分析。

## 作者贡献：用自己的话概括

1. **「任务组织」将数据科学目标分解为可调整的任务与动作两层。** 既保留分析依赖，又能在局部代码出错时修复具体步骤。

2. **「执行时适应」依据中间执行结果迭代修订分析过程。** 将规划与实际数据反馈连接起来，减少一次性计划偏离真实执行条件的问题。

3. **「可执行验证」结合可编程动作、工具使用和运行反馈推进任务。** 用实际执行检查发现可修复错误，并在多类数据科学任务上检验完成能力。

## Strong points（我们的判断）

1. 机器状态预测的流程示例清楚说明为什么后续分析依赖中间观察（§3.1、图2）。

2. 任务级依赖和动作级调试分离，修订粒度与失败来源对应（§3.1–3.3）。

3. 既测试表格分析也测试 ML 与开放任务，提供多种任务完成证据（§4）。

## Weak points（我们的判断）

1. 运行成功和代码检查不能保证结论在统计或业务意义上正确，需要更独立的结果核验（§3.2–3.3）。

2. 开放任务集仅20个、ML集8个数据集，难覆盖复杂数据环境的全部失败类型（§4.1、附录D）。

3. 多轮上下文增长会导致失败；论文在较短上下文模型上报告了这一现象，适应能力有实际资源代价（§4.2）。
