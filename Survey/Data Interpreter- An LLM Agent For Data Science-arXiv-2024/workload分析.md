# Workload 分析

**要验证的问题。** 检验执行反馈、分层任务规划和工具使用能否提高数据科学任务完成质量，尤其是一次生成代码难完成的多步分析。

**数据、任务单位与gold。** InfiAgent-DABench为52个CSV上的257道分析题，以参考答案准确率评测；ML-Benchmark选8个Kaggle数据集，依任务用分类/回归指标并归一化汇总；另有作者构造的20个开放任务及MATH测试。真实数据集与作者设计任务应分开；任务单位是一次完整分析，不是数据表每一行。

**具体use case：输入目标 → 使用前 → 使用后。** 原文图2是机器状态预测流程：输入设备数据，目标预测正常/故障。使用前，一次计划可能在缺失值处理或建模代码失败后无法继续；使用后，Agent探索数据、清洗、构造特征、训练与验证，并依结果修订任务。这里是论文流程的说明性重述，没有给该单例捏造准确率或费用。

**Baseline与比较条件。** DABench比较无Agent的LLM、XAgent、AutoGen；ML还比较OpenInterpreter、TaskWeaver、OpenDevin；开放任务比较AutoGen/OpenInterpreter/OpenDevin。必须按相同底层模型看表1：gpt-4-0613下Data Interpreter为73.55，并非所有设置都优于无Agent；gpt-4o下94.93才是摘要高分。表中星号为引用结果，不是全部重跑。

**证据边界。** 支持反馈修订有实际用处，但既未测试跨记录共享，也未与充分设计的固定条件程序做同质量对照；不能据不同轨迹宣称运行结构不可预定义。
