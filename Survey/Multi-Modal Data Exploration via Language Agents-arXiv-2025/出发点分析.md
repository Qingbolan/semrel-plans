# 出发点

**场景**：医院、企业的数据分散在关系库、文本、图像中。像“吸烟的肺癌患者过去 12 个月病灶进展”这样的问题，必须同时查结构化表和影像，单一的 text-to-SQL 或 VQA 系统都无法独立回答（§1，Figure 1 左）。

**已有系统的不足**（§1–2）：
- ThalamusDB、MindsDB、VIVA 需要用户写 SQL，并手工指明哪些谓词作用于图像/视频列；
- CAESURA 与 MAT 采用 ReAct 式逐步决策，先出逻辑计划再出物理计划，按顺序执行，上下文 token 多、延迟高（§2 脚注 3、§3）；
- 许多框架的规划层级固定，失败后只能整体重来，且常在自建数据上评测，缺乏有 gold 答案的基准。

**目标**：三个问题——异构数据理解、工作流编排（分解、分派、依赖与并行）、可解释性（展示答案如何得出、用了哪些数据）（§1）。

阅读者分析：可解释性动机主要来自医疗场景的合规需求，但论文没有对解释的忠实度做任何度量，只展示了中间步骤（见“评测与边界”）（阅读者分析）。

依据：[arXiv 2412.18428v2](https://arxiv.org/abs/2412.18428v2)，§1–2、Figure 1，PDF pp.1–3。
