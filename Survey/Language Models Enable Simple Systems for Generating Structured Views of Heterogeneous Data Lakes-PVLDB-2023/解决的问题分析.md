# 解决的问题

**输入**：一个文档集合 D（如一批 FDA 510(k) 审查报告），可选用户预定义的属性（§2，p.3）。

**输出**：结构化视图（表）。分两种任务（§2）：

| 任务 | 含义 | 评测指标 |
|---|---|---|
| OpenIE | 系统自己发现属性并抽值 | Pair F1（文档、属性、值三元组） |
| ClosedIE | 给定属性，只抽值 | Text F1 |

**三种实现**（§3，pp.4–7）：

| 实现 | 做法 | 代价 |
|---|---|---|
| Evaporate-Direct | 逐文档让 LLM 同时识别属性和抽值 | 随文档数线性增长 |
| Evaporate-Code | 先在少量文档上做 schema 识别，再按属性生成抽取函数，在全集上运行 | 随属性数增长，与文档数无关 |
| Evaporate-Code+ | 每个属性生成多个候选函数，用 LLM 在样本上的抽取作伪标签打分、过滤，再用弱监督聚合 | 同 Code，另加少量评估调用 |

**Code+ 的聚合（Algorithm 1，p.7）**：在样本上同时运行候选函数和 LLM；用 LLM 判断空输出是"弃权"还是"真没有值"；按与 LLM 输出的一致度打分，去掉得分 ≤0.5 的函数；剩余函数在全集上投票，再用弱监督得出最终值。作者指出标准弱监督的三个假设在此不成立：函数会在不适用时弃权、函数好于随机、输出是有限类别。

**不保证的事**：复用的是抽取程序，而不是逐条重新发现；同一函数不能保证覆盖所有异构格式（阅读者分析）。

依据：[arXiv 2304.09433v3](https://arxiv.org/abs/2304.09433v3)，§2–3、Algorithm 1、Figure 4，pp.3–7。
