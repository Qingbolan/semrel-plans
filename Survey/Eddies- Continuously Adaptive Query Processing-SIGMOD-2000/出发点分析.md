# 出发点

**固定顺序会在执行中失效**：查询开始时选出的执行顺序，可能在查询结束前就不再合适。远程服务器负载和网络速度会变化；算子处理一条记录的耗时、过滤后保留的记录比例，也可能随执行进度改变。只在开始时估计一次代价，无法应对这些变化（§1）。

**例子**：员工表按年龄从小到大存储，查询要求薪资大于 100,000。如果年龄与薪资相关，扫描前段和后段通过该条件的比例就会不同。开始时能排除大多数记录的筛选，到后面可能留下更多记录；把它始终放在昂贵操作之前，收益也随之变化。

**思路**：让执行器持续利用运行反馈决定下一步，每条记录完成一个算子后再选择接下来可执行的算子。调整可以发生在同一条查询的执行过程中，而不必等整段流水线结束。

**范围**：论文聚焦单节点执行器中的过滤与连接顺序。远程数据源是变化来源之一；查询条件、参与关系和初始连接算法仍由系统事先确定。

依据：[SIGMOD 2000 原文](https://dsf.berkeley.edu/cs286/papers/eddies-sigmod2000.pdf)，§1–2（本轮未能重新对照页码）。
