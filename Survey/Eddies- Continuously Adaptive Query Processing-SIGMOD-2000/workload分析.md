# Workload分析

**验证的问题。** 当算子成本、选择率或来源速度改变，运行中逐元组路由能否跟随较好的执行顺序。

**数据与任务。** 合成关系R=10,000、S=80,000、T=10,000、U=50,000条，每条100字节；可控的选择谓词耗时与选择率，另有索引连接延迟实验。任务单位为过滤或连接查询；答案由同一查询语义定义，不采用人工gold。指标为总时间、输出随时间变化及元组路线比例。

**最清楚的use case（原文§4）。** 输入U，执行两个昂贵选择谓词→返回同时满足两者的元组。若固定先跑慢且少排除的谓词，会多做无效工作；eddy根据消耗/产出反馈把更多元组先送到更合算的谓词。实验分别改变耗时和选择率，不能把合成delay单位说成真实语义模型调用费用。

**Baseline与公平性。** 两种 `static orderings`、`naive eddy`、`lottery-based eddy`；变化实验还比较有无window-based forgetting。枚举静态顺序提供最佳/最差参照，路由方案在线获得反馈。相同输入和谓词；eddy仍有预优化器选择初始连接配对，不能说其不需要任何初始结构。

**依据与边界。** §4实验设置、表1、图4–6；§5变化与延迟实验。延迟输入遇到状态积累时有不利案例，论文据此讨论ticket策略和状态问题；不是动态执行总优于静态计划的证明。
