# 评测与边界

**环境**（§5.1，p.7）：
- 主实验在 EC2 g4dn.2xlarge 上运行（32 GB 内存、8 vCPU、T4 16 GB 显卡，GPU 只用于计算嵌入，不在本地部署 LLM）；
- 扩展实验在双路 Xeon Gold 5218、384 GB 内存的 Ubuntu 服务器上运行；
- 被测版本：LOTUS 1.1.3（文本嵌入用 e5-base-v2，图像嵌入用 clip-ViT-B-32）、Palimpzest 0.8.2（MaxQuality 目标）、ThalamusDB 0.1.15、BigQuery（2000 slots）。

**各场景平均**（Table 4，各系统只对自己支持的查询求平均，因此系统之间不完全可比）：

| 场景 | LOTUS | Palimpzest | ThalamusDB | BigQuery |
|---|---|---|---|---|
| Movie | $0.62 / 0.68 / 147.9 s | $0.82 / 0.73 / 115.2 s | $0.02 / 0.82 / 82.6 s（8/10 条） | $0.55 / 0.75 / 42.2 s |
| E-Commerce | $0.22 / 0.75 / 149.2 s | $0.42 / 0.70 / 192.5 s | $0.21 / 0.44 / 363.7 s（5/14 条） | $2.42 / 0.67 / 44.7 s |
| Wildlife | $0.14 / 0.95 / 117.0 s（4/10 条） | $0.10 / 0.40 / 21.1 s | $0.07 / 0.46 / 11.9 s | $0.11 / 0.53 / 25.8 s |

**按算子汇总**（Table 5，p.12，只纳入所有可用系统都支持的查询；格式为质量 / 延迟 / 费用）：

| 算子 | LOTUS | Palimpzest | ThalamusDB | BigQuery |
|---|---|---|---|---|
| Filter | 0.896 / 194.4 s / $0.34 | 0.777 / 72.2 s / $0.40 | 0.698 / 101.1 s / $0.19 | 0.574 / 26.7 s / $0.36 |
| Join | 0.614 / 541.1 s / $2.74 | 0.703 / 454.3 s / $3.29 | 0.487 / 387.3 s / $0.14 | 0.601 / 69.4 s / $1.02 |
| 全部算子平均 | 0.731 / 212.1 s / $0.86 | 0.715 / 165.0 s / $1.06 | 0.592 / 244.2 s / $0.17 | 0.677 / 31.7 s / $0.45 |

作者只在均值之差至少达到 3 个标准差时才下比较结论。最便宜的系统和质量最高的系统并不一致，所以不能把费用最低解释为最好（§5.5）。

**分场景要点**（§5.3）：
- Movie：Q1/Q5/Q6 带 LIMIT，系统间费用相差 100× 以上，因为 LOTUS 先对全部数据求值，再执行 LIMIT；
- E-Commerce：只有 LOTUS 和 BigQuery 能完整实现，但 BigQuery 的 Q10/Q11 未在合理时间内完成；LOTUS 的费用方差最大，因为每次运行用不同样本确定嵌入距离阈值；
- Wildlife：LOTUS 不支持音频，只能跑 10 条中的 4 条；
- MMQA：只有 Palimpzest 能完整支持；
- Cars：涉及音频的 Q2/Q5/Q6 在各系统上要么不被支持，要么表现差；Palimpzest 不支持关系 join，需要手工用 Pandas 完成 join。

**规模实验**（§5.4、Figure 1，pp.10–11）：
- 规模取基础规模的 0.5×、1×、2×、4×、8×。任一查询超过 1 小时，该系统就不再测更大规模，但超时的查询不会被强行终止；
- E-Commerce 和 MMQA 上，只有 BigQuery 能扩展到最大规模。MMQA Q7 在规模 400 时需要 160,000 次调用，LOTUS 约 $50，Palimpzest 约 $60；E-Commerce Q8 在规模 4000 时，BigQuery 约 $140；
- 内存：E-Commerce Q8 在 ThalamusDB、LOTUS、Palimpzest 上分别需要约 250、150、100 GB，因为图像对占用的内存没有释放。LOTUS 在 Cars 157k 规模时，LLM 调用失败可能使任务停滞 48 小时以上；
- 整个规模实验的 LLM 费用为 $9,935.80，运行约 18 天。这是总费用，不是单条查询的费用。

**边界**：
- 只测一个后端模型。提示模板各系统不同，所以差异中混有提示设计的影响；
- BigQuery 的温度等参数不对用户开放，所以它在 Wildlife 上的质量方差较高；
- 所有数字均为作者报告，未复现（阅读者分析）。
