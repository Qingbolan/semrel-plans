# workload分析

**验证什么。** 统一模型后，不同语义引擎在算子质量、费用、延迟和规模上的差异是否仍显著；这是系统比较，不是证明开放探索必要。

**数据、单位与gold。** 5场景55查询：Movie10、Wildlife10、E-Commerce14、MMQA11、Cars10。表2的全量语料含1,582,560文本、84,295图片、2,037音频行；主实验实体规模分别2,000/200/500/200/19,672（按Movie/Wildlife/E-Commerce/MMQA/Cars）。原始素材来自标注评论、商品、相机陷阱/声音、MMQA等；Cars车辆属性和跨模态关联含合成，不能称纯真实业务记录。gold把语义调用替换成原数据标签后执行查询。指标含F1、聚合相对误差、Spearman、ARI、费用、延迟、内存；并非每任务同一指标。

**最有说服力用例（原文§4.5例4.5的重述）。** 输入机场表的航空公司名称与logo图片，目标配对公司和logo。使用前需手写跨文本—图片匹配或逐对调用模型；使用后各引擎执行同一语义join，比较是否找对配对及处理成本。论文没有为此例给一个可脱离表4的统一加速数字。

**baseline及公平性。** LOTUS1.1.3、Palimpzest0.8.2、ThalamusDB0.1.15、BigQuery（预留2000 slots）按§5.2配置；固定Gemini2.5Flash、关闭reasoning、适用系统并发20，每实验5次。Palimpzest关闭Abacus与模型选择，BigQuery并发无法控制，提示保留系统默认；故不是各系统完整优化器的上限排名。表4须按支持查询比较，不能把缺功能当等质量零成本。

**证据与界限。** §3–5、表2–4。大规模测试LLM总费用$9,935.80、约18天是整个扩展实验成本，不是单查询费用；最大的可用数据量并非全部跑完。
