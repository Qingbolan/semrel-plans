# 贡献与评价

**论文声称的贡献**（§1，p.186:3）：
1. ThalamusDB：针对多模态数据上带自然语言谓词的复杂查询的确定性近似查询处理系统；
2. 降低大数据集上模型推理开销的处理方法；
3. 让用户在多种代价与误差指标间取舍的多目标优化器；
4. 在多个真实数据集上与 MindsDB、ABAE 等基线比较。

**机制要点**：

| 组件 | 细节 |
|---|---|
| 系统构成 | Python 实现，DuckDB 做关系处理；图片、音频列在 DBMS 中存为文件路径（§2、§7.1） |
| 动作空间 | 对每个谓词：按无序、或按查询中某列升序/降序计算一批相似度；或请求标签（§5，优化算法） |
| 计算步长 | 每步处理图像、文本 1%、音频 0.1% 的元素（§4.1、§7.1） |
| 优化加速 | 可变步长的“粗化”方案（β = 1.01）在 YouTube 12 个耗时案例上把优化速度平均提高 2.4 倍，结果质量相当（§7.3） |
| 误差度量 | 界误差 (u − l)/(u + l)，无需知道真值，用于优化（§7.4） |

**阅读者评价**：
- 优点：控制对象是最终答案的界，而不是中间算子的准确率；同时覆盖图像、音频、文本和关系连接。
- 优点：对基线的比较条件交代清楚：给 MindsDB 免费的真实阈值，给 ABAE 免费的标签和用 oracle 模型分数充当的代理分数。
- 局限一：确定性保证不覆盖模型错误；Figure 16 显示用较小的 Sentence-BERT 时界可能不包含真实结果（§7.4）。
- 局限二：用户标签由人工设定的阈值模拟，没有测真实交互的延迟与标注分歧（§7.1）。
- 局限三：存在不利数据分布：如求椅子最低价时有 1,000 条更便宜的铅笔广告而计算上限只有 500 项，下界就无法收紧（Example 3，§4.3）。
- 局限四：基线只支持很小的查询子集（MindsDB 12 个、ABAE 8 个），35.0 倍加速不能外推到全部模态与查询。

依据：§1、§4–5、§7，pp.186:3–186:24。
