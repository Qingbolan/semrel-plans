# 出发点

**动机场景**（§1，pp.2–3，Listing 1）：工厂监控要找“有人但没戴安全帽”的视频帧，查询含 `ObjectDetector` 与 `HardHatDetector` 两个昂贵 UDF 谓词。谓词求值顺序决定总耗时，经典做法按 cost/(1−selectivity) 打分排序。

**局限一：统计不可靠**。已有 ML 中心 DBMS 要么假设 UDF 选择率与代价已知，要么在样本上先跑 UDF 估计。但 `ObjectDetector` 的代价随帧内框数变化，缓存复用也会改变代价；优化期采样还增加优化时间和优化器复杂度（§1 p.2）。

**局限二：UDF 执行不可扩展**。不同 UDF 的资源需求不同，静态优化无法在运行中按 GPU 利用率调整 worker 数；LLM 等 UDF 的延迟与输入/输出长度强相关，round-robin 会造成 worker 负载失衡，作者称数据感知均衡可带来最高 1.3× 加速（§1 p.3）。

**目标**：不替换模型、不改变谓词语义（因而不影响结果准确率）的前提下，用运行时反馈同时优化谓词顺序和硬件利用（§1、§3.1）。

依据：[DOI 10.1145/3725408](https://doi.org/10.1145/3725408)，§1、§3.1，pp.1–6。
