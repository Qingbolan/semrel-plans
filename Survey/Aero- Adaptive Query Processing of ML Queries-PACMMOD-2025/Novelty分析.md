# 贡献与评价

**论文声称的贡献**（§1，p.3）：
1. Aero：把自适应查询处理（AQP）用于 ML 查询，通过运行时监控 UDF 统计与 Eddy 路由策略决定谓词顺序；
2. Laminar：在 AQP 框架内的自动伸缩组件，包括低开销伸缩策略 gacu 与数据感知负载均衡；
3. 在视频、图像、LLM 文本四个用例上，相对静态优化最高 6.4× 加速且不影响准确率。

**机制要点**：

| 组件 | 细节 |
|---|---|
| Cost-driven 路由 | 并发执行时谓词以流水线方式重叠，选择率作用下降、慢谓词成为瓶颈，因此只按代价排序（§4.1，Fig. 3–4） |
| Reuse-aware 路由 | 估计代价 = (1 − 缓存命中率) × 实测代价，按批次调整，适配部分缓存（§4.2，p.10） |
| gacu | 查询开始时贪心分配多个 worker 上下文，启动画像阶段只激活 1 个，再按显存占用决定激活数，单 GPU 上限 50（§5.1） |
| 数据感知均衡 DLB | 默认以输入大小（文本长度、帧大小）估计代价来分配批次，用户可自定义启发式（§5.2） |
| 实现 | 基于 EvaDB，路由器与 worker 用 Ray remote function 实现；急切物化，丢弃不满足的元组（§6） |

**优点（阅读者分析）**：
1. 模型与谓词保持不变，性能收益与质量折损可以分开看（§7.1–7.2）；
2. Q4 专门测部分缓存，显示跨查询历史如何改变最优顺序（§4.2、§7.3）；
3. 路由策略、Laminar 对比 Ray Serve、组件拆解、阶段耗时都有实验，收益来源较清楚（§7.3–7.6）。

**不足（阅读者分析）**：
1. 只有 4 个数据集、6 条作者构造的查询，均为 2–4 个谓词的合取（§7.1）；
2. Viva 只开启谓词重排，关闭了输入过滤和模型替换，比较的是“不换模型”的路由能力（§7.1）；
3. 最大收益来自 Q3 的 GPU 利用率（Laminar），而非顺序本身：Q3 上加 Eddy 只得 1.36×，再加 Laminar 得 6×（§7.5）；
4. Q4 人为设定已缓存区间，热态收益不能当作冷启动收益（§7.1 Q4）。

**与语义算子工作的关系（阅读者分析）**：Aero 的“按实测代价自适应排序谓词”与 LLM 语义过滤排序问题同构，但它不估计逐行选择率，且 cost-driven 策略在串行 LLM 调用场景下是否仍优于 score-driven 需另行验证。

依据：[DOI 10.1145/3725408](https://doi.org/10.1145/3725408)，§1、§4–7，pp.3、7–22。
