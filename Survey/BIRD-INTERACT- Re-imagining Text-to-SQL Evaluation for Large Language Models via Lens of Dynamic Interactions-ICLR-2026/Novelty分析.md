# 贡献与评价

**论文声称的贡献**（§1，pp.2–3）：
1. 高保真交互环境：在 LiveSQLBench 上为每题配分层知识库（HKB，DAG 结构）、元数据、可执行数据库，以及两阶段函数驱动用户模拟器；
2. 两种评测设置：协议式 c-Interact 与自主式 a-Interact；
3. 覆盖完整 CRUD 的任务集，带可执行测试用例：FULL 600 题（最多展开 11,796 次交互）与 LITE 300 题。

**机制要点**：

| 组件 | 细节 |
|---|---|
| 歧义注入 | 用户请求的意图级/实现级歧义；知识歧义（删除单条知识，或遮蔽多跳知识链的中间节点）；环境歧义（如关键字段 NULL）。每个歧义配 gold SQL 片段作澄清来源（§3.2） |
| 后续子任务 | 按分类法标注，强调与前一子任务的状态依赖（§3.2、附录 H.5） |
| 两阶段模拟器 | 第一阶段 LLM 把提问解析为 AMB()（预标注歧义）、LOC()（合理但未预标注，用 AST 检索定位 SQL 片段）、UNA()（拒绝索要答案等不当请求）；第二阶段据此生成回复（§3.3） |
| 标注 | 12 名专家，标注者一致率 93.3%/93.5%（LITE/FULL，Table 1） |

**阅读者评价**：
- 优点：用执行测试与有状态的后续任务检验实际效果，而不是比较 SQL 字符串；专门构造 UserSim-Guard 检查模拟器泄漏，并与人类用户做相关性分析（§6）。
- 局限一：歧义经人工注入且有预设澄清，不能用来推断现实用户中各类不确定性的频率。
- 局限二：人类对齐实验只有 100 题、7 个系统，Pearson 0.84 的 p 值为 0.02（Table 3），样本较小。
- 局限三：a-Interact 的动作价格与预算是作者设定的；Table 2 的“Avg. Cost”是美元 API 费用，归一化奖励与真实用户等待不是同一量。
- 局限四：每个模型只跑一次（§5），没有方差估计。
- 原文内部不一致：§3.2 写后续子任务用“5 类分类法”，附录 H.5 与 Table 8 列出 6 类（约束变化、话题切换、属性变化、基于结果、聚合、基于新建对象的状态依赖）。

依据：§1、§3、§5–6、Tables 1–3、附录 H.5，PDF pp.1–10、29。
