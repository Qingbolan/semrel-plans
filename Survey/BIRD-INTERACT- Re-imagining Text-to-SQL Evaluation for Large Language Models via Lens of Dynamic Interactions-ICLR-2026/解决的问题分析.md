# 解决的问题

**任务形式化**（§2，p.3）：系统 S 与用户模拟器 U 在环境 E = {D, M, K} 上多轮协作，D 是可执行数据库，M 是 schema 元数据，K 是外部知识。给定相关子任务序列 Q = {q1, …, qn}，系统通过交互为每个子任务生成 SQL；交互历史逐轮拼接。只有前一个子任务成功，后一个才会发布。

**实现取值**：n = 2。q1 是含歧义的优先子任务，q2 是后续子任务，后者可能依赖 q1 修改后的数据库状态或新建对象（§2、§3.2，pp.3–4）。

**判定标准**：每个子任务标注 gold SQL 与可执行测试用例，预测 SQL 通过全部测试即正确（§2）。

**指标**（§2、附录 F，pp.3、23）：
- 成功率 SR：分别报告 q1 与 q2 的完成比例；q2 的成功率即端到端完成率；
- 归一化奖励：q1 占 70%、q2 占 30%；c-Interact 中首次通过 q1 得 0.7，调试后通过得 0.5（Figure 3）。

**预算**（§4，pp.5–6）：c-Interact 的澄清轮数上限 τ = m_amb + λ_pat，m_amb 为标注歧义数，λ_pat 模拟用户耐心；a-Interact 总预算 B = 6 + 2·m_amb + 2·λ_pat，每个动作按价格扣预算（ask 2、submit 3、execute 1 等，附录 J Table 9）。

阅读者分析：歧义是人工注入、每个都配有唯一澄清答案，因此该问题定义测的是“能否问到预设的那条信息”，而不是现实中不确定性的分布（阅读者分析）。

依据：§2、§3.2、§4、附录 F 与 J，PDF pp.3–6、23、30。
