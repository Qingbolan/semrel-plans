# 具体用例

**三个工作负载的计划**（Figures 4–5，p.8）：

| 工作负载 | 直接输入 | 辅助数据 | 逻辑计划 | 输出 |
|---|---|---|---|---|
| BioDEX | 医学报告 | 反应标签集合 | map 抽取反应 → top-k 召回标签 → map 重排 | 排序后的反应标签 |
| CUAD | 合同全文 | 41 类条款定义 | 一个 map 同时抽取 41 个字段 | 各条款对应的文本片段 |
| MMQA | 问题表 | 图像、文本、表格三类集合 | 三路：map 生成检索串 → 语义 join → group by 问题 → map 拼接 → project；三路 join 汇合 → map 作答 | 答案列表 |

**Abacus 实际选了什么**（§4.3 pp.9–10）：
- **CUAD**：10 次运行全部用 Mixture-of-Agents 实现那个 map，平均精确率 87.2%、召回率 53.0%。作者解释为聚合模型只保留多个提议模型都高置信的片段。对比之下，DocETL 的优化器花 20–40 分钟把 map 改写成 2–7 步的流水线，3 步时 F1 最高 63.7%，7 步时低至 35.3%；LOTUS 不优化 map，便宜快速但质量低。
- **BioDEX**：两个 map 都用 Reduced-Context，只保留报告中与不良反应相关的片段，既省 token 又让模型聚焦。LOTUS 的 join 级联阈值取决于采样到的元组，最坏情况下需要超过 10 万次 LLM 调用。
- **MMQA**：图像 join 是费用和延迟的主要来源；Abacus 在 75% 的运行中选择 EmbeddingJoin，其阈值较保守，因此调用 LLM 更多，质量略高但费用和延迟也略高。

**注意**：Figure 1 的论文检索程序是说明性示例，不是第四个评测数据集。BioDEX 的标签集合是检索对象，金标签只用于评分，两者用途不同。

依据：[arXiv 2505.14661v3](https://arxiv.org/abs/2505.14661v3)，§4.2–4.3、Figures 1、4、5，PDF pp.2、8–10。
