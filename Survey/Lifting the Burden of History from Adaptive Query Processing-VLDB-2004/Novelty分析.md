# 贡献与评价

**论文的贡献**（§1 末、§7，pp.949、958）：
1. 识别 eddy 的根本局限——路由历史的负担：路由决定通过连接状态产生长期影响；
2. 提出 STAIR 算子及 promotion/demotion 原语，允许在执行中修改并迁移状态，撤销过去的路由决定；
3. 证明任意状态操作下结果正确（附录 A）；
4. 在 PostgreSQL 7.3（Telegraph 项目）中实现，并与 SHJ、EddyJoins、SteMs 比较。

**额外用途**（§3.3，pp.953–954）：中途更换环形查询的生成树；数据源延迟时用 promotion 预计算部分结果（推广了只处理初始延迟的 query scrambling）；灵活选择保留哪些中间结果，例如立即降级以把内存降到 SteMs 水平，或在滑动窗口查询中只缓存长寿命中间元组。

**阅读者评价**：
- 优点：用一个具体的因果例子（Fig. 1）说明“能改路由”不等于“能消除旧决策的代价”，并把状态操作做成可证明正确的原语，而不是启发式补丁。
- 优点：实现中 STAIR 同时充当对称哈希连接和 SteM 的实现基础（§4），四种架构在同一代码基上比较。
- 局限：迁移策略是贪心的，发现路由变化就立即迁移、不考虑迁移成本，可能抖动或在查询末尾做无收益的大迁移（§4.2）；实验中 STAIRs 最坏比 EddyJoins 慢 2.25 倍（§5.3）。
- 局限：eddy 只处理单个 SPJ 查询块，聚合、分组、子查询仍交给传统 PostgreSQL 算子（§4）；更换环形查询生成树的细节被略去（§3.3）；正确性证明只覆盖无环查询。
- 局限：路由仍依赖选择率统计与 rank ordering 启发式（§4.1）。
- 与 SemRel 的关系（阅读者分析）：任何在运行时改变执行方案的系统，都要考虑已累积的中间状态能否迁移或复用；仅增加运行时路由不足以说明适应有效。

依据：[VLDB 2004](https://www.vldb.org/conf/2004/RS24P2.PDF)，§1、§3.3、§4、§5.3、§7，pp.948–958。
