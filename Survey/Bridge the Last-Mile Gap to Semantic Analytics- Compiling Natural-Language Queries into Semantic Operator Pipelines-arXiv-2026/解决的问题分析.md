# 解决的问题

**输入**：自然语言问题 q、异构数据上下文 D（表、文本段落、图片的任意组合）、目标后端 B。**输出**：在 B 上可执行的语义算子流水线 P_B，执行后返回 q 的答案（§3.1，p.4）。

**两段式分解**（§3.1）：先做后端无关的中间计划生成 (q, D → I)，再做计划到可执行代码的映射 (I, B → P_B)。

**Phase A：Query-Data Linker**（§3.3，p.5；最多 2 次 LLM 调用）：
- 把问题短语标为三类：matched（作为值出现在某数据源中）、topical（描述数据源主题而不在内容中，如“South Moravian”是表标题）、absent（需从其他数据源解决，如“folk festival”）；有表时只按表打标签；
- 同时找桥接实体：能连接两个数据源、却不在问题中的值；没有具体行被锁定时，把可作 join 键的整列作为桥接实体；
- 可选第二次调用：对照离线生成的数据预览，核查桥接实体是否真的出现在另一数据源中。

**Phase B：Planner**（§3.4，p.5；1 次调用）：输出动作计划，每步是三元组（算子 ∈ {σ, ⋈, γ}、数据源、自然语言谓词），当前实现只支持 `sem_filter`、`sem_join`、`sem_agg`。matched 短语变成带列引用的过滤谓词；topical 短语禁止进入过滤条件，以免过滤掉所有行；桥接实体按基数变成过滤锚点或 join 键。

**Phase C：Code Generator**（§3.5，p.6；1 次调用）：输入动作计划和离线生成的三层参考文档（API 签名、每种问题类型一个可运行的示范流水线、运行约束）。参考文档按（后端，数据集）离线生成一次：数据画像 agent → 参考文档 agent 生成 N 个候选 → critic agent 选最优。

**每题在线代价**（§3.6，p.7）：单源问题 3 次 LLM 调用，组合问题加桥接核查共 4 次；后端执行的 LLM 调用不在范围内。这是单遍编译，不依赖执行反馈或重试循环。

阅读者分析：问题设定假定数据上下文已给定且规模可放进预览/画像，不包含开放式数据发现；“桥接实体”本质上是在编译期先执行一部分查询（表上的排名推断由 LLM 完成）。

依据：[arXiv 2606.04641v1](https://arxiv.org/abs/2606.04641v1)，§3.1–3.6、Figure 1–3，pp.3–7。
