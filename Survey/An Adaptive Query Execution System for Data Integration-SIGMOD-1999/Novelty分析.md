# Novelty分析

实际任务是跨网络自治来源完成关系查询，困难不是只有不知道最优连接顺序：来源可能慢、突发或可替代，错误估计又会影响剩余工作。若计划没有调整入口，系统可能长期等待或持续执行已知不合适的方案。

以下三条归纳作者§8所总结的贡献。

1. **「执行组织」将部分规划、执行和再优化组织成同一闭环。** 关键统计未知时先执行有用片段，再利用实际结果安排余下工作，避免一开始就必须提交完整计划。（§2–3）
2. **「自适应算子」针对网络到达和来源替代设计可调整的执行行为。** 双流水连接尽早产出结果，dynamic collector 按政策启停重叠或镜像来源，减少等待及资源耗尽的影响。（§4）
3. **「代价验证」把物化、重复规划和状态复用的代价放入实验。** 说明闭环收益不仅来自更好的新计划，还依赖降低切换和重新搜索成本。（§6.4–6.5、§8）

## Strong points（我们的判断）

1. **不确定性来自真实数据集成条件。** 来源自治、弱统计与网络波动分别对应具体调整方式，动机和实现紧密相连。（§1–4）
2. **明确允许不完整计划。** 这是“传统数据库必定先完成整个计划”的直接反例；事件规则也不仅改变一个全局算子顺序。（§3）
3. **状态复用有负面证据。** 不带 usage pointers 的状态保存更慢，提醒复用需要计入维护开销。（§6.5）

## Weak points（我们的判断）

1. **全局策略选择仍有限。** 框架能表达多种规则，但没有证明规则组合在未知延迟与误差下总是经济；实验采用具体触发策略。（§3.1–3.3、§6.4）
2. **物化会牺牲流水性。** 片段边界支持可靠再优化，也增加数据保存成本；§6.4的结果不能外推为频繁重规划总有收益。
3. **来源行为实验仍受控。** §6使用 TPC 派生数据与网络配置，不足覆盖真实自治来源长期故障和复杂重叠政策的全部组合。

依据：§1–4；§6.4–6.5；§8。 [原文](https://www.cis.upenn.edu/~zives/research/adaptive_exec.pdf)。
