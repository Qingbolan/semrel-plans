# 贡献与评价

**论文声称的贡献**（§8，p.11）：

1. **执行组织**：自适应能力内建于架构核心，部分规划、执行和再优化组成闭环；关键统计未知时先执行有用片段，再据实际结果安排剩余工作（§2–3）。
2. **自适应算子**：双流水连接尽早产出结果，并给出两种内存溢出处理办法；dynamic collector 按 policy 启停重叠或镜像来源（§4）。
3. **实验验证**：双流水连接优于 hybrid hash join；交替规划执行优于先算完整计划；保存优化器状态加速再优化（§6）。

论文还把 query scrambling、choose nodes、运行时再优化等此前分散的技术纳入同一框架（§8）。

**阅读者评价——优点**：

- 不确定性来自真实数据集成条件，每类不确定性都对应具体机制，动机与实现贴合（阅读者分析）。
- 明确允许不完整计划，是"必须先定好整棵计划"的直接反例；规则也不只改一个全局算子顺序（§3）。
- 给出状态复用的负面证据：不带 usage pointers 时更慢，提醒复用需计入维护开销（§6.5）。

**阅读者评价——不足**：

- 框架能表达多种规则，但没有证明规则组合在未知延迟与误差下总是划算；实验只用了具体触发阈值（如基数偏差 2 倍，§6.4）（阅读者分析）。
- 物化边界支持可靠再优化，但牺牲了流水性；§6.4 的结果不能外推为频繁重规划总有收益（阅读者分析）。
- 实验在 TPC-D 派生数据和受控网络上进行；collector 的 policy 没有单独的实证评测（阅读者分析）。

依据：[原文](https://www.cis.upenn.edu/~zives/research/adaptive_exec.pdf)，§1–4、§6、§8，pp.1–11。
