# 工作负载

**要验证的问题**：在统计弱、来源慢且内存有限时，部分执行后重规划以及可调整的连接算子，能否缩短等待和完成时间（§6，p.8）。

**数据**（§6.1，p.8）：用 dbgen 1.31 生成 10 MB 与 50 MB 的 TPC-D 数据，存于 IBM DB2 UDB 5.20。这是合成的业务基准；查询答案由关系语义确定，没有人工 gold。

**查询**：

| 实验 | 数据 | 查询 |
|---|---|---|
| 双流水连接（§6.2） | 50 MB | 全部两表、三表连接；示例 lineitem ⋈ order ⋈ supplier |
| 广域网（§6.2） | 50 MB | partsupp ⋈ part，四种来源快慢组合 |
| 内存溢出（§6.3） | — | part ⋈ partsupp，需约 48 MB 内存 |
| 交替规划执行（§6.4） | 10 MB | 7 个不含 lineitem 的四表连接 |
| 保存优化器状态（§6.5） | — | 未单独列出查询 |

**环境**：DB2 服务器为双 450 MHz Pentium II、512 MB 内存；执行引擎在 450 MHz Pentium II、256 MB 内存的 NT 工作站上，10 Mbps 以太网。广域网实验把华盛顿大学的 wrapper 数据经法国 INRIA 的 echo server 反弹回来，带宽约 82.1 KB/s，RTT 约 145 ms（§6.1–6.2，p.8）。

**测量方式**：每个查询先跑一次预热，再在测量条件下跑 3 次取平均。§6.4 使用早期 Java 优化器；其余实验用手写计划以便控制（§5–6.1，p.8）。

阅读者分析：广域网实验是真实网络路径上的受控实验，不是独立的异构业务来源（阅读者分析）。

依据：[原文](https://www.cis.upenn.edu/~zives/research/adaptive_exec.pdf)，§5–6，p.8–10。
