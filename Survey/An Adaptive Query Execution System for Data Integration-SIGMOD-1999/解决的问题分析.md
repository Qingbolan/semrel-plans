# 解决的问题

**输入与输出**（§2，p.3）：输入是在 mediated schema 上的 select-project-join 查询、来源目录与 wrappers；目录包含来源语义描述、重叠或镜像关系以及可能不可靠的统计。输出是来自已知来源的查询答案。query reformulation 由独立组件完成，不在执行器范围内。

**可调整的对象**：

| 层次 | 机制 | 位置 |
|---|---|---|
| 规划 | 关键统计缺失时只提交部分计划；片段结束时物化，按实际基数重新优化 | §3，pp.3–5 |
| 规则 | 事件（超时、内存不足、片段完成）触发条件检查，动作可改算子行为、重排或回到优化器 | §3.3，p.5 |
| 连接 | 双流水哈希连接，两侧数据谁先到就先处理；内存溢出时用 Left Flush 或 Symmetric Flush | §4.2–4.3，pp.5–7 |
| 来源 | dynamic collector 按 policy 启停重叠或镜像来源 | §4.1，p.5 |

**正确性与成本**：换镜像不等于可以任意遗漏其他来源，collector 的策略依据来源重叠关系与应用要求（§4.1）。重规划要计入物化成本和优化器状态维护；不带 usage pointers 的保存状态在实验中比从头优化还慢（§6.5，p.10）。

**未覆盖**：目录之外的来源发现与语义映射（阅读者分析）。

依据：[原文](https://www.cis.upenn.edu/~zives/research/adaptive_exec.pdf)，§2–4、§6.4–6.5，pp.3–10。
