# 出发点

**场景**：数据集成系统为大量自治来源提供统一查询接口，例如在多个书目、影评或商品来源上做查询（§1、§4.1，pp.1、5）。作者关注的是中等规模、跨内网与互联网的来源，而不只是返回少量数据的 Web 来源。

**三个不确定性**（Abstract、§1.1，pp.1–2）：

1. 缺少可靠统计：来源自治，基数与直方图常常没有或不准；
2. 数据到达不可预测：常见初始长时间延迟和之后的突发到达；
3. 来源重叠与冗余：慢或不可用的来源可由镜像或重叠来源替代。

**目标变化**：在线查询更看重首批答案的时间，而非系统总工作量（§1.1）。因此一次性优化后照表执行，会等待慢来源或沿用错误的连接选择。

**核心观察**：适应需要在两个层次进行。一是优化器与执行器之间交替规划与执行，二是执行器内部使用能随数据到达和内存变化调整的算子（§1.2，p.2）。这比"在已知算子间重排"更丰富，但仍以目录中给定的语义映射和候选来源为前提。

依据：[原文](https://www.cis.upenn.edu/~zives/research/adaptive_exec.pdf)，Abstract、§1.1–1.2、§4.1，pp.1–2、5。
