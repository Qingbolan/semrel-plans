# 具体用例

**原文示例**（§6.1，p.362）：生成邮寄名单的程序反复执行同一查询——“取最近收入金额超过 `:amount` 的站点，并用城市代码补齐城市名”。

**两种候选计划**：
- 门槛高、命中少：用金额索引取少量站点，再用城市代码索引逐条补齐地址（B-tree 扫描 + 索引嵌套循环连接）。
- 命中多：先把 city 表读入内存哈希表，再顺序扫描 site 文件并探测，每页只读一次（文件扫描 + 哈希连接）。

**动态访问模块的执行**：
1. 访问模块包含两种计划所需的状态记录和支持函数，顶部是一个 choose-plan 算子；
2. 激活时，choose-plan 在 open 阶段读取数据库中的一条控制记录，得到门槛值；
3. 据此选定一个计划，完成该计划状态记录的链接，并对其调用 open；
4. 之后 next/close 直接转给被选中的输入。

**效果**（Table 1）：输出 1 条时索引计划成本 0.429 s，哈希计划 4.563 s；输出全部 13,229 条时分别为 36.257 s 与 10.713 s。在输出 501 条与 752 条之间，两者优劣反转。

阅读者分析：交叉点位置是阅读者从 Table 1 读出的；原文实验中计划是强制指定的，没有给出 choose-plan 按控制记录自动选择时的实测曲线。（阅读者分析）

依据：§6、§6.1、Table 1，pp.362–363。
