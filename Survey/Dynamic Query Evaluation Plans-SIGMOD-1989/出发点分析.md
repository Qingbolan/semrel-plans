# 出发点分析

应用反复执行同一条带变量的数据库查询，例如按不同账单门槛筛选用户并补齐地址。门槛、数据分布与可用内存不同，索引查找和扫描连接的优劣会反转；编译时猜一个典型值可能让大量后续调用持续使用昂贵计划。

关键观察是：不知道实际参数，不等于必须到运行时重新完成整个优化。可以提前准备少量备选组件和选择条件，实际调用时再绑定。本文是“延迟确定部分计划决策”的直接前身，不支持把延迟绑定本身作为语义处理的新贡献。

依据：§1–6（pp.358–363）；§7–8（pp.364–365）。 [原文](https://sigmodrecord.org/?download_id=10724&smd_process_download=1)。
