# 贡献与评价

**论文声称的贡献**（§1–2、§6）：
1. 提出 TAG 作为数据库上自然语言问答的统一范式，涵盖 Text2SQL 与 RAG；
2. 构建首个端到端 TAG 基准：80 个修改后的 BIRD 问题，分别需要世界知识或语义推理；
3. 评测表明标准方法的精确匹配率都不超过 20%，而手写 TAG 管道高出 20–65 个百分点，显示构建高效 TAG 系统的研究机会。

**阅读者评价**：
- 优点：把数据库的精确计算与 LM 的语义处理放进同一个问题定义；基准暴露的失败不只是 SQL 语法错误，而是系统无法表达或执行用户真正需要的计算。
- 优点：手写管道平均 2.94 秒，比其他方法最多快 3.1 倍（相对 Text2SQL + LM 的 9.08 秒），说明批量 LM 推理可以让 TAG 不慢（§4.3）。
- 局限一：手写管道掌握专家的 schema 知识，与自动方法不在同一条件下比较。
- 局限二：总体精确匹配只覆盖 60 个非聚合问题；20 个聚合问题只做了定性分析（Figure 2），定量分析留作未来工作。
- 局限三：每种类型每个子类只有 20 题左右，单题变化就会造成 5 个百分点的差异；只用一个模型（Llama-3.1-70B-Instruct）。
- 局限四：真值由人工标注，精确匹配对排序类问题很苛刻，作者也承认排序题较难（§4.3）。
- 原文内部不一致：§4.1 实验设置写 Llama-3.1 70B，附录 B 写“Llama-3.1 80B”；Llama-3.1 没有 80B 版本，应以 §4.1 为准。
