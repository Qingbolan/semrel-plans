# Workload 分析

**要验证的问题。** 检验逐步生成并执行SQL/Python、查看中间表和投票，能否改善含隐含字段与多步变换的表格问答。

**数据、任务单位与gold。** WikiTQ训练14149、测试4344问答；TabFact使用小测试集1998项真假判断；FeTaQA训练7326、测试2006项自由文本回答，均来自已有表格基准/人工问题。单位为一张给定表与一个问题。WikiTQ用官方答案集合比较，TabFact用二值准确率，FeTaQA用ROUGE-N/L；不是执行代码成功率。

**具体use case：输入目标 → 使用前 → 使用后。** 原文图1：Cyclist列含“Alejandro (ESP)”等值，问前十名哪个国家人数最多。使用前没有独立Country列，直接group by不存在字段会失败；使用后先筛名次，再用Python抽国家，SQL分组计数得到答案。该案例说明数据语义变换，不是外部源发现或论文单例统计。

**Baseline与比较条件。** 需训练基线含Tapex、OmniTab、Lever、TaPas、PASTA、T5；无需训练比较Binder、Dater，另有同模型Codex+CoT消融。主模型Codex；无投票温度0，投票0.6。WikiTQ68.0%对应s-vote；TabFact最佳86.1%仍低于有监督PASTA90.8%，不能宣称所有数据集全面最佳。

**证据边界。** 投票质量与运行代价需一起看；ROUGE不是事实完整性保证。已给定表的不同变换，不证明未知环境必须逐记录探索。
