# Novelty 分析

用户问“前十名中哪个国家的骑手最多”，但国家藏在姓名括号里，不能直接按现成列聚合。一次性SQL或纯语言推理容易遗漏清洗和解释。论文用逐步执行生成中间表，让后续推理面对更明确的数据。

## 作者贡献（用自己的话概括）

1. **「任务求解」**将表格问答拆成可执行的逐步变换，使隐含字段先显式化再统计，降低一次生成复杂程序的困难（§1、§3）。
2. **「工具协同」**按当前子问题选择SQL或Python并观察中间表，兼顾关系计算和复杂字符串处理（§3）。
3. **「答案选择」**研究整链、树探索和执行结果投票，利用不同候选的一致性改善答案，而不把一次生成当作最终结果（§3.4、§4）。

## Strong points（我们的判断）

1. 国家藏在姓名中的例子清楚展示任务语义为何需要数据变换（图1–2）。
2. 三种问答形式及SQL/Python、迭代数、投票消融，能定位组件实际作用（§4）。
3. 区分需训练与无需训练基线，避免把监督成本差异隐藏在单一排行中（表1–3）。

## Weak points（我们的判断）

1. TabFact采用1998项小测试集，不能直接把分数当全量TabFact结果（§4.1）。
2. 投票增加调用，最优策略随底层模型改变；准确率改善不能忽略其延迟成本（§4.3–4.4）。
3. FeTaQA使用ROUGE衡量文本相似，不能完全保证答案事实或推理链正确（§4.1，指标边界判断）。
