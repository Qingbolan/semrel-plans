# 出发点

**现有 agent 在数据科学任务上不可靠**：前人工作（Huang et al., 2023）显示，即使使用 GPT-4，AutoGPT、LangChain 和 ResearchAgent 在数据科学场景的任务完成率也不高。主要原因是 LLM 难以生成合理的实验计划，并且会出现幻觉（§1，p.1）。

**微调代价高**：数据科学任务必须执行代码才能拿到反馈，所以收集微调样本很耗时；对数十亿参数的模型做反向传播也很费算力（§1）。

**可用的外部知识**：Kaggle 有大量获胜队伍的技术报告和高分代码。作者用经典的案例推理（检索、复用、评估、修订、保留）来利用这些经验：通过保留成功案例来“学习”，不更新模型参数（§1–2，pp.1–2）。

**与 RAG 的区别**：RAG 只有“检索 + 生成”，解的分布只对一个检索到的案例求边际。CBR 还会根据评估反馈调整检索到的案例、修订解，并把好解存回案例库（§2，Eq.1–3，pp.2–3）。

**部署需求**：同一分布的分类/回归任务会反复出现。先在开发阶段承担探索成本，之后只需轻微改写成功代码，就能降低对 LLM 能力的要求，也能使用开源模型（§1、§3.2）。

依据：[arXiv 2402.17453v2](https://arxiv.org/abs/2402.17453v2)，§1–2、§3.2，Eq.1–3，PDF pp.1–5。
