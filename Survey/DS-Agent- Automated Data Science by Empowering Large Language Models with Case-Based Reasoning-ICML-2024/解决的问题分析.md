# 解决的问题

**任务形式**：每个任务是一个元组 (τ, D_train, D_valid, D_test, M)，分别是自然语言任务描述、训练集、验证集、测试集和评价指标。agent 要读懂 τ，生成用 D_train 训练模型的代码，在 D_valid 上按 M 评估；论文报告的是模型在 D_test 上的表现（§3，p.3）。每个任务还附一个随机猜测的基线脚本 `train.py`，作为起点（附录 B.1）。

**开发阶段**（§3.1，Figure 3(a)，Algorithm 1）每轮依次执行：
1. Retrieve：按任务描述与案例的嵌入余弦相似度，取 top-k 个人类经验案例；
2. ReviseRank：LLM 根据上一轮的执行反馈，对这 k 个案例按效用重新排序；
3. Reuse：Planner 参考排在第一的案例制定实验计划；
4. Execute：Programmer 写代码并执行，出错时由 Debugger 反思后重写，Logger 总结这一轮的结果；
5. Retain：如果测试集表现提升，就把（任务描述，脚本）存入人类经验库 C 和 agent 案例库 B，然后回到第 2 步。

**部署阶段**（§3.2，Eq.5）：从 agent 案例库 B 中取出描述最相似的一个（任务，代码）对，由 Adapter 直接改写成当前任务的代码。不迭代，也不使用执行反馈。

**两阶段的知识来源不同**：开发阶段用的是 Kaggle 的文本经验，部署阶段用的是已执行成功的 agent 代码。

**评价口径**（§4.1，p.5）：

| 维度 | 开发阶段 | 部署阶段 |
|---|---|---|
| 能否完成 | 成功率：在固定步数内建出模型 | 一次通过率：一次尝试就建出模型 |
| 模型质量 | 按任务指标计算 mean rank、best rank | 同左 |
| 资源 | 每次运行的 API 费用 | 同左 |

依据：[arXiv 2402.17453v2](https://arxiv.org/abs/2402.17453v2)，§3–4.1、Figure 3、Algorithm 1、附录 B.1，PDF pp.3–5、12–13。
