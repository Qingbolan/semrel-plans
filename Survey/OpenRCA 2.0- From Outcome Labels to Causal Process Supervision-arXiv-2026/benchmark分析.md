# 评测与边界

**智能体设置**（§3.1，p.5）：统一采用源自 Deep Research agent 的 ReAct 式工具增强架构；11 个骨干模型共享同一套工具和提示模板，不提供依赖图。

**指标**（§3.2，p.5）：
- 结果层：EM（预测根因集合与真值完全相同）；F1 / Precision / Recall（按“服务, 故障类型”对计算）；AnySvc（至少说对一个根因服务，忽略故障类型，最宽松）。
- 过程层：PR（说对至少一个根因服务，且能从它沿预测图走到一个真值告警节点，最宽松的过程指标）；Node F1、Edge F1（预测图对 G* 精确匹配）；SQL Exec（证据 SQL 能否执行）。
- 无依据诊断 = 满足 AnySvc 但不满足 PR。

**三点发现**（§3.2，p.6）：
1. 结果分低估了失败：从 AnySvc 76.0% 到 Recall 33.2% 的落差主要来自故障类型标错；从 AnySvc 到 PR 61.5% 的 14.5 个百分点是无依据诊断。PR/AnySvc 区分了 F1 相近的模型：Qwen3.6-Max 约 91%，Sonnet 4.6 只有约 66%。
2. 每个模型的 Edge F1 都低于 Node F1，平均差 18.8 个百分点；Gemini 差距最大（67.9 对 36.8）。
3. 各列最大值分散在四个模型上，没有单一骨干全面领先。

**实验 2（按系统，附录 Table 8，pp.28–29）**：以 Opus 4.7 为例，Hotel Reservation 上 AnySvc 99.3%、EM 54.9%，TrainTicket 上降到 75.3% 与 15.6%，OTel Demo 介于两者之间（81.6%、26.3%）。系统间差距大于模型间差距。

**标注可靠性**（§3.4，pp.7–8）：100 个均匀随机实例，两名作者背靠背审核，94/100 一致；6 例分歧都是认为漏了弱支撑路径，没有错误纳入的边。

**边界**：
- 作者承认（§5，p.9）：依赖真实受控干预、足够完整的服务依赖图、有可观察的传播信号、可代表无干预分布的基线，任一不满足时数字应视为上界；规则集可能漏掉词表外机制；结果只适用于测试床范围，向生产环境迁移需另行校准；
- 不适用于（附录 A.5）：认证某个智能体可上线、推广到 service mesh / serverless / 全事件驱动架构、无遥测痕迹的故障；
- 阅读者整理：EM、AnySvc、PR 的判定条件不同，不能当作同一指标的前后变化；池化分数受 TrainTicket（320/500）主导；论文未评测诊断成本或跨实例复用。
