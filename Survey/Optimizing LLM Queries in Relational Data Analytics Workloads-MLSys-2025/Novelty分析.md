# 贡献与评价

**论文声称的贡献**（§1 p.2）：
1. 指出通过重排输入表的行和字段，可以显著加速基于 LLM 的批量数据分析；
2. 提出最优但指数复杂度的 OPHR 和利用函数依赖、表统计量的贪心 GGR，并证明固定字段顺序的命中数最多可差 m 倍；
3. 构建 16 个查询、7 个真实数据集的基准；Llama3-8B/70B 上端到端最多快 3.4 倍，按 OpenAI 和 Anthropic 计价最多省 32%。

**优点（阅读者判断）**：
1. 把数据库里现成的函数依赖、基数和长度统计接到推理缓存上，复用对象具体，而且不改推理引擎，可以直接套在现有分析系统和服务平台上（§3–4）。
2. 同时设置 No Cache 和 Cache (Original) 两个基线，能把“开缓存”和“重排”各自的贡献分开（§6.1.3）。
3. 16 个查询覆盖短输出（filter、聚合）和长输出（projection）任务，展示了收益随 decode 占比增加而缩小的边界（§6.2）。
4. 附录 D.1 在小样本上与 OPHR 对比，GGR 的命中率相差不到 2%，求解时间快几个数量级（Table 6，p.15）。

**不足（阅读者判断）**：
1. 重排可能改变模型输出；准确率只在 5 个 filter 查询（各人工标注 100 行）和 FEVER RAG 上检查（§6.4）。
2. 收益依赖重复前缀多、prefill 占比高；decode 占主导的任务收益明显变小（§6.2）。
3. GGR 是启发式，字段得分持平时可能偏离最优；OPHR 对比只在最多 50 行的子集上做（附录 D.1）。
4. 基线中没有“按某列简单排序”之类的低成本重排方法，无法判断 GGR 相对朴素重排多出多少收益。
5. §6.5 说 GGR 求解时间“不到 LLM 查询时间的 0.01%”，但最长 12.6 s（PDMX），而图 3 的查询时间在数千秒量级，比例应在 0.1%–1% 左右；结论（开销很小）不变，但数字表述偏乐观。
