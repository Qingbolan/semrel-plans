# 解决的问题

**输入**（§3.1 p.3）：一条 LLM 查询中一个 LLM 算子所涉及的表 T（n 行、m 个字段），算子形如 `LLM("Summarize: ", pr.*)`，参数是提示文本加一组字段。字段以 JSON 形式拼进提示（§5 p.6）。

**输出**：一个元组列表 L，既决定行的先后，也允许每一行有不同的字段顺序。每个元组连同用户问题构成一次 LLM 请求。

**目标**（式 (1)(2)，p.3）：最大化前缀命中数 PHC。对每一行，从第一个字段起，与上一行逐格完全相同的连续字段计为命中，命中值为这些字段长度的平方和；平方用来近似注意力计算随长度的二次增长。搜索空间为 n!×(m!)^n。

**两个简化假设**（§3.1）：至少一整行能放进 KV 缓存；只有整格完全相同才算命中，子串不算。

**算法**：
- **OPHR**（§4.1 pp.4–5）：对每个字段的每个不同值 v，把表拆成“含 v 的行去掉该字段”和“其余行”两个子表并递归，取 PHC 最大的拆法。作者用归纳法证明其最优，但复杂度指数级，10 行的表就要几分钟（§6.1.3 p.7）。
- **GGR**（Algorithm 1，§4.2 p.5）：每层只选命中贡献最大的那个值 v 拆分，递归深度 O(min(n, m))，但每层扫描求不同值，整体对表大小可能是二次复杂度。
- **函数依赖**（§4.2.1 p.6）：选中字段 f 后，与 f 有函数依赖的字段直接紧跟其后，不再参与后续搜索。
- **表统计量与提前停止**（§4.2.2 p.6）：按行/列递归深度或命中阈值停止，之后用基于平均长度的统计分数给子表定一个固定字段顺序。实验用行深度 4、列深度 2 或阈值 0.1M（§6.5 p.10）。
- **何时达到最优**（§4.2.3 p.6）：单行或单列时与 OPHR 相同；函数依赖准确且覆盖所有字段时也能达到最优；字段得分持平时可能次优。

**边界**：共享的是相同 token 前缀的 KV 状态，不是不同行之间的答案；每行仍各自调用一次 LLM。重排改变了提示内容，模型输出可能随之变化，论文只在部分查询上检查了准确率（§6.4）。
