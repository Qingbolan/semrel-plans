# 具体用例

**原文示例**（Figure 1，§2，pp.589–590）：

```sql
SELECT nodeId, temp ± .1°C, conf(.95)
WHERE nodeID in {1..8}
```

用户要节点 1–8 的温度估计，误差 0.1°C 以内、置信度 95%。

**执行过程**：
1. 查询处理器把查询翻译为模型上的概率计算，发现仅凭模型达不到要求的置信度；
2. 规划器认为最省的做法是读节点 1、2 的电池电压和节点 4 的温度，即观测计划 `{[voltage,1], [voltage,2], [temp,4]}`；
3. 结合拓扑生成按此顺序采集的路径，下发网络，收回读数；
4. 用读数更新模型，再返回带置信度的结果，如“1, 22.3, 97%；2, 25.6, 99%；……”。

用户问的是温度，模型却选择读电压，因为电压与温度高度相关，而读电压的能耗比读温度低数个数量级（§2，Figure 2、Table 1）。

**规模化的表现**（§5.5，Figure 5）：Garden 值查询中，ε 小于 0.1 度时每次都要观测所有节点；ε 达到 1 度或更大时只需很少观测；中间值时，观测集中在清晨和傍晚温度变化快的时段。
