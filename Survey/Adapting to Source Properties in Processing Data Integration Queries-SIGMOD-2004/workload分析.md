# Workload分析

**验证的问题。** 运行中发现统计错误、数据有序或预聚合机会后，能否切换计划并复用状态，同时补齐跨分区结果。

**数据与任务。** 100MB TPC-H(scale 0.1)及同规模Zipf=0.5的TPC-D派生偏斜数据，均为合成基准。纠错查询为3A、10、10A、5；3A/10A删除原查询日期过滤以增加难度，含3–5表连接。至少4次运行及95%置信区间。无人工gold，目标是完整关系答案；指标含运行时间、stitch-up时间、复用/丢弃元组数。

**最清楚的use case（原文§4.4）。** 输入customer/nation/supplier等TPC数据、连接聚合查询及缺失或错误基数→输出同一聚合答案。先选的连接产生昂贵中间结果；ADP在执行中改计划，复用已有状态，stitch-up补齐旧新区段组合。收益见图2、表1，不将其解释成发现新的查询谓词。

**Baseline与公平性。** `Static`、`Adaptive`、`Plan Partitioning`，分别有 `No Statistics` 与 `Cardinalities`配置。No Statistics统一假定每表20,000条；Cardinalities获得来源基数，须在相同信息配置内比较。Plan Partitioning固定三次连接后物化，不等于最佳自适应分段策略。纠错实验内存足够并允许hash表内存扩张，用于隔离CPU而非磁盘I/O。

**依据与边界。** §3.5、§4.4、图2/表1；§5与§6分别测试有序数据和预聚合。来源异构是系统背景，主要实证并非真实异构数据湖；stitch-up有显著成本，不能当成免费共享。
