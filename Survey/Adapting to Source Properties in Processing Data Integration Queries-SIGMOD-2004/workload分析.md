# 工作负载

**数据**（§3.5，p.6）：没有通用的数据集成基准，作者用 TPC-H scale 0.1（100MB），另用微软研究院提供的 TPC-D 生成器造了同规模、主要属性 Zipf z=0.5 的偏斜数据集。两者都是合成数据，以主外键连接为主。

**查询**（§4.4，pp.7–8）：取符合 SPJ+聚合模型的 TPC-H Q3、Q10、Q5。Q3 只需约 3 秒，作者删去其日期选择谓词得到 Q3A；同样从 Q10 得到 Q10A。最终是 3 表连接（Q3A）、两个 4 表连接（Q10、Q10A）和 5 表连接（Q5）。

**运行环境**：3.06GHz Pentium IV、Windows XP、1GB 内存（200MB 缓冲池）；只允许顺序读取输入关系；关闭查询输出；每个实验至少运行 4 次并给出 95% 置信区间（§3.5）。纠错实验全部在内存中运行，并允许哈希表动态扩容，以隔离 CPU 代价（§4.4）。

**信息条件**：No Statistics（优化器假定每个关系 20,000 元组，约为 TPC 数据的中位数）与 Cardinalities（给出来源基数）两种（§4.4，p.8）。

**其他负载**：§4.5 用 ORDERS 与 10 万行 Zipf 表再与 LINEITEM 连接测试可预测性；§5 只测 LINEITEM ⋈ ORDERS 单个连接，并随机交换 1%、10%、50% 的元组制造“基本有序”数据。

阅读者分析：负载规模小（100MB）、单机执行，“远程来源”只在 §4.4 的 802.11b 无线网络实验中真实出现；结论适用于主外键连接为主的关系查询，不能直接推广到语义谓词或非关系来源（阅读者分析）。

依据：§3.5、§4.4–4.5、§5，PDF pp.6–10。
