# Workload 分析

**要验证的问题。** 检验并行学习多条执行经验时，能否比简单扩大batch更快、且保留后续任务成功率；对象是提示学习过程。

**数据、任务单位与gold。** AppWorld为多步API任务，训练90项、Test-Normal留出，指标TGC/SGC；Terminal-Bench2.0使用60条已发布训练轨迹及29项留出任务，三次Accuracy@1；FiNER是财报实体类型，Formula是财报数值推理。它们是基准任务和轨迹，不是生产流量调查。还记录学习耗时、费用和playbook大小。

**具体use case：输入目标 → 使用前 → 使用后。** 用AppWorld任务批学习作说明性重述：输入多条API执行反思，目标让后续任务少犯已知错误。使用前把40条更新一次合并会丢失具体建议；使用后分组聚合、打乱重复反思并调节batch，以保留有用经验。表1是聚合实验，不代表某个具体API任务已获得相同幅度改善。

**Baseline与比较条件。** 比较ACE、GEPA的低/固定batch、普通并行版本与Combee，控制基础学习框架并做scan/shuffle/batch消融；不同任务和模型的结果不能混成一项。最高17倍是Terminal-Bench设置的学习耗时改善，并非Agent业务执行速度；正文另报告学习费用与后续质量。

**证据边界。** 没有证明新任务可直接复用历史业务事实；收益也不能自动抵消每次把更长playbook送入模型的所有部署成本。
