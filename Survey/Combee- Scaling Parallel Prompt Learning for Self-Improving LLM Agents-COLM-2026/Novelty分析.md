# 贡献与评价

**论文声称的贡献**（§1，p.2）：
1. 指出提示学习扩展到高并行时的问题与已有方法的失败（context overload）；
2. 设计 Combee：并行扫描聚合、增广打乱、动态批量控制器；
3. 在 ACE 与 GEPA 上实现，作者预期能推广到其他“生成—反思—更新”框架；
4. 在四个基准上评测，同等成本下最高 17× 加速，保留大部分或全部顺序学习质量。

**阅读者评价——优点**：
- 问题诊断有量化证据：条目数、有用命中数、准确率随批量单调下降（§2.2、Figure 2）。
- 同时在 ACE 与 GEPA、DeepSeek-V3.1 与 GPT-OSS 120B 上验证，降低了结论只依赖一种实现的风险（§4、附录 F）。
- 消融较完整：复制份数 p、小组大小、动态批量、与分层摘要的对比，以及用 LLM 评委把“聚合质量”与“playbook 变长”分开（表 3、表 8–9、附录 G）。
- 报告了分阶段成本：Terminal-Bench 上只多 12 次 LLM 调用、约 $0.04 整理成本（附录 H，表 12）。

**阅读者评价——不足**：
- 聚合仍由 LLM 生成，没有信息保留保证；作者在附录 B 承认稀有信号、相互矛盾或强相互依赖的反思仍可能丢失。
- 规模有限：AppWorld 训练 90 题、Terminal-Bench 89 题；作者承认“每天数千条轨迹”的场景未测（附录 B）。
- 阈值 τ 固定、每个候选批量只试跑一次，未做敏感性分析（§3.3、附录 B）。
- 主要结果多为单次运行；只有 GEPA 金融基准补了三次重复（附录 E，表 4–5）。
- 正文与附录有几处数字不一致，见“评测与边界”页末尾。

阅读者分析：对本项目而言，它是“经验构建成本”的近邻工作；不能把改进提示后的准确率提高解释为事实证据复用。

依据：§1–4、表 1–3，PDF pp.2–10；附录 B、E–H，pp.15–20。
