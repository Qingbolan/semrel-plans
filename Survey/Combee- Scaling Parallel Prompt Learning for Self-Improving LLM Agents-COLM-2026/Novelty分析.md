# Novelty 分析

大批 Agent 轨迹能提供经验，但串行更新慢，直接扩大一次更新的输入又会损失细节，削弱随后任务的成功率。Combee 解决的是经验学习的质量与等待时间矛盾，使并行执行产生的经验能更快用于下一轮任务。

## 作者贡献：用自己的话概括

1. **「问题诊断」识别并行提示学习中的信息丢失。** 大批反思即使放得进上下文，也可能被压缩成泛化建议，丢失对任务有用的具体经验（§2）。
2. **「并行学习方法」将经验分批聚合并给予不同组合的保留机会。** 分层扫描与复制打乱控制每次更新负担，减少单次聚合和不利分组造成的遗失（§3.1–3.2）。
3. **「效率调节与验证」随学习收益选择并行批量。** 在两种学习框架和四类任务上比较质量、学习时间与成本，而非只扩大并发数（§3.3、§4）。

## Strong points（我们的判断）

1. 把复用经验的构建成本本身列为问题，补全只讨论调用记忆的效率视角（§2–3）。
2. 在 ACE 与 GEPA 上共同验证，降低结论仅依赖一种经验表示实现的风险（§4）。
3. 报告费用、延迟、最终质量，并对聚合和复制量做消融，有助于解释收益来源（§4、表1–3）。

## Weak points（我们的判断）

1. 聚合仍是模型生成，信息保留没有完备保证；复制量继续增加也可能退化，最优设置依赖任务（§4.4、表3）。
2. 延迟控制依赖拟合模型与阈值，默认阈值在实验固定；异质工具时延下是否仍合适需验证（§3.3及脚注1）。
3. Terminal-Bench 留出仅29项，最高加速比应限于该设置，不能推广为所有长链 Agent 的稳定收益（§4.1–4.2）。

对本项目：可作为经验构建成本的近邻；不能把改进提示后的准确率提高解释为已经实现事实证据复用。
