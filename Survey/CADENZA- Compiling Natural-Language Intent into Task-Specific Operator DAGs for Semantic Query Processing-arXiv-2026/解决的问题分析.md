# 解决的问题分析

来源：[CADENZA v3](2606.29151v3.pdf)，§2–6、§7.1–7.2。

- **输入**：语义算子实例（模板、自然语言 intent、输入关系及 I/O schema）、算子与后端目录、质量/延迟/成本偏好，以及验证样本；缺少标签时由 teacher model 生成代理标签。
- **输出**：预算内搜索得到的可执行物理计划，包含 typed task DAG、各任务的后端路由及调优参数；不是全局最优性的保证。
- **核心困难**：自然语言不直接确定 DAG；不同记录适合不同后端；候选计划评估需要真实推理，搜索本身昂贵。
- **解决路径**：LLM 生成并修复 seed plans → 依赖检查的结构重写与语义候选扩展 → 为任务构建 router → Bayesian optimization 联合调路由、后端参数及关系阈值。

## 范围与边界

1. 核心优化单位是**单个 semantic operator instance**。论文明确将跨语义算子的联合优化置于范围之外；多算子查询通过组合局部优化结果执行（§1）。
2. 已有逐记录后端路由、composite/RAG 后端和运行时失败恢复，不能概括为完全静态执行。论文没有将根据中间观察发现新数据源、扩展证据集合并修改后续逻辑计划作为核心优化问题（§5、§6.3；后半句为范围判断）。
3. 已支持 DataFrame 批量推理和按 intent signature 缓存物理计划，缓存受 data profile 约束；这些不是开放式探索轨迹或证据共享的实验验证（§6.1–6.2）。
4. 语义候选不默认保持等价，依赖验证/teacher 信号选择。附录 G 的标签噪声实验仅针对一个 E-Commerce join，不能推出普遍鲁棒性。

## 实验证据及口径

SemBench 五个场景共 55 个查询。默认使用 50 个验证样本、3 次 seed synthesis 尝试和 20 次 BO trials；主实验关闭计划缓存，小输入可绕过优化（§7.1）。表 3 相对 LOTUS 汇总为质量 +0.10、延迟 3.80×、成本 4.88×；不支持或失败的基线查询被排除。§7.2 的部分超时结果由小规模运行外推，因此不应把摘要的最大收益当作所有查询或相同质量条件下的收益。
