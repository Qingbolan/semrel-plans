# 评测与边界

**基线**（§7.1.5，pp.10–11）：LOTUS v1.1.4（GPT-4.1-mini 为 oracle，GPT-4.1-nano 或嵌入为代理）；Palimpzest v1.1.1 + Abacus（MaxQualityAtFixedCost，$10 约束）；ThalamusDB v0.1.15（误差设 0、去掉 token 上限）；DocETL v0.2.6（只支持文本）；作者扩展的 AFlow（20 次 MCTS）和 DyFlow。AOP、CAESURA、Unify 因要求自然语言输入被排除。

**环境与口径**（§7.1，pp.9–10）：2×RTX 3090、64 核 Xeon、512 GB 内存；LLM 经 Azure，费用 = API 费用 + 本地 GPU 按 $0.71/小时估算；温度 0，并发 20。默认 GPT-4.1 规划，绕过优化时用 GPT-4.1-mini（音频用 gpt-audio-mini）。所有用验证集的系统都不用人工标签，而用 oracle LLM 打标签；最终质量另对 ground truth 评估。每个实验重复 3 次取几何均值。

**实验 1（端到端，Table 3，p.10）**：Q 为 CADENZA 减基线的算术均值，L/C 为基线/CADENZA 的几何均值，只算该基线能完成的查询。

| 对比系统 | ΔQ | 延迟 × | 费用 × |
|---|---|---|---|
| LOTUS | +0.10 | 3.80× | 4.88× |
| Palimpzest | +0.11 | 4.42× | 21.83× |
| ThalamusDB | +0.28 | 4.33× | 1.51× |
| DocETL | +0.08 | 13.19× | 8.62× |
| Extended AFlow | +0.26 | 1.40× | 1.96× |
| Extended DyFlow | +0.21 | 1.07× | 1.40× |

摘要中的 +0.49、165.7×、310.3× 是各场景里最好的单项（MMQA 对 ThalamusDB、E-Commerce 对 DocETL），不能当总体。

**实验 2（逐场景，附录 B，Tables 7–12，pp.16–17）**：CADENZA 并非处处占优。Cars 上它比 LOTUS 慢且贵（3,467 s/$1.63 对 2,402 s/$1.23），费用也高于 ThalamusDB（$2.66 对 $1.93）；Wildlife 上比 ThalamusDB 慢（326 s 对 154 s）。BioDEX 上质量 RP@5 = 0.31 最高，但 AFlow/DyFlow 只花 $0.43/$0.72，CADENZA 为 $4.62。

**实验 3（优化开销，Table 4，p.10）**：

|---|---|---|---|---|

**其他实验**：
- 权重敏感性（Table 5）：质量优先 Q 0.78、$4.82；效率优先 Q 0.41、$0.08；默认 Q 0.65、$0.30；
- BO 次数（Figure 5）：10 次即可找到低延迟计划，20 次后主要增加调参费用；
- 与预设单一计划的 Coarse 对比（附录 C，Tables 13–17）：每个场景、每种偏好下三项全部占优；
- 统一效用扫权重（附录 D，Figure 7、Table 18）：5 组权重下 CADENZA 的平均效用都最高或并列最高；
- 约束优化（附录 H，Table 20）：预算收紧到 0.1 倍时 Q 从 0.544 降到 0.228。

**边界**：
- 原文承认：只优化单个算子；分布漂移需定期重优化；BO 预算如何随意图和参数空间设定留待未来工作（§1、§6.2、§7.3.2）。
- 阅读者整理：验证标签来自 teacher 而非人工；标签噪声只在一个二元 E-Commerce 连接上测了 10%/20% 翻转，且只看选中计划是否变化（附录 G）；部分 E-Commerce 结果由 SF500 外推；基线均值只在各自能完成的查询上计算，不同行的分母不同；AFlow/DyFlow 为作者改造版本；敏感性与消融只在 Movie 上做。
