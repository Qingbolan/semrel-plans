# 贡献与评价

**论文声称的贡献**（§1，pp.2–3）：
1. CADENZA：SQPE 级优化器，把语义算子实例编译成 TxRA 计划，并按质量/延迟/费用偏好选可执行计划；
2. TxRA：在关系代数上加任务算子，让语义处理能作为算子 DAG 表达和优化；
3. 逻辑规划器：合成种子计划、做依赖检查的结构重写、用模板生成语义替代；
4. 物理规划器：数据感知 router + 四族实现，并用 BO 联合调参；
5. 在 SemBench 上相对现有系统的场景级平均最多 +0.49 质量、165.7×/310.3× 延迟/费用改进。

**核心新意**：把一个语义算子内部的任务结果当作关系优化对象，同时联动结构选择、逐行实现路由和连续参数调优。作者明确说路由本身不是孤立的新技术，贡献在于把它挂到每个任务算子上并与后端、关系参数一起调（§1，p.2）。

**与已有系统的区别**（§8，p.13）：

| 系统 | 优化对象 | CADENZA 的差别 |
|---|---|---|
| LOTUS | 用代理模型逼近参考 LLM 算法 | 不只调级联阈值，还改写算子内部结构 |
| Palimpzest/Abacus | 固定结构下搜索变换与实现 | 每个语义算子不再只绑定一个逻辑算子 |
| DocETL | 管道级重写（map/filter/reduce 等） | 中间任务输出成为可过滤、可路由的关系属性 |
| AOP、Unify | 预注册通用与符号后端 | 按意图合成实现与 router |

**为什么不用 DP**（§1，p.2）：合成计划开放、中间输出可能在下游被纠正（如 OCR 噪声），不满足最优子结构，提前剪枝可能丢掉最终赢家；因此整计划在样本上执行评估，而非逐子计划估代价。

**阅读者评价**：
- 消融（Table 6）支持“物理层决定实现哪种折中”：去掉 BO 质量从 0.71 降到 0.62、费用从 $3.0 升到 $7.9；去掉 router 费用升到 $16.6。只用通用 LLM 后端可达 0.65，但费用是完整系统的约 8 倍。
- 只做单算子优化；作者声称多算子查询上组合局部最优已“抓住大部分收益”，但没有与跨算子联合优化做对照（§1）。
- §6.2 缓存的是按意图签名和数据画像对应的物理计划，不是跨查询共享中间数据或答案；分布漂移仍需重新采样调参。
- 语义替代只靠 50 条 teacher 标注样本经验排序，不提供一般语义正确性保证。

**评测口径需保留的条件**（§7.1–7.2，pp.9–11）：24 小时超时；部分 E-Commerce 结果用 SF500 运行后按基数外推；每个基线的均值只在它能执行的查询交集上计算；ThalamusDB 设误差 0、去掉 token 上限；Palimpzest 在连接密集查询上关闭 Abacus；AFlow/DyFlow 是作者扩展版。

**原文内部不一致**（阅读者分析）：
- Cars Q3：§7.2 写“manual transmission, damaged in images”，附录 J.4 写“image shows the car is not damaged”。
- Wildlife Q8：§7.1.1 把它列为音频过滤，附录 J.2 中是图像或音频的联合查询。
- §7.2 的场景倍数（如 E-Commerce 对 DocETL 165.7×/310.3×）无法由附录 Table 11 的单元格直接相除得到（3,803/85 ≈ 44.7×，0.55/0.17 ≈ 3.2×）；可能是逐查询比值的几何均值，原文未说明附录表的聚合方式。
