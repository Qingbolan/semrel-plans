# Novelty 分析

## 问题定义与重要性

语义数据处理已经能用自然语言指定筛选、抽取和匹配任务，但“能表达任务”不等于“能以合适的成本处理整张表”。例如，识别商品包装中的敏感声明，既可以直接询问视觉 LLM，也可以先提取文字再判断；对所有图片都使用同一种昂贵处理方式，会浪费简单记录上的推理成本，而一律换用便宜方法又可能漏掉困难记录。

CADENZA 的重要观察是：**同一语义目标存在不同的计算路径，而且每条路径中的不同任务、不同记录需要的处理能力不同。** 因而需要解决的不是单纯选一个更便宜的模型，而是联合决定如何完成任务、在哪里减少不必要处理，以及哪些记录值得投入更强的推理。这决定了语义查询能否从逐条调用模型，变成可以经济地处理大量数据的系统能力。

## 作者贡献（用自己的话归纳为三条）

1. **「优化对象」让语义算子内部的工作也能被数据库优化。** 针对图片声明识别等任务，把提取出的文字、回答和置信度变成可操作的中间数据，使系统能够在任务内部过滤、重排和选择实现，减少把整个任务交给一次昂贵模型调用的限制。
2. **「求解路径」为同一自然语言目标寻找不同的完成方式。** 因为视觉问答与 OCR 后文本判断的成本和信息损失不同，系统生成并评估多种任务分解，同时区分等价重写与近似替代，解决“用户只说明要什么、没有指定怎样做得划算”的问题。
3. **「成本分配」把更强的处理能力留给真正需要的记录和步骤。** 利用输入难度差异，联合选择各子任务的后端与筛选阈值，在有限优化预算下平衡质量、延迟和成本，避免所有记录支付同样的高推理代价。

来源：[论文原文](2606.29151v3.pdf)，§1、§3–5。以上归纳作者对已有语义处理任务的贡献。

## 对本项目问题定义的支持

CADENZA 支持的是：**语义处理正在从固定模型调用走向按 intent 生成并优化任务计划。** 更准确地说，本文主要优化单个语义算子实例，而非整个查询的联合计划。

本项目要进一步研究的是：当完成目标所需的数据尚未确定，下一步处理什么取决于当前记录和刚获得的证据时，如何组织高效执行。例如，从包装中识别出声明后，还需按型号寻找证书；证书的覆盖范围又决定是否继续查询批次或更新记录。此时，昂贵的不只是既定任务的推理，还有发现相关数据、判断证据是否足够以及决定后续步骤。

**为什么重要：** 预先扫描全部异构数据可能浪费大量工作，过早固定输入又可能漏掉必要证据；逐记录独立探索虽能适应差异，却可能反复查找同一证书、解析同一文档。研究问题因此落在：如何保留这种按需探索，同时识别可以批量处理和复用的工作。该场景与成本判断是本项目待验证的动机，不能仅由 CADENZA 推出 Data Agent 的性能结论。

## Strong points（我们的判断）

1. **抓住了具体的优化机会。** 包装声明识别展示了“同一目标、不同计算路径”的实际价值，把为何要打开语义算子讲清楚，而不只展示更复杂的计划结构（§1、图 2）。
2. **明确区分等价与近似。** OCR 转换、文本切分可能丢失信息，论文没有把这些替代强称为等价重写，而是用验证信号评估质量，符合语义处理的不确定性（§3–4）。
3. **消融支持执行策略的价值。** 去掉逐记录 router 后，成本从 $3.0 升至 $16.6、质量从 0.71 降至 0.63，支持按记录分配处理能力的收益；该汇总包含 SemBench 与 BioDEX，排除 bypass 查询（§7.4，表 6）。

## Weak points（我们的判断）

1. **候选选择对验证信号的可靠性仍缺充分证据。** 非等价方案依赖少量样本和 teacher 标签筛选，而标签噪声实验只覆盖一个 E-Commerce join；难以据此判断长尾记录或系统性 teacher 偏差下是否仍能选对计划（§7.1.6、附录 G）。
2. **局部优化没有解决跨算子的取舍。** 论文按单个语义算子实例优化，未联合考虑上游误差、输出规模对下游质量与成本的影响；多算子查询的收益不等于证明局部最优组合足够好（§1、§7.2）。
3. **部分实验口径限制了收益的解释。** 汇总排除基线不支持或失败的查询，部分超时结果由小规模运行外推，且 join-heavy 查询中有关闭 Abacus 的设置；因此最大加速比不能直接代表所有查询或完整基线配置下的收益（§7.1–7.2，表 3）。
