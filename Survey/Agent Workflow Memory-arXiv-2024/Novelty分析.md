# 贡献与评价

**论文声称的贡献**（§1，pp.1–2）：
1. 提出 AWM：从智能体轨迹中归纳可复用的工作流并写入记忆，可离线也可在线（无监督）运行；
2. 在线模式下工作流会“滚雪球”：先学到简单工作流，再以其为子目标构建更复杂的工作流（Figure 1、Figure 6）；
3. 在 WebArena 和 Mind2Web 上取得当时最好的公开结果，并在跨模板、跨网站、跨领域设置上检验泛化。

**机制要点**：

| 组件 | 细节 |
|---|---|
| LM 归纳 | 同一提示用于两个基准：找出多任务间重复的动作子集，每个工作流至少两步，非固定元素用变量名表示（附录 A.1，p.14） |
| 规则归纳（对照） | 按动作序列去重，WebArena 上再按任务模板去重，并删除参数不合法的 CLICK/TYPE 步（§4.1、附录 B，pp.8、16） |
| 按网站分组 | 两个基准都按网站分组分别运行 AWM，使记忆中的工作流与测试任务相关（§3，p.4） |
| 作为动作（AWM_AS） | 把工作流包装成可调用的高层函数；智能体只在 18.5% 的任务里调用它们（§5，pp.9–10） |

**阅读者评价**：
- 从经验中抽取子程序/技能并非新思路（论文 §6 引用 DreamCoder、Voyager、TroVE 等）；新意在于把它做成网页智能体的上下文记忆，并给出不需标注的在线版本。
- 与 Synapse（检索整条相似样例）对比，AWM 元素准确率 +5.0、步骤成功率 +4.0（Table 3），是“抽象子过程优于具体样例”的直接证据；规则归纳与 LM 归纳在 WebArena 上只差 0.1（Table 5），说明主要收益来自“有工作流记忆”本身，而非 LM 归纳的精细程度。
- 任务级成功率的提升并不稳定：Mind2Web cross-website 上 AWM_online 为 1.6，低于 MindAct 的 2.0；cross-domain 上 AWM_offline 为 0.7，低于 1.0（Table 4）。摘要强调的是步骤成功率。
- 记忆不是越多越好：离线+在线合并的结果介于两者之间，cross-task 任务成功率从 4.8/4.0 降到 1.6（附录 C，Table 11）；状态描述同时加 HTML 也变差（Table 8）。长期积累需要选择机制。
- 在线入库依赖 LM 评估器判成功，误判会把错误轨迹变成工作流（作者在 §3.2.2 承认）；论文没有量化这一影响，也没有核算归纳、评估和携带记忆带来的 token 成本。

**原文内部不一致**（阅读者分析）：
- 相对 SteP 的提升，§1 写 7.9%，§3.1.1 写 7.6%；按 Table 1（35.5 vs 33.0）算为 7.6%。
- §3.1.1 称各网站比 BrowserGym 高 11.8–30.7 分；按 Table 1 与 BrowserGym_ax-tree 逐项相减为 12.8–30.7。
- §5 称 AWM_AS 与 AWM “总体成功率相同，3.2”，但 Table 9 为 3.6 对 4.8。
- §3.1.3 称跨模板子集上 AWM “在每个网站都最高”，但 Table 2 中 Shopping 为 24.5，低于 SteP 的 26.5（只在自主方法中最高）。

阅读者分析（与本项目的关系）：AWM 是“操作经验复用”的基线，复用的是怎么做，不是事实答案；也不说明路径无法预先写成条件程序。

依据：[arXiv 2409.07429v1](https://arxiv.org/abs/2409.07429v1)，§1、§3–6、Tables 1–11、附录 A–C，PDF pp.1–16。
