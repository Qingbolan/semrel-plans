# 工作负载

**要验证的问题**：从旧轨迹抽取的子过程能否改善后续网页任务；这种收益在跨任务模板、跨网站、跨领域时能否保留（§3，p.4）。

**数据集**：

| 基准 | 规模与内容 | 评测方式 | 用到的设置 |
|---|---|---|---|
| WebArena | 812 个任务，5 个可交互网站（Shopping、CMS、Reddit、GitLab、Maps），覆盖电商、论坛、协作开发、内容管理 | 执行后检查功能正确性 → 任务成功率 | 只有测试集，因此只跑在线模式（§3.1，pp.4–5） |
| WebArena 跨模板子集 | 每个任务模板随机取一例：Shopping 51、CMS 45、Reddit 24、GitLab 45、Maps 32 | 同上 | 排除“同模板重放”带来的收益（§3.1.3，Table 2，p.6） |
| Mind2Web | 带人工动作标注的真实网站任务，分 cross-task、cross-website、cross-domain 三个测试划分；训练集只覆盖部分测试网站（cross-task） | 每步元素准确率、动作 F1、步骤成功率；全部步骤正确才算任务成功 | 离线与在线都跑（§3.2，p.6） |

摘要称两个基准合计“1000+ 任务、200+ 领域”；正文未给 Mind2Web 各划分的任务数。

**任务单位**：一个自然语言指令 + 一个网站环境；在线模式下，同一网站的测试任务按流顺序处理，记忆随之增长（§3，p.4）。

**模型**：WebArena 用 gpt-4-0613，温度 0；Mind2Web 同时用 gpt-3.5-turbo 和 gpt-4，归纳与动作生成用同一模型（§3.1–3.2，pp.5、7）。网页表示用 accessibility tree；Mind2Web 沿用 MindAct/Synapse 的元素过滤。

阅读者分析：任务由人构建，网站是仿真或真实快照，不含生产日志；Mind2Web 的步骤级评测是在固定参考轨迹上逐步打分，智能体偏离参考路径即判错，与 WebArena 的执行评测不可直接比较。具体用例见“具体用例”，基线与结果见“评测与边界”。

依据：[arXiv 2409.07429v1](https://arxiv.org/abs/2409.07429v1)，摘要、§3、Table 2，PDF pp.1、4–7。
