# 工作负载

**数据集**（Table 2、§3.2，pp.5–6）：

| 数据集 | 属性数 | 文件数 | token 最大 / 最小 / 平均 | 多模态 | 来源与内容 |
|---|---:|---:|---|---|---|
| WikiArt | 19 | 1,000 | 1,665 / 619 / 789 | 是 | WikiArt.org，19–21 世纪艺术家传记及作品图片 |
| NBA | 28 | 225 | 51,378 / 73 / 8,047 | 否 | Wikipedia，分为球员、球队、经理、城市 4 类文档 |
| Legal（表中记作 LCR） | 19 | 566 | 45,437 / 340 / 5,609 | 否 | AustLII，2006–2009 年澳大利亚判例（正文说 570 个） |
| Finance | 30 | 100 | 838,418 / 7,162 / 130,633 | 是 | Enterprise RAG Challenge，100 家上市公司 2022 年的年报和季报 |
| Healthcare | 51 | 100,000 | 63,234 / 2,759 / 10,649 | 否 | MMedC，从 68 万篇中抽样；疾病、药物、机构三类共 6,100 篇 |

**复杂度**：
- WikiArt 和 NBA 篇幅短、结构清晰；
- Legal 的属性需要语义推断，例如 `first_judge`（是否为一审判决）；
- Finance 单篇最长约 100 页；
- Healthcare 文档最多，并混有广告、政策等其他类别。

只有 Healthcare 和 NBA 包含多类文档，因此支持 join（§3.2）。

**预处理与输入**：PDF 等复杂格式用 MinerU 解析，每个数据集整理成一个 JSON 文件，每个对象是一篇文档（text、image URL、metadata）（§3.2）。属性描述和 schema 属于查询规范；gold 关系表属于评测环境，不能作为被测系统的输入。

**环境与模型**（§4.1，p.8）：
- 硬件：Ubuntu，4 颗 Xeon Gold 6148（共 80 核）、2 张 RTX 4090、1 TB 内存、6 TB SSD，Python 3.7；
- 模型：默认 LLM 为 GPT-4.1-mini，默认嵌入模型为 Qwen3-Embedding-0.6B。

阅读者分析：
- §4.6 的并发实验是 1/2/4/8 个线程，不是在每个提示中放 1/2/4/8 篇文档；
- §4.7 中块长上限 512、下限 128 token 是分块参数，也不是批大小；
- 正文没有统一的提示内批处理约定，不能用文件总数代替批大小。

依据：[arXiv 2510.27119v1](https://arxiv.org/abs/2510.27119v1)，§3.2、§4.1、§4.6–4.7、Table 2，PDF pp.5–8、11–12。
