# 评测与边界

**评测**：论文没有基线、指标或定量实验。可以视为功能验证的只有示例输出：

- **示例 1（§2.1）**：连字符词"Self-isolation"被切成 `Self`、`-`、`isolation` 三个 basedata；正则 `\S-\S` 命中 `word_0`–`word_2`；`\d` 的输出中 `word_4` 出现两次，推断是"14"中的两个数字各匹配一次，这与原文"每个正则恰好一次匹配"的说法不完全一致（阅读者分析）。
- **示例 2（§2.2）**：ACL Anthology 语料文档加载成功；修改标注方案后报告 58 个校验异常。示例异常说明，因为 `np_form` 的值无效，依赖它的 `coref_class` 也被视为额外属性。
- **示例 3（§2.3）**：LitCovid 文档转换后可重新加载，并得到正确的默认值。

**与其他工具的比较**：只有定性讨论（§1）——转换器适合常见格式之间的转换；brat、WebAnno、INCEpTION 适合多人分布式标注；MMAX2 更轻量、自包含。

**边界（来自原文的范围说明）**：

- 需要 Python 3.6 以上；标注方案相关功能需要 JVM、JPype 与 MMAX2 jar（§1、§2.2）。
- 校验只检测和报告，不修复或合并不一致（§2.2）。
- 校验发生在单个 markable 层面；`set_attributes` 即使抛出异常也会写入属性（§2.2，PDF p.4）。

阅读者分析：缺少大规模语料上的性能数字，也没有与 MMAX2 Discourse API 或转换器的定量对比；作为数据工具，其可靠性需要通过使用者自己的验证来确认。

依据：§1、§2.1–2.3，PDF pp.1–5。
