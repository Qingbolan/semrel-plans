# 解决的问题

**实例**：表 T、问题 Q、可选段落 P，输出答案 A。问题类型包括短答案（WikiTQ）、事实核查（TabFact）、数值推理（FinQA），以及需要结合表外段落或图片的多模态问题（§2，p.2）。

**四个阶段（§2.1，pp.2–3）**：

1. **预处理**：重命名与 SQL 保留字冲突的列名并去除特殊字符；由 LLM 选出相关列并生成列描述元数据；从表外文本中保留相关信息。
2. **计划**：few-shot 生成逐步计划，每步标为 SQL 或 LLM；再用一次 LLM 调用验证并修订计划。
3. **执行**：SQL 步在 MySQL 上运行，每步产生中间表；LLM 步的输入为列子集、源表、提示和目标列名，生成的值作为新列追加。出错时回退到最近一次成功的中间表。
4. **答案提取**：把最终中间表和问题交给 LLM 生成答案。

**优化（§2.2，p.3）**：把过滤、聚合等 SQL 操作提前以减少 LLM 输入；LLM 推理分块并行；合并相邻的 SQL 步；按上下文窗口切分大表。

所有阶段使用同一个 LLM，温度 0.01（§3，p.5）。

依据：§2、§3 LLM Models、Figs.2–3，PDF pp.2–5。
