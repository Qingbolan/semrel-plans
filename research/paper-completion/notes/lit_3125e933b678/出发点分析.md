# 出发点

本体匹配（OM）要在源本体和目标本体之间找出对应实体。作者把现有系统分为两类：基于知识的专家系统（如 LogMap、AML）精确但耗人力、依赖领域专家；基于机器学习的系统（如 BERTMap）需要训练或微调数据。作者认为把训练-测试范式直接搬到 LLM 不现实：重训不可行，微调所需样本量（文中引用约 1000 条）远多于一个领域本体通常的 100–200 个实体，而且仅能通过 Web API 访问的模型存在泄露敏感数据的风险（§2，p.2）。

早期 LLM 方法把每一对实体写成"是否等价"的二分类提示（§2，p.2）。§4.2 指出这种做法有两个问题：拼接两侧检索信息容易超出 token 限制；比较次数是源、目标实体数的乘积（pp.5–6）。§1 还列出 LLM 的三项一般缺陷：知识时效性、领域幻觉、非语言任务（规划、路由）能力弱（p.1）。作者因此希望用智能体的规划、工具和记忆来弥补这些缺陷。

依据：§1–§2，pp.1–3；§4.2，pp.5–6。
