# 评测与边界

**实验 1（基数，Table 1，已渲染核对）**：比值 f = 2|R_D| / (|R_D|+|R_M|)，报告 1−f 的百分比（越接近 0 越好，只平均非空结果的查询）。Flan −47.4、TK −43.7、GPT-3 +1.0、ChatGPT −19.5。负值表示 Galois 返回的行数少于标准答案；小模型漏掉大量行，GPT 系列行数接近标准答案。输出 schema 由计划构造保证与 R_D 一致。

**实验 2（内容，Table 2，仅 ChatGPT）**：人工把 T_M、T_M^C 的文本拆成记录，并把各方法结果元组与 R_D 对齐；数值相对误差 <5% 视为正确。

| 方法 | 全部 | 仅选择 | 聚合 | 连接 |
|---|---|---|---|---|
| Galois R_M（SQL） | 50 | 80 | 29 | 0 |
| NL 问答 T_M | 44 | 71 | 20 | 8 |
| NL + CoT T_M^C | 41 | 71 | 13 | 0 |

作者认为 NL 问答结果可视为 LLM 知识的上界，Galois 更高说明自动生成的提示链有效；精心设计的 CoT 提示并未更好。

**成本**：不报告 API 执行时间；GPT-3 平均每条查询约 20 秒、约 110 个批量提示，分布随结果规模偏斜。

**边界**：作者在 §3、§6 列出单属性键假设、schema 歧义、LLM 不知道自己知道什么、缺乏来源追溯、无 schema 查询的等价性、跨 LLM 可移植性、知识更新成本、长尾覆盖与偏置等问题，并承认原型尚未达到与 DBMS 相当的准确率和性能。

内容评测只覆盖一个模型、靠人工对齐，未给出每类查询数量与方差；连接类在 Galois 与 CoT 下都是 0，样本很少时百分比不稳定（阅读者分析）。
