# 解决的问题

**形式化**（§2，p.3）：给定由 N 个数据文件组成的数据湖 𝔻 和一个数据科学问题 q，系统 π_s 生成一个 Python 程序 p；执行 p 时它自行从 𝔻 读取、处理相应文件并算出答案。评价有两部分：μ_generation 执行 p 并把输出与标准答案 y_q 比较；μ_retrieval 根据 p 与标准相关文件集 𝔻_q 评估数据发现质量。

**工作单元**：一个问题 + 一个数据湖 → 一个最终程序。原文附录 A（p.19）说明，为与 KramaBench 原设计一致，每个子任务（领域）各自构建独立数据湖。

**系统接口**（§3，pp.4–6）：

| 组件 | 输入 | 输出 |
|---|---|---|
| 离线聚类 | 数据湖文件名（默认仅文件名，由 Gemini-2.5-Pro 分类） | C 个文件簇 |
| file agent（离线） | 本簇文件（可抽样查看） | 对文件结构、预处理方式的分析 |
| file agent（在线） | 黑板请求 | 若能贡献：相关文件、加载代码、处理步骤与样例，写入只有主智能体可读的响应板 β_r |
| search agent | 黑板请求 | 最多 3 轮检索、每查询 3 个网页后的回答；不响应本地文件请求 |
| 主智能体（ReAct） | 问题 q 与历史 | 规划/推理/执行代码/请求帮助/作答五种动作，最多 T=10 步，输出程序 p |

响应不写回公共黑板，以避免子智能体互相影响（§3 脚注 2，p.4）。

依据：§2–3，pp.3–6；附录 A，p.19。
