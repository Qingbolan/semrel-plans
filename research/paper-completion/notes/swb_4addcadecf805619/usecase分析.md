# 具体用例

**用例：真实论坛问题——行末汇总公式结果**（Figure 1，p.2）。

用户在为一场马术比赛记录成绩，表格有多个分区和汇总奖项。他用 IF 函数算出各项得分，但不会在行末求和，已尝试 `=VALUE`、`=SUM`、`=SUMPRODUCT` 都不成功，并在示例中手工算出了绿色单元格应有的总和。对比 SheetCopilotBench 的合成指令：“对 Vendor/Client 列为 Company A 的行求 Subtotal 列之和，并写入标题为 Total Expenses 的新行。”

**评测方式**（Figure 2，p.4）：基准把这类帖子整理成自包含指令，并附答案位置，例如“标记每个人是否成年，单元格级 `D2:D6`”。模型生成 Python 代码；代码在原表和两个改数后的表上运行；三个结果分别与答案比对，如通过 2 个、失败 1 个，则软分为 2/3，硬分为 0。

**失败案例**（§3 Case Study，pp.9–10）：在一个工作表中有两张带格式的表时，GPT-4o 读取表格时列对齐错误，把属于 “Green” 列的值标成黄色；另一次只读了查找表的前十行，导致后续行未被高亮。

阅读者分析：这类任务与语义算子的关系在于，指令要求理解非规整表格结构、按语义条件修改单元格；但本基准评测的是“生成代码修改文件”，不是逐行调用 LLM 的语义过滤或抽取。
