# 评测与边界

本文没有实验、基线对比或结果表，以下只记录它提出的评测观点。

- **评测方法**：先回顾已有的评测方法，再强调需要多角度、按场景评测，以支持模型选择和训练数据合成（§1.1 Part III，PDF p.2；§2.5，p.4）。
- **指标**：执行准确率与精确匹配准确率是常用指标；查询变体测试用于衡量鲁棒性（§2.5，p.4）。
- **调试**：核心任务是判断生成的 SQL 与原查询是否语义等价；NL2SQL-BUGs 提供错误分类和检测基准（§2.6，p.4）。

开放问题（§2.7，p.4）：

| 问题 | 关键挑战 |
|---|---|
| 多数据库 NL2SQL | 选择数据库、整合异构模式、汇总结果、跨领域适配 |
| 可信与可解释 | 自动澄清歧义查询、解释 SQL 逻辑、交互式调试 |
| 交互式系统 | 让用户逐步构建查询，把自动生成与专家修改结合起来 |
| 低成本方案 | 通过模块化设计、多智能体协作、按模型反馈生成训练数据，降低 token 消耗与延迟 |

边界（阅读者分析）：本文只是教程大纲，不能作为任何方法性能的证据来源。具体结论应回到被引用的综述（arXiv:2408.05109）或各方法的原始论文。
