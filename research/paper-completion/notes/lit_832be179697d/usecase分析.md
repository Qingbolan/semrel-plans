# 具体用例

本文没有给出完整的端到端例子。最具体的场景来自 §1 对调试的说明：模型可能生成与原查询不等价的 SQL，例如在 SELECT 子句中选错了列。可信的 NL2SQL 系统需要判断生成的 SQL 是否正确，不正确时追溯原因并修正（§1，PDF p.1；§2.6，p.4）。

§2.7 中的"多数据库 NL2SQL"也描述了一个场景：真实应用中，一条查询可能需要跨越多个模式异构的数据库。系统需要动态选择相关数据库、整合不同模式、汇总查询结果，并跨领域调整查询（p.4）。

阅读者分析：按教程的分类，一个可落地的流程是"模式链接 → 生成多个候选 SQL → 执行校验 → 自一致性选择 → 语义错误检测"，可对应到 §2.4 和 §2.6 的模块。这是阅读者的组合，原文没有作为单一流程给出。

依据：[PVLDB 18(12): 5466–5471，2025，教程提案，doi:10.14778/3750601.3750696，6 页](https://www.vldb.org/pvldb/vol18/p5466-luo.pdf)，§1、§2.4、§2.6–2.7，PDF pp.1、3–4。
