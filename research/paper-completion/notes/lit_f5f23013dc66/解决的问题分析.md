# 解决的问题

**形式化**（§3，pp.3–4）：knob 集合 K={k1,…,kn}，每个 ki 的取值域 Ri 为连续区间或类别集合，联合空间 R=R1×…×Rn。给定数据库实例 DB 与负载 W={q1,…,qm}，寻找配置 r★∈R 使目标指标 M（如查询延迟最小或事务吞吐最大）最优。

**优化目标**：相对默认配置的提升 p，由吞吐提升 (tps−tps_default)/tps_default 与延迟下降 (lat_default−lat)/lat_default 按权重 w1、w2 组合；权重由 LLM 依据用户需求 R 与任务描述 T 一次性给出（§6.1，p.7）。

**两阶段流程**（§4，p.4）：

| 阶段 | 输入 | 输出 |
|---|---|---|
| 1. LLM 自适应 knob 选择（静态压缩） | 候选 knob、手册/网页/LLM 知识、用户需求 R、任务描述 T（数据库、负载、硬件） | 按 MoE 加权分数排序的前 N 个 knob 及收窄后的 [L,U] |
| 2. 空间分解调优（动态压缩） | 上一步的空间、历史样本 D_t | 每次迭代 1 个待评估配置；最终取 D_N 中最优配置 |

**工作单位**：一次迭代 = 提出一个配置 → 重启数据库 → 运行目标负载 → 记录性能（§7.1.5，p.10）。知识阶段对每个 knob 取多来源范围交集：L=max(...)、U=min(...)，描述按手册 > 网页 > LLM 的优先级合并（§5.1，p.5）。
