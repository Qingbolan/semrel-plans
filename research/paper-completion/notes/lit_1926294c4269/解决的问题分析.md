# 解决的问题

本文是教程，不定义一个可求解的形式化问题，也不给出算法的输入/输出契约。它要回答的问题是：如何组织一个“LLM 增强的数据管理系统”，使其在面对数据管理任务时降低幻觉、成本并提升复杂任务的准确率。

教程给出的“工作单位”是一条用户请求（DB user request）。通用流程（§2.1 General Workflow）为：先为任务准备 RAG 知识（写入向量数据库）、工具集与通用或微调后的 LLM；对每个请求，agent 用 LLM（1）理解意图，（2）合成执行流水线（部分步骤调用 RAG 或工具 API），（3）执行、评估并迭代修正，直到输出经过验证的结果或“无法回答”。单轮可答的请求直接检索知识生成提示；多轮请求交给 agent 生成多轮流水线，并有缓存层减少 LLM 交互（§1 “LLM Prompt and LLM Agent”）。

阅读者分析：该描述是架构层面的愿景，没有规定输入数据格式、输出质量度量或终止条件的具体判据，因此不能当作可直接评测的任务定义。

依据：[PVLDB 17(12) 4213–4216](https://www.vldb.org/pvldb/vol17/p4213-li.pdf)，§1、§2.1，PDF pp.1–3。
