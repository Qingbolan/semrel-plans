# 具体用例

**原文用例：splicing connectors 的线缆长度检查（§III-C–D、Fig. 3、Fig. 5，PDF pp.4–5、7）**

1. **Code Prompt**：用户任务说明要求编写函数，分析图像中线缆与连接器的布局是否异常，返回布尔值和原因字符串；专家从正常图像中归纳规则，例如线缆长度必须落在 [L_min, L_max] 范围内。
2. **Code Generation**：GPT-4 把规则解析为 `if L_cable ∉ [L_min, L_max]`（式 1），并选择 size() API 测量线缆长度（式 2）。
3. **Code Execution**：执行生成的代码，size() 返回实际长度，与范围比较；若越界则输出异常和原因。

同一类别下的其他规则包括：只能有 1 根线缆（数量）、线缆两端应按位置顺序接到对应连接器（位置）、线缆颜色应与连接器编号匹配（匹配）（Fig. 5）。

**结果**：splicing connectors 类别准确率 0.989，代码生成成功率 0.550（错误 0.150、缺失 0.300），人工评估推理准确率 0.976（Tables II、IV、V，PDF pp.7、9）。

阅读者分析：这种"规则 + 可执行检查"的模式可类比于在图像集合上执行带解释的语义过滤谓词；但前提是已有对象定位，否则 count/size 等 API 没有可靠输入。
