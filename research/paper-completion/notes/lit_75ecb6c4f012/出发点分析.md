# 出发点

现有 SQL 改写多为规则范式：手工规则泛化差；LearnedRewrite 用 MCTS 搜索规则组合；LLM-R² 和 R-Bot 用 LLM 推荐规则，但仍受规则集覆盖面限制（Introduction，p.1）。作者指出规则方法的根本问题：表达力不足，难以覆盖 CTE 改写、求值顺序与子计划复用等结构性改写；规则间依赖形成脆弱的搜索空间；不能从执行反馈中学习适应新的查询结构（p.1）。同期的 QUITE 用无训练的多智能体推理时迭代修正，作者认为它需要多轮迭代且缺乏训练期反馈（pp.1–2）。

直接让 LLM 改写又会因缺乏执行感知和语义锚定而出现性能退化或不等价（Abstract，p.1）。SQL 改写没有标注目标，质量由不可微、延迟且相互冲突的可执行性、等价性、效率决定，因此作者认为监督学习不适用，转而用强化学习（p.2）。

三项挑战（p.2）：LLM 缺执行感知；缺少把改写行为与等价性和性能关联的稳定信号；从一开始同时优化等价和效率会使训练不稳定。

依据：[arXiv v2，9 页](https://arxiv.org/abs/2508.09023)，Introduction，pp.1–2。
