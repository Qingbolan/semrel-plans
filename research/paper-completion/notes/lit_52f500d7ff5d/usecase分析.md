# 具体用例

原文 Figure 1 与 §2.1.2 给出的事件管理用例（PDF pp.2、4）：

- **数据**：ServiceNow incident 表的合成版本，字段包括开单时间、事件描述、类别、指派人员等；标注者让“解决时长 TTR”随开单日期线性增长（Dataset 2），或在某时间段内让硬件类事件 TTR 突然线性上升（附录 Table 3，PDF p.19）。
- **用户输入**：普通用户给出高层目标，如“分析 data.csv 中的事件趋势，了解影响运营效率的事件类型”。
- **智能体过程**：提出“哪些设备比其他设备故障更多？”等具体问题，写 pandas 代码出图，逐步覆盖描述、诊断、预测、规范四类 insight。
- **期望输出**：总结“硬件类事件更多”“墨尔本某台打印机故障”，并给出行动项“开单更换该资产”。

对比 Figure 1 上半部分：现有基准由专家给出精确问题（做线性回归并用 R² 评估拟合），智能体只返回数值解释，没有可执行的建议。

阅读者分析：若把这一用例映射为语义算子流水线，它更接近“探索式规划 + 多次聚合/分组查询 + 总结”的组合，而单次语义过滤或抽取无法覆盖；评测只看最终文本 insight，不检查中间代码或图的数值正确性。

依据：§1、§2.1–2.2、Figure 1、附录 Table 3，PDF pp.2–5、19。
