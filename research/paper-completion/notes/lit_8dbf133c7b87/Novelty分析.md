# 贡献与评价

**原文声称的贡献**（§1，p.4）：

1. 直接在查询空间而不是计划空间中变换。
2. 在提示中加入数据库感知规则（Table 2，p.7）：R1–R4 消除冗余（用 CTE 避免重复计算、合并对同一基表的扫描、删除冗余过滤、删除冗余的 PK-FK 连接）；R5–R6 依据选择率（EXISTS/IN 的选择、自连接表预过滤）。每个提示只带一条规则和一个示例。
3. 基于 token 概率的 MCTS：只有当最高 token 概率低于 θ=0.7 时，才展开 k=2 个分支；itermax=8，节点价值为有效改写的代价加速，无效改写记为 0（§5，pp.10–13）。
4. 等价检查：相关抽样、调整常量、注入合成元组（XData 思路）做结果比对，再用 QED/SQLSolver 证明，必要时在全库上比对结果；回退检测使用 SEER 角点强制计划，引擎不支持时改为比较抽样执行时间（§6，pp.14–15）。

**阅读者分析**：贡献偏向工程组合与实证研究。规则集刻意保持很小，提升很大程度来自 R5–R6 这类利用统计信息的提示；去掉 R1–R6、只用基本提示加 MCTS 时，CSGM 从 11.5 降到 5（§7.2.2，pp.18–19）。

**阅读者分析**：Table 5 中 MCTS 的“单独”CPR 为 26，而正文称 MCTS 单独使用（以 Prompt 1 为种子）只得到 11 个 CPR，表与正文矛盾（p.18，已渲染核对）。

依据：§1、§4–7，PDF pp.4–19。
