# 贡献与评价

**论文声称的贡献**（§1，pp.2–3）：
1. 利用 LLM 调用的高延迟，设计流水线式在线学习架构，让本地模型训练与 LLM 执行重叠；
2. Larch-A2C：把过滤排序建模为 MDP（每行一个 episode），用算子感知 GGNN 编码树结构与数据嵌入，以 A2C 从执行反馈学习；
3. Larch-Sel：基于“逐实例选择率估计是主要瓶颈”的观察，拆为在线选择率估计 + 精确组合排序；
4. 三个真实数据集、三种工作负载上 token 超额相对 PZ、Quest 降低 3–19 倍。

**机制要点**：

| 组件 | 细节 |
|---|---|
| Larch-A2C | 3 层 GGNN，隐藏 256；AND/OR 边用不同权重；奖励 −c(f_i)/C_ep,total；单步 TD(0)；作者解释不用 PPO/GAE 是因为每个 episode 只有 2–10 步且训练有一步滞后（§3.2、§4.1） |
| Larch-Sel | 嵌入投影到 64 维，特征 [d ‖ f ‖ d⊙f ‖ cos(d,f)] 共 193 维；两层 MLP 约 144K 参数；每次 LLM 求值后做一次 BCE 梯度步；所有谓词共享权重（§3.3.1、§4.1） |
| DP 排序 | 在独立性假设下对任意 AND/OR 树求最小期望代价；子问题数 O(3^n)，复杂度 O(n·3^n)；n=10 约 59 万状态、单核约 20 ms；每行用新估计重新求解（§3.3.2） |
| 延迟隐藏 | 三阶段：预测后启动后台更新 → LLM 推理 → 记录并剪枝；训练滞后一轮（§3.4） |

**阅读者评价**：
- 自适应查询处理（Eddies 等）和按选择率排序的经典结论（原文引用 [22][27]）早已存在；新意在于用预计算嵌入做逐行选择率预测，以及认为 LLM 延迟让逐元组更新这种较重的在线学习变得可行。
- Larch-Sel 超过拿到真实全局选择率的 OraclePZ/OracleQuest（9 个配置中 8 胜 1 平，Table 2），这是“逐行估计优于全局估计”的直接证据。
- Larch-Sel 的 DP 仍假设谓词独立；作者承认 Larch-Sel 优于 A2C 部分是因为所测工作负载的谓词相关性“适中”（§4.2）。强相关场景下两者孰优，论文没有专门测试。

依据：[arXiv 2606.07923v1](https://arxiv.org/abs/2606.07923)，§1、§3.2–3.4、§4.1–4.2、§4.6、Table 2，PDF pp.2–11。
