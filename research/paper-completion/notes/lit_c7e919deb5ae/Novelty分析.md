# 贡献与评价

原文主张：
1. 把零样本 Text-to-SQL 表述为 MCTS 树搜索上的渐进式 SQL 构造；
2. LLM-as-Action-Model：每一步由 LLM 执行动作并生成 CoT，存在节点中维持上下文；
3. 基于执行结果自一致性的自监督奖励，不需要训练奖励模型；
4. “即插即用”：不微调即可提升小型开源模型（Qwen2.5-Coder 7B/14B/32B、Phi-4）。

阅读者分析（诚实评估）：
- 多个动作直接继承已有工作：问题改写来自 rStar，schema 选择与值检索沿用 CHESS-SQL，SQL 生成采用 CHASE-SQL 的分治 CoT，修正为执行反馈纠错（§4.1，p.5）。新意在于把这些步骤放进一个由 MCTS 动态组合的动作空间，以及用执行一致性同时作为搜索奖励和最终选择依据。
- 自一致性奖励衡量的是“多次采样是否一致”，并非正确性；对系统性错误（多次采样都错得一样）无能为力。原文未分析此类失败。
- 动作消融（Table 5）各动作的贡献只有 0.4–1.8 个点，且在 147 题的子集上测得，单个动作的作用在统计上较难确认（原文未报告方差或显著性）。
- “零样本”指不用 Text-to-SQL 标注微调；但 A1 使用 few-shot 提示，且搜索需要访问并执行真实数据库。

依据：[arXiv:2502.17248v2（ICML 2025，PMLR 267），21 页](https://arxiv.org/abs/2502.17248)。
