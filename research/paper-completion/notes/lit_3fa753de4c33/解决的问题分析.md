# 解决的问题

输入：用户自然语言分析请求（如 GAAP 示例或“为什么上月产品 X 收入下降”），加上企业异构资产——数仓表、看板、业务文档、交互日志、历史任务。输出：端到端分析工作流的结果，包括可审阅的计划 DAG、SQL/Python 产物、图表与交互式报告，每个结论链接回数据来源；同时产生回流到语义层和技能库的候选更新（§1.4、§2.3）。

工作单位：一次分析任务（Host 将其表示为 DAG，节点状态包括 ready/running/completed/failed/skipped/awaiting user revision，§5.2）。三个子系统职责正交：DataBridge 回答“用什么事实”，Skill-Hub 回答“怎么分析”，Host 回答“怎么运行”（§2.1）。作者特意将易变、领域特定的业务事实（DataBridge）与稳定、领域通用的方法（Skill-Hub）分开，以便同一技能在不同证据上复用（§2.1）。

接口：Host 通过 MCP 访问 DataBridge，通过开放的 Agent Skills 标准消费 Skill-Hub（§2.2）。

覆盖的任务类型：业务监控与异常诊断、趋势增长分析、用户交互洞察、周期性报告、临时深挖分析（§1.4）；L0 路由的任务族为元数据查询、数据查询、BI 业务分析、数据探索、统计建模、报告生成（§4.3）。

依据：[arXiv 2607.11019v2，24 页](https://arxiv.org/pdf/2607.11019v2)，§1.4、§2.1–2.3、§4.3、§5.2，PDF pp.5–9、15、18。
