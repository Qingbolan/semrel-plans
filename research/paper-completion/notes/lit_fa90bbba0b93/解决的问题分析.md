# 解决的问题

**形式化**：给定任务 T（Kaggle 式竞赛描述与数据），在解空间 S 中寻找 s* = argmax h(T, s)，其中每个候选 s 是完整的端到端 ML 管线代码（预处理、特征工程、训练、预测），h 为任务指标（准确率、AUC 或损失等）（§3.1，Eq.1，PDF p.5）。

**工作单元**：图 G=(V,E) 中的一个节点 = 一个可执行的候选解。主边 E_T 表示"由父节点经算子生成"，参与 UCT 选择与回传；参考边 E_ref 表示额外借鉴了其他节点的信息，不参与回传；E_ref 为空时退化为标准 MCTS（§3.2.1，Eq.2，PDF p.5）。

**一次迭代的输入/输出**：

| 环节 | 输入 | 输出 |
|---|---|---|
| 选择 | 以概率 w(t) 走 UCT（c(t) 分段衰减），否则从全局 top-K 精英节点按 1/rank 抽样 | 待扩展节点 v_t |
| 扩展 | v_t 及参考集 R（空 / 本分支最近 k 个 / 跨分支 top-N / 多分支最佳轨迹） | 新代码节点 |
| 模拟 | 在解释器执行代码 | 奖励 −1（失败/无指标）、1（成功但未刷新分支最优）、2（刷新分支最优） |
| 记忆 | 规划文本或报错信息作为查询，BM25+FAISS 经 RRF 融合 | 相关成功/失败记录 |

依据：§3.2.2 Eqs.3–9、§3.3、§3.4，PDF pp.5–9。

**最终产出**：最优 solution.py、submission.csv 与 top-k 候选（Figure 1，PDF p.2）。每任务最多 500 步扩展、12 小时（§4.1，PDF p.9）。
