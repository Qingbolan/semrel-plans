# 具体用例

**索引新增引起的回退**（§3 场景 1，p.3）：DBA 在 JOB 数据库上新增若干索引后，一条多表连接查询的耗时达到以前的 φ 倍。DBG-PT 检测到回退后，取出回退前后两份已执行计划，按 Fig. 1 的模板生成提示（p.3），大意为：

> 以下是同一查询的两个计划：P1 = `$Plan1`，P2 = `$Plan2`。从 P1 切换到 P2 时出现了回退。查询运行在 `$DBMS` 上。请给出加速 P2 的配置建议，或在可能时将其恢复为 P1。

LLM 返回 `plan_diff`（例如新出现的索引扫描及随之改变的连接策略）、`recommendations`（与该 DBMS 兼容的 SQL 命令，如禁止该查询使用某索引或某连接算法的提示）及 `reasoning`。§1 举例：若新索引导致计划连锁变化，可用提示让优化器在该查询上不使用该索引；若查询曾因 nested loop 更快，可显式禁用其他连接策略（p.1）。

这里的具体 SQL 建议内容是按原文描述归纳的，论文没有给出真实的 LLM 回复样例（阅读者分析）
