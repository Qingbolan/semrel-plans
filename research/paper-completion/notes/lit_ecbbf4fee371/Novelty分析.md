# 贡献与评价

原文声称这是首个研究“用指令微调让 LLM 成为通用 DP 求解器”的工作（§1，PDF p.2）。主要技术点：

1. **数据配置**：在不超过非 LLM 方法所用训练数据（约 115k 实例池）的约束下，根据单任务微调实验（§5.5、Figure 3）决定配比：ED、DI 全用，SM 取大量，EM 取适量（如 DBLP-GoogleScholar 只取池中 1/3）；全部正例保留；ED 中含缺失值的实例复制为“视为错误/不视为错误”两版（§3.1，PDF p.3）。
2. **知识注入**：通用知识（缺失值、错误类型、缩写）与数据集特定知识（约束、规则、重点属性），微调后成为模型内置知识，推理时也可由用户追加（§3.2、§4，PDF pp.4–5）。
3. **推理数据蒸馏**：8k/11k/14k/20k 四档推理数据（Table 2），用于赋予解释能力（§3.3，PDF p.5）。

**结果层面的贡献**：13B 在已见任务平均分最高；三种基座的 DP 平均分分别提升约 36、19、22 分（Table 6）；Open LLM Leaderboard 平均分下降不超过 1.32（Table 7）（§5.2–5.4，PDF pp.6–8）。

阅读者分析（评价）：

- 方法本身是成熟的指令微调与 LoRA 组合，新意主要在面向结构化数据的数据配置与知识注入经验。
- 基线数值均引自先前工作（§5.1，PDF p.6），没有在同一环境重新运行，GPT-3/3.5/4 与 Jellyfish 的提示、知识注入也不完全相同。
- 文中有小的不一致：§5.1 称 7B 用 15k 推理数据，§5.6 称选择 14k（Table 2 中为 14,420）（PDF pp.5、8）。
- 解释能力的评测由 GPT-4o 两两比较，且 GPT-4o 不知道正确答案（附录 C.4，PDF p.18），衡量的是“看起来更好的解释”，不是解释的忠实性。

依据：§1、§3–5、Tables 1–2、6–7、附录 C.4，PDF pp.2–8、18。
