# 解决的问题

数据模型为带 schema 的关系表，属性取值为数值（含二值）或文本（含类别）。与传统“给出整个数据集、找出全部错误/匹配”的定义不同，本文每次只处理一条记录或一对对象，使提示易写且不超过 token 限制（§2，PDF pp.2–3）。

| 任务 | 输入实例 | 输出 | 是否用于微调 |
|---|---|---|---|
| ED 错误检测 | 一条记录及一个属性 | 该单元格是否有错 | 是 |
| DI 数据填补 | 一条记录及缺失值属性 | 推断出的正确值 | 是 |
| SM 模式匹配 | 一对 (属性名, 描述) | 是否指同一属性 | 是 |
| EM 实体匹配 | 一对记录 | 是否指同一实体 | 是 |
| CTA 列类型标注 | 无表头表格（或列） | 每列在预定义类型集中的类型 | 否（未见任务） |
| AVE 属性值抽取 | 实体文本描述与预定义属性集 | 抽取的属性值 | 否（未见任务） |

（§2，PDF p.3）

**提示结构**：系统消息、任务描述、注入知识（通用知识如“缺失值不应作为判断依据”，或数据集特定知识如“出版物作者名顺序可能不同”）、实例内容、问题、输出格式；推理版额外要求先解释再在单独一行给出最终答案（§3.2–3.3、Figure 2，PDF p.4）。

**推理数据**：用 Mixtral-8x7B-Instruct-v0.1 生成推理过程，生成时在提示末尾附上正确答案作提示，使其朝正确方向推理；该提示不出现在给 Jellyfish 的输入中（§3.3，PDF p.5）。

按实例而非按表处理，意味着 ED 需对每个单元格调用一次模型，原文在 Limitations 中承认这在大规模数据上影响效率（PDF p.10）（阅读者分析）

依据：§2–3、Figure 2，PDF pp.2–5、10。
