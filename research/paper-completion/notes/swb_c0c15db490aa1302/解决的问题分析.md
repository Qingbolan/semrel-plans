# 解决的问题

**任务**（§3）：输入一条已小写化、去 HTML 的财报附注句子；输出逐 token 的 IOB2 标签，共 139 个 XBRL 标签 × B/I + O = 279 个 token 标签。标签取 US-GAAP 分类体系中的标签名（tag name），不含 XBRL 的其他属性。

**评价单位**（§5）：实体级——金标准片段跨多个词时，模型须标出完全相同的片段才算正确；报告 micro-F1 与 macro-F1，便于比较词级与子词级模型。

**扩展设定"推荐引擎"**（§9.3）：假设需要标注的 token 已知，模型为每个 token 返回最可能的 k 个标签，用 Hits@k 衡量正确标签是否在前 k 内。

**不在范围内**：6,008 个标签中出现少于 1,000 次的长尾标签、表格标注、跨句关系与数值推理（§3、§2"Numerical reasoning"段）。作者明确说本任务的标签更依赖上下文与数字形态，而非数字的确切值（§2）。

阅读者分析：这是带大规模细粒度标签的序列标注，可视为"句子 → (片段, 财务概念) 集合"的抽取算子；句子已被启发式规则预过滤，真实部署还要包括该过滤步骤。

依据：[ACL 2022，13 页](https://aclanthology.org/2022.acl-long.303)，§2–3、§5、§9.3，PDF pp.2–4、7–8。
