# 解决的问题

本文是综述，按任务梳理输入与输出（下表据原文定义整理）：

| 任务 | 输入 | 输出 | 位置 |
|---|---|---|---|
| 表搜索（ad-hoc 表检索） | 文本查询 q（关键词或自然语言）、表集合 C | 按相关性独立打分的表排名 (T1,…,Tk) | §3.1，PDF p.4 |
| 可连接表搜索 | 查询表 | 可做等值、模糊或语义连接的表，用于补充属性 | §3.2，PDF p.5 |
| 可合并表搜索 | 查询表 | 可纵向拼接、补充元组的表 | §3.2，PDF p.6 |
| 其他目标导向发现 | 查询表或目标 | 满足分位数谓词、相关属性、提升 ML 效果、因果关系、解释显著特征的表 | §3.3，PDF p.6 |
| 模式匹配 | 两张或多张表 | 列对应关系或语义相似列的簇 | §4.1，PDF p.7 |
| 实体解析 | 多个数据集的元组 | 指向同一实体的元组；流程为可选预处理、分块（blocking）、匹配 | §4.2，PDF pp.11–12 |

Table 1（PDF p.8）按查询类型、任务、模型开源/闭源、推理方式（微调/零样本/少样本）列出 7 篇 LLM 发现方法；Table 2（PDF p.8）对 19 篇模式匹配与实体解析方法按任务、输入（元数据/取值/外部知识）、模型与推理方式分类。

阅读者分析：这些任务与本项目的语义连接、语义过滤直接对应。综述强调"语义连接"已有嵌入方法（PEXESO、DeepJoin、WarpGate 等），但尚无用 LLM 直接做可连接/可合并表搜索的方法（PDF p.6）。

依据：§3–4，PDF pp.4–12；Tables 1–2，PDF p.8。
