# 出发点

作者指出当时的 TQA 方法有三点不足：(1) 多数只处理单表，而真实问题常需要连接多表，例如“Tom 的年终奖是多少”要把 Employee 与 Salary 表按员工号连接；MultiTabQA 能处理多表但需要预训练和微调。(2) 对 LLM 能力利用不足，例如 ReAcTable 在中间步骤得到空结果时无法区分是错误还是真的为空，并且把表数据直接写入提示对大表不可行。(3) 数据分散在 MySQL、S3、API 等多个系统，现有方法要求先做 ETL。

PingCAP 的实际场景是 TiDB Cloud 计费分析，数据分布在 BigQuery、TiDB 和实时 API 中，迁移到单一系统代价过高。
