# 解决的问题

**任务定义**（§2，p.4）：NL2SQL 为 `S = Parser(Q, D, T)`；NL2BI 为 `S = Parser(MQ, D, V)`，输入是多轮问题序列 MQ、数据库 D 和视图 V，输出一条可执行 SQL。虚拟列是 BI 中常用但物理上不存在的计算列，只存储计算规则，例如 `dau` 对应 `count(distinct if(uid is not null, uid, null))`（§2，p.4）。

**系统三个模块**（§3，Fig.3，p.4）：

| 模块 | 输入 → 输出 | 方法 |
|---|---|---|
| 多轮对话匹配 | 历史问题序列 → 一个含完整意图的"当前问题" | 4 层 ERNIE Tiny 先判断问题是否同时含维度和指标（Eq.3），不含时从最近一条完整问题起，把之后的问题一起输入第二个 ERNIE 模型改写（Alg.1，p.5） |
| 单视图选择 | 当前问题 → 一个视图 | 选包含全部目标列且列数最少的视图，即 `V = Select(Vs, Cols)`；用 SFT ERNIE Tiny 分类（§4.2，pp.6–7） |
| 分阶段流程 | 问题+视图列 → JSON → SQL | LLM 只输出 JSON 中间结果，由 Apache Superset 中的规则模板生成 SQL；复杂计算通过嵌入 JSON 的虚拟列映射（JnM）取得（§5，pp.7–8） |

**View Advisor**：单视图选择失败的问题交给 DBA 评估是否新建视图；选中视图的命中计数可用于删除久未使用的视图（§3，p.4；§4.2，p.7）。

**工作单位**：一条（可能为多轮中的）中文 BI 问题，输出一条 SQL 及 Superset 可视化结果。
