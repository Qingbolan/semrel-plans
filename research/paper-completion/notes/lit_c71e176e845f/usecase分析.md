# 具体用例

**Fig.1 三轮对话（p.2）**：视图 `video.t6628` 含 200 多列。

| 轮次 | 用户问题 | 期望 SQL 要点 |
|---|---|---|
| Query1 | 近七天短视频播放量 | 按 `event_day` 分组求 `sum(sv_vv)`，日期 2024-04-04 至 04-10 |
| Query2 | 周同比呢？ | 本周子查询与日期加一周的上周子查询 `LEFT OUTER JOIN`，计算 `(本周-上周)/上周` |
| Query3 | 播放时长呢？ | 在 Query2 基础上加入 `sum(playtime)/60` 及其周同比 |

原文指出，现有 NL2SQL 方法能处理 Query1，但无法生成 Query2 的同比结构，也无法识别 Query3 是在延续前文意图（§1，p.2）。

**ChatBI 的处理**：多轮匹配模块判断 Query2、Query3 缺少维度或指标（标签 0），于是从最近一条完整问题 Query1 起，把对话输入 ERNIE 模型改写为完整问题；视图选择模型选中 `t6628`；LLM 输出 JSON 指出指标、维度和比较方式；Superset 模板生成带周同比的 SQL；"分钟级播放时长"可直接命中虚拟列 `stay_time_min = sum(staytime)/60`（§4–5，pp.5–8）。

上面把 Fig.1 和 §5.2 的虚拟列示例串成一个流程，是阅读者的组合；原文没有给出该例在 ChatBI 中的 JSON 中间结果（阅读者分析）
