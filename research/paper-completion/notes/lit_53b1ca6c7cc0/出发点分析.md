# 出发点

论文的出发点有两条实际需求（§1，p.1）：其一，现实中的时间序列常伴随文本描述、元数据、外部约束等上下文，而多数方法把序列当作孤立数值；其二，实践者需要端到端的分析工作流，预测只是更大求解回路中的一步。

作者认为通用 LLM agent 虽是合适的交互界面，但直接把序列序列化为文本会造成两种错位（§1 p.1–2；§2.2 p.3）：

| 错位 | 原文含义 |
|---|---|
| 数据类型错位（datatype misalignment） | 趋势、周期等统计性质在 token 化与语言注意力中失真；数值接近不等于 token 接近，小数位值被扭曲，长序列稀释上下文 |
| agent 过程错位（agentic-process misalignment） | 切片、聚合、分解、平滑、异常定位、数值校验等原本自然的操作变成间接的语言推理步骤；长数值序列挤占上下文窗口 |

附录 A 给出更细分析：数值-token 距离失配、小数位失真、next-token 与 next-value 目标失配、长上下文时间信息稀释（§2.2 末，p.3）。由此提出中心问题“如何构建时间序列原生的 agent harness”（p.2）。

阅读者分析：这一动机与数据系统里“不要把结构化数据塞进 prompt，而是让模型调用算子在原生表示上执行”的思路一致；论文本身没有从数据库角度表述，只在附录 D 提到数据科学 agent（DS-Agent、Data Interpreter）作为相关工作。

依据：[arXiv 2606.05404v1](https://arxiv.org/abs/2606.05404)，§1、§2.2，PDF pp.1–3；附录 A。
