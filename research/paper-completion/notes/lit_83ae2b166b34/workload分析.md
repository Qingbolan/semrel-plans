# 工作负载

**文档来源**（§4，p.4）：从 Common Crawl 采样 1,000 篇视觉丰富的专业文档，再按 Flesch 可读性等级抽出 100 篇；最终数据集有 82 篇文档。每篇文档平均 4,257 个文本 token（含标题、子标题、段落、图注等）（§4，p.5；§6.3）。Figure 2 给出按词数的文档分布（附录 A.1，p.9）。

**问题收集**：通过 Mechanical Turk，先定义问题类别，再按类别分层收集；标注者先读文档，再按指定类别写问题（§4，p.4）。

**问题类别与占比**（§4，pp.4–5）：

| 类别 | 占比 | 类别 | 占比 |
|---|---|---|---|
| 文本问题 | 26.2% | 表格推理 | 7.4% |
| 抽取 | 21.2% | 图问题 | 6.5% |
| 摘要 | 16.4% | 改写 | 5.2% |
| 文档外问题（仅凭文档无法回答） | 8.6% | 结构问题 | 3.7% |
| 分类（文档类型） | 3.7% | 跨页任务 | 1.1% |

**难度标注**（Table 1，p.4）：

| 项目 | 数量 |
|---|---|
| 文档 | 82 |
| 问题 | 908 |
| 简单 | 393 |
| 中等 | 144 |
| 困难 | 266 |
| 不确定 | 105 |

难度由评测阶段的标注者标注（§6，p.6）。各类别的正负例见附录 Tables 4–5（pp.11–12）。

阅读者分析：结构问题和跨页任务合计不到 5%（约 44 题），而这正是 PDFTriage 动机所针对的类别；样本量小，按类别的偏好百分比（如结构问题 75%）波动可能很大。平均 4,257 token 的文档在当今长上下文模型中可以整篇放入，规模属于“中等长度”。

依据：§4、§6、Table 1，PDF pp.4–6；附录 A.1、Tables 4–5，pp.9–12。
