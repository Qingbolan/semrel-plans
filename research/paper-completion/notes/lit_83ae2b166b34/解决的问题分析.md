# 解决的问题

**任务**：给定一篇较长的结构化文档（原生数字 PDF）和一个自然语言问题，生成答案（§3，p.3）。答案可以是短答案、摘要、抽取内容或改写文本，取决于问题类别（§4）。

**PDFTriage 的三步**（§3，Figure 1，pp.3–4）：

1. **生成文档元数据**：用 Adobe PDF Extract API 把 PDF 转成类 HTML 树，提取章节、章节标题、页码、表格和图；结构信息映射成 JSON，作为给 LLM 的初始提示；内容转为 markdown。
2. **LLM 分诊（triage）**：LLM 根据问题和元数据选择要取回的内容，可调用 5 个函数：

| 函数 | 作用 |
|---|---|
| `fetch_pages` | 取指定页的文本 |
| `fetch_sections` | 取指定章节的文本 |
| `fetch_figure` | 取指定图注的文本 |
| `fetch_table` | 取指定表格标题对应的文本 |
| `retrieve` | 用自然语言查询文档并取回相关块 |

（附录 B.5，Table 6，p.17）

3. **回答**：每轮调用一个函数，通过 OpenAI 函数调用 API 在多轮对话中进行，最后一轮输出答案；所有实验使用 gpt-35-turbo-0613（§3.2–3.3，p.4）。

**评测单位**：一个“文档–问题”对及三个系统各自的答案，由人工排序并按多项质量打分（§5.3）。

阅读者分析：函数取回的仍是文本（表格和图都通过标题/图注定位文字），模型看不到图像本身，所以“图题”实际依赖图注和周边文字。
