# 解决的问题

**输入：** 一个由后端语义算子系统表达的算子流水线（计划），每个算子有类型、自然语言指令、可见字段，以及工作量估计 n̂——filter/map 为估计输入行数，join 为估计候选对数（§2.2，p.3）。

**输出：** 一个混合执行计划：每个支持的算子被路由为原生（由后端 LLM 执行）或编译（CX，本地运行生成的函数）；以及最终查询结果（§2，pp.2–3）。编译接口为：
- sem_filter → compiled_filter(row) → bool
- sem_map → compiled_map(row) → value
- sem_join → compiled_join(left, right) → bool
生成函数内部禁止调用 LLM（§2，p.3）。

**路由规则（§2.2，p.3）：** 当且仅当算子受支持、n̂ ≥ 阈值 n*、且通过“可编码性”筛查时编译。n* = A/r + 1，A 为一次性编译开销，r 为原生每单位代价。默认以时间为代价：filter/map 编译 25s、原生每行 2.5s，n*=11；join 编译 28s、每对 0.15s，n*=187；按费用的阈值为 filter 17、map 14、join 17。可编码性筛查是保守的词法检查，遇到讽刺、细腻或主观判断、多跳推理等要求则不编译。未物化输入的基数用固定选择率 0.5 传播估计。

**工作单元：** 路由决策单位是单个算子；执行代价单位是行或候选对；评测单位是 QA 问题（每题一条流水线）、SemBench 查询或 DocETL 作业（§3.1，p.4；Table 2 标题）。

**不在范围内：** 图像相关问题、sem_agg 等其他算子（§1 p.2、§3.1 p.4）。
