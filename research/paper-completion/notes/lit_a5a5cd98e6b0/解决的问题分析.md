# problem

**任务定义**（§1，p.2）：混合问答 = 基于表格与非结构化（多模态）内容的语料回答问题；本文聚焦表格 + 非结构化文本，图像扩展见附录 C。

**输入**：问题；SQLite 数据库，其中结构化表（如 HybridQA 的 Wikipedia 表 w）与非结构化文本表 documents(title, content) 并存，后者用 FTS5 建 BM25 全文索引（Table 1，p.4；§4.1，p.5）。parser 看到的是每张表的 CREATE 语句加 n 条示例行（documents 除外）以及模糊字符串匹配得到的“bridge”值提示（p.6）。**输出**：一条 BlendSQL 查询及其执行结果；执行返回 “smoothie” 对象，含最终结果与中间推理步骤（§2，p.3）。

**两个角色**（§2.1，p.3）：parser 根据 few-shot 示例和库上下文生成 BlendSQL；blender 是执行各 ingredient 的 LLM；核心实验两者都用 GPT-4-0613。

**Ingredients**（§2.2，pp.3–4）：
- LLMMap：一元标量函数，对列的每个值生成新列值（如“这是团体项目吗？”）；
- LLMQA：聚合函数，把表子集变成一个标量，可用 options 约束输出必须是某列已有值（通过 guidance 操纵 logit_bias 实现约束解码）；事实核查版 LLMValidate 只返回真/假；
- LLMJoin：为两组值建立映射，生成辅助表做 INNER JOIN，用于无外键但可语义对齐的情况（如 “joshua fields” 与 “josh fields (pitcher)”）。

**优化**（§2.3，p.4）：尽可能先在子查询中执行所有 SQL 谓词并写入临时表，确保 LLM ingredient 只接收必要的数据子集；这些优化用测试套件验证。

**工作单位**：一题一条 BlendSQL；LLMMap 对列的去重值调用（附录 A.1，p.12）。
