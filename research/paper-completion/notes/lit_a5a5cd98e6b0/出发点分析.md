# motivation

作者批评许多端到端混合问答系统是“prompt-and-pray”：用户难以控制和观察中间推理（摘要，p.1）。同时 Transformer 上下文有限，完整的结构化+非结构化上下文往往装不进单个提示，更不用说 few-shot 设定。

**中间表示的问题**（§1，p.1）：Scratchpad、CoT、ReAct 等分解方法都以自然语言作为中间推理表示，作者认为自然语言是有损且含糊的；改用类 SQL 语法分解，可借关系代数的组合性获得更确定的推理与可解释的中间步骤。

**相关线索**（§1，pp.1–2）：Agent/规划器框架把任务拆给多个工具，BlendSQL 的 parser 相当于规划器，但把复杂的 AST 编码在单个字符串里；text-to-SQL 在 Spider 上效果好，且 SQL 作为中间表示在对话状态跟踪等任务上也有效；混合问答需要隐式决定访问表格、文本或两者，已有工作把端到端模型与 SQL 解析器作为隔离系统路由，无法相互传递信息。UniK-QA 把表转成文本，BlendSQL 反其道而行，把所有文本放进表中。

**与 BINDER 的区别**（p.2）：专为 SQL 设计、支持多表库中的非结构化内容并能执行优化 JOIN、别名、CTE 等 SQLite 操作；支持按模式做约束解码；用户可自定义任意 ingredient。

阅读者分析：本文的出发点是 NLP 的“可控分解 + 长上下文规避”，而不是数据库的代价优化；其“可扩展”主要指不把非结构化文本交给 parser、只把 SQL 过滤后的子集交给 LLM。
