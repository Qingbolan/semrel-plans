# 评测与边界

**基线**（§7.1.2，PDF p.11）：GPT_single（每个谓词/投影一次 LLM 调用，附整篇文档）、GPT_merge（全部谓词与投影合并为一次调用）、RAG_seq（LlamaIndex 顺序切块，128 token，取 top-k，k = max(1, 5%×文档长度/128)）、RAG_tree（LlamaIndex 树式切块、递归摘要）。查询评估使用 GPT-4-32k。

**指标**：元组级精度与召回、输入加输出 token 数与美元成本、三次运行的平均延迟。

**实验 1–2（Table 2，PDF p.12，每查询每文档平均值）**：

| 策略 | 精度 PUB/CIVIC/NOTICE | 召回 PUB/CIVIC/NOTICE | 成本 $ PUB/CIVIC/NOTICE |
|---|---|---|---|
| GPT_single | 0.74 / 0.45 / 0.71 | 0.38 / 0.45 / 0.77 | 0.98 / 0.33 / 0.3 |
| GPT_merge | 0.63 / 0.34 / 0.66 | 0.4 / 0.45 / 0.72 | 0.8 / 0.2 / 0.2 |
| RAG_seq | 0.51 / 0.12 / 0.36 | 0.38 / 0.13 / 0.38 | 0.02 / 0.02 / 0.01 |
| RAG_tree | 0.51 / 0.2 / 0.2 | 0.38 / 0.04 / 0.17 | 0.07 / 0.04 / 0.02 |
| ZenDB | 0.72 / 0.73 / 0.73 | 0.53 / 0.84 / 0.74 | 0.03 / 0.03 / 0.02 |

作者称相对 GPT_single 成本节省约 29×、10×、4×；在 Civic 上精度高 28%、召回高 39%。

摘要中的"精度最多高 61%、召回最多高 80%"与 Civic 列的绝对差一致（0.73−0.12、0.84−0.04），应理解为百分点而非相对提升（阅读者分析）。

**实验 3（预处理成本，Tables 6–7，PDF p.13）**：表填充用 GPT-3.5-Turbo，Publication/Civic/Violation 分别为 $0.048、$0.005、$0.005；SHT 构建与表填充总计约 $0.1、$0.015、$0.015。

**实验 4–5**：去掉动态摘要或节点名对精度与召回影响最大，抽取式摘要影响最小（Figure 11）；ZenDB-light（GPT-3.5-turbo）精度约降 7%、召回约降 3%，成本约降至 1/100（Figure 12，PDF p.13）。

**边界**：仅支持无嵌套查询与文档内连接；LLM 结果不一致问题未处理（§4.2）；无模板或模板噪声大的情况留待未来（§9，PDF p.14）。

Publication 上 ZenDB 召回仅 0.53，QG3 召回 0.34（Table 3），多谓词查询的漏检依然明显（阅读者分析）。
