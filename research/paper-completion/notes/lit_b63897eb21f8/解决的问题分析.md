# 解决的问题

**输入**：带视觉格式的模板化富文本文档集合 D（PDF、Word），经 pdfplumber 提取为带字体、位置特征的词序列，再按相同格式合并为短语序列（§3.1，PDF p.4）。

**中间结构 SHT**：每个文档一棵单根、有序树，节点是标题短语；每个节点覆盖从自身到下一个同级或祖先右兄弟之前的文本区间。若真实 SHT 满足"格式良好"（同级节点视觉模式相同、同一视觉模式的视觉前缀唯一），且 LLM 能正确识别非标题，则 `oracle_gen` 能恢复真实 SHT（Theorem 3.1，PDF pp.4–5）。

**用户接口**：用扩展 DDL 定义文档表（DTable），例如 `CREATE TABLE … WITH DESCRIPTION`，属性可随时惰性追加，每个属性附自然语言描述（§4.1，Figure 5，PDF pp.3、6）。

**支持的查询**（§4.2，PDF p.7）：无嵌套的 SELECT-FROM-WHERE，可带 SUM/COUNT/AVG/MAX/MIN；谓词形如 `attr op 常量`，op 包括比较、`LIKE`、`IN`；多个 DTable 只能按 doc_id 等值连接，即只支持同一文档内连接。

**查询语义**：等价于先用 LLM 把所有属性读取和表达式填满 DTable，再按普通 SQL 执行。作者承认 LLM 可能使属性值与谓词判断不一致（如抽取的类型为 B，但"type = A"判为真），这一问题不在本文范围（§4.2，PDF p.7）。

**输出**：查询结果元组及其来源文本区间（provenance）（§6.2，PDF p.10）。
