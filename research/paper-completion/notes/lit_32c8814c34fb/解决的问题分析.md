# 解决的问题

**形式化（§3.1，p.3）**：给定原始数据集 D_raw = {x_i}、少量高质量 seed 样例集合 S、可选自然语言描述 T，从算子库 O 构造数据准备流水线 P*。P 是 k 个算子的 DAG，每个算子 o_j 带参数 θ_j；执行 D_out = Exec(P, Θ, D_raw) 按拓扑序应用算子。目标是缩小 D_out 与从 S 推导出的质量要求 C 之间的差异，最终有效性由下游 LLM 训练或代理评测衡量。

| 项 | 内容 |
|---|---|
| 输入 | 原始训练数据（JSON 记录）、20 条 seed（主设置）、可选任务描述 |
| 中间产物 | 数据画像 C（目标 schema、格式约定、质量约束、难度偏好，§3.2）、逻辑算子 DAG、实例化代码、经验记忆 M |
| 输出 | 可复用的准备流水线及其在全量数据上产生的 SFT 训练集（1k / 5k 条） |
| 工作单元 | 一条训练样本（instance）；评测单元是“骨干模型 × 预算 × 基准”的 SFT 结果 |

**两层循环（§3.3–3.4，p.4）**：
- 算子级：对逻辑 DAG 做检查（依赖缺口、接口不兼容、DAG 不连通等），通过插入桥接算子、替换、重排、改边修复；缺能力时生成新算子并加入算子库（式 3）。
- 流水线级：把 DAG 实例化为代码，在采样子集 D_s 上试跑，与 seed 比较得到“欠满足/过约束/缺失”等差异信号，转为经验写入记忆 M（式 4），再重算画像、重编排，直到试跑输出满足 seed 要求后再跑全量。

阅读者分析：成功标准由 seed 隐含的质量要求与 LLM judge 决定，并不存在逐条“金标准输出”；因此“数据准备正确性”只能通过下游 SFT 分数与 judge 分数间接衡量。
