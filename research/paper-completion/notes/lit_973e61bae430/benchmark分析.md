# 评测与边界

**基线**（§8.1，PDF p.10）：DDPG++（RL）、GP（iTuned/OtterTune 所用高斯过程）、SMAC（随机森林代理 BO，作者视为不读文本的最强方法）、DB-BERT（读手册 + RL）。GPTuner 基于 SMAC3 与 OpenAI API，默认 GPT-4。

**实验 1（性能对比）**：

| 设置 | 论文报告结果 | 位置 |
|---|---|---|
| PostgreSQL TPC-H | 20 次迭代内延迟降 44.4%，之后再降 12.7%；DB-BERT 前 20 次降 37.5%，之后仅 3.4%；不用知识的方法平均慢 26 倍收敛，终值平均差 35.6% | §8.2、Figure 4，PDF p.10 |
| PostgreSQL TPC-C | 收敛快 12.6 倍并达到最高吞吐 | 同上 |
| PostgreSQL 汇总 | 达到各基线最佳性能所需优化时间平均减少 92.6% | 同上 |
| MySQL TPC-H | 一开始就把延迟降 48.5%，超过所有基线 100 轮内的最好结果 | §8.2、Figure 5，PDF p.10 |
| MySQL TPC-C | 1029 tx/s（默认 240 tx/s），比 DB-BERT 高 10%，比 DDPG++ 高 131.7% | 同上 |

**实验 2（扩展性）**：规模因子 50 时第 30 次迭代即超过其他方法，最终延迟降 42.5%；knob 数 50/100/150 时均最好（Figures 6、8，PDF p.11）。

**实验 3（鲁棒性）**：过滤步骤识别 27 条错误知识中的 20 条（召回 74%），正确知识 123 条中保留 109 条（特异度 88.6%），输入知识准确率由 82% 升至 94%；GPT-4 在 50 条人为不一致摘要中识别 39 条（78%）并全部改正。过时知识影响小，错误知识影响程度不一，但仍优于 SMAC（§8.4、Figure 7，PDF p.11）。

**实验 4（成本）**：知识准备与结构化随 knob 数线性增长；gpt-4-turbo 处理 150 个 knob 约 2101.6k token、23.7 美元、4 小时，结果可复用到大版本更新前（Table 3，§8.5，PDF p.12）。

**边界**：结果以图表曲线呈现，正文无逐方法数值表；“16 倍”“30%”为摘要级汇总，正文未给出逐项计算（阅读者分析）。只评估离线调优；模块消融见技术报告；作者建议生产环境人工复核知识（§8.4、§8.6、§9，PDF pp.11–12）。
