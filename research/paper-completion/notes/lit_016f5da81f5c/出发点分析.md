# 出发点

LLM 显著提升了 NL2SQL 能力，Spider 排行榜上 LLM 方法与 PLM 方法的差距不断拉大（Figure 2，PDF p.2）。作者追问：是否已可放心部署于生产？排行榜第一是否总是最佳选择（§1 Q1–Q2，PDF pp.1–2）？

作者以 BI 场景说明三个现实需求：跨多个数据领域、复杂 SQL（多表 JOIN、嵌套、聚合）、同一意图的不同问法。Example 1（Figure 3）在 Spider 开发集上显示：Competition 领域里最好的 PLM 方法 RESDSQL-3B+NatSQL 达 83.9% EX，比最好的提示方法 DAILSQL（GPT-4）高 3.3%；仅含 JOIN 的子集上 PLM 方法领先，嵌套子集上 LLM 方法领先（§1，PDF p.2）。

由此得出"一刀切不成立"，需要工具从不同角度系统评估。作者同时指出已有实验的三点局限：只报整体结果而忽视使用场景；缺乏 LLM 与 PLM 方法的直接全面比较；对 LLM/PLM 模块组合的设计空间探索不足（§2.3，PDF p.4）。

出发点是"方法选型"，即帮从业者按场景选模型，而非提出新的 NL2SQL 任务定义（阅读者分析）。
