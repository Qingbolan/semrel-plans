# 解决的问题

**对象**：语义查询中由语义算子（map、aggregate、filter、join、top-k）产生的输出。SIC 可以约束算子生成的属性，也可以约束不生成属性的算子本身（如 filter 的推理过程）（§3.1，p.4074）。

**接口**：在 pipe SQL 语法中写 `ASSERT <pred>`，可用 AND 组合；每个约束可带 `RETRY <threshold>` 和失败模式 `CONTINUE` / `IGNORE` / `ABORT` `ON FAIL`（§3.1，p.4074）：

- CONTINUE：继续执行，错误向下游传播（输出元组被标记）。
- IGNORE：丢弃无效元组及其依赖元组（如同一聚合窗口）。
- ABORT：取消整个查询。

**约束类别**（Table 2，p.4075）：

| 类别 | 含义 | 执行方式 |
|---|---|---|
| Domain | 值属于类型/正则/取值集/长度范围 | 确定性 |
| Inclusion/Exclusion | 包含或排除某些词、内容、语气 | 字符串/正则为确定性；提示词描述时用 LLM |
| Grounding | 输出基于源数据 | 抽取式：确定性包含检查；生成式：LLM 或事实核查模型 |
| Soundness | 推理过程逻辑合理 | LLM 判官检查 CoT |
| Relevance | 输出与任务相关 | LLM 判官，可默认对所有生成属性启用 |
| Assertions | 任意谓词 | 黑盒，难优化 |

Grounding 约束沿血缘递归作用于所有祖先属性，因此每个约束只需比较本算子的输入和输出（§3.2，p.4075）。

依据：§3，pp.4074–4076；Listing 1、Table 2。
