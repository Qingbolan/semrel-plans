# 贡献与评价

**论文声称的贡献**（§1，p.2；§5，p.11）：

1. 分治 CoT：在一次 LLM 调用内把问题分解为伪 SQL 子问题，再组装并优化（Alg.1，p.4）。
2. 查询计划 CoT：把 SQLite `EXPLAIN` 输出改写成人类可读的三步推理（定位表、执行操作、选择列）（§3.3，p.4）。
3. 在线合成示例：针对每个测试问题，按 SQL 特征指南 `R_f` 和过滤后 schema 指南 `R_t` 现场生成少样本示例（Alg.2，p.5）。
4. 微调的两两比较选择代理，替代 self-consistency。

**评价**：值检索沿用 CHESS 的做法（§3.2，p.3），查询修正采用已有自反思方法（§3.4，p.5），二者不是新贡献。主要新意在生成器多样化与"成对比较 + 累计计分"的选择器组合。

阅读者分析：消融显示选择器贡献最大——用 self-consistency 替换选择代理掉 4.17 点，而单独去掉任一生成器仅掉 0.65–1.24 点（Table 7，p.11）。所以三个生成器单独的边际价值不大，主要价值在扩大候选覆盖面（Venn 图，Fig.3a，p.10）。

阅读者分析：论文未报告每题 LLM 调用数、延迟或费用；21 个候选的两两比较意味着每题最多 210 对、双向比较，推理成本可能显著，但原文没有量化。另，§3.5 称未微调的 Gemini-1.5-pro 二元准确率 58.01%（p.6），Table 5 却写 63.98%（p.8），两处口径未解释。
