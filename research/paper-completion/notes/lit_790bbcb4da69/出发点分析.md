# 出发点

作者认为 LLM 驱动的 Text-to-SQL 方法有三方面不足（§1，PDF p.1）：

- **L1 框架不完整**：方法层面存在空白，例如不核验数据库中实际存储的值、不对生成结果纠错、缺少少样本示例。
- **L2 多智能体衔接不稳**：LLM 不稳定，智能体之间缺乏一致性保证，后执行的智能体可能只用了一部分上游输出，导致幻觉累积。
- **L3 指令构造研究不足**：指令和步骤对 SQL 质量影响很大，前 LLM 时代曾用中间语言来缓解，但 LLM 时代对此研究较少。

作者据此参照人写 SQL 的过程：先了解库结构，用简单查询探查值的存储形式；再根据问题搭出 SQL 骨架、填入细节；根据执行结果逐步修改；遇到难题时参考别人的写法（§1，pp.1–2）。

另一个动机是可迁移性：实际中很难为特定任务准备大量定制训练数据，因此作者选择不做 SFT 或 RL，只在基础 LLM 上改架构（§1，p.2）。

依据：[arXiv:2502.14913v1（2025-02-19，ACM 模板会议信息未填写），15 页](https://arxiv.org/pdf/2502.14913v1)，§1，PDF pp.1–2。
