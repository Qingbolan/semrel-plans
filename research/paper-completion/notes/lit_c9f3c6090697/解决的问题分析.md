# 解决的问题

本文没有统一的形式化问题，而是以“数据库优化任务”为对象，例子集中在查询改写与索引调优（§1、§3）。

| 任务 | 输入 | 输出 | 目标 |
|---|---|---|---|
| 查询改写 | 提示 = `[Instruction] [Examples] Input: [x] Output:`，x 为 SQL | 等价且延迟更低、可在 PostgreSQL 执行的 SQL | 降低执行延迟（§1 Fig. 1，p.1；§2.2，p.3） |
| 索引调优 | 指令、示例、一组工作负载查询，可附 schema 或数据统计 | 一组索引 | 在空间预算内降低负载代价（§1，p.1；§3.2，p.8） |

三条技术路线的对比见 Table 1（p.4）：输入提示约调数千个参数、需几十个样本、只接受文本；微调涉及数百亿参数、数千样本、可接受非文本特征；预训练涉及千亿参数、百万级样本。

阅读者分析：工作单位是一条查询（改写）或一个负载（索引调优）；论文没有定义统一的评测集合或任务接口，这与基准论文不同。

依据：§1、§2.1–2.2、Table 1、§3.2，PDF pp.1–4、7–8。
