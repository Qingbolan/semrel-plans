# 贡献与评价

**论文声称的贡献（§1，p.2）：**
1. 把多智能体服务中的 KV-Cache 管理形式化为“预测未来访问模式”的问题，并给出预测器设计准则：融合跨工作流转移模式与单请求语义信号；多步（K 步）预测避免短视。
2. PBKV 的两条管理原则：分层驱逐（先回收已结束工作流的 retired cache，再按前瞻分数驱逐活跃缓存）与保守预取（只用空闲 GPU 空间和空闲 PCIe 带宽）。
3. Lipschitz 型保证：驱逐代价的遗憾随每节点预测误差线性增长，预测完美时趋于 0（Theorem 5.1，p.6；证明在附录 G）。
4. 在三类工作负载、两种模型上实现与评测。

**与已有工作的差异（§7，p.9）。** Continuum 面向 ReAct 单 agent 工具调用，用学到的 TTL 固定缓存；KVFlow 依赖静态 Agent Step Graph；Parrot、Ayo、Autellix 假设近似静态 DAG；PASTE、Speculative Actions 处理动态结构但只预测下一步。PBKV 的区别在于多步预测 + 跨工作流聚合打分。

**阅读者评估。**
- 消融显示最大增益来自“生命周期感知”这一不依赖预测的简单规则：PBKV-LAE 单独即把命中率提升最多 1.66×（Table 1，p.7）；预测器带来的 HE 增量明显，预取增量较小，作者也承认（§6.2）。
- 预测器训练与准确率实验只在 HoVer+LangChain 上报告（§4.1、附录 C），另两个工作负载的预测准确率未给出。
- 与 KVFlow 的比较只在作者构造的静态场景（FinanceBench+CrewAI）进行，因为 KVFlow 在动态循环下无定义（§6.1，p.6）；因此“优于 SOTA”的结论仅限静态工作流。
