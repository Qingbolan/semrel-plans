# 具体用例

原文没有贯穿全文的单一示例，下面按原文描述的组件拼出一个典型流程，组合方式为阅读者分析，各环节依据原文。

**用例：自动完成一次表格数据建模与可视化任务**

1. **规划者-执行者**（§3.1.2，pp.5–6；Figure 5）：规划者根据用户请求和之前的执行结果生成下一步或完整计划，执行者与环境交互完成具体步骤。
2. **预处理**（§4.2.1，p.18）：从数据库（SQL）或 API 收集数据；处理缺失值、用哈希或编辑距离去重、用 Z-score/IQR 检测异常值。
3. **编码者-审查者与反思**（§3.1.2；§3.4，pp.14–17）：编码者写代码，审查者检查并给意见；运行报错时依据错误日志做局部反思修正。
4. **建模与评估**（§4.2.4–4.2.5，p.19）：选择算法、用 Optuna/Ray Tune 调参；按任务用准确率、F1、RMSE 或轮廓系数等评估。
5. **可视化反馈**（§4.3，p.20）：如 MatplotAgent 把生成的图作为反馈信号，用来发现并纠正分析错误。

**原文指出的失败点**（§6，p.21）：智能体常误读不规则模式、把类别列当数值列、忽视缺失值结构；上游的错误过滤或错误合并会无声地传到后续建模，而现有反思只检查最近一步代码。

依据：§3.1.2、§3.4，pp.5–6、14–17；§4.2–4.3，pp.18–20；§6，p.21。
