# 评测与边界

**评测形式**：本文没有基线、指标或数值结果。§4 的 4 个案例只做定性判断，如“工作流顺利”“正确完成”（pp.18–25）。

**对已有基准的概述**（§3.7，pp.15–16）：
- DS-1000：1000 道题，覆盖 7 个 Python 数据科学库，按执行结果评测；
- MLAgentBench：机器学习研究工作流；
- InfiAgent-DABench：端到端数据分析。

作者指出，可视化等输出难以直接比较，评测方法仍是开放问题。

**原文列出的挑战**（§5，pp.26–28）：
- 模型层面：研究生水平的统计问题仍然困难，完整工作流的自动化成功率低（引 Spider2-V），多模态推理不足；
- 落地层面：本地部署与隐私之间的权衡；高并发下每个会话独立沙箱带来的资源压力；与 IDE 工作流的整合。

**可复现性**（§6，pp.29–30）：同一任务在不同提示措辞下会改变检验方法、图表类型和默认超参数。作者建议导出 Notebook、固定随机种子、使用 Git 和 Snakemake/Nextflow。

**阅读者分析**：
- 不能把本文当作数据智能体的性能证据，案例更像能力演示；
- Table 1 是作者对各系统的主观归类，部分条目是“-”（未知）。

依据：[arXiv:2412.14222v2，46 页](https://arxiv.org/pdf/2412.14222v2)，§3.7、§4–§6，PDF pp.15–30。
