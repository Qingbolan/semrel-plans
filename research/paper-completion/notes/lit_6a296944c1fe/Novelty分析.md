# novelty

原文自述三点：（1）评估分析理解而非流水线完成；（2）由已知潜在世界生成观测，为目标驱动分析提供真值并支持部分得分；（3）暴露早期分析错误（漏掉客群、合并事件、错误归因）如何传导到后续结论。

构建流程四阶段：SME 用声明式配置指定 Z（人设及精确人口权重、缺陷时间线、季节性评论分布、产品基础评分、人设偏好）→ 专家从 Z 手工推导评分细则（定量答案机械导出，定性答案由 LLM 评审按部分得分条件打分）→ 结构化生成（加权抽样分配人设，评分 = 基础分 + 缺陷影响 + 人设偏置 + 噪声）→ LLM 依据结构参数和人工评论风格生成评论文本。质控：结构一致性查询验证；对少量随机样本做定性抽查，修正泄露潜在状态、信号稀释、引入非预期因子或风格捷径等问题。一个重要设计是避免 Z 采用 LLM 分布先验：人设被手工设计为具体类型（如重视手套抓握的高尔夫爱好者、偏好美国制造的爱国买家），使 agent 套用通用先验标签会被扣分。

阅读者评估：这是 4 页的 workshop 短文，思路（合成潜在结构 + 恢复度评分）清晰，但规模很小：只有一个电商用例、18 个评分条目、一个 agent 产品（CoCo + Claude Opus 4.7）的三种配置，评审完全依赖 LLM，且作者明确尚未验证评审稳健性。贡献应视为评测框架提案与初步证据。

依据：[arXiv:2605.24183v1，4 页](https://arxiv.org/abs/2605.24183)，摘要、§3、§5，PDF pp.1–4。
