# 解决的问题

**任务定义**（§2，p.3）：输入自然语言问题或陈述 Q，以及可选上下文 D（段落、表格、图像或其组合）；输出正确回应 Q 的答案 A。表格问答中 Q 是问题，表格事实核验中 Q 是关于表的陈述。

**Binder 程序**：一个符号语言表达式 Z，在原语言无法提供所需功能处插入 API 调用 f(Q̂; D̂)。Q̂ 是原语言无法回答的子问题，D̂ 是回答它所需的上下文（如 Made_in 列）。若 Q̂ = Q 且 D̂ = D，就退化为端到端 LM 求解（§2.1，p.3）。

**两种 API**（§2.3，p.4）：`f_col` 把子表映射为一个新列，可放在 SQL 列名的位置；`f_val` 把子表映射为一个值，用于难以写成“新列 + ORDER BY”的情形，如“最适合正式场合的衬衫”。

**执行**：扩展语法后把程序解析成 AST，自底向上求值，支持嵌套 API 调用；API 输出存为与原语法兼容的变量，再交给现成解释器执行（§2.1，p.3）。

**推理流程**：给定 k 个示例（Qi, Di, Zi），Codex 生成 n 个候选程序，分别执行后多数投票得到答案（§2.2，p.4）。WikiTQ 与 MMQA 取 n = 20、温度 0.4；TabFact 取 n = 50、温度 0.6；执行阶段 API 调用温度为 0（附录 A.2，p.18）。

依据：§2.1–2.3、附录 A.2 与 Table 8，PDF pp.3–4、18。
