# 贡献与评价

**原文声称的贡献**（摘要、§1，pp.1–2）：

1. 把统一的 LM API 绑定到通用编程语言（SQL、Python），扩展其语法覆盖面，取代任务专用语言和神经模块。
2. 同一个 LM（Codex）既当程序解析器，又当执行时 API 的底层模型。
3. 免训练，只需几十个上下文示例；在 WikiTQ 和 TabFact 上超过需要上万条训练样本微调的方法。
4. 相比端到端方法，更可解释、可扩展到大表、对噪声更稳健；还可推广到 Python 和多模态（MMQA）。

核心新意是“在 SQL/Python 语法内部插入 LM 调用，并让 LM 自己决定插在哪里”。这与后来数据库领域的语义算子（在查询中嵌入 LLM 过滤、映射）思路相通，但 Binder 的程序由 LM 少样本生成，没有代价模型或调用优化（阅读者分析）。

**证据强度**：对“覆盖面提升”的支持较直接——在程序不可解子集上 Binder 比 Codex SQL 高 10.1 个百分点（Table 3）；在 100 个双方都答对的不可解样例中，虚假正确程序比例为 12% 对 33%（§4.1，p.6）。可扩展性与鲁棒性实验各只用 150 个样本的子集（§4.3，pp.7–8）。

依据：摘要、§1、§4.1–4.4、Table 3，PDF pp.1–2、6–9。
