# 工作负载

| 数据集 | 评测集合 | 说明 |
|---|---|---|
| WikiTableQuestions（WikiTQ） | dev 与 test | 需要复杂表格推理；按 SQUALL 约 20% 不能用纯 SQL 回答（§3.1） |
| TabFact | 官方小测试集 2,000 条 | 小表上的二分类事实核验；因时间成本只测小测试集（§3.1，p.5） |
| MultiModalQA（MMQA） | dev | 跨文本、表格、图像；图像先用 OFA 转成文字描述，按 Yoran et al. 预先检索相关段落和图像（§4.4，pp.8–9） |

**WikiTQ dev 划分**（附录 C.4，p.23）：按 SQUALL，程序不可解 625 条（22.08%）、可解 2,206 条（77.92%），合计 2,831 条（合计为阅读者计算）。作者在原始表上重新执行 SQUALL 的 SQL 后得到新划分：不可解 1,251 条（44.19%）、可解 1,580 条（55.81%），原因是 SQUALL 标注前人工清洗过部分表格。

**示例与成本**（§3.1，p.5）：每个数据集人工标注 14 个 Binder 程序作为上下文示例，受 Codex 8,000 token 上限约束；提示只输入表 schema 和前三行。TabFact 另用 vote-k 选择性标注 200 条训练样例作为检索池，按 SentenceBERT 向量内积为每题检索示例。评估 1,000 个样例约需 6 小时（每例生成并执行 20 个程序，Codex 限 200 次/分钟）。

**派生子集**（§4.3，pp.7–8）：大表实验从 WikiTQ dev 随机抽 150 题，用 Codex 把表扩充到 100/200/500 行，再由两名标注者重新写问答；噪声实验同样抽 150 题，把金标准列中 15% 的单元格替换为编辑距离最近的 WordNet 词或 ±1 的数字。

依据：§3.1、§4.3–4.4、附录 C.4，PDF pp.4–5、7–9、23。
