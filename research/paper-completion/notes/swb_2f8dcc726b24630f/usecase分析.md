# 具体用例

**原文工作流：O365 登录**（附录 A.7，PDF pp.12–13）：

1. 告警进入后，行为分析智能体根据规则名把它路由到 O365 登录工作流；
2. 证据获取智能体调用 `runStructuredQuery(GetRecentHighRiskActivity, account+tenant, key=user_email, time_iso)`，统计该用户近期高风险活动的行数；
3. 从告警中取出 O365 登录规则自身的风险分（而非整张工单的总分）；
4. 推理协调智能体按策略判定：风险分 ≤ 1000 为不可行动；> 1000 且近期高风险次数为 0 为不可行动；> 1000 且近期有高风险活动则可行动；
5. 输出 JSON 报告，含用户邮箱、高风险活动计数、原始行和理由摘要。

**另一工作流：多 ISP / 不可能旅行**（附录 A.5，p.11）：查询近期登录活动的地理位置和 ISP 字段，在 8 小时窗口内评估登录之间的距离与时间，并考虑 VPN、移动网络等合理解释，给出 `impossible_travel` 布尔值作为是否可行动的依据。

附录 A.7 的输出字段名为 `recent_activity_riskScore_greater_than_2000_count`，而策略阈值写的是 1000，二者口径不一致，原文未解释（阅读者分析）。

阅读者分析：这类分诊可看作"对每条告警做带工具查询的语义判定"，判定条件中既有确定性的数值阈值，也有需要语言理解的部分（如 VPN 等合理解释），适合拆成结构化过滤与 LLM 判定两步（阅读者分析）。
