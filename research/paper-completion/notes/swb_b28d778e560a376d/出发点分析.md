# 出发点

学术界（LOTUS、Palimpzest、ThalamusDB 等）和工业界（BigQuery AI Functions、Snowflake）都出现了用 LLM 求值、以自然语言配置的语义 SQL 算子，例如 `AI.IF(pic, 'the picture shows a red car')`（§1 Example 1.1，PDF p.1）。

作者指出这改变了查询优化的两点：（1）LLM 的每字节处理成本比关系处理高多个数量级，优化重点转向减少 LLM 调用、输入 token 与模型规模；（2）LLM 输出随机且不总是正确，准确率成为需要优化的指标。目标可写成“最小化 LLM 延迟与成本，同时最大化准确率”（§1，PDF p.2）。

TPC-H、TPC-DS、JOB 不含语义算子；多模态问答基准只评模型输出质量，不评成本与执行时间（§1、§2.4，PDF pp.2–3）。作者因此要做一个类似 TPC 风格、但聚焦语义算子开销与质量的基准。该想法源于 Dagstuhl 研讨会 25182（致谢，PDF p.12）。

依据：§1、§2.4，PDF pp.1–3。
