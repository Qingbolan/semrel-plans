# 出发点

结构化数据分析已很成熟，但大多数真实数据是图像、对话等非结构化形式。若不先转为结构化形式，传统 SQL 引擎只能支持有限查询；而预处理（实体检索、表单理解）又需要在预定义分类体系上训练（§1，PDF p.1）。

作者逐一指出已有途径的不足（§1，PDF pp.1–2）：

- 全文检索可扩展，但无法处理复杂语义推理；
- RAG 能在相关子集上问答，却不直接适用于跨整个大型数据库的聚合与语义分析；
- 长上下文 LLM 即使不计成本，做数据分析也仍有困难；
- 把 LLM 当作 SQL 的 UDF（如 Cheng et al.）仍需扫描整个数据库，对大规模非结构化集合代价过高。

**核心观察**：经典 SQL 引擎的效率来自两点，一是避免全表扫描的索引，二是选择最优执行顺序的编译。UQE 把"索引"转化为"学习搜索或抽样"，用统计上可靠的方法避免全扫描；再用编译系统决定子句执行顺序与组合，在保持语义的前提下最少调用 LLM（§1，PDF p.2）。

阅读者分析：这里的"效率"主要指 LLM 调用次数，采用的是近似查询处理思路，即结果为带方差的估计，而非精确答案（阅读者分析，依据 §5 自称属于 approximate query engine，PDF p.7）。
