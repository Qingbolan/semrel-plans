# 出发点

社区依赖公开基准及排行榜来比较 Text-to-SQL 技术并选型部署，而这些基准在问题构造与答案评测上都高度依赖人工标注，因此标注是否正确至关重要（Abstract、§1，PDF p.1）。

已有证据显示问题存在：Arcwise 团队报告 BIRD Mini-Dev 有 32% 的例子标注有误，另有研究报告 BIRD 金融领域 49% 的例子有误（§1，PDF p.1）。Spider 2.0 团队虽已用 LLM 改写问题并在两轮校验中分别修正了 45% 和 5% 的例子，但此前没有人系统审查过 Spider 2.0-Snow（§1，PDF p.2）。

作者把标注错误归为四类（§1，PDF p.1；判别标准见 §4.4，p.5）：

| 类型 | 含义 |
|---|---|
| E1 | SQL 语义与问题逻辑不符（漏/多过滤条件、比较符错、公式错） |
| E2 | 对数据或模式理解不足导致 SQL 与数据库不符（非唯一键连接未去重、缺聚合、缺格式转换） |
| E3 | SQL 与相关领域知识不符，或问题中给出的领域知识本身错误 |
| E4 | 问题有歧义：多种合理解读或输出格式不明 |

Figure 1 给出两个动机例子：Spider 2.0-Snow sf_bq291 中 Snowflake 的 ST_POINT 经纬度参数顺序写反（E1）；BIRD Mini-Dev 第 46 题把"1–12 年级"等同于包含幼儿园的"K-12"（E3）（PDF p.2）。

阅读者分析：动机的核心是"测量工具本身失真"——如果评测的金标准有一半是错的，排行榜上几个百分点的差距就失去意义。这对任何以执行结果为金标准的查询基准都适用。
