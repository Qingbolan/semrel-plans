# 解决的问题

**任务**：数据库异常诊断。输入为一次异常（含起止时间）、可调用的观测与优化工具、从文档抽取的经验；输出为根因及优化建议（§2–3，p.2）。

**异常类型**（§2，p.2）：运行缓慢、磁盘满、执行错误、挂起、崩溃五类。观测来源为日志、指标、追踪；例如 PostgreSQL 的 `pg_stat_statements`、Prometheus 监控指标。

**D-Bot 两阶段**（§3，pp.2–3）：

| 阶段 | 步骤 | 内容 |
|---|---|---|
| 准备 | 文档→经验 | 按章节切块（超 1k token 递归再切），逐块生成摘要，再结合相似摘要抽取经验（§4） |
| 准备 | 提示模板生成 | 用约 5 对输入–输出样例让 LLM 生成候选任务描述，按自定义评分（如检出根因比例）排序，保留 top-10，选最好的一个（§5） |
| 维护 | 工具学习 | 用 BM25、LLM 嵌入或稠密检索匹配工具，把 API 描述交给 LLM 调用（§6） |
| 维护 | LLM 诊断 | 树搜索（UCT 选择、反思、回溯），连续若干次（如 5 次）找不到新根因则终止（§7） |
| 维护 | 协作诊断 | Chief DBA、CPU Agent、Memory Agent 三个智能体按发言顺序和可见性规则交流，并做聊天摘要（§8） |

**经验格式**（§4，p.3）：四个字段 name / content / metrics / steps。示例 `many_dead_tuples`：活/死元组总数超过 1000、表大小超过 50MB 且死元组率超过 0.02 时判为根因。

依据：§2–8，Figures 2–4，PDF pp.2–6。
