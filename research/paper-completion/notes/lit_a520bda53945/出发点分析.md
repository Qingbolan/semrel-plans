# 出发点

原文指出已有语义分析工作的三类局限（§1，p.1）：
1. 基于编码的方案（如 Palimpzest、LOTUS）需要人写语义算子流水线，成本高；
2. 扩展 SQL 加入语义算子的方法难以处理拿不到 schema 的非结构化数据；NL2SQL 仅限 SQL 数据库，不能跨数据源；
3. 用自然语言对非结构化数据做分析的方法需先抽取成结构化数据，不适用于无法导出 schema 的场景。

三项挑战：从成千上万、缺少元数据的生产数据集中发现与问题相关的数据（以银行系统为例）；在数十种算子构成的庞大计划空间中生成逻辑正确的计划；检测计划错误并有效存储、复用错误反馈以抵抗 LLM 幻觉（§1，p.1）。

阅读者分析：其定位是“NL → 语义算子计划”的自动化入口，与 Palimpzest/LOTUS 的声明式接口互补；优化和执行层作者明确不声明贡献（§2.2 Remark，p.3）。
