# 解决的问题

要解决的是：在 SQL 内直接表达语义操作和混合检索（RAG）流水线，并让系统自动处理 LLM 调用的低层执行细节。

- 输入：DuckDB 中的表（也可通过 DuckDB 扩展访问 Parquet/CSV、PostgreSQL、MySQL），以及作为函数参数或模式对象给出的模型与提示。
- 处理单位：标量函数以单个元组为单位映射出一个新属性（文本、JSON、布尔、嵌入向量）；聚合函数把多条元组归约为一个值（文本/JSON、排序、最相关/最不相关元组）。见 Table 1，PDF p.2。
- 输出：普通 SQL 结果；可用 CTE 串联多次 LLM 预测（Query 2，PDF p.2），或组合向量检索、BM25、fusion 与 llm_rerank 构成混合检索（Query 3，PDF p.3）。
- 另有 ASK 功能把自然语言问题转换为带 FlockMTL 函数的 SQL（§2，PDF p.2）。

依据：[arXiv:2504.01157v1](https://arxiv.org/abs/2504.01157)，§2、Table 1、Queries 2–3，PDF pp.2–3。

论文没有给出语义算子的形式化语义或正确性定义，llm_filter 等函数的“正确输出”由 LLM 决定。（阅读者分析）
