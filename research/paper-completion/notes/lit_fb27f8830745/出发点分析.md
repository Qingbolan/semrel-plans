# motivation

企业电子表格工作簿可能含数百万单元格、跨表依赖和嵌入图表。现有方法分两类：压缩式（SpreadsheetLLM 的 SheetCompressor 把工作表压缩进上下文）和检索式（FRTR 把行/列/窗口/图像切块后做混合检索），但都是单次检索后生成，没有迭代修正；朴素全文注入则会超出上下文。真实分析师会跨表交叉引用、追踪单元格依赖、逐步收集证据，单次流水线无法模拟这一点，因为 LLM 不能重新查询、探索相邻区域或根据中间结果修正检索。此外，此前没有工作系统评估多模态嵌入模型对表格+图像混合内容的检索效果。

作者也认为现有 agent 方法（SheetAgent、SheetBrain、TableMind）要么依赖代码执行（可能陷入无效循环），要么需要微调/强化学习；BRTR 改为让通用 LLM 通过原生 function calling 使用结构化检索工具，不需训练，并限制工具调用次数。

依据：[arXiv:2603.06503v1，15 页](https://arxiv.org/abs/2603.06503)，§1–2，PDF pp.2–4。
