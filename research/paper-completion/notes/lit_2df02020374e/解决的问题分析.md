# 解决的问题

定义 2.2：给定查询 q 和规则集合 R，从 R 中选出规则序列 α，按序应用得到 q_α，目标是使 q_α 的执行代价最小。规则是三元组（条件 c、变换 t、匹配函数 f）。

R-Bot 的输入是一条 SQL、Calcite 规则集合以及离线准备的证据库（规则说明与改写问答）；输出是规则序列、改写后的 SQL 和 recipe 说明（Figure 2）。工作单位是单条查询。

在线流程：

1. 用匹配函数检索可用的规则说明；用“结构 + 语义”嵌入检索 top-k 问答（默认 k=10）；由 LLM 针对当前查询生成 recipe。
2. 按问答相关度给规则累计打分，得到初始序列；再依 recipe 过滤、排序；交给 Calcite 执行改写。
3. 反思：比较改写前后代价，并让 LLM 检查 recipe 是否都已实现，四种组合分别决定结束、继续新一轮或重新排序。

LLM 只决定选哪些规则、按什么顺序，等价性由规则引擎保证。（阅读者分析）
