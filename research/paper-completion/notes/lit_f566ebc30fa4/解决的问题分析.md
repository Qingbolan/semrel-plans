# 解决的问题

- 输入：自然语言问题 Q、数据库 DB（模式、外键与实际数据值）；BIRD 还附带 evidence 外部知识提示（见 Fig.4 示例）。ICL 生成器需要同一基准训练集作为示例库（§3.3，p.10）。
- 输出：一条最终 SQL，按执行结果与标准 SQL 是否一致评判（EX）。
- 处理单位：单个问题。离线阶段对每个新数据库一次性为 TEXT 列（排除 UUID/纯数字 ID 类列）建立按列的值向量索引（Qwen3-Embedding-0.6B + Chroma HNSW，§3.1，pp.6–7）。
- 在线流程：关键词抽取→每列 top-K 值→三路模式链接（直接、反向：先生成草稿 SQL 再解析、基于值相似度阈值）取并集并按外键补全闭包（Alg.2）→骨架式/ICL/分治三生成器并行（Alg.3）→每个候选单次通过“语法→逻辑→质量”检查器链，发现问题才调用 LLM 修复（Alg.4、Table 2）→执行聚类，最大簇占比超过 θ_conf 直接输出，否则对 top-K 簇代表做三次采样的成对裁决，以 Conf×WinRate 打分（Alg.5，§3.5）。

阅读者分析：问题定义沿用标准单轮 Text-to-SQL；系统需要对库执行候选 SQL，因此默认可以在线访问并执行真实数据库，这在只读权限受限或大表扫描昂贵的环境中是额外成本。

依据：[arXiv v3，PACMMOD Article 158，28 页](https://arxiv.org/abs/2510.17586)，§2–§3，pp.4–14。
