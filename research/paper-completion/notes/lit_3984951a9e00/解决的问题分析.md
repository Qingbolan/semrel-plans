# 解决的问题

**任务**：跨域 Text-to-SQL。输入为自然语言问题 q 和目标数据库 D 的 schema，输出 SQL 查询；目标数据库不出现在示例候选集的数据库中（§3.2，p.4）。

论文把问题拆成三个可调“旋钮”（§3，pp.3–6）：

| 旋钮 | 形式化 | 研究对象 |
|---|---|---|
| 问题表示 | 选择表示函数 σ(q, D)，最大化 P(s\*\|σ(q, D)) | BS、TR、OD、CR、AS 五种表示；外键与“with no explanation”规则 |
| 上下文学习 | 从候选集 Q 中选 k 个示例 Q′，并决定如何组织 | 随机、问题相似、掩码问题相似、查询相似、DAIL 选择；全信息、仅 SQL、DAIL 组织 |
| 监督微调 | 在训练集 T 上最小化生成 SQL 与标准 SQL 的损失，同时选择 σ | 开源 LLaMA 系列 |

**DAIL-SQL 的定义**（§3.3，pp.5–6；附录 A.2，pp.15–16）：问题表示采用 CR（`CREATE TABLE` 语句含主外键）；选例时先把问题中的表名、列名、值掩码，按句向量欧氏距离排序，再用预测 SQL 骨架与候选 SQL 的 Jaccard 相似度过滤（阈值 τ，实验中 0.9，排行榜提交 0.85）；组织时只放问题与 SQL，去掉示例的 schema 以节省 token。预测 SQL 由 Graphix 生成；排行榜提交改用 GPT-4 先跑一遍。

**评测单位**：单个问题–SQL 实例，指标为精确集合匹配（EM）和执行准确率（EX）（§4.1，pp.6–7）。

依据：§3–§4.1、附录 A.2，PDF pp.3–7、15–16。
