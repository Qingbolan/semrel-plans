# 解决的问题

**任务对象**：在句子中识别 VMWE，即找出构成同一表达的词元（可不连续）并标注类别（§1、§10，PDF pp.2、6）。类别体系见 §1（PDF p.2）：

| 类别层级 | 类型与示例 |
|---|---|
| 通用 | VID 动词习语（德 `schwarz fahren`"逃票"）；LVC.full / LVC.cause 轻动词结构（`držati govor`"发表讲话"） |
| 准通用 | IRV 固有反身动词（葡 `se queixar`）；VPC.full / VPC.semi 动词-小品词（英 `do in`、`eat up`）；MVC 多动词结构（法 `laisser tomber`） |
| 语言特有 | LS.ICV，目前仅意大利语（`smetterla`） |
| 实验类 | IAV 固有介词动词，可选标注 |

**数据单位与格式**（§5，PDF p.4）：句子级 `.cupt` 文件，即在 UD CoNLL-U 基础上增加一列 VMWE 标注；形态句法层（词元、词性、形态特征、依存）来自 UD 树库或 UDPipe 自动分析，并非 PARSEME 标注员产出。

**划分问题**（§6，PDF pp.4–5）：每种语言重新划分 train/dev/test，使测试集相对 train+dev 恰有 300 个未见 VMWE、开发集相对 train 有 100 个未见 VMWE。理由是 1.1 共享任务观察到系统性能与训练集大小弱相关，而与测试集中未见 VMWE 的比例强相关。

**评测指标**：全局基于 MWE 的 P/R/F1（Table 1，PDF p.8）。
