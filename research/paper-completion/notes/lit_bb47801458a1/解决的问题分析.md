# 解决的问题

输入：关系表 + 一条 SemaSQL 查询。NL 表达式写作 `s'…{列}…'`，占位符指向列；SemFilter 放在 WHERE/HAVING，SemProj 放在 SELECT，SemJoin 放在 JOIN ON，SemAgg 用 `sem_agg()` 并可配 GROUP BY（§3.1，pp.3–4）。输出：普通 SQL 结果表（过滤后的行、新文本列或聚合文本）。

工作单元：每个语义算子的参考算法按元组调用 LLM——SemFilter/SemProj 为 O(|T|) 次，SemJoin 为嵌套循环 O(|T1|·|T2|)，SemOrderBy 为选择排序 O(|T|²) 次比较，SemAgg 为一次（超上下文时分层聚合）（Table 1，§2.1，p.3）。

系统要解决的是：在不降低（相对参考路径的）质量的前提下，减少 LLM 调用次数与 token，并在执行时选择延迟/成本帕累托最优的路径。用户可设定对结果不一致的容忍度 τacc（§5.1–5.2，pp.6–7）。

明确不在范围内：单算子算法改进、存储层优化、LLM 路由与模型选择、隐私治理与外部推理容错（§2.2 末，p.3）。
