# 出发点

作者认为现有语义查询系统有两种表达方式且各有缺陷：基于 DataFrame 原语的系统（Lotus、Palimpzest）有专门算法，但缺少 DBMS 的向量化、流水线并行、I/O 与内存管理；把 LLM 调用封装为 SQL UDF（FlockMTL、pgAI）则让语义逻辑对优化器不可见，实现与维护负担落在用户身上（§1，p.1）。

另一层动机是语义算子破坏了经典优化的前提：其结果依赖 NL 表达式、提示方式和具体模型；SemFilter 只有在逐元组独立提示且温度为 0 时才可交换，SemProj/SemJoin 的交换律、结合律一般不保持语义；代价由外部推理环境（KV cache、continuous batching、网络）决定，难以用数据库统计静态估计（§1 p.2；§2.2 p.3）。因此作者主张把语义算子当作计划中的一等算子，优化目标是减少 LLM 调用，并在精度约束下权衡延迟与 token 成本。

依据：§1–2，PDF pp.1–3。
