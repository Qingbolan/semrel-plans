# 出发点

作者从工业 BI 部署中归纳出三项挑战（§1，pp.4860–4861）：

- **C1 功能缺失**：传统 BI 系统覆盖数据管理、SQL 生成、洞察发现，但依赖启发式规则；LLM 方法（如 MAC-SQL、CHESS）只优化 NL2SQL 准确率，把 SQL 执行当作终点，缺少归因分析等下游任务和领域知识库，用户需在 SQL 编辑器、看板平台、知识检索之间手动切换。
- **C2 交互受限**：主流 NL2SQL 面向单轮对话（SRD）；多轮对话（MRD）中后续问题常省略已给出的上下文（如 Fig.1 中第二、三问省略"2023 年"），且缺少面向用户的意图澄清。
- **C3 领域适配成本**：不同领域表结构（金融嵌套表 vs 广告宽表）与业务算子语义差异大。作者的部署统计显示，直接迁移模型约三分之二的生成 SQL 有业务逻辑错误；传统微调平均需 5.5 人日标注 200 条种子查询。

阅读者分析：这些统计（三分之二、5.5 人日）是作者内部部署数据，论文未给出测量方法细节（阅读者分析）。
