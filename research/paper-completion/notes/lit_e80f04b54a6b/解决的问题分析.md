# 解决的问题

**总体任务**：给定自然语言查询和相关数据集（企业数据库表或笔记本中的变量），在笔记本中生成或修改 SQL、Python、图表或 Markdown 单元，完成 BI 任务；用户可接受、编辑或拒绝结果（§III，p.4）。

| 子问题 | 输入 | 输出 |
|---|---|---|
| 知识生成（§IV-A） | 表 schema S、脚本历史 H、血缘 L、分数阈值 T | 库/表/列三级 JSON 知识：描述、用途、标签、派生列计算逻辑等 |
| 知识检索与 DSL 翻译（§IV-C） | 用户查询、知识图谱 | 改写后的查询、top-K 知识节点、含 MeasureList/DimensionList/ConditionList 的 JSON DSL |
| 智能体通信（§V） | 用户查询与各智能体能力 | FSM 执行计划；六字段信息单元（Data Source、Role、Action、Description、Content、Timestamp） |
| 上下文管理（§VI） | 笔记本单元、查询 | 按变量引用构建的 DAG，经遍历和按任务类型剪枝后的最小相关单元集 |

覆盖的任务类型：NL2SQL、NL2DSCode（数据科学代码）、NL2VIS、NL2Insight，以及内部场景中的异常检测、因果分析与时间序列预测（§VII-A、§VII-D，pp.9–11）。

工作单元：评测时为单条查询（公开基准的单个问题、内部数据集中的查询-表-列对或查询-DSL 对）；部署时为笔记本中的一次单元级或笔记本级请求。

阅读者分析：DSL 是连接自然语言与 SQL/Vega-Lite 的中间表示，评测中的 NL2DSL 准确率反映的是这一中间层，而非最终 SQL 执行结果。
