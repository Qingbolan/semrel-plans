# 出发点

BI 工作流包括数据准备、分析和可视化，通常需要数据工程师、数据科学家与分析师协作，并使用 VS Code、Power BI、Tableau 等不同工具（§I，p.1）。已有 LLM 智能体多聚焦 NL2SQL、NL2VIS 等单项任务，角色、任务与工具的割裂导致反复沟通、延迟和错误（§I，p.1）。

作者归纳了三项挑战（§I，pp.1–2）：

- **C1 缺乏领域知识**：真实业务表大而脏，列名语义模糊，查询含企业黑话；微调和持续预训练难以获得及时语料，手工构建知识库低效。
- **C2 跨任务信息共享不足**：复杂查询跨多个智能体，例如 SQL 智能体取到的数据要准确传给图表智能体；ChatDev、CAMEL 等依赖自然语言通信，易失真。
- **C3 上下文管理**：笔记本中代码、结果、图表等多模态上下文交织，只有部分与当前任务相关；全部塞入或只用单模态上下文都不合适。

作者在腾讯的调研显示 85% 的表缺少完整元数据，但大多数表关联了 SQL 或 Python 处理脚本（§IV-A，p.5），这成为自动生成知识的出发点。

阅读者分析：动机来自企业部署场景，"85%"是作者内部调研数字，原文未给出调研的表数量或方法。
