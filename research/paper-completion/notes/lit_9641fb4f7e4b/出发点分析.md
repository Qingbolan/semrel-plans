# 出发点

LLM 解决复杂任务依赖手工设计的 agentic workflow，即带详细指令的 LLM 调用序列；设计和调优这类工作流费人力，也难以迁移到新领域（§1，PDF p.1）。

已有自动化方法各有缺口（§1、§3.2，PDF pp.1–2、5）：
- DSPy 一类方法需要先手工搭好工作流，再做 prompt 优化；
- TextGrad、GPTSwarm 等方法的优化目标与表示难以覆盖多样的工作流结构；
- ADAS 用代码表示工作流，表达能力较完整，但采用线性启发式搜索，在有限轮数内难以找到有效的工作流。

作者还指出，把历史工作流不断堆进 prompt 让 LLM 生成新结构，会随着 token 累积丢失信息，难以朝具体指标优化（§4，PDF p.6）。

阅读者分析：真正的动机是“搜索效率”，即在代码表示带来的巨大空间中，用树结构保存经验并定向修改，而不是提出新的工作流表达能力。
