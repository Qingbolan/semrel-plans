# 出发点

现有 agent 基准（SWE-Bench、Terminal-Bench、BrowseComp 等）测的是模型在人工设计的工作流中执行任务的能力，而 agent 脚手架本身（提示、控制流、工具）几乎全由人写（§1，pp.1–2）。随着模型变强，直接测任务执行的基准很快饱和（Fig.1，p.2）。

作者想测更高一层的能力：模型能否像系统架构师一样，自主设计、实现、评估并迭代一个任务求解 agent（§1，p.2）。理由有二：一是它连接"写代码片段"和"构建完整软件系统"；二是可作为递归自我改进的可操作代理指标。作者还从安全角度说明，高优化压力可以暴露错位行为（§1，p.2）。

与相关工作的区别：ADAS、Gödel Agent 等提出 meta-agent 框架，MAC 不提新架构，而是评测通用代码 agent 充当 meta-agent 的能力；作者称其为 PostTrainBench 在 agent 开发上的对偶（§2，p.3）。

依据：[arXiv:2606.04455v1，20 页](https://arxiv.org/pdf/2606.04455v1)，§1–2，PDF pp.1–3。
