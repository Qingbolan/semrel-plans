# 贡献与评价

**论文声称的贡献**（§1，p.2）：(1) 关系型 LLM serving 的新架构和通用 API，支持现有语义算子实现；(2) 支持流水线、高并行并控制驱逐的自适应调度器；(3) 内存估计、pin 与死锁检测/恢复等内存管理技术；(4) 与依赖物化和请求中心 serving 的现有 SQPS 做比较。作者称 Kalypso 是“第一个关系型 LLM serving 系统”（p.2）。

**关键机制**：
- **自适应阶段预算**（Algorithm 1，§5.3 pp.6–7）：初始时除末阶段外每个阶段只给 minBudget（执行一个任务并保留其前缀所需内存），末阶段拿剩余内存。每个阶段按等待队列长度与阈值 high_s = α·budget_s/minBudget_s、low_s = β·budget_s/minBudget_s 判定饱和或饥饿；饱和则以 Δ 为块把空闲预算转给末阶段，饥饿则把预算向上游转移。实验 α=1、β=0.5（§7.1）。
- **token 上界估计**（§6，p.8）：filter 等可设静态上界；map 类算子在线记录输出/输入 token 比，取校准后的第 99 百分位作为上界，超出则中断、提高上界并重新入队。
- **虚拟 pin 与显式 pin**（§6）：虚拟 pin 不改引擎，靠控制启动哪些任务、占多少内存，并假设 LRU 驱逐；显式 pin 改 vLLM 约 200 行（§7.4）。死锁通过“有等待请求但无运行请求”检测，检测到后解除全部 pin 并临时切到虚拟 pin。

**阅读者评价**：
- 把关系执行中的流水线/物化取舍与内存感知准入控制搬到 KV cache 层，定位清晰，且与 SQPS 层的调用削减方法互补（原文 §1、§8 亦如此表述）。
- 调度器为启发式（阈值 + 固定块转移），论文没有给出最优性或复杂度分析；α、β、Δ 的敏感性未单独报告（Δ 的取值未在正文给出）。
- “不改变语义和准确率”在机制层面成立，但实验中 Kalypso 与 Lotus 的级联配置并不相同（见 benchmark 分析），论文未报告任何输出质量指标。
- §5.1 末尾残留一句像是作者自查注记的话：“Figure 4 says that the queue contains the outputs of the tasks. The rest of the paper … say that the queue contains the new tasks.”（p.5），说明 v2 文本仍有未清理处。
