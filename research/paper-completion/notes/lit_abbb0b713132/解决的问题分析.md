# problem

**输入**：一道自然语言 beyond-database 问题；一个删除了部分列/表的 SQLite 数据库；SWAN 提供的元数据——需要由 LLM 生成的缺失列/表清单、连接已有表与 LLM 生成表的最小键（PK-FK）、以及取值列表（如出版商名称）（§3.2–3.4、§4.1.1，pp.3–4）。**输出**：查询执行结果，与原 BIRD 金 SQL 在原库上的执行结果比较。

**每题提供**（§3.5，p.3）：(i) 把 LLM 生成值视为物化表并与库表连接的混合 SQL；(ii) 使用 BlendSQL 函数直接调用 LLM 的混合 SQL；(iii) 对应的 BIRD 金 SQL。这些混合查询都是人工编写、可执行的；**从自然语言自动翻译为混合查询留作未来工作**。因此本文评测的不是 text-to-SQL，而是“给定人工混合查询时，LLM 生成数据的正确性及其对结果的影响”。

**两类数据生成挑战**（§3.3，p.3）：自由形式生成（如由学校名生成学校网址）与取值选择（如从给定出版商列表中选）。

**键设计**（§3.4，p.3）：整数外键对 LLM 无意义，因此改用有意义的键，如 (superhero_name, full_name)，并保证无重复。

**两种解法**（§4，pp.3–4）：
- HQDL（模式扩展）：每个键调用一次 LLM 生成整行所有缺失列，用 csv reader 解析并插入新表；一对多关系压成逗号分隔长字符串；随后执行普通 SQL。
- 混合查询 UDF：在 SQL 中直接调用 LLM 函数（以 BlendSQL 实现，示例展示 BigQuery ML.GENERATE_TEXT 写法）。

**工作单位**：评测以“题”为单位计执行准确率；事实性以“生成的单元格”为单位计 F1，再按库平均（§5.1，p.5）。
