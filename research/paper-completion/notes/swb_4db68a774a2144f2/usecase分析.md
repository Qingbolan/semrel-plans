# 具体用例

**Venmo 发起收款请求**（AppWorld 024c982，§6.1、Figure 2，pp.5–6）：三个实例共享骨架——解析请求账户、认证、解析收款人、创建请求、报告。三者共发出 34 次 API 调用，其中约一半是不绑定任何运行时值的 schema 查询（`api_docs`），因而被移除。一次带修正凭据的认证重试被合并；`page_index` 0,1,2 而查询不变的三次好友列表调用被识别为分页循环。

依赖方面，`venmo.auth` 产生的 access token 被 `venmo.payment_requests` 消费，被确认为硬边；九次调用之前读取的手机分支密码也被找回为非相邻硬边。收款人解析有两条分支：两个实例用 `venmo.search_friends`，一个用 `phone.search_contacts`。由于轨迹没有显示是什么条件选择了分支，该选择被标为 LLM_OR_DYNAMIC。

热会话下运行时调用为 3、3、5 次，合计 34→11。

**对照用例**：Spotify/Todoist 意图共 106 次调用；每首歌的搜索被保留为并行 fan-out。但所有实例都读过“添加”和“删除”两份文档，且没有任何调用记录操作方向。由于两者都是不可逆的相反变更，编译器拒绝输出可执行图（§6.1、Figure 3，pp.6–7）。
