# 解决的问题

**输入**：一个意图簇 `C = {τ1…τm}`，即同一任务的若干变体轨迹，以无监督方式发现。每条轨迹为 `τ = (c, u, e1…en, y, z)`：系统上下文、用户请求、执行事件、最终输出和元数据；事件可以是消息、推理摘要、工具调用（名称 + 结构化 JSON 参数）、工具输出或异常、状态更新、人工批准。允许“部分可观测”：只记录参数而不记录输出（§2，pp.2–3）。

**输出**：工作流 `W = (V, E, B, G, I, O)`。节点类型包括 START/END、TOOL、TRANSFORM、DECISION、LLM、HUMAN。每个参数绑定到字面量、工作流输入、先前输出、确定性变换或 LLM 结果；绑定的来源类别为 CONSTANT、USER_INPUT、COPY_EDGE、TRANSFORM_EDGE、LLM_OR_DYNAMIC（§2、§3.4，pp.2–4）。

**关键判定**：对 `a ≺ b`，只有当 `b` 的某个参数值 (i) 可追溯到 `a` 的输出，且 (ii) 其他来源（用户话语、嵌入的静态上下文、schema 默认值、其他更早调用的输出）都被排除时，才承认硬边 `a → b`。每条硬边附带证据元组 `⟨consumer, arg_path, value, presumed producer, exclusions⟩`；存在合理替代来源时降级为 suspected，不施加顺序约束（§3.3，pp.3–4）。

**拒绝编译**：如果不可逆副作用在轨迹中欠定，就不输出可执行图，而是升级处理（§3.5，p.4）。
