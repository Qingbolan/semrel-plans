# 评测与边界

**基线**（§2.4、Table 1，PDF p.5）：训练集词典 + Levenshtein 滑窗查找；链接沿用训练集中同一提及的码；索引把链接结果汇总。

**参赛概况**（§4.1、Table 2，PDF p.10）：47 支注册队伍，9 支提交；NER 9 队、链接 7 队、索引 4 队，共 68 个 run，每队至多 5 个 run。

| 子任务 | 基线 F1 | 最佳队伍 | 最佳 F1 | 来源 |
|---|---|---|---|---|
| NER | 0.4744 | BIT.UA（Transformer+masked CRF+数据增强） | 0.7985 | Table 3，p.11 |
| 链接 | 0.4613 | Vicomtech（SapBERT 语义检索/交叉编码） | 0.5707 | Table 4，p.12 |
| 索引 | 0.5619 | Vicomtech | 0.6242 | Table 5，p.13 |

**实验观察（§4.3，PDF pp.12–13）**：9 支 NER 队伍全部使用 Transformer，RoBERTa 最常见。使用 GPT-3.5/GPT-4 少样本提示的队伍（Samy Ateia）三项均较弱，召回尤低：GPT-4 的 NER F1 为 0.4814，链接 F1 为 0.1976，索引 F1 为 0.2695。作者推测 LLM 未能有效捕捉提及与 SNOMED 码的对应。索引子任务没有新系统，均复用前序系统。

**边界**：链接为端到端评测，分数混入 NER 误差（§2.3，p.5）；测试集无词表码的提及被剔除（§3.3，p.8）；SNOMED CT 缺概念、缺上位码、近义重复码使人工规范化本身也困难（§5，pp.14–15）。

阅读者核对：§4.2 正文称 BIT.UA 最高召回为 0.7984，但 Table 3 中 BIT.UA 各 run 召回最高为 0.7894（run1），run4 为 0.7878；索引最佳"精确率 0.6371、召回 0.6295"分别来自 run4 与 run1/run5，并非同一个 run（阅读者分析）。
