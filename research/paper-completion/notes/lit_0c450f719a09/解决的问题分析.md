# 解决的问题

输入是应用以 SemanticFunction 形式提交的一组 LLM 请求：每个请求是带 `{{input:x}}`/`{{output:y}}` 占位符的提示模板，占位符绑定 Semantic Variable（可带字符串变换），并在 `get` 时对最终变量标注性能目标（端到端延迟或吞吐）。输出是各 Semantic Variable 的值。

服务端的工作单位是会话内的请求 DAG：节点为请求和变量，边由占位符引用确定。系统要把请求分配到 GPU 引擎，使各应用的端到端目标得到满足，同时提高集群利用率。

关键原语（Figure 8）：`GetProducer`/`GetConsumers` 恢复依赖；`GetPerfObj` 取目标；`PrefixHash` 在每个变量边界处计算前缀哈希，用于快速发现可共享前缀。

不支持动态控制流和原生函数（如 Python 代码），这些仍需在客户端执行（§6）。

依据：[原文](https://www.usenix.org/system/files/osdi24-lin-chaofan.pdf)，§4.1–4.2、§6–7，PDF pp.5–9。
