# 解决的问题

**输入**（§3，Setup，p.3）：一个 DuckDB 数据库连接、表名和 LLM API key；也可传入 Pandas DataFrame，由系统注册为 DuckDB 视图。可选输入是与表相关的自然语言文档。

**输出**（§3.3，p.6）：一是供分析师使用的画像页面，语义上确为错误的项标红色感叹号并附解释，仅在统计上异常的项标绿色对勾并附解释；二是汇总语义上下文、统计画像、语义画像和语义复核的 JSON 文件，供 Text-to-SQL 等下游 LLM 应用构造提示（Fig.5，p.5）。

**三步流程**（§1，p.2；Fig.2–3）：

1. **语义上下文**：根据前 5 行和文档生成表摘要，要求 LLM 用 `<u></u>` 标出所有列，并用测试程序检查是否覆盖全部列；把列分层分组并输出 JSON，检查每列恰好出现一次；对每组取 10 行生成列摘要（§3.1，p.3）。
2. **语义画像**：对每类错误，让 LLM 给出期望值，如是否允许缺失、期望分位数、期望字符串样例，并附推理文本（Thought）（§3.2，p.4）。
3. **语义复核**：比较统计画像与语义画像；有差异时由 LLM 判断是否可接受，输出布尔报警和推理文本（§3.2，p.4）。

**错误类型与统计画像来源**（Table 1，p.3；§3.2）：重复、列类型、唯一键、伪装缺失值（统计侧用 FAHES）、缺失值、数值异常（0–4 分位数）、字符串异常（统计侧用 RAHA 提取正则）、缺失记录（分组计数）。处理顺序为先表级，再列组级，最后单列级。每一步用户都可查看和编辑（§3.1.4、§3.2.9）。
