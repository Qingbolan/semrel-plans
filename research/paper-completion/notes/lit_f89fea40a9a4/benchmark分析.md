# 评测与边界

基线（§7.1，PDF p.10）：LLM（直接回答）、RAG（单次检索后生成）、IterRAG（迭代生成检索查询，5 轮）、RecurRAG（递归分解查询，5 轮）。这些都是不修改模型的固定流水线方法。

指标：准确率，使用 CRAG 官方自动评测（规则匹配加 GPT-4 判定）；平均端到端延迟；平均 token 消耗。

**实验 1（准确率，§7.2，PDF p.11）**：原文称在各类问题上 AOP 都优于基线，提升最多达 45%。正文只给出 Comparison 类的数值，其他类别只有柱状图（Fig. 7）。

| 方法 | Comparison 准确率 |
|---|---|
| LLM | 9.30% |
| RAG | 24.3% |
| IterRAG | 33.9% |
| RecurRAG | 38.1% |
| AOP | 54.1% |

阅读者核算：54.1−9.30=44.8 个百分点，“45%”应指与直接问 LLM 相比的绝对差（阅读者分析）。

**实验 2（效率与非结构化分析，§7.2–7.3，PDF p.11）**：

- 延迟：与 IterRAG/RecurRAG 相当，比 RAG 慢（Fig. 8a）。
- token：比 RAG 多，比 IterRAG/RecurRAG 少（Fig. 8b，原文归因于上下文管理）。
- 优化消融：Multi-hop 上关闭并行/预取（AOP-Seq）需 17.8 s，开启后 7.3 s，加速 2.4 倍（Fig. 9a）。
- 非结构化分析：25 条查询上比基线最多高 52%（Fig. 9b）。

阅读者分析的局限：只用了一个 8B 模型；没有报告重复运行的方差或显著性；基线不包括 LOTUS、Palimpzest 等语义算子系统或其他自动编排方法；25 条查询的样本很小；代价模型和基数估计的准确性没有单独评测；“首个”的说法以作者综述的相关工作为准。
