# 解决的问题

问题被表述为：给定结构化或半结构化数据源（关系库、数仓模式、分析数据集、日志），为每一列生成上下文相关、人可读的描述，并注入数据目录（Article Scope，PDF p.2）。

框架有三部分（Methodology，PDF p.3）：数据抽取层（智能采样代表性行以适配上下文窗口，发送前脱敏）、LLM 处理模块（GPT-4，零样本/少样本/上下文增强/模板/自适应提示，Table 2）、元数据注入服务（语法与语义校验后写入目录）。

原文没有给出形式化定义、输入格式、提示文本、采样规模或输出长度限制。工作单位可推断为“列”（原文称列描述是企业数据理解的原子单位，PDF p.3），但未说明是一列一次调用还是批量调用；Operational Considerations 只提到批处理时把多列合并到一次 API 调用（PDF p.6）。

依据：Article Scope、Methodology、Operational Considerations，PDF pp.2–4、6。
