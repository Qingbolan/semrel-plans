# 贡献与评价

**原文贡献**（§1 列 7 项，归并如下）：

1. **HO-Tree 表示与树操作**：显式建模表头与内容的层级、包含关系。
2. **HO-Tree 构造**：Excel 转 HTML 后用无头浏览器截图，让 VLM 列出可能的 JSON 键作为候选表头，再用嵌入相似度与单元格匹配；按三条规则切分子表——整行/整列合并单元格视为 L.4 顶层表头；同时存在顶部与左侧表头时，单元格多的一侧构造 MTree；检测到 L.3 时递归切分。最后 DFS 合并。
3. **问题分解与对齐**：按问题相似度动态检索分解示例；先自顶向下检索、失败后转自底向上；按列类型（离散、连续、非结构化）分组，以提高大表检索精度。
4. **两阶段验证**：前向检查执行结果非空、与问题相关；后向生成同答案的替代问题，比较其流水线与原流水线的相似度，作为可靠性分数。
5. **SSTQA 数据集**及与 9 个基线的对比。

**阅读者分析（评价）**：

- 主要新意在表示层：把布局理解从问答中剥离，LLM 只看 JSON 化的表头并生成操作。消融中去掉 Table2Tree 降 15.15 点，是最大的单项贡献，支持这一设计。
- 验证机制较启发式：后向验证只给出相似度分数，论文未说明阈值如何影响最终答案，也只报告了 4.78% 的“假阴性率”。
- SSTQA 由作者构建、问题部分由 LLM 生成后再经人工核验，评测方法与数据集出自同一团队，存在评测设计偏向本方法的风险。
- 主模型 DeepSeek-V3 与基线“DeepSeek-V3 直接作答”对比，能较干净地衡量框架增益：Table 5 中为 72.39 对 63.22。
