# 具体用例

**原文场景**（Figure 1、§3.1、§3.5）：一份 10-K 中的句子或表格里有多处需要打标签的数字（Figure 1 用蓝色标出）。完整流程为：

1. **FinNI**：模型读入一个句子或带 `<table>`、`<tr>`、`<td>`、`<th>` 结构的表格，输出 `{"results": [{"Fact": ..., "Type": ...}]}`；没有可标注数值时输出空列表。
2. **FinCL**：对每个抽出的事实，构造"实体 + 类型 + 上下文"查询。上下文采用结构感知方式：句中实体用整句，表格实体按行列位置构造（附录 H）。用向量检索取前 200 个 US-GAAP 概念，由 LLM 选出一个，例如 `us-gaap:CashAndDueFromBanks`（§3.1 示例）。

**检索效果**（附录 H、Table 13）：结构感知上下文的整体 Acc@200 为 0.3274，其中句子 0.6535、表格仅 0.2959；固定 50 字符窗口在表格上 Acc@200 只有 0.0089。

**误差传递**（§4.4、Table 8）：以 DeepSeek-V3 为例，端到端流水线准确率 0.1074；给定金标准实体（FinCL）0.1889；给定含金标准的候选只做重排 0.2144。

阅读者分析：表格事实是 XBRL 数值的主体，而检索在表格上覆盖不到 30%，这对把此类任务做成"检索 + LLM 判定"的语义算子是直接的警示：候选生成阶段决定了上限。

依据：[arXiv 2505.20650v5，17 页](https://arxiv.org/abs/2505.20650)，§3.1、§3.5、§4.2、§4.4、Figure 1、Tables 8、13、附录 H，PDF pp.2–7、14。
