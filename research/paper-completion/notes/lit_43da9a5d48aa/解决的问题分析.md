# problem

- **场景**：日用消费品供应链 agent 仿真，商品从生产商经批发商到门店再到顾客。部分生产商交付低质批次；质量差不会作为标签出现，而是体现在下游的顾客需求、门店订货、批发分配和门店销量中。
- **输入**：仿真产生的运营记录（原始数据；实验 2 另加冗余汇总表）和任务提示（短提示或无歧义提示）。
- **输出**：一个 JSON 对象，含被判定为质量问题来源的"供应商-商品"组合集合。
- **评分**：与确定性真值比较的 Jaccard 指数；每条轨迹另记完成时间。失败（无 JSON 输出，或 stdout/stderr 1200 秒无变化）允许重试一次，仍失败记 0 分。
- **工作单位**：一条轨迹＝一个模型配置在一种条件下的一次完整 agent 运行；聚合单位是"模型配置 × 条件"的 5 条轨迹。

阅读者分析：任务把 EDA 操作化为"从多表运营痕迹中反推隐藏原因"的集合预测，答案是封闭的，因此可自动评分；但它只代表一种业务问题。论文未给出仿真规模（表数、行数、生产商/商品数量），只说数据集在项目仓库公开。

依据：[arXiv:2606.00051v1，16 页](https://arxiv.org/abs/2606.00051)，§4.2–4.4，PDF pp.6–7；Data Availability，p.14。
