# 解决的问题

**问题定义（§2.1，p.3）**：给定源表集合 S = {S_1..S_n}、目标 schema Σ*、可用算子类型集合 O，寻找流水线 P 把 S 转换为满足 Σ* 的目标表 T̂ = (Σ*, D̂)。每张表 S_i = (Σ_i, D_i)，schema Σ_i = (τ_i, C_i) 含表级文本描述与列规格（列名、类型、语义描述），源表 schema 可缺失并从数据推断。真值表 T* = (Σ*, D*) 只用于评测；输入中只给 Σ*，不给目标元组。

| 项 | 内容 |
|---|---|
| 输入 | 多张源表 + 目标表的表级描述（如 "I need a table containing ratings by genre for each director in 2019 and 2020"）与列级描述 |
| 输出 | 算子流水线 P = (S, o(1) → … → o(k)) 及其执行产生的目标表 |
| 算子 | 31 种、8 类：数据清洗、值规范化、schema 编辑、行选择、聚合、表组合、表重塑、程序合成（ExeCode 执行 LLM 生成的 Python）（§2.2，pp.3–4） |
| 工作单元 | 一个 ADP 任务（一组源表 + 一个目标 schema）；评测以整张目标表是否精确匹配计 |

**推理形式（§4，pp.5–7）**：环境维护物化的中间表状态树 G，节点是中间表集合，边是单个算子实例。智能体循环输出 ⟨plan⟩（分析当前树，决定扩展哪个父节点或终止）、⟨expand⟩（用从根到父节点的完整算子序列做前缀匹配来指定父节点，避免索引歧义）、⟨execute⟩（环境逐个执行算子、建新节点；失败则在父节点记录错误轨迹）、⟨answer⟩（叶节点满足 Σ* 时返回根到叶路径）。最大探索轮数为 5（§6.1，p.10）。

阅读者分析：这里的“目标 schema 描述”本质上是 NL2SQL 查询结果的列描述（训练与评测数据都由 SQL 结果反推），因此任务更接近“以表描述驱动的多表变换合成”，而不是开放的数据清洗。
