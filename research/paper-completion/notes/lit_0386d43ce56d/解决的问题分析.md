# 解决的问题

**输入**：一张带列头的单表脏数据（§2.2），不需要额外的元信息。**输出**：被判定为错误的单元格索引（§5）；修复由外部工具完成（Baran、HoloClean 或插补）（§2）。

**流程**（Figure 1、§3）：

1. 抽取列名，用 LLM 判断数据集是 IoT 还是非 IoT 关系表。
2. IoT：LLM 把列映射到元上下文模型（Figure 2）中的概念（`ssn:System`、`ssn:Sensor`、`iot-lite:Location` 等）；随后拆分多传感器行、补全缺失概念列（可合成值）、按规范重命名列；从 LLM、Wikipedia、Wikidata 查询传感器的最小/最大值；最后把每行转换成 RDF 三元组。
3. 非 IoT：枚举所有列对，让 LLM 判断是否存在语义关系、确定概念以及是否为属性关系，构建层次化 RDF 图。
4. 从上下文模型抽取 OFD，执行检测：缺失值规则（统一各种空值占位符为 NaN）和函数依赖规则（按决定列分组，取依赖列众数作为合法值，偏离者标错）（§5）。

**OFD 类型**（§2.1）：拒绝依赖、匹配依赖、设备链接、时间、位置、监控、能力依赖；非 IoT 数据只适用匹配与拒绝依赖。

阅读者分析：检测阶段的函数依赖判定是“组内众数即正确”，在某组多数值本身出错时会漏检或误报，论文没有讨论这种情况。

依据：[arXiv:2404.18681v1](https://arxiv.org/pdf/2404.18681v1)，§2–5、Figures 1–3，PDF pp.2–6。
