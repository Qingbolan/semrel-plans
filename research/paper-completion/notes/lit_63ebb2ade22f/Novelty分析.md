# 贡献与评价

**论文声称的贡献**（§1–5，§7）：

| 组件 | 做法 | 作者主张的新意 |
|---|---|---|
| 前端语言 | 嵌入 Python 的 DSL，含 fork/join、image/video | 与 LMQL、Guidance 同属低层系统，但自带协同设计的运行时（Table 1，p.4） |
| RadixAttention | 基数树映射 token 序列到分页 KV cache；LRU 逐叶淘汰；引用计数保护运行中请求；缓存与运行请求共享内存池 | 首次把 KV cache 当作基于树的 LRU 缓存，支持多级共享、缓存感知调度、前后端协同与分布式（§3、§7） |
| 缓存感知调度 | 按最长匹配前缀优先排序；定理 3.1：缓存不小于最长请求时，DFS 顺序达到离线最优命中率 | 证明见附录 A.3 |
| 压缩 FSM | 合并正则 FSM 中相邻的单一转移边，一次前向解码多个 token | §4、附录 B |
| API 推测执行 | 首次调用忽略停止条件多生成，后续原语复用，节省输入 token 费用 | §5 |

**作者承认的局限**：贪心缓存感知调度可能导致饥饿（§3，p.6）；压缩 FSM 存在 token 与字符串错位导致的概率失真（附录 B.3）；编译模式不支持数据依赖控制流（附录 D.1）；附录 D.2 的提示重排优化不严格保持语义，依赖 GPT-4，15 个测试模板中 12 个成功。

RadixAttention 与压缩 FSM 是面向工作负载结构的执行层优化，论文脚注 3 也提到 vLLM 已部分集成 RadixAttention（p.7）。但正文多数结果以归一化柱状图给出，缺少逐基准的绝对数值表，“6.4 倍”具体对应哪个基准和基线无法从文字中复核（阅读者分析）。

依据：§1–5、§7、Table 1、附录 A.3、B.3、D，PDF pp.1–10、15–20。
