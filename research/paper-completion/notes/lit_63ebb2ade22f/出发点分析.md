# 出发点

作者观察到 LLM 的用法正从单轮对话转向“程序化使用”：智能体、少样本学习、自洽采样、思维树等都需要多次相互依赖的生成调用，并要求结构化输入输出，作者称之为 LM 程序（§1，p.1）。

现有方案有两类问题（§1，p.2）：

1. **编程困难**：需要大量字符串拼接、提示调优、脆弱的输出解析和手写并行。
2. **执行低效**：vLLM、TGI、TensorRT-LLM 等推理引擎不了解工作负载结构。多次调用共享前缀时，请求结束后 KV cache 即被丢弃，造成重复计算；JSON 等正则约束解码只能逐 token 屏蔽，无法一次解码确定的多 token 片段。

核心思路是系统性利用 LM 程序的多调用结构，前端与运行时协同设计（§1，p.2）。

阅读者分析：对语义算子系统而言，这一动机对应“批量 LLM 调用共享长提示（指令、少样本、文档上下文）”的执行层优化，与算子语义本身无关。

依据：§1，PDF pp.1–2。
