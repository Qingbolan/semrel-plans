# Benchmark specification v0.1

Unit: (frozen environment E, fixed task T, one demonstration x0, subsequent relation R, private gold G).

The benchmark is method-neutral. It must support conclusions when fixed programs equal or exceed Agents. Semantic operators preserve relational inputs/outputs and composability; runtime adaptation is an experimental variable, not a forced property.

Required chain A: authentic sources → correct construction → executable traditional static LOTUS baseline with reproducible quality shortfall → same-environment Data Agent improvement and measured cost → downstream impact.

The shortfall is a hypothesis to test, not a mandated result. Resource-only ablations diagnose information benefit; they do not prove Agent advantage. The current objective must not drift into cost-only optimization on already-accurate static workloads.
Required chain B: one observed Agent execution → automatic extraction → frozen operator → independent records → quality retention and amortized savings.

Current implementation covers PCB control construction/execution/scoring and development-pilot construction plus recorded static/fixed-review/tool-Agent execution for CUAD and BioDEX. Source acquisition, model execution and scoring are separate receipts; inspect report.md for actual results. Neither full research chain has passed. The DataSpace development prototype now implements one observed native Agent execution → automatic Python synthesis → frozen applicability-aware operator → isolated execution on 300 later fund entities (299 correct, 1 ABSTAIN). This is engineering evidence, not an Agent-quality advantage or independent quality/cost confirmation; handwritten SQL scores 300/300. See docs/dataspace-amortization-pilot.md.

States: PLANNED → SOURCE_VERIFIED → BUILT → EXECUTED → SCORED → VALIDATED. Each transition needs artifacts; a successful build does not mean VALIDATED. Construction publishes only after hash checks and retains no partial destination on failure. Experiment validity is reviewed separately from runtime completion.

Verdicts: Boolean labels for the PCB task, runtime ABSTAIN as null plus explicit status. Other workloads may require semantic UNKNOWN; never equate it with ABSTAIN or FALSE.

No API keys, private reasoning, current-evaluation answer-bearing paths, current-gold-selected crops or hidden tool supervision may enter runtime assets. No permissions-management platform is required, but untrusted runners must eventually mount public assets alone.

Historical experience H may be an explicitly approved subset of frozen E: previous inputs, system outcomes, independently sourced human labels and correction evidence. H is separate from development D, demonstration x0 and evaluation relation R by declared source-entity splits and duplicate audits; current G_R remains private. Labels and researcher-derived lessons must have distinct provenance and confidence. An evaluation example used to construct H becomes development material and cannot remain independent confirmation. Historical cases are supervision, not an exemption from leakage controls.

Compare identical H access through fixed examples, fixed retrieval/tool workflows and adaptive Agents. A single extraction trace may consult multiple historical cases; disclose that supervision rather than claiming one labeled example. Include history preparation/review/index costs. See [historical experience design](docs/historical-experience.md). PCB history catalogs remain development-side metadata. CUAD now has an executed annotation-backed history pipeline; its eight-new-document comparison did not establish history-driven Agent quality gains. See docs/contract-history-results-2026-09-05.md.

Release gate: two justified workload families, frozen split and task semantics, independent gold, environment validity experiments, strong comparable baselines, full costs and reproducible claim-to-figure mapping. This is our design gate, not an official VLDB checklist.
