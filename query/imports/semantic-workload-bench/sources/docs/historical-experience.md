# 历史纠错经验作为异质环境资源

更新：2026-09-05。PCB两个历史案例仍为登记状态；CUAD已完成8份历史合同、8份新合同的五臂实测，未支持历史驱动的Agent优势。[结果与固定DAG](contract-history-results-2026-09-05.md)。

## 具体问题

环境可以同时包含任务记录、参考模板、工具代码、过去的系统输出、人工标注和纠错依据。目标是检验系统能否识别历史经验的适用条件，将其用于新记录，避免重复犯错，再从一次新的执行轨迹提取可复用算子。目录规模、历史标签数量和异质文件类型本身不是有效性证据。

PCB 的具体错误是：差分图中的独立块不一定是原图中的孤立铜。这个问题有真实失败记录和可计算证据，不需要虚构工单、专家意见或生产规范。

原研究单位 `(E,T,x0,R,G)` 保持不变，`H` 是冻结环境 `E` 的一个有来源的资源子集。`H` 表示历史经验；`D` 为开发资料；`x0` 为单次示范；`R` 为独立后续关系；`G_R` 始终是 evaluator-only 当前 gold。根据源实体划分并审计 H、D、x0、R 的交集与近重复。合法共享的通用参考和模板要单独登记，不能将共享参考等同独立实体或隐藏答案。

## 已登记的两个真实案例

机器可读资源见 [history-cases.json](../environments/pcb/history/history-cases.json)，来源为旧仓库完成的独立记录实验；本次没有重新推理或补人工专家标注。

| 历史源 ID | 官方 class5 标签 | LOTUS 带模板 | 工具型 Agent | 用途 |
|---|---|---|---|---|
| 12000085 | FALSE | TRUE，错误 | FALSE，正确 | 通过局部检查区分桥连/附着增生与孤立铜的改正案例 |
| 50600063 | FALSE | FALSE，正确 | TRUE，错误 | 已取得几何证据仍作出错误孤立性判断的退步案例 |

两例是看过结果后的开发选择，标签均为负，不是平衡或代表性抽样。它们现在只能用于历史库设计和开发，不能用于宣称历史经验改善测试质量。

在 50600063 中，官方标注包含 `109 170 148 198 4`（spur），没有 class5。Agent 将差分框 `[130,180,139,189]` 中的 61 像素块判为孤立铜。沿用该次 Agent 已选择的阈值 128、模板容差 2，复核发现该区域属于原图 23,496 像素的完整铜连通域，模板支持比例约 0.9974。[几何复核](../artifact/evidence/pcb-native-lotus-20260905/failure-analysis-50600063.json)支持“该次最终判定与已取得的原图连通性证据不一致”；不证明所有错误都由同一原因造成。

必须分别标记三种可信度：官方人工类别标注；模型当时的输出；研究者从工具观测归纳的候选经验。当前只有类别标签来自原作者人工标注。文字经验不是人工专家签署的 SOP，也不是经过跨任务验证的规则；不得提升为系统指令或无条件覆盖当前证据。

## 资源最小契约

| 字段 | 要解决的问题 |
|---|---|
| 历史 ID、源实体、任务/谓词版本 | 判断是否同一任务，检查当前样本与历史样本重叠 |
| 原始输入与参考资源的来源、版本和 hash | 回到实际证据，而不是只读取“以前错了”的结论 |
| 原判断、模型/工具版本及可观察动作 | 分清模板错误、预处理错误、工具失败与最终判断错误 |
| 人工标签、标注者来源与标注时间 | 区分人工确认、程序复核、模型建议；未知时间明确 null |
| 纠错依据、候选经验及适用条件 | 判断能否迁移，识别例外与版本不匹配 |
| 选择规则、公开批准状态、允许用途 | 避免事后挑例、测试答案混入和无意挂载 evaluator 文件 |

当前 catalog 记录六个源资产的固定 URL、SHA256、大小，不复制原图。其 annotation URL 只能在构造经过批准的历史快照时解析，不能让模型遍历源锁推断当前测试答案。当前PCB builder/CLI仍没有这些PCB历史资产的加载接口；新CUAD历史运行器单独实现，不代表PCB catalog已经接入。

## 冻结、标签与泄漏边界

1. 先确定历史可见截止点、来源与 H/D/x0/R 分配，再生成公共经验快照；不要等看见 R 的错误后再补入经验而继续评分同一 R。
2. 历史人工标签在批准的 H 内是显式监督资源；当前 R 的标签、gold 裁剪、答案目录、评测反馈和相同/近重复案例不得进入运行上下文。边界取决于数据角色，不能把全部历史标注都称为 oracle，也不能用“历史”重命名当前答案。
3. 当前 100 条一旦用于经验选择与规则开发，就转为开发暴露。连同此前 79 条，已登记 [179 条排除记录](../environments/pcb/history/exposure-exclusions.json)。只换记录 ID 不保证板组或原图独立；剩余官方 test 记录不自动成为独立确认集。
4. 在新的独立批次上评分；按板组、患者、合同、报告等实际源实体分组，并审计像素/文本近重复、模板关联及训练来源。无法建立分组独立性时，结果只标开发/记录级迁移。
5. 当前构造与运行中的 public/private 快照保持冻结。不递归挂载仓库 `environments/`、源锁、历史结果收据或 exposure registry；未来只挂载 allowlist 批准的 H 资产及任务资源。

## 比较矩阵与归因

复用现有 B0–B7，不新增一个与原协议脱节的系统分类：

| 配置 | 历史经验的使用方式 | 解释范围 |
|---|---|---|
| B0，H 不可见 | 完整必要输入上的直接 LOTUS | 无历史资源的消融；不能单独证明 Agent 机制 |
| B1 | 相同模型、固定挑选的经验示例 | 普通 few-shot 是否足够 |
| B2 | 固定检索相关历史＋公开工具和检查流程 | 固定 RAG/验证流程是否足够；允许分支、循环、缓存 |
| B4 | 根据当前疑点选择历史证据、工具和验证步骤 | 与 B1/B2 比较是否存在额外自适应收益 |
| B3 | Coding Agent 一次生成批处理程序 | 排除普通代码生成即可解释的收益 |
| B5 | 从一次新的真实执行轨迹提取并冻结算子 | 在独立 R 上保持质量并摊销开销 |

B1/B2/B3/B4/B5必须共享允许的历史库、标签、参考与工具；检索数量、摘要、排序、缓存及预算都记录。数据条件不同的 B0 消融只说明信息价值。保持原定“静态质量不足→同环境 Agent 改善→单轨迹提取”主线，不能只给 Agent 纠错标签来制造差距。

本地廉价模型可作为额外部署轴，但须保留同模型主对照和强模型静态对照。低成本 LOTUS 与更强 Agent 的差距不能归因于 Agent 机制；本地 GPU/CPU 成本不能记成零。

## 单轨迹不等于单样本监督

一次 `x0` 执行可以查询 H 中多条历史经验，但必须报告：H 中有多少带标签案例、实际访问多少、标签/经验从何获得，以及提取器的直接输入。不得把多条历史原始轨迹拼接后称为只用一次执行；如果环境允许读取历史轨迹，还需单列历史轨迹数量和实际读取量。

消融区分原始历史案例、历史摘要、候选规则、当前执行轨迹和固定重放。只有静态示例或摘要已足够时，不宣称自动提取/动态调用产生了独有收益。

总成本包含历史整理/标注与审核、索引或摘要、示范探索、提取、验证、共享预处理、执行、重试与升级。历史确已存在时，可另报沉没成本不计入的部署情景，但不得只展示该情景或把未知标注成本填零。

## 验证门槛与当前结论

历史库加入前冻结主指标、质量要求、预算与新划分。报告错误改正和新引入错误、类别平衡指标、证据充分性、历史条目访问、工具行为、失败、下游清单/计数及完整成本；按实体聚类估计不确定性。检验是否检索到相近但不适用的经验，以及是否把候选经验误当无条件规则。这些是待执行实验，不是现有成功结果。

已有100条旧仓库实验：LOTUS仅图89%、带模板91%、工具型Agent92%，改对9条又引入8条，精确配对p=1.0；平衡准确率81.99%→75.00%；固定专业程序100%。[本地导入收据](../artifact/evidence/pcb-native-lotus-20260905/provenance.json)及[统计](../artifact/evidence/pcb-native-lotus-20260905/paired-analysis.json)保留阴性结果，不当作新仓库复跑或经验增强成功。

BioDEX/CUAD 的既有冻结 pilot 不在本次改变。未来迁移经验机制时，需要分别核验历史标签、术语/任务版本和合同/报告级独立性，不能把当前 test 的专家答案变成 glossary 或示例库。候选优先级保持不变。
