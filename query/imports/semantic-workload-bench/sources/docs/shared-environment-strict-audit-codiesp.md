# CodiEsp：长编码环境确实存在；严格目标暂为 Partial fit

本轮按原任务审查医学文本提及编码，不把标签改称患者确诊、保险支付或指南符合性。更接近 HSCodeComp 的术语/层级归类结构，但也可能退化为 GENIA 式固定提及链接；尚无 D/E 正向证据。

## 原件和实际规模

已下载并打开[原始 overview](https://ceur-ws.org/Vol-2696/paper_263.pdf)、[完整官方评测仓库](https://github.com/TeMU-BSC/CodiEsp-Evaluation-Script)（commit `976fc1119845d0cd252f1f1103c799c280f32a1d`，17 个 tracked 文件）、[官方 v1.4 全数据 ZIP](https://zenodo.org/records/3837305)。ZIP 11,239,591 bytes、7,525 members，官方 MD5 匹配且 CRC 通过。源码 MIT；数据、任务指南、词表的 Zenodo API 均为 CC-BY-4.0。卫生部 PDF 有自身版权声明，不能将代码 MIT 或数据 CC-BY 自动覆盖这些手册；再发布许可仍需逐资产核实。

共享资源已实际下载：2018 诊断手册 312 PDF 页、操作手册 304 页；完整诊断分类书 1,492 页、操作分类书 679 页，共 2,787 页（未计 DOCX 指南）。四份 PDF 共 20,513,630 bytes。另有任务指南 DOCX 45,688 bytes、词表 ZIP 1,832,226 bytes；解压诊断词表 71,486 行、操作词表 87,170 行。页数不能直接当 token 数或必要阅读量。

## 表 3：类 Python DAG 与真实数值例子

实际抽样病例 `S1139-76322017000100010-1` 是儿童头痛及后续乳糜泻检查。原文明确否认呕吐，但 X 仍给 `r11.10`；这不是临床存在判断的 gold。另一个真实操作例 `S1698-44472005000300015-1` 将双侧颞下颌关节 MRI 编为 `bn39`，不是强行补足七字符。

| 类 Python 的 DAG | 具体输入/值 | 普通或语义；E 的作用 |
|---|---|---|
| `rows = scan(spanish_txt)` | 1,000 TXT；示例儿童病例 | 普通读文件；源 ID 仅用于评测关联 |
| `mentions = sem_map(rows, task_rules)` | 同一病例的头痛、乳糜泻、呕吐等提及 | 语义；识别任务范围，不能默认剔除否认提及 |
| `candidates = retrieve(index(E), mentions)` | 呕吐候选 `R11.10`，MRI 候选前缀 `BN39` | 索引/候选检索可固定预处理；检索不是 gold |
| `coded = sem_map(mentions, candidates, relevant_rules)` | `r11.10`；另例 `bn39` | 关键语义代码选择，检查任务与编码粒度 |
| `output = distinct(coded.codes)` | D/P 原任务要求代码排序（主指标MAP）；集合指标为补充。X源文件保留各span，但官方评分按病例-code命中一处计分 | 普通集合操作；不能对 X 粗暴去重 |
| `score(private_gold, output)` | 18,435 X 标注行；不是推理输入 | 独立评测，未执行模型评分 |

## 20 例证据审查与十问剩余边界

选择：所有 1,000 个病例按 `SHA256("codiesp-strict-v1" + NUL + record_id)` 排序取前 20，跨原划分，已视为开发暴露；不是新确认集。20 例共 373 个 X 标注，373/373 偏移还原与参考文本完全一致；357/373 在所下载词表中精确命中代码，16 个未命中含非最终诊断代码，不能直接判错。分类书全文代码/操作前三字符的页码命中为 346/373，未命中可能涉及排版或编码粒度，不能推断 E 中不存在依据。[逐项定位记录](../artifact/evidence/shared-environment-strict-codiesp/localization20.json)区分上述检查。完整抽样原文和标注保存在本地审计证据，严禁作为模型公开资源。自动定位记录另列词表行/分类书 PDF 页，页命中只证明地址，不证明编码正确、规则充分或必须读 E。**完整 C 仍为 0/20**，不是模型准确率 0%。

实读指南 G2/G12/G12.2/P4/O1，并核对部分完整病例和全部抽样代码/证据列表：患者存在判断与 mention 编码不等价；任务会保留非最终代码；临床术语缩写与医学知识的外部依赖尚未全部封存。没有专家逐条认证 20 病例全部代码规则，也没有因找到否认提及就宣布标注错误。

原始 1,000 record_id 去掉末尾病例编号后有 936 个论文样式前缀；train∩dev 15、train∩test 21、dev∩test 4 个共享前缀。这是文件名级来源重复线索，不等于患者相同，也不是近重复全文审计。后续需按来源论文及病例实体隔离，不能直接把官方随机划分宣称新实体确认。

为什么不是普通 RAG/条件分类？目前没有排除它就是“提及识别＋词表检索＋固定规则链接”。最可能击败复杂 Agent 的基线是同资源的多候选链接、固定层级导航和规则校验。环境很长和人工编码真实使它值得保留 Partial，但不证明运行时探索必须、更不证明可从一次执行学习出优于 E-only 编译的结构。

原件与 SHA256：[source.json](../artifact/evidence/shared-environment-strict-codiesp/source.json)；[本地统计](../artifact/evidence/shared-environment-strict-codiesp/statistics.json)。没有模型、参数、prompt 版本或运行成本：本轮均不适用；没有安装或执行作者代码，没有 commit。


## 词表版本追查：已解决16个抽样代码未命中的来源问题

上轮精确匹配使用 Zenodo 3632523 的 Version 1 诊断词表（71,486 行），而完整官方评测仓库自带诊断词表为 98,288 行，多 26,802 个代码、无删除。操作词表两份字节相同，均 87,170 行。全量 gold 对比：旧诊断词表缺 479/11,158 个病例—代码对；仓库诊断词表缺 0。操作 gold 3,246 对在两版均全部覆盖。抽样中先前未命中的16个标注代码在仓库词表全部存在，故当前抽样词表定位为373/373。旧定位结果保留为版本差异证据，不能继续称这些代码未提供。

官方 `codiespD_P_evaluation.py:120` 对预测做 valid_codes 精确集合过滤；`format_gs` 对 gold 只做小写和去重，不做同样词表过滤。若向这个入口传旧词表，正确预测也可能被删除。上述479是集合覆盖审计，不是执行官方评测器后的分数，更不是模型错误率。这里只实读源码并用标准库复算集合，没有安装或执行作者脚本。

实验环境应使用冻结仓库commit中的词表，并把任务允许的非最终代码纳入合法输出；不能把旧表作为强静态基线的合法代码限制。新表恢复代码地址和输出可达性，仍未证明所有代码的临床语义/规则闭合。C完整0/20、D/E未知、Partial判定不变。

## MRI局部规则链复核：明确一条可预处理的路径

实读病例`S1698-44472005000300015-1`全文、X第8584/8591行，以及操作分类书PDF第480页（印刷页461，BN0–BN3表）：B=影像，N=颅面骨，3=MRI，9=双侧颞下颌关节。正文写双侧ATM的MRI，但未写造影剂状态；冻结词表含`BN39YZZ`（其他造影剂）和`BN39ZZZ`（无造影剂），另含允许输出的非最终`BN39`。G12/G12.1/G12.2允许操作仅保留四或七字符，故此例四字符目标有明确局部解释，不能擅自补无造影剂轴。

两条BN39证据偏移均精确还原，见[MRI局部证据收据](../artifact/evidence/shared-environment-strict-codiesp/mri-rule-path.json)。这只闭合一个代码的主要信息与粒度选择，不等于整个病例所有D/P/X标签闭合，也不提高C完整20例计数。

| 固定Query | 原文事实 | E路径 | 原gold | 强固定对照 |
|---|---|---|---|---|
| 返回报告全部操作代码，局部审查MRI提及 | MRI；双侧ATM；造影剂未说明 | 表BN3的解剖值9→G12.2粒度 | bn39，两处mention | `extract_modality_anatomy_contrast → table_lookup → specificity_guard` |

这条路径中的表索引与四/七位粒度规则可事前编译。侧别与技术识别仍是语义步骤，但一套固定语义列也能表达；不能凭此例声称已出现新的可学习执行家族。没有运行该对照，也没有以人工给定正确slots冒充模型正确抽取。其价值是明确下一步应挑战的baseline，而非为Agent提供必胜实例。


## 外部缩写资源：缺口范围进一步限定

指南O1针对非西班牙语提及，要求标注者知道其意义且收入SEDOM词典；不是“所有大写字符串都必须查询词典”。本轮在已暴露20例正文中选择PET、EPOCH、KPTT、BAAR、HLA、CDDP六项复查，共7处出现；对应病例X标注的证据文本精确搜索这些字符串命中0行。因此这些具体出现不能用作O1导致gold外部依赖的正面证据，也不能凭大写词数估算需要资源探索的比例。该检查不证明所有缩写无需词典，未对全部提及做语言及概念判定。

官方旧PDF两种路径返回404；词典站两个HTTPS域名返回证书主机名不匹配，未取得2018历史词典。官方2022应用说明及现行搜索可见页面说明资源持续更新；现行版本不自动等于标注时E。此次只收窄证据主张，G的完整外部知识闭合仍未知，C0/D/E及Partial不变。

[请求及资源收据](../artifact/evidence/shared-environment-strict-codiesp/sedom-resource-audit.json)、[7处正文上下文](../artifact/evidence/shared-environment-strict-codiesp/abbreviation-contexts.json)、[对应gold证据匹配](../artifact/evidence/shared-environment-strict-codiesp/abbreviation-gold-links.json)。这是一项定向审查，不是自动识别外语缩写的评测。

## 全量X偏移顺序与官方区间读取不兼容

只读全量18,435条X原行，135条多片段未按位置排序；其中131条按官方read_gs的首start/末end算法形成反向区间。train/dev/test分别为65/33/37条未排序，63/33/35条反向。示例trainX第23行`1773 1782;222 228`被读成[1773,228]，而这些片段的包围区间是[222,1782]。原片段本身可有效，不能说这些案例没有正确证据。

129条反向区间的start-end差超过20。默认容差10下，官方判断要求pred_start位于[gold_start-10,gold_start]、pred_end位于[gold_end,gold_end+10]，因此正常pred_start≤pred_end不可能同时满足这些129项。按病例-code合并并考虑任一参考命中即可的规则，110个病例-code至少一个参考受此影响，72个病例-code的所有参考均有这个问题。

这是对已冻结数据和源码的静态可满足性分析，未运行作者评分器，也不是模型损失实测。官方程序可能接受其他异常格式；本结论明确限定正常正向预测区间。不能将此类漏分解释为Agent/LOTUS的语义失败，更不能直接将72除以18,435当任务错误率。
