# Shared-environment执行家族核验：AnnoCTR

**结论：△ Partial fit，不进入Strong fit。** 真实报告、独立人工链接与冻结的大知识库已经取得；但完整环境下固定检索为何不够、是否存在少数可复用的语义执行家族，都没有直接证据。当前更像共享知识库上的条件实体链接，而非已证实的HSCodeComp式分支导航任务。

## 1. 判定口径

本轮采用严格A—H条件。旧账本12个“可构造开发候选”不等于12个Strong fit；不沿用旧计数。本轮重新审计1个候选：完全满足0、接近1、已审淘汰0；历史其他候选仍待新标准审计。无法给出有依据的Top5排名，更不能把未审来源排入前五。

这里“不进入”不意味着数据无价值：它能用于实体链接、资源检索及弱监督实验。也不意味着已经证明任何固定模型足够准确；目前是缺少新目标要求的静态不足与执行家族证据。一次调用、固定检索、Coding Agent和E-only预处理均应作为可用强对照。

## 2. 一页任务表

固定q：给定威胁报告、其中一个明确指定的提及与局部上下文，将提及表达的攻击技术概念链接到冻结ATT&CK集合。它不是判断该攻击是否已经发生，也不是把所有安全事件都视为技术正例。

| 输出列 | 一句话定义 | 取值 |
|---|---|---|
| record_id | 原样返回给定记录标识 | 字符串 |
| technique_ids | 返回在报告语境下被提及的技术集合；归父技术的规则须与版本一致 | 去重ID列表 |
| evidence_refs | 指向支持判断的报告位置及冻结定义位置 | 文件/行或偏移列表 |
| status | 区分有支持结论、输入语义不确定和执行未完成 | OK / UNKNOWN / ABSTAIN |

这是建议契约，尚未生成统一public/private视图。原导出并没有足够证据支持把No Annotation直接映射为UNKNOWN或空集合；上述状态不能被写成已与全部源gold绑定。

## 5. DAG（表3）

```python
reports = scan_texts()                         # 普通算子
items = load_given_mentions(reports)           # 明确给定的任务输入
index = build_index(E.definitions)             # 只依赖E，可一次完成
for batch in split_by_report(items):           # 普通算子；静态集切批
    candidates = retrieve(index, batch.context) # 固定检索；查询内容来自记录
    links = sem_map(link_and_normalize,         # 核心语义结果决定链接gold
                    batch, candidates, E.task_rules)
    emit(validate_id_sets(links))              # 普通校验
result = groupby_report_unique_ids()            # 普通聚合
```

目前没有证据迫使该DAG中的语义调用变成不同程序。候选集合不同不等于执行家族不同；同一固定检索程序本来就能返回不同定义。论文§4.3使用KG预编码/候选检索，且将子技术预测转换为父技术；§4.4还采用固定“发现→分类”程序。论文未提供同模型、同预算下完整E静态与Agent比较，不能把其旧模型误差解释为固定结构的能力上限。

## 6. 四路推演及拆分（表4）

| 臂 | 相同任务表之外的输入 | 预期质量/风险（未实测） | 执行过程 |
|---|---|---|---|
| 静态仅任务表 | 记录 | 已知技术名/编号可能答对；冻结版本及近义边界未知 | 一次语义映射；明示ID可普通抽取 |
| 静态+完整E | 记录+完整定义和规则 | 成本可能高；没有证据证明不能正确；超过某模型上下文需具体测量 | 预处理索引/固定检索+一次调用作为同资源强基线 |
| 逐记录Data Agent | 记录+可探索E | 可迭代查候选；也可能只是昂贵重放固定检索 | ==查提及候选定义、平台、父子关系==→比较→输出 |
| 批处理Data Agent | 整批+可探索E | 可共享定义索引与候选缓存；是否有家族级额外收益未知 | ==一次建立定义与层级索引==→批内分组→==复用候选定义==→逐项判断 |

ρ_E：定义读取、名称/父子索引，可预处理；ρ_P：检索、候选比较、ID校验，所有记录共用；ρ_G：语义路由到不同可复用中间程序，目前没有观测证据；ρ_R：解释每条动作与上下文。四项没有真实轨迹，比例不能填数字。20例分成明示ID2、词面或概念名8、行为解释7、局部不足3，仅是审查分组；既非耗时比例，也非执行K。11个目标标签同样不是K。

共享技术定义属于ρ_E，固定“检索+比较”属于ρ_P。要主张ρ_G，需要实际轨迹出现可复用的不同中间任务，并证明路由条件无法由同资源固定预处理或一个统一语义程序充分覆盖；现材料尚未提供。

## 8. 真实实例与十问补充

样本4：报告描述字符串在二进制中加密、运行时由解密循环恢复；gold T1140。E第515行描述恢复被混淆的信息，短引“decode or deobfuscate”。该行为与定义相符；固定检索与单次比较同样能处理，尚未显示必须特殊探索。

样本5：提及已写T1562.001，gold父技术T1562。论文的父技术归并规则解释这种映射，不应误称层级推理困难或标签矛盾。样本2的“恶意Excel样本”本身不能证明解释器行为；不能靠gold反推宏执行。

q及信息不足状态见任务表；E组成、N、标注者、定位见表1与表2。E文件已冻结，但作者知识库抽取日期与早于全部报告的时间关系尚未验证。报告之间有动作、工具、目标和叙事差异；没有测出不同执行结构的分布。跨记录共享的是索引，按家族共享的中间计算未证，每条独有的是动作解释。记录原gold字段明显泄漏，隐式行为是否全由E闭合也未确认。**目前没有足够依据回答“为什么不是普通RAG/条件链接”——现有最强证据正支持这种解释。**

作为首批目标实验的风险高：最可能被预索引实体检索+固定消歧、或明示ID/名称规则击败。E-only预处理能消除大量ρ_E；能否覆盖其余部分需实测。若实验目标是发现家族级ρ_G，不应仅凭本数据大知识库规模优先投入Agent实验。
