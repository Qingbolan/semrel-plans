# 制造质检场景：官方数据、规则与一次示范复用的对抗审查

## 当前建议

优先用 **MVTec LOCO AD 的装配/装袋合规检查** 建立第一条可审查流程；将 **MVTec AD 2 的多光照异常检查** 留作感知与取证策略对照。当前可以验证“记录是否符合该数据集规定的正常配置”，不能声称已经拥有“是否应返修、如何返修、返修后是否合格”的真实业务闭环。

本次浏览官方数据页、原始论文和相关方法论文，并只读本地 LOCO-Annotations 的两个代码/提示文件。未下载这两个 MVTec 数据集、未选定真实 pilot 图像 ID、未运行模型、未形成新 gold。以下 pilot 配额和流程均为待执行方案，不是实验结果。

## 1. 两个官方来源能提供什么

| 来源 | 已核对的独立材料 | 最适合的任务 | 缺少什么 |
|---|---|---|---|
| **MVTec LOCO AD** | 官方提供3,644张图、5类别、结构/逻辑异常及像素标注；对应IJCV 2022论文 | 相同品类上反复执行装配规则核验 | 非工厂ERP/MES工单；未提供维修动作、成本、报废判定、维修后结果 |
| **MVTec AD 2** | 官方提供8类、逾8,000图、正常训练/验证、公开测试gold；部分测试gold仅服务器评测 | 复杂成像条件下异常发现与定位 | 主要是视觉异常；没有可据此推出返修处置的政策/结果标签 |

两者均由 MVTec 官方发布，数据许可为 CC BY-NC-SA 4.0。LOCO 官方描述是受真实工业检验启发的场景；不能升级表述成已验证生产线业务。AD2 当前官方引用为 IJCV 134(4), 2026，预印本最初提交于2025-03-27；不能仅写成“2025 arXiv数据集”。[LOCO官方数据页](https://www.mvtec.com/research-teaching/datasets/mvtec-loco-ad)；[AD2官方数据页](https://www.mvtec.com/research-teaching/datasets/mvtec-ad-2)。

### LOCO：已有来源规则，仍需明确公共任务边界

原论文§3.1明确：screw bag应含两垫圈、两螺母、一长一短螺钉；splicing connectors要求两连接器夹位数相同、由一条线连接，夹位数与线色对应，两端接入相对位置满足镜像关系。这些可形成公共规则材料。长短类别、线色对应关系等若需正常参考图解释，应从训练材料固定选取，并向所有系统提供相同参考。[LOCO原论文§3.1](https://link.springer.com/article/10.1007/s11263-022-01578-9)。

**建议的共享 batch question：**

> 在这一批同型号装配图像中，哪些记录违反已冻结的 LOCO 正常装配规则？返回记录 ID、违反的规则、支持判断的图像区域，以及执行不足时的 ABSTAIN。

这里的“正常装配规则”是来源定义的 benchmark 规则，并非供应商批准的工艺规范。不能把论文改写卡片包装成真实工厂SOP，也不能给零件编造订单、BOM版本、客户或工单历史。

若只问逻辑合规，`logical_anomalies` 与 `good` 可作为首轮候选；不能把所有 `structural_anomalies` 自动映射成逻辑不合规。若任务扩大为所有异常，必须同时覆盖相应结构判定义务。独立的图像级标签可以评分最终判定，但违反哪一条规则的解释仍需独立核验，不由模型自述自动当真。

### AD2：可研究多光照证据选择，不能套装配规则

AD2含8,004张图，公开测试含相同场景在不同照明下的图像与标注；训练/验证只含正常图。它明确覆盖重叠、透明、反射、细小缺陷和图像边缘缺陷，原论文对照表不把logical defects列为AD2特性。可将同一场景的不同照明作为可获取证据，但必须先核对文件的scene对应关系。[AD2原论文§III](https://arxiv.org/html/2503.21622v1)。

可用任务是“发现这批检查场景中的已定义异常并定位”，而非“判断批中哪些产品需要返修”。同一场景的各照明版本应归同一个输入实体；不得把它们随机拆到示范与测试，制造泛化结果。多视图取证可能改善判断只是待测假设；固定读取所有视图是必要强对照。

## 2. 最小可审查数据湖

第一版无需虚构杂乱目录。以下材料就能组成有用途的环境：

1. **候选关系**：opaque record ID、真实类别、公开图像资源引用；保留来源hash和版本于manifest。
2. **知识材料**：有出处的类别规则、训练集正常参考图、工具真实接口与适用条件。规则可规范化，但每条应指向原论文段落或实际数据说明。
3. **证据材料**：完整分辨率图片；AD2若有已核实配对，再加入同scene其他照明。裁剪是工具动作，不是预先由gold mask生成的“关键区域”。
4. **工具**：真实图像打开/裁剪、实际运行的检测/分割模型及确定计算。记录模型权重来源与训练数据，绝不把人工目标标注伪装成感知结果。
5. **私有评估**：测试标签、异常mask、缺陷类型和解释标注；它们不能经文件名、路径、工具返回字段进入公共环境。

固定外层 DAG 可以是：

```text
scan(batch)
  -> bind_public_product_rule
  -> sem_filter("violates the frozen inspection specification")
  -> project(record_id, verdict, evidence, violated_rule)
  -> count_and_group
```

`bind_public_product_rule` 仅按公开类别找对应规范，不读取异常标签。关键语义节点可由直接VLM、固定清单、生成程序、通用Agent或冻结的复用策略实现。若需要输出完备的逐条检查状态，可由同一节点附带结构化审计结果，但不能把最终解释当作第二套未经定义的任务。

## 3. 一次示范如何复用，才能经得起检查

一次 Agent 示范的目标应是产生可运行、可验证的处理策略，例如：加载规则和正常参考，打开图像，按需定位部件，确定数量/类型/连接位置，调用确定性比较器，验证并输出。保存公开动作、工具输入输出、引用、成本、错误和终止原因，不要求保存私人思维链。

冻结产物至少包括：输入输出契约、规则引用、工具依赖、可观察分支条件、预算与终止策略。后续记录只能替换图像和观察值，不能靠人工改代码才继续运行。示范图上的裁剪坐标不能硬编码到不同摆放的产品；必须由实际定位动作或有依据的配准重建。

**不把一次成功当成可复用性证据。** 对后续独立记录逐条执行，保留失效案例。展示“无需重新通用规划”是否减少成本，同时检查是否损失质量。若还需通用Agent处理未覆盖情况，应明确报告升级比例和总成本，不以静默fallback隐藏。

公开规则、正常参考、示范标签以及全部工具必须对各对照一致。Agent查看规则后胜过只给图的VLM，只能证明额外材料有帮助，不能证明动态机制必需。

## 4. 25条起步 pilot（尚未抽样）

**首选 LOCO 单一类别；建议先 screw_bag，下一轮再 splicing_connectors。** 先做单类能保持同一任务，避免把跨品类规则差异混成所谓批处理收益。

- 固定来源快照后，按 `SHA256(source-relative-path)` 排序，以一张逻辑异常图作为唯一开发示范，再从未用测试图中取12张good与12张logical anomaly，合计25条。示范/评分名单在模型运行前冻结，且示范图永久从后续评分集合排除。
- 所有系统可获得同一份规则与固定训练集正常参考。正常参考属于支持材料，不计作额外测试行，但读取成本需计入。
- 平衡配额仅用于pilot覆盖，不代表实际生产缺陷率。若某类别无法满足配额或规则无法解释其logical gold，保留诊断记录并调整已命名的新方案，不能看模型结果后删除难例。
- 此处尚未下载源文件，所以不提供猜测的`000.png`等ID，不宣称已构成25条可运行数据集。
- 输出至少包括25条完整轨迹、24条评分结果、复用策略文件、全部失败和成本记录。25条只能检验可运行性，不能支持总体显著优势。

如果要避免使用异常示范，也可另立“仅一张正常图示范”协议；但这不能保证触发异常分支。两种示范信息量不同，必须分开报告，不能训练时多看异常而声称one-shot normal-only。

**AD2第二pilot**：先盘点公开测试的唯一scene ID与照明对应关系，再固定20–30个不同scene作为批记录。其他照明放入各scene证据集合；抽样配额按实际scene数确定，不按图像数量倒推独立实体数。现阶段不能编造10/10或12/12类别配额保证，因为本次尚未下载并核对scene计数。

## 5. 必须保留的强对照与新颖性边界

| 对照 | 比较义务 |
|---|---|
| 直接VLM + 同规则/正常参考 | 区分一次判定与工具执行的收益 |
| 固定多裁剪/全部视图 + 固定清单 | 不人为削弱固定流程的证据覆盖 |
| **LogicQA** 类正常性总结 → 固定问题清单 | “生成检查表后反复用”已有直接相关工作 |
| **LogiCode / Coding Agent** 规则 → Python + 相同真实感知API | “生成一次程序后批量执行”已有直接相关工作 |
| 批内缓存与计划复用的通用Data Agent | 不能靠每行从零规划把Agent故意做贵 |
| 一次示范得到的冻结策略 | 保持质量时是否节省包括示范/编译在内的总成本 |

LogicQA（ACL Industry 2025）明确将生成的问题组成清单用于逻辑异常检测；LogiCode（2024预印本）明确用LLM生成Python检查逻辑规则。因此场景成立不等于方法新颖，不能把这些方法压成single-VLM baseline，也不能仅凭生成清单或代码宣称新的动态算子机制。[LogicQA正式论文入口](https://aclanthology.org/2025.acl-industry.29/)；[LogiCode原论文](https://arxiv.org/abs/2406.04687)。

### 已核实的 LogiCode 感知边界

本地仓库 `external/repository/LOCO-Annotations` 的 commit 为 `80a8f17186fa5e273ccd1442b2c66f2a6b1196b7`。读取 `Generated_code_examples/connector_anomly_detection.py` 与 `Request_prompts/connecter_prompt.txt` 后确认：`Image.find()` 打开图片同名JSON，从`shapes`的`label/points`构建实例mask；`read_image_text()`也从JSON读文本。它不是从原始图像预测对象的检测器。

这段实现可作为 **annotation-given 条件下的逻辑/代码执行对照**，但若给Agent使用而不给静态方法同样人工标注，就形成信息不对称；若将其称为端到端图像工具，就混淆了oracle感知与真实感知。[对应固定版本源码](https://github.com/22strongestme/LOCO-Annotations/blob/80a8f17186fa5e273ccd1442b2c66f2a6b1196b7/Generated_code_examples/connector_anomly_detection.py)。

该提示还包含500–1300像素线长范围。这是该研究实现中的像素条件，不是本次确认的MVTec工艺公差，更不能换算成毫米或迁移到改变分辨率的图像。其`connector`标签粒度与原论文中的连接器/夹位命名也须核对，不能混用对象数。不得照抄这些阈值作为新的“真实制造规范”。[固定版本提示文件](https://github.com/22strongestme/LOCO-Annotations/blob/80a8f17186fa5e273ccd1442b2c66f2a6b1196b7/Request_prompts/connecter_prompt.txt)。

## 6. 闭环验收与拒绝条件

- **场景验收**：存在来源可核验的批记录、适用规则、真实证据工具和独立最终标签；同一固定DAG可完整运行。一张“效果看起来好”的示例图不满足此项。
- **材料必要性**：比较同模型“无规则材料/有规则材料”，并记录具体哪项义务得到补足。规则已是答案级别的测试解释或mask时，拒绝该材料进入公开湖。
- **复用验收**：示范后冻结策略，在剩余记录上实际运行，报告无需人工修改的覆盖率、错误和总成本。只展示生成脚本不算运行闭环。
- **同信息比较**：感知模型、正常参考、规则和可访问视图相同；示范、索引、工具训练、编译和恢复成本都计入。不可将别的论文AUROC/F1-max直接当成本实验准确率。
- **阈值边界**：缺少来源公差时，不编造数值阈值。由正常训练数据校准的模型阈值须称为实验决策阈值并冻结，不能称工厂验收标准。
- **拒绝返修主张**：没有处置政策与维修后结果时，输出停在异常/合规判定。不能自动生成repair/scrap标签或“返修成功率”。
- **拒绝预设gap**：固定清单或代码达到同样质量且更低成本，就接受结果；场景仍可作为对照，但不能据此证明动态执行必要。
- **拒绝新颖性替换**：已有逻辑规则编程或清单复用被重命名，不构成新的可组合动态算子库。需要明确与已有执行策略的差异并实测其价值。

下一项具体工作是取得LOCO官方原始类别、记录快照/许可、冻结25条名单与source-backed规则，再跑同材料的固定检查流程和一次示范复用；不是补写一个并不存在的返修业务故事。
