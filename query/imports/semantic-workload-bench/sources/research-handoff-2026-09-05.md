# 研究接手文档：从单次 Data Agent 轨迹到可复用语义算子

适用对象：未参与此前讨论的新研究者或新 Agent。

本文件整合用户已明确的目标、讨论修正、已存在的仓库产物和下一步建议。状态截点为 2026-09-05 本次只读检查；共享工作区仍可能继续变化。这里的建议不等于此前所有候选都已经获选为主实验。不要仅凭本文件启动旧进程、覆盖输出或把未完成实验写成结果。

## 1. 先理解我们究竟要做什么

用户确认的核心研究问题：

> 当下静态的语意算子在开放世界的部分场景下解决问题的效果有所不足，而 Data Agent 有更强的通用性但成本过高，如何从 Data Agent 的执行轨迹中学习出新的语意算子，构建动态算子库，达到在保证效果的前提下提高效率的目标。

进一步明确的重点：**我们的方法从 Agent 单次任务执行的轨迹中提取算子，算子服务后续重复批处理。** Agent 是执行示范的来源，研究对象是“示范到算子”的转化及其复用收益。

目前最重要的工作是构造能够检验这个问题的**数据任务与数据湖环境**。不要先设计庞大的动态算子框架，再为机制寻找任务。

研究链路：

```text
固定批处理任务 + 异质数据环境
        ↓
Agent 在一个示范记录上执行任务并产生可观察轨迹
        ↓
我们的方法提取、参数化并冻结语义算子
        ↓
算子处理独立后续记录
        ↓
比较关键步骤质量、下游结果和包含构造开销的批处理总成本
```

这是一组待验证假设，不能预设静态必败、Agent 必胜、单条轨迹必然泛化。

## 2. 用户对场景的关键修正——不得退回旧理解

### 2.1 默认方法能够完成任务

用户强调：没有利用数据湖中的工具、文档或知识时，系统也可以执行并输出结果；只是关键步骤效果不好，影响后续步骤。

因此目标不是单纯的“不给外部证据就完全无解的问答”。也不通过删除必要输入、截断关键条款或隐藏已知元数据制造失败。

### 2.2 数据湖不仅装待处理数据，也装帮助处理的数据与工具

环境可以包括图像、长文本、表格、关系、模型权重、工具代码、使用文档、领域参考和正常样例。每类材料都要能解释具体作用，例如改善定位、实体关联、数量判断、例外处理或专业概念解释。

用户补充的四类能力需求：**长文本重复处理、复杂关系梳理、逻辑判断、关键知识补充。** 不应把问题缩小为“图片分类时调用一个模型”。

不需要构造执行权限管理系统；多模态数据环境本身是重点。评测 gold 与公开输入仍必须隔离。

### 2.3 固定业务流程，不要求已有标准化操作流程

外层输入关系、任务目标、算子语义和下游 DAG 固定；关键步骤具体怎样实现可以由探索获得。不能因为没有现成 SOP 就否决一个真实任务，也不能编造 SOP、BOM 或返修政策并宣称来自真实企业。

### 2.4 “批处理”必须有可复用内容

同一批记录应共享明确的谓词或参数化转换目标。几百个完全不同的问题不是天然适合单次示范复用的 workload。

分别考虑：同文档多次访问时的解析/关系缓存，以及同任务跨文档时的处理策略复用。缓存带来的收益与轨迹学习带来的收益要拆开。

### 2.5 研究贡献中心是转化方法

“Agent 找到了有用工具”仅提供示范，不是最终贡献。“写成脚本”也不自动构成新方法。需解释从一条走过的路径中，如何识别可参数化部分、保留必要分支、避免样例绑定，并在新输入上保持语义。

若提取结果是有效的固定程序，接受并报告；不要为名称中的“动态”强行加回通用规划。

## 3. 最小研究对象与成功标准

一个完整实例组为 `(E, T, x0, R, G)`：冻结环境 E、固定任务 T、一条示范记录 x0、未参与提取的后续关系 R、独立私有评分依据 G。

必须交付：

1. 一句话 workload 与真实业务对应。
2. 原始记录、辅助资源、关系和可用工具构成的环境快照。
3. 固定任务及下游流程；关键步骤输入输出明确。
4. 默认路径可执行、资源增强有帮助的初步证据。
5. 一条示范轨迹、从其产生的可执行算子和独立后续运行。
6. gold、质量指标、完整成本和强 baseline。

原始期待是 2–3 个可跑任务，单个批任务几百至一两千条，完整湖可以更大。先用 20–30 条验证场景，不为达到规模复制样本或混合任意任务。对数量不足的来源如实报告。

最初聊天出现过 9.27 行程目标，但年份、当前截止时间未重新确认；不要把它当当前执行期限。

## 6. 评测必须保留的对照和边界

至少比较：默认语义调用；加入相同规则/参考的固定调用；固定检索与工具程序（允许预写分支）；Coding Agent 一次生成批程序；支持共享缓存的 Data Agent；单轨迹提取算子；同轨迹摘要/简单重放。

环境增益与转化方法增益分开：

- 无资源/有资源比较说明辅助环境价值。
- 方法比较必须共享模型、资源、工具和预算；不能只让Agent使用专业模型或人工标注。
- Coding Agent 也能读文档、探索、写脚本。Data Agent 的角色不能靠产品名称定义。
- 不把固定 DAG 等同不允许条件分支；不把通用Agent每行从零规划当唯一成本基线。

一次示范协议：一算子一轨迹，冻结后再评后续记录。示范选择、失败重试、任何开发集使用均披露。多条轨迹分别构造独立算子可测方差，但不能合并后仍称 one-trace。gold 不参与示范后手改阈值或补分支。

记录可观察的状态、动作、工具输入输出、证据、错误、预算和终止原因；不要求私人思维链，不保存密钥。算子至少有输入输出、依赖、适用范围、预算、ABSTAIN/回退行为和版本。

三值与状态必须分清：gold TRUE/FALSE/UNKNOWN；执行 ABSTAIN；未标注 UNANNOTATED；无效记录 INVALID_RECORD。未知不自动等于否定，异常标签不自动等于返修动作。

单一 sem_filter 只负责关系筛选；若需要详细抽取或定位，使用 sem_map 或独立审计字段，不悄悄改变公共语义。最终还要保持可组合性，不能变成每个接口都调用无限制 Agent。

## 7. 指标与成本

关键步骤质量与最终清单/聚合质量同时报告；用 gold 中间结果替换预测，观察下游变化，验证该步骤确实重要。

成本包括示范探索、提取/编译、验证、共享预处理、后续执行、工具/GPU和回退。允许各baseline同等缓存和批内复用。报告 token、金额、wall-clock、并发、工具调用、覆盖率和错误类型。

不要用“时间×Token×准确率”作为唯一目标。比较质量—成本前沿或给定质量容忍度下的效率；质量保持的非劣界需在确认实验前定义。小pilot不足以证明稳定优势。

分组防泄漏：同图多QA、裁剪、多视角属于同实体；同合同多命题属于同文档；金融按报告/公司年份及跨集来源重叠审计。专用模型训练数据和参考图不能与确认样本混用。

## 8. 相关工作与已发现的陷阱

论文入口与第一轮摘要见构造计划第12节。需要重点阅读 LOTUS、DocETL、Palimpzest、Agent Workflow Memory、SKILL-DISCO 与 Agent Distillation；尚未完成全文新颖性分析。

制造方向还必须比较 LogicQA（正常性/问题清单复用）及 LogiCode（规则生成代码）。已有本地审查发现 LogiCode 的 `Image.find()` 读取同名 JSON 人工 shapes；它不是实际感知模型。可以作为给定标注的逻辑对照，不能伪装成原图检测工具或Agent独享能力。

禁止重犯：

- 把源文件夹的类别答案暴露给模型。
- 把 gold mask 生成的裁剪当普通查看工具。
- 把模型论文分数当本地工具已验证质量。
- 用 weak bootstrap 模型失败证明“静态算子失败”。
- 用资源缺失/任务歧义证明 Agent 必要。
- 为制造复杂度编造工单、历史规范、专业阈值或修复标签。
- 将一次成功代码演示、AI审查共识或测试通过升级为研究结论。
- 不计首次探索和人工调整成本；只展示挑出的成功示范。

## 9. 新接手者应当先做什么

1. 阅读本文件、构造计划、根目录 `AGENTS.md` 和 `report.md` 最近条目；只读确认当前新增输出，避免覆盖并行工作的产物。
2. 先选择一个最小场景，以现成24对DeepPCB控制任务或LOCO装配规则任务为可行入口；如果当前用户仍指定医疗项目，则保留其范围，先解决可用权重与真实质量问题。ContractNLI可作为长文独立路线。这里不是要求同时全面实现所有候选。
3. 写明唯一任务、记录单位、默认路径、哪项辅助资源改善哪种错误、下游输出及独立gold。完成20–30条真实材料审查。
4. 先跑默认、同资料固定流程/工具、强Agent小对照，判断环境是否有实际价值。保留负结果，避免一直加机制直到只剩Agent能做。
5. 冻结一条示范及后续样本。明确哪些步骤由“我们的方法”自动提取，哪些目前是研究者手工构造；手工演示只能作可行性证据。
6. 算子冻结后运行后续记录，评分并计入所有成本。若需要对测试逐条修脚本，本轮不能称成功复用。
7. 成立后再扩至数百条、加入第二任务与迁移；若不成立，记录失败原因并选择下一来源。
