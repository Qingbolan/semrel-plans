# 增量174：TDTB关系单位与论元字段核验

复用173全部原件及commit `226b2f898c7044345fcabec7d449f4d7da29b5d1`，仍9/15。本轮改变下一步依据：原生token行、连接词链接和关系表不能混为同一种计数；原生单连接词指针下还存在一侧论元未直接出现的情况。

实际遍历180个9列TSV：11753个非N意义token，872行有连接词链接；从最后一列`arg1[id] / arg2[id]`聚合得到10865个被引用连接词ID。train/dev/test分别8278/1243/1344。10865个中10781个同时找到arg1和arg2，84个只找到一侧，涉及59篇。所有链接ID、论元指向ID均存在，论元引用没有指向N标签；字段不存在未识别的非空论元语法。

这**不证明84个都是gold错误**：尚未验证连接词配对的论元共享、隐含论元约定和派生转换。不能直接丢弃一侧或补另一侧，更不能把未完成当false。

派生rels文件按字面TAB解析、关闭CSV引号处理后也是8278/1243/1344，总10865。README的8279/1244/1345恰好每split多1，与把表头当数据的计数吻合；未核验作者计数程序，不断言其确切原因。默认csv.DictReader会把文本中的未转义引号当引号语法，错误地合并行；第一次得10567，已纠正并在收据注明。所有实际行均12字段。

派生表没有空unit1_toks/unit2_toks，但这不证明全部来自人工论元：84个直接指针缺侧案例需要逐条映射才能解释派生非空来源。原生11753减872为10881，也不直接等于10865，不能用简单相减当连接词归并算法。根目录两套数据的ID覆盖已在173说明。
