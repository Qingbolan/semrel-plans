# 制造质检：先验证完整场景

本轮优先产出是20–30条可执行记录、能改善关键步骤的资源环境，以及一次示范在后续样本上的实际复用。动态算子提取方法暂不展开。

首选候选是装配一致性检查，见`tasks/assembly-consistency-pilot-v1.json`。共享问题是“哪些装配件违反适用的数量、线色和接线位置约束？”固定DAG保留sem_filter节点。LOCO论文的规则是有来源的数据集约束，不是厂商返修手册；只支持不合规筛选，不能将anomaly标签改成返修、报废或优先级。

## 进入实验的四道门槛

1. 数据输入可运行：每条record可解析、资源可达、每个实现返回同一语义的结果，ABSTAIN不冒充无缺陷。只有任务JSON不算通过。
2. 环境增益：同模型、同记录比较直接图像、固定文档/参考、固定专业工具和Agent；报告最终清单的改善。不能凭已有模型论文分数宣称本地增益。
3. 复用：在一个discovery示范上生成并冻结资源绑定、工具配置和逻辑；剩余记录只换输入，不能查test gold改阈值或补特例。记录探索一次与重复执行的独立成本。若固定程序足够，接受这个结果。
4. 独立评分：官方标签/masks或可核验业务结果单独保管。实例标注、答案解释及gold selected context不是模型工具输出。

## 已发现的直接对抗证据

- [LOCO论文](https://link.springer.com/article/10.1007/s11263-022-01578-9)明确数量、位置和匹配约束，适合检验规则取用。它是工业场景启发的受控采集，不能写成生产线真实返修工单。
- [LogicQA](https://aclanthology.org/2025.acl-industry.29/)已从正常参考归纳并复用检查问题。静态基线必须包括这类固定清单，不能只给单次直接VLM。
- [LogiCode官方代码](https://github.com/22strongestme/LOCO-Annotations)，本地commit80a8f17186fa5e273ccd1442b2c66f2a6b1196b7：`Generated_code_examples/connector_anomly_detection.py`与`Request_prompts/connecter_prompt.txt`中的`Image.find()`直接读取同名JSON的`shapes`标签和轮廓。它不是从原始图像获得实例的真实检测模型。可作“给定人工实例标注”的静态逻辑对照，不能将该API作为Agent独享的感知工具来证明图像任务优势。代码中的像素范围也不能自动提升为工厂质检标准。
- DeepPCB有对齐模板和独立六类位置标注，能做模板辅助缺陷定位/特定缺陷筛选；本轮24条全有open类，因此“是否有任意缺陷”的全正例任务无鉴别力。原作者说明加入了人工缺陷，不可描述成纯自然缺陷；不存在返修gold。

完整数据湖必须让每类资源都有职责：原始待检图、合法模板或正常参考、规则说明、实际可用工具与其说明、其他类别的真实资料。不加入虚构历史规范、随机噪声或答案文件来制造环境复杂度。

当前门槛仍待真实pilot和同资源实验；上述是来源审核与实验约束，不是Agent成功或动态库收益结论。
