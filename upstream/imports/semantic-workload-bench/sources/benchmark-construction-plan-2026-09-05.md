# 从单次 Agent 轨迹到批处理语义算子：Benchmark 与数据湖构造计划

日期：2026-09-05（Asia/Singapore）。状态：第一轮网络检索、元数据核验与构造设计完成；尚未构造本计划中的运行环境，未运行模型对比。本文是独立候选计划，不改变现有实验或主线程任务。

## 1. 要验证的场景

研究问题：在部分开放世界数据场景中，默认静态语义算子能够完成任务，但关键步骤的质量有限并影响下游；Data Agent 可以利用环境资源改善该步骤，却存在重复探索成本。我们的方法从 Agent **单次任务执行轨迹**中提取可复用语义算子，处理后续批次，在保持质量的前提下降低总成本。

一句话 workload：**对共享业务目标的大量异质记录，重复执行涉及长文本、关系梳理、逻辑判断或专业知识的关键语义步骤；步骤的有效实现可以从一次环境内执行示范中获得，并在新记录上复用。**

“开放世界”在本 benchmark 中操作化为：系统事先不知道哪些资源有用、怎样组合使用，但可访问的材料和工具在实验开始前冻结。它不意味着必须开放实时互联网，也不意味着没有辅助材料就无法输出答案。

需要分别验证的三个假设：

1. 环境资源能改善关键步骤及其下游结果。
2. Agent 在环境中的执行具有可重复利用的过程，逐次探索产生额外成本。
3. 从单次轨迹提取的算子能在未见记录上保留效果，并摊薄探索和构造成本。

三者都不是已证实结论。环境增益可以来自知识或工具；是否需要运行时分支是另一项实验问题。若最终提取的是有效的固定程序，应如实报告，不为“动态”预先加入无用机制。

## 2. 构造单位与验收条件

一个 benchmark 单位是 `(环境快照 E, 固定任务 T, 示范记录 x0, 后续输入关系 R, 私有评分依据 G)`，不是一个孤立 QA。

一个 task family 的各记录共享谓词或参数化转换目标；数据可变，证据布局和必要分支也可变。不能将几百道任意问题包装为一个“判断问题是否成立”的表面统一任务。

| 条件 | 必须提供的证据 |
|---|---|
| 默认路径可执行 | 完整任务输入、可评分输出；不通过截断必需输入人为制造失败 |
| 环境资源有用 | 在同一输入上加入知识/工具的对照，而非只展示资源清单 |
| 关键步骤影响下游 | 固定下游，分别输入预测中间结果和 gold 中间结果，测差异 |
| 存在过程复用 | 指明哪些检索方法、解析步骤、工具配置、逻辑检查适用于后续记录 |
| 单次示范成立 | 每个提取出的算子只使用一条轨迹；示范选择规则和所有失败尝试可追溯 |
| 能独立评分 | 既有人工标注或新增独立标注，不把 Agent 输出变成 gold |
| 数据湖真实可核验 | 原始资源有来源、版本和关联依据；新增业务规则显式标为 benchmark 自定义 |

## 4. 数据任务 A：工业组件完整性与异常筛选

### 4.1 真实业务对应与任务边界

对应工业视觉质检中的批量异常筛查。首先使用原数据支持的“异常/正常”目标，不把它提升为没有 gold 的安全评级、实际返修决策或医学诊断。

固定 DAG：`scan 产品记录 → sem_filter 异常判定 → project 待复核记录 → group/count 按产品类别汇总`。

共享谓词：**按照该类别的正常结构与异常定义，图中产品是否存在结构或逻辑异常？**

第一批优先检查 LOCO 的 pushpins、screw_bag、splicing_connectors。先分别按类别构造任务，再验证跨类别复用；一次 pushpins 示范不能自然推出适用于其他产品的工具策略。

默认实现：通用视觉模型读取图片和产品类别后直接判断。环境增强的候选实现：读取正常定义、选择训练集正常参考图、局部查看、比较组件数量/位置；必要时调用经过独立验证的检测或分割工具。是否提升准确率尚待实验。

### 4.2 数据湖内容

| 资源 | 现有/拟补建 | 使用约束 |
|---|---|---|
| 查询图片、产品类别、原始来源 | 现有；重新建立公开 manifest | 类别可公开，缺陷类别和答案不可公开 |
| 正常参考图片 | 作者提供正常训练图及参考入口 | 每个系统可访问同一候选池；不把 test 图混入参考池 |
| 类别知识 | MMAD 已发布 `domain_knowledge.json` | 审计生成材料；若使用测试图总结，仅作有污染风险的辅助实验 |
| 图像查看、裁剪、相似图检索 | 拟提供通用工具 | 索引由公开材料生成，裁剪不得使用 gold mask |
| 专用检测/分割模型及 model card | 尚未选定，需补建 | 必须核实权重、类别覆盖、训练数据、许可证、硬件及运行质量；不能假定存在有效权重 |
| 异常标签、mask、QA 答案 | 现有私有 gold | 只允许评分器访问 |

真实元数据样例：`MVTec-LOCO/pushpins/test/good/000.png` 的异常判断答案为 No，因此该谓词 gold 为 FALSE。这只是本次读取的发布标签，未查看图片、未人工复标。该路径中的 `good` 泄漏答案，公开实例必须更换为不含标签的 ID；原路径仅保留在私有映射中。[固定版本样例源](https://raw.githubusercontent.com/jam-cc/MMAD/1490f887b9570613565fa6a7b15d5f81aa183c54/dataset/MMAD/mmad.json)

本次只读统计：LOCO 子集共 1,566 个图片记录，其中 breakfast_box 275、juice_bottle 330、pushpins 310、screw_bag 341、splicing_connectors 310。它们是原始候选数，未做去重和分割。对当前 `conversation` 字段计数为 39,670，与 README 的 39,672 不同；构造版本必须用实际文件统计，不静默修正或混用。

### 4.3 如何承载单次轨迹转算子

从一次执行中候选提取：类别资源定位、参考图选择方法、必要视觉观察、数量/位置关系检查、输出规范。样例图片 ID、具体计数和已得答案不能写死进算子。

先测试“一类别一条示范→同类别未见图像”；不同单条示范分别训练独立算子，报告方差。跨产品类别作为后续迁移测试，不混入第一阶段结论。

下游指标：异常复核清单 precision/recall、每类别异常数量绝对误差；若另建固定处置规则，只能称为自建模拟分流，不称真实工厂处置 gold。定位为独立扩展，不在没有验证时与异常筛选混成一个分数。

关键否决条件：知识文本存在实例泄漏且无法清理；专用工具表现不优于默认路径；固定“正常参考图+类别知识”基线已完全解决，而轨迹提取无额外成本收益。最后一种可保留为简单负对照。

## 5. 数据任务 B：合同终止后信息保留例外审查

### 5.1 输入与固定任务

使用 ContractNLI 原生固定命题 `nda-20`：在返还或销毁保密信息后，接收方是否仍可保留部分保密信息。语义以原英文命题为准，不自行更换法律口径。

固定 DAG：`scan 合同全文 → sem_map 证据与三值结论 → filter 明确允许保留 → project 复核清单`。

主要算子输出 `{decision: TRUE|FALSE|UNKNOWN, evidence_spans}`；Entailment→TRUE，Contradiction→FALSE，NotMentioned→UNKNOWN。UNKNOWN 不代表明确禁止，也不等于执行失败 ABSTAIN。

该任务要求在同一合同内结合定义、主体、返还/销毁条款及例外；完整文档本身就是默认输入。不得靠把关键条款移出默认输入来制造环境优势。

### 5.2 辅助环境与重复处理

公开湖包含合同全文及原始 span 边界、可获得的原 PDF、文档结构索引、章节/定义引用、通用条款类别说明，以及文档搜索和引用跟踪工具。PDF 可达性尚未核验，不以“有 PDF 名称”冒称已具有视觉数据。

辅助规则说明仅解释判断流程、术语和证据要求，不增补合同没有约定的事实。CUAD 类别说明可作为候选背景资源，是否适用本命题需验证；外部法律不能覆盖 ContractNLI 的文本蕴含标注。领域手册若由研究者编写，必须注明自建、版本、编写材料和是否看过测试样例。

候选提取内容：先定位信息返还/销毁，再追踪保留、备份、法定义务等相关例外；解析适用主体和范围；读取交叉引用；输出支撑或反驳证据。具体关键词和路径只是待验证方法，不是作者数据集提供的标准流程。

同文档多命题场景可以复用全文解析和关系抽取；同命题跨文档可以复用判断策略。两项分别报告，不能用缓存带来的收益替代策略复用证据。

真实记录：原 train 文档 `id=34`，`nda-20` 标为 NotMentioned，因此本任务 gold 为 UNKNOWN；该文档 `nda-16` 标为 Entailment，证据 span 为 39、40。它说明“要求返还/销毁”并不能直接推出“禁止任何保留”。本次只核验字段，未独立复核法律内容。[固定数据包](https://raw.githubusercontent.com/stanfordnlp/contract-nli/eced6528dd3c1d14d73f9a87df8f7bdbc03126f9/resources/contract-nli.zip)

### 5.3 规模与局限

本次读取到 train/dev/test 分别为 423/61/123 文档。一个固定命题的原生 test 只有 123 条，不能称为上千条独立合同。第一阶段保留原 split：示范只从 train 选择，dev 用于预注册后的方法开发，test 锁定评分。

若需要几百条确认集，可在实现前建立独立文档级重划分并公开与原 split 的关系，但不得在看完模型结果后重划。用 17 个命题扩充可以增加文档—命题对数量，却不能增加独立文档数；不同命题应分别作为任务，不混报单一算子的样本量。

否决条件：当前强长上下文模型已接近满分且无效率空间；辅助知识无稳定增益；NDA 长度不足以承载“长文本”主张。必须统计实际 token 长度和关系难度，不能单凭合同类型认定长文困难。

## 6. 数据任务 C：财务指标提取、口径统一与阈值筛选（第二阶段）

业务对应：批量阅读报告，提取同一种指标及其年份、单位、分母或比较基期，形成可核验指标表，再按给定阈值筛选。第一阶段聚焦一个指标 family，例如同口径收入增长率；最终指标选择由原始样本可用量决定。

固定 DAG：`scan 报告记录 → sem_map 指标/期间/单位/证据 → deterministic_compute → filter 阈值 → project 筛选清单`。

环境：报告页图、可独立获得的 OCR、保留合并单元格的表格结构、页码与章节、指标术语说明、表格读取/页面查看/计算器工具。默认 VLM 仍得到必要页面；增强环境提供更可靠的结构化读取与计算方式。

候选来源是 TAT-DQA；TAT-QA 提供文本表格对照；MultiHiertt 补充多表层级。它们原本是 QA benchmark，不是已经存在的同指标批任务，必须先做 family census：按问题文本和报告字段识别候选，再独立审核语义一致性。不能借 gold 推导选择每条最有利的处理路径。

构造有两种合法方式：

1. 原生映射：找到足够多语义一致的问题，把答案/单位映射为指标值；新阈值是事先固定的 benchmark 配置，最终 gold 由核验后的指标确定。
2. 重新标注：从真实报告中抽取同一指标所需材料，双人独立标注值、年份、口径和证据。属于自建任务，不沿用原 QA gold 的名义。

禁止将页面视觉任务宣称为长篇完整报告任务；若需完整报告，必须重新获取并核对来源与页码。没有足够同 family 样本时，保持为小规模诊断，不用任意 QA 凑千条。

评分：指标值和单位正确率、年份/口径正确率、证据命中、阈值筛选 F1、最终名单和聚合误差。只提升计算器算术不一定体现轨迹提取价值；须比较直接生成固定抽取+计算程序。

## 7. 数据湖最小结构与工具契约

构建两个领域内自洽的湖（工业、合同），金融通过可行性后加入。统一访问协议即可，不把不相关领域随意拼成一个目录来制造异质性。

建议结构（尚未创建）：

```text
public_lake/
  manifest.json                # 来源、版本、哈希、资源类型
  records/                     # 待处理记录；稳定无答案 ID
  raw/                         # 原始文本、图片、表格或 PDF
  references/                  # 正常样本、类别说明、手册
  relations/                   # 实体、文档引用、页表关联及来源
  tools/registry.json          # 工具说明、输入输出、版本、成本模型
  tools/docs/                  # 真实用法、限制和示例
private_eval/
  source_id_map.jsonl
  gold.jsonl
  splits.json
run_artifacts/
  demonstration_trace.jsonl
  learned_operator/
  predictions.jsonl
  costs.jsonl
```

每条资源记录至少包含 `resource_id, source_uri, version, sha256, modality, entity_or_category, provenance, license_status`。关系边注明源字段或抽取来源；模型抽取边不当成人工确定事实。

通用工具按实际需要实现：`search_resources`、`open_document`、`read_table`、`follow_reference`、`view_image/crop_image`、`retrieve_reference`、`run_model`、`calculate`。工具不实现 `get_gold` 或隐藏人工语义判断；索引和模型输出必须由公开材料独立计算。

每个专用模型的注册项包含任务范围、训练材料、权重哈希、预处理、输出解释和成本。昂贵共享预处理单独计费；所有系统可以在相同条件下缓存，不把一次全湖预计算藏进工具。

不做权限系统。评分材料与运行材料通过隔离目录和明确读取边界区分，执行工具只提供该实验所需能力。

湖大小先服从语义完整性：保留选定发布范围的全部相关类别/文档和自然存在的其他资源；后续用同领域无关资源按 1×/5×/10× 扩张检验发现成本，明确这是受控扩张，不宣称真实企业湖分布。

| B0 | 默认静态语义步骤，完整原始输入 | 默认质量和成本是多少？ |
| B1 | 静态步骤+公开知识/正常参考，固定选择方法 | 资源直接加入是否已经足够？ |
| B2 | 固定检索/固定工具流程，允许预写条件分支 | 是否只需普通程序，而无需 Agent 逐次探索？ |
| B3 | Coding Agent 根据任务和同一环境一次性生成批处理程序 | 我们是否优于直接写程序？ |
| B4 | Data Agent 批处理，允许共享缓存和公开中间产物 | 强 Agent 的批量质量—成本前沿是什么？ |
| B5 | 我们的方法从一条 Agent 示范提取算子 | 单次轨迹转算子是否有增益？ |
| B6 | 相同示范的文字摘要/简单参数化重放 | 是否优于简单经验复用？ |

DocETL/Palimpzest 作为优化型比较对象，在确认适配成本后纳入；不得把已有优化能力省略成单次裸调用。固定物理计划也能含分支，必须公开其资源获取与控制逻辑。

进行两组不同目的的实验：

- 环境价值实验：B0 与逐项加入知识、文档结构、工具的版本比较。此处信息条件不同，只说明环境增益。
- 算子提取实验：B1–B6 共享可访问资源、base model、最大预算与评分协议；比较轨迹带来的质量保持和效率收益。

提供“无轨迹、仅任务+环境”的提取器消融，隔离新增轨迹信息；B3 与 B5 使用相当的构造预算。若提取器可读开发集 gold 或运行额外样例，须单独命名监督设置，不能仍称严格单次示范实验。

对每一条示范独立生成一个算子，禁止合并其他示范轨迹。开发阶段可用多个独立 one-trace episode 测方法稳定性；确认集不用于挑选最好的示范或算子。失败示范的重试次数和筛选成本全计入，并同时报告无条件表现及成功示范条件下表现。

## 9. 划分、gold 与规模

先每条主线用 20–30 条不进入确认集的记录检查资源和标签；随后冻结示范池、开发集和确认集。方法设计与资源补建在确认实验前完成。

工业同图不同 QA、近重复图、原图/裁剪、同物体多视图视为同一分组；合同按文档及模板近重复分组；金融按报告/公司年份和来源重叠分组。不能只按 QA ID 随机切分。

目标：2 个可跑主任务，第三个金融任务条件成熟再加入。每类主任务期望 200–1,000 条后续记录；受真实来源限制时如实缩小。工业可按类别报告约百条级确认结果，合同原 test 为 123 文档；扩展到更多记录需新增来源或重新标注。批规模曲线采用实际可用的 10/30/100/300/1,000 点，不重复复制记录假装独立样本。

gold 保留原标签与证据，新增复杂组合谓词必须重新核验。所有争议、缺证、未标注和运行失败分别记录：`UNANNOTATED`、gold `UNKNOWN`、execution `ABSTAIN`、`INVALID_RECORD` 不互相替代。

公共数据集可能被模型预训练见过；无法证明“未训练领域知识”。使用领域依赖、时间切分和新材料可以测试鲁棒性，但仍需明确污染不确定性。专用工具如果在原 benchmark 上训练，只在其未见划分上评估并公开训练范围。

## 10. 指标与通过门槛

不把用时、Token、准确率相乘为唯一分数。报告质量—成本前沿，并在预先指定质量容忍度下比较效率。

质量包括关键步骤 macro-F1/各类 recall、证据充分性、下游名单 F1/计数误差、ABSTAIN 覆盖率。延迟包括首次构造、批次 wall-clock、p50/p95；成本包括输入/输出 token、模型调用、工具调用、GPU/CPU 时间与总费用。报告并发、缓存与服务配置。

总成本：`C_ours(N)=C_demo+C_extraction+C_validation+C_shared_preprocess+Σ C_operator(i)+C_fallback`。与实际允许共享状态的 Agent 总成本比较；回退不能只计成功算子部分。若存在近似稳定边际成本，可估算回本点，但最终以实测批曲线为准。

建议门槛属于设计参数，须在确认实验前冻结：

- 可行性阶段：目标记录的 gold 与必要输入均可达；争议样例独立裁决；资源增益有方向一致的证据。
- 确认阶段：提取算子相对 Agent 的质量下降不超过预注册非劣界（可先讨论 2 个百分点），同时总成本显著降低。样本太小导致置信区间过宽时报告“不足以确认”，不把点估计当证明。
- 使用文档/图像分组配对 bootstrap 或合适的配对区间，避免将同一文档上的多命题当独立样本。
- 分别移除知识、工具、关系结构、缓存和轨迹提取，定位增益来源。用 gold 中间结果替换关键步骤输出，检验下游误差传播。

## 11. 执行里程碑与停止条件

| 阶段 | 行动与可交付物 | 完成条件 |
|---|---|---|
| M0 来源核验 | 主候选 resource inventory、许可证、split/标签/schema、20–30 条人工可审样例 | 原始数据、辅助资源、私有 gold 三者界限清楚 |
| M1 两个最小数据湖 | 工业与合同 frozen manifest、工具 registry、固定 DAG、评分脚本 | 无答案路径/参考泄漏，工具可复现运行 |
| M2 环境增益试验 | B0/B1/B2/Agent 小规模比较和失败分类 | 找到真实资源增益，或明确否决该候选 |
| M3 单次示范协议 | 固定示范选择、episode 划分、trace schema、B3/B6 | 任一算子只使用一条轨迹且成本完整 |
| M4 批量确认 | 未见记录上 B1–B6、成本曲线、下游与消融结果 | 质量保持与成本收益可判断，允许阴性结果 |
| M5 第三任务/迁移 | 金融 family census 或新增工业类别 | 独立来源足够且 gold 可核验；否则不扩展 |

第一轮执行顺序：先核验 MMAD 领域知识与 LOCO gold，再完成 ContractNLI 固定命题环境；金融先统计同 family 可用量，避免提前投入完整报告湖建设。本文尚未执行 M1–M5。

如果 Agent 与静态程序无稳定差距，但从轨迹得到的程序能节省构造或执行成本，可以报告效率结果，不能据此声称静态算子存在表达能力障碍。若单次轨迹不能迁移，报告失败边界；多轨迹扩展必须作为新设置。

## 12. 必须对照的论文与新颖性问题

| 论文/系统 | 已核实相关点 | 本研究需要区别或对照的部分 |
|---|---|---|
| [LOTUS / Semantic Operators，2024 预印本](https://arxiv.org/abs/2407.11418) | 可组合语义操作及其多种执行实现 | 新增的是从执行示范学习实现；不能把“算子”定义成只能一次 prompt |
| [DocETL，PVLDB 2025](https://arxiv.org/abs/2410.12189) | 面向复杂文档的 agentic query rewriting 与评估 | 与查询重写/长文分解的差异，必须通过同资源实验说明 |
| [Palimpzest，2024 预印本](https://arxiv.org/abs/2405.14696) | 声明式 AI 数据分析及质量/成本/延迟优化 | 区分既有候选实现选择与从一条环境轨迹产生新实现 |
| [Agent Workflow Memory，2024 预印本](https://arxiv.org/abs/2409.07429) | 从经验归纳并复用工作流 | 对比文字 workflow memory，测可执行算子与批处理复用增益 |
| [SKILL-DISCO，2026-06 预印本](https://arxiv.org/abs/2606.26669) | 将成功轨迹归纳、编译为可执行过程技能 | 与核心方向高度接近；需阅读全文核对单/多轨迹、控制流表示和实验范围 |
| [Agent Distillation，2025-05 预印本](https://arxiv.org/abs/2505.17612) | 用轨迹训练带检索/代码工具的小模型 | 与无需权重训练的任务算子提取区分；若实际训练权重则需直接比较 |

以上相关性来自论文摘要和官方项目第一轮核验，并非完成全文系统综述。不能预先宣称“首次从 Agent 轨迹学算子”。本 benchmark 的拟议特征是同一异质环境中的单次示范、固定批任务、下游误差传播、完整摊销成本及关系算子契约；是否构成研究新颖性需要进一步核对。
